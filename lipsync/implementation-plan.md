# lipsync 実装計画書

要求仕様 [lipsync.md](lipsync.md) を実装へ落とす計画。TDDで見出し単位のステップを進める。本書は仕様を
変更せず、仕様が実装での確定に委ねた詳細(母音合成プロファイルの初期値・各生成パラメータの初期目安・
アルゴリズム)を定め、着手順序とテスト方針を決める。仕様と矛盾が生じた場合は仕様(lipsync.md)を正とし、
本書を直す。

---

## 1. 前提と依存

- 実装言語 Python 3.11+。`mmd_toolbox` 本体の必須依存 `numpy`/`scipy` の範囲に収める(重い依存を増やさない)。
- VMD のモーフキー書き出しは `mmd_toolbox.vmd.io` / `mmd_toolbox.vmd.types`。`lipsync` はVMDのバイナリ構造を
  直接扱わない。
- **`lipsync` コアは決定論的な純粋変換**: 入力(開き量を同梱した口形イベント列と生成パラメータ。§4.7)から
  モーフキー列を生成する。音声・vpr・RMS・外部ツール・ネットワークに依存しない(入力の作り方は呼び出し側。
  lipsync.md §6)。
- 生成パラメータ(タイミング・誇張)の**具体値**は呼び出し側(各CLIのプリセット)が与える。本計画は `lipsync`
  が持つ既定(母音合成プロファイルの初期重み)とアルゴリズム、および各パラメータの初期目安を定める。

---

## 2. 実装ステップ(着手順)

各ステップは「テスト作成 → レビュー → 収束ならコミット」「実装 → レビュー → 収束ならコミット」を回す。
入力は合成した口形イベント列(各イベントに開き量を同梱。§4.7)＋生成パラメータのフィクスチャで与え、外部依存を持たない。

| ステップ | 内容 | 主な受入条件 |
|---|---|---|
| L-0 | 雛形・データ型: 口形イベント(母音/両唇閉鎖/無音＋時刻・モーラ境界)、開き量、生成パラメータの型。モーフキー出力と `mmd_toolbox` 連携 | 入力型を受け取りモーフキー列を返す骨組み。VMD出力がラウンドトリップする |
| L-1 | 母音合成プロファイル(4.1): 母音→標準口モーフ重み、開き量スケール、母音別倍率、上限クランプ、誇張係数の適用 | 各母音が既定プロファイルで複数モーフへ重みを置く。合成総量が上限を超えない |
| L-2 | 形状(4.9): アタックで開き・保持・リリースのキー配置 | 短いアタック/リリースと一定保持。保持中フレーム揺れなし |
| L-3 | 同母音連結(4.2): 連続同一母音を一保持区間へ統合、節点で開き量を線形変化 | 境界で再アタック・閉口を挟まない。開き量差は緩やかに反映 |
| L-4 | 協調調音(4.3): 隣接母音の遷移長を口形差・区間長・両唇閉鎖有無で決定 | 口形差が大きいほど短い中間口形。短いモーラで自動短縮 |
| L-5 | 先行準備(anticipation): 母音口形を音の開始より先行。両唇音は子音開始までに閉口完成 | 先行が前区間長で自動短縮され前区間を侵食しない |
| L-6 | 最小保持(4.4): 最小保持未満の区間を併合/間引き | 小刻みなパクつきが出ない。短区間が前後へ吸収/併合される |
| L-7 | きびきび遷移: 直前口形を次キー直前まで保持してから切替 | 線形補間のだらだらした移行が出ない |
| L-8 | 子音・無音の閉口キー: 両唇閉鎖で一瞬の閉口、無音/休符で全母音0付近 | 入力の口形イベントどおり閉口キーが入る(音量判定はしない) |
| L-9 | 疎キー配置・30fps量子化(4.5): 要所に疎キー、整数フレーム量子化、キー衝突解決 | 全フレームに置かない。量子化後にキー重複・欠落が出ない |
| L-10 | 任意の伸び表現: 長い母音にゆるやかな揺らぎ | 一定長超の母音にのみ控えめに適用。既定で過剰にならない |

依存関係: L-3〜L-7 は L-1/L-2(プロファイル・形状)に依存。L-9 は全ステップの出力を整数フレームへまとめる。

## 3. テスト方針(共有コア回帰の既知値フィクスチャ)

- `mmd_toolbox` のテスト規約(pytest・決定論・乱数シード固定・ネットワーク/GPU 不要)に従う。
- **共有コアの回帰はツール間比較では捉えられない**: `song2vmd` と `vpr2vmd` は同じ `lipsync` コアを通るため、
  両者の出力を突き合わせても共有コアの不具合・回帰は相殺されて見えない。よってコアの正しさ・回帰は
  **既知値フィクスチャ**で別途担保する(ツール間比較では代替しない)。
- 入力(開き量同梱の口形イベント列・生成パラメータ。§4.7)→モーフキー列 の決定論的変換を、合成した入力フィクスチャと
  手書きの**既知の期待キー値**(モーフ名・フレーム・ウェイト)で双方向に検証する。出力VMDはラウンドトリップでも
  確認する。
- 各ステップの振る舞い(プロファイル合成、協調調音の遷移長、同母音連結、最小保持の併合/間引き、量子化の
  衝突解決)を、それぞれ独立した決定論的ユニットテストで検証する。
- テストデータはファイルとして持たず、テストコード内のフィクスチャとして組み立てる(MMD産ファイルは不要。
  `lipsync` コアは音声・vprを介さないため)。

## 4. 確定する詳細(初期値・アルゴリズム)

仕様が実装での確定に委ねた項目を、初期値と手順としてここで確定する。値は出発点で、視覚確認で調整する。
**時間はフレーム(30fps、1秒=30フレーム)基準**で扱い、最終的に整数フレームへ量子化する。プリセット別の
具体値(タイミング・開き量レンジ・誇張係数の数値)は各CLIが与え、本書は既定プロファイルとアルゴリズム、
各パラメータの初期目安を定める。**データ型とコア関数の契約は §4.7、生成パラメータの一覧・既定値(初期目安)は
§4.8** で確定する(L-0 の「型」の正本)。

### 4.1 母音合成プロファイル(初期重み)

各母音の口形を標準口モーフの重みの組として定義する(保持値1.0時の相対重み。行=目的母音、列=標準口モーフ)。

| 目的母音＼モーフ | あ | い | う | え | お |
|---|--:|--:|--:|--:|--:|
| あ | 1.0 | – | – | – | – |
| い | 0.1 | 1.0 | – | – | – |
| う | – | – | 1.0 | – | 0.2 |
| え | 0.2 | 0.2 | – | 1.0 | – |
| お | – | – | 0.2 | – | 1.0 |

表中の **–** は重み **0.0(寄与なし)** を表す(空欄・未設定ではない)。

- **主モーフと補助モーフ**: 各目的母音と同名の標準口モーフ(あ→"あ"・い→"い"・う→"う"・え→"え"・お→"お")を
  主モーフとし、同じプロファイル行で主モーフ以外に非ゼロ重みを持つモーフを補助モーフとする(表中 0.0 の
  モーフは寄与しない)。
- **合成値の算出順**(決定論):
  1. 目的母音のプロファイル行を選ぶ(表中 **–** は 0.0)。
  2. 補助モーフの重みに誇張係数 `exaggeration` を掛け(主モーフの重みには掛けない)有効プロファイルとする。
     誇張係数は呼び出し側のプリセットが与え、補助重みの増減でアニメ的な分かりやすさを調整する(既定 1.0)。
  3. 保持値 `hold = clamp(open_amount × vowel_scale[目的母音], 0.0, open_cap)` を求める(母音別倍率は
     呼び出し側が与える。既定 1:1:1:1:1)。
  4. 各モーフの暫定重みを `raw[m] = 有効プロファイル[m] × hold` とする。
  5. `sum(raw)` が `open_cap` を超える場合のみ、全モーフの暫定重みに `open_cap / sum(raw)` を掛けて
     比例縮小し、プロファイルの重み比を保ったまま合成後の総量を `open_cap` に収める(超えない場合は縮小しない)。
- **クランプは2段**: 保持値 `hold` の `open_cap` クランプ(手順3)と、合成後総量の比例縮小(手順5)のみとし、
  各モーフを個別に `open_cap` で頭打ちする処理は行わない。最終値は 0.0 未満を 0.0・1.0 超を 1.0 に防御的に
  丸めてよいが、既定値ではこの丸めに依存しない。
- **出力モーフ名・エンコード**: 標準口モーフは "あ"/"い"/"う"/"え"/"お" の5モーフ。出力は
  `mmd_toolbox.vmd.MorphKey`(`name_raw` は cp932・15バイト固定)。閉口は専用モーフを設けず全母音を 0.0 に
  落として表す(lipsync.md §3・§4)。プロファイル重みは `lipsync` の既定として持ち、`GenerationParams` とは
  別に定義する(誇張係数で補助重みのみ調整。差し替えは初期スコープ外)。

### 4.2 同母音連結

- 連続する同一母音区間を1つの保持区間へ連結する(再アタック・閉口を挟まない)。連結対象は時間順
  イベント列内で **shape が同一母音のまま連続する極大列**とする。両唇閉鎖・無音は母音合成プロファイルの
  対象外なので、同母音連結の境界として扱う。**1イベントだけの列は §4.9 の単一区間形状に一致**する。
- 同母音グループ `e_1..e_n`(時刻 `start_1` < 各内部境界 `b_i = end_i = start_(i+1)` < `end_n`)には、
  **先頭にのみアタック・末尾にのみリリース**を置き、内部境界には 0.0 キー・閉口キー・再アタックキーを
  置かない。保持領域を `hold_start = start_1 + attack_frames`、`hold_end = end_n - release_frames` とする。
- 連結後も、元の各小区間の開き量に対応する強弱節点を保持領域内に残し、節点間はモーフキーの線形補間
  ([vmd-interp.md](../mmd_toolbox/vmd-interp.md))で緩やかに保持値を変える。各モーフについて次のキーを置く:
  - **アタック**: `(start_1, 0.0)`・`(hold_start, w_1)`。**リリース**: `(hold_end, w_n)`・`(end_n, 0.0)`。
  - **強弱節点**: 各小区間 `e_i` の中央 `mid_i = (start_i + end_i) / 2` に、その小区間の保持値 `w_i` を置く。
    これにより各小区間は中央付近でその開き量を保ち、境界付近で次の開き量へ緩やかに遷移する。単一区間の
    グループは内部に開き量差が無く、強弱節点を別途置かずに §4.9 の単一区間形状へ帰着する。
- 各節点の保持値 `w_i` は §4.1 の合成手順で小区間ごとの `open_amount` から求める。同一グループ内では
  母音プロファイルは共通で開き量(保持値)だけが小区間ごとに変わるため、各モーフは同じ節点位置で重み
  `w_(i,m) = プロファイル_m × hold_i` を持つ。
- 本節は `hold_start ≤ mid_1 ≤ … ≤ mid_n ≤ hold_end` を満たす通常長のグループを対象とする。グループ長が
  短くこれを満たせない場合は本節で独自に短縮せず、§4.4 の最小保持・競合短縮で処理する。本節の時刻は
  フレーム単位の目標位置で、整数フレーム量子化・同一フレーム衝突・隣接キーのずらしは §4.5 でまとめて行う。

### 4.3 協調調音の遷移長

- 隣接母音の遷移長 = clamp( 基準長 ×(1 − 0.5・口形差), 1, min(重なり上限, 短い側区間長の1/2) ) を四捨五入で
  整数フレーム化する(基準長=重なり上限。初期目安は §4.8)。**口形差が大きいほど遷移を短くして素早く切り替える**
  (差ゼロ=同一母音は連結)。
- **口形差**(0〜1): 両母音の合成プロファイル(4.1の重み)の正規化ユークリッド距離。
- 間に両唇閉鎖があれば閉口を優先し、母音間遷移は作らない。両唇閉鎖以外の子音種別による微調整は将来対応
  (口形イベントに子音種別を加える。lipsync.md §3)。

### 4.4 最小保持・競合短縮

- **最小保持未満の区間**: 隣接が同一母音なら併合(連結)し、異なる母音なら隣接側の遷移へ吸収して間引く
  (独立キーを置かない)。どちらへ吸収するかは隣接区間の開き量が大きい側を優先する。
- **区間内の競合短縮(優先順位)**: 1区間でアタック+リリース(+遷移)が区間長に収まらない場合、保持を最優先で
  確保し、アタック/リリースを比例縮小(各最小1フレーム)。先行(anticipation)は前区間長の1/2を超えない範囲へ
  自動短縮し、協調調音の重なりは隣接区間長の1/2を上限とする。優先順位は 保持 > アタック/リリース >
  先行・協調調音。

### 4.5 疎キー配置・量子化

- 各母音区間につき要所(開き始め・保持・遷移直前・閉じ)に疎にキーを置く。全フレームには置かない。
- **30fps 整数フレームへの量子化**: 四捨五入する。同一モーフ・同一フレームに複数キーが衝突したら最後に
  決まる目標値へ統合し、隣接キーと潰れて重なる場合は後続キーを最小1フレームずらす。

### 4.6 任意の伸び表現

- 一定長(例 0.6秒)超の母音にのみ、保持値を中心としたゆるやかな開閉の揺らぎを加える(初期: 振幅 ±0.05・
  周期 ~0.5秒。既定は控えめ)。フレーム単位の細かな追従はしない。揺らぎ量は呼び出し側が調整できる。

### 4.7 データ型とコア契約

`lipsync` コアの公開データ型と関数契約をここで確定する(L-0 の「型」の正本)。型は Python の dataclass /
Enum で表す。時刻はすべてフレーム(30fps、float)。

- **口形種別** `MouthShape`(列挙): `A` / `I` / `U` / `E` / `O`(母音 あ/い/う/え/お)、`BILABIAL`(両唇閉鎖)、
  `SILENCE`(無音・休符)。`BILABIAL` と `SILENCE` は出力上はどちらも閉口(全母音 0.0)だが、両唇閉鎖は
  閉口完成のタイミングを持つため生成上の扱いを区別する(lipsync.md §3・§4、4.3)。
- **口形イベント** `MouthEvent`: `shape: MouthShape`、`start: float`(開始フレーム)、`end: float`(終了フレーム)、
  `open_amount: float`(開き量 0〜1、母音区間のみ有意。既定 0.0)。1イベント=1モーラ(lipsync.md §2)。
- **イベント列の契約**: 時間順・隙間なく連続(終端=次の始端)・非重複・全時間軸被覆(lipsync.md §2)。
  これを破る入力は呼び出し側の不備とし、コアは前提として扱う。
- **生成パラメータ** `GenerationParams`: §4.8 の各フィールドを持つ平坦な dataclass。既定値は §4.8(初期目安)。
  具体値は呼び出し側プリセットが上書きする(lipsync.md §2.3。具体値の例は song2vmd 実装計画 §4.4。vpr2vmd は
  本既定を用い実データで調整する。vpr2vmd 実装計画 §5)。
- **コア関数**: `generate_morph_keys(events: Sequence[MouthEvent], params: GenerationParams) -> list[MorphKey]`。
  決定論的な純粋変換(乱数・外部依存なし)。入力時刻は float フレームで受け、出力 `MorphKey.frame`(int)へは
  4.5 の規則で量子化する。返すのは時間順の `mmd_toolbox.vmd.MorphKey` 列(あ/い/う/え/お)。`VmdDocument` への
  組み立て・VMD書き出し(`mmd_toolbox.vmd.io`)・他セクション(ボーン等)は呼び出し側が行う(lipsync.md §5)。

### 4.8 生成パラメータの一覧・初期目安

`GenerationParams` の各フィールド。意味は lipsync.md §2.3 が正本で、ここで名前・単位・`lipsync` 既定(初期目安)を
確定する。既定は出発点で、各CLIプリセットが上書きする(具体値の例は song2vmd 実装計画 §4.4。vpr2vmd は本既定を
用い実データで調整する。vpr2vmd 実装計画 §5)。フレーム単位は30fps。

| フィールド | 意味(lipsync.md §2.3) | 単位 | 既定(初期目安) |
|---|---|---|--:|
| `open_cap` | 開き量の上限(開けすぎ防止) | 0〜1 | 0.8 |
| `vowel_scale` | 母音別の開き量倍率(a, i, u, e, o) | 倍率 | (1, 1, 1, 1, 1) |
| `attack_frames` | アタック(開き) | フレーム | 2 |
| `release_frames` | リリース(閉じ) | フレーム | 2 |
| `transition_frames` | きびきび遷移(直前口形を保持してから切替) | フレーム | 2 |
| `min_hold_frames` | 最小保持 | フレーム | 3 |
| `coartic_overlap_max` | 協調調音の重なり上限(=4.3 の基準長) | フレーム | 2 |
| `anticipation_frames` | 母音口形の先行準備(≤2) | フレーム | 1 |
| `exaggeration` | 母音合成プロファイルの誇張係数(補助重みへ乗算) | 倍率 | 1.0 |
| `vibrato_threshold` | 伸び表現を適用する母音長の下限 | フレーム | 18(=0.6秒) |
| `vibrato_amp` | 伸び揺らぎの振幅 | 0〜1 | 0.05 |
| `vibrato_period` | 伸び揺らぎの周期 | フレーム | 15(=0.5秒) |

- `open_cap` は保持値クランプの上限であると同時に、§4.1 の合成後総量(誇張適用後)を比例縮小で収める上限でも
  ある。`lipsync` 既定は lipsync.md §3 の「強い声で 0.8 前後」に合わせた保守的な上限 **0.8**。各CLIは必要に
  応じ上書きする(song2vmd は `--open-max` で上書きし `pop` では 0.90)。適用順は §4.1。
- `open_cap` を除くタイミング・誇張の既定(アタック2/リリース2/遷移2/重なり上限2/先行1/最小保持3/誇張1.0)は
  song2vmd の `pop` プリセット(同 §4.4)と整合させた出発点。`open_cap` だけは `lipsync` の保守的既定(0.8)で、
  song2vmd `pop`(0.90)とは独立に上書きされる。`vibrato_*` は 4.6 の初期値で、消費側が渡さない場合はこの既定が
  使われる。

### 4.9 形状(アタック・保持・リリース)

各母音区間の名目エンベロープ(形状の出発点)を定める。§4.1 で求めた各モーフの保持値 `w_m` に対し、単一の
孤立した母音区間 `[start, end]` につき、各出力モーフへ次の4点を置く:

1. `(start, 0.0)` — 区間開始は閉口 0.0。
2. `(start + attack_frames, w_m)` — アタックで保持値 `w_m` まで開く。
3. `(end - release_frames, w_m)` — 区間の大半を `w_m` で一定保持する。
4. `(end, 0.0)` — リリースで閉口 0.0 へ戻る。

これにより短いアタックで開き、保持区間を一定値に保ち、短いリリースで閉じる。保持中はフレーム単位で揺らさない
(揺らぎは §4.6 の伸び表現でのみ任意に加える)。

- **対象は通常長の区間**: 本節は `start + attack_frames < end - release_frames` を満たす区間を対象とする。
  アタックとリリースが競合する短区間(`start + attack_frames ≥ end - release_frames`)は本節で独自にクランプ
  せず、§4.4 の最小保持・競合短縮で処理する(前提を満たした区間が本節へ渡る)。
- **境界の扱いは前段の名目形状**: 孤立区間は閉口 0.0 から開き、閉口 0.0 へ閉じる。連続同一母音での境界の
  再アタック・閉口の回避は §4.2、隣接母音の協調調音による境界の中間口形は §4.3 が決め、本節はその前段の
  名目形状を与える。両唇閉鎖・無音区間の閉口キーは、その区間の口形イベントに従って別途置く(L-8)。
- **量子化は別管轄**: 本節の時刻はフレーム単位の目標位置として扱う。整数フレームへの量子化、同一モーフ・
  同一フレームのキー衝突解決、隣接キーが潰れた場合のずらしは §4.5 でまとめて行う。本節では同一フレームに
  重複する 0.0 キー(隣接区間の閉じと次区間の開き)をそのまま残してよい。

## 5. リスクと未確定

- **パラメータ初期値**: プロファイル重み・遷移長・最小保持などの既定値は §4.1/§4.7/§4.8 で確定済み(実装は
  これを正本とする)。ただし値は出発点であり、MMD/MMM 上の視覚確認で調整の余地がある。変更が要るときは実装で
  独自に決めず、本計画(必要なら仕様 lipsync.md)を先に更新してから実装と整合させる(§6)。
- **入力の多様性**: `vpr2vmd`(vpr由来)・`song2vmd`(音声由来)の双方が作る口形イベント列・開き量で破綻
  しないこと。両者の差は入口側で吸収され、`lipsync` には同じ抽象入力(lipsync.md §2)で渡る前提。

## 6. 仕様への影響

- 仕様(lipsync.md)の記述変更が必要な不整合は無い。本計画は仕様が実装での確定に委ねた詳細(4章)の置き場で
  あり、仕様の決定を覆さない。
- 実装着手後に 4章の数値確定で仕様の前提が崩れた場合は、正本である lipsync.md を先に更新してから本計画と
  実装を整合させる。
