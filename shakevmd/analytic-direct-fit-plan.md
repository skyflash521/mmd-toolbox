# 改修計画(将来): shakevmd 滑らか出力の解析直接フィット化

ステータス: 将来の改修案(未着手・未スケジュール)。まず §5 の設計未確定点を確定し、
試作で §6 の効果(MMD 60fps 目視)を確認できてから本実装へ進む(効果確認は B-2' の試作を要するため、
試作を本実装前の工程に置く)。

## 1. 現状と動機

shakevmd の `--smooth`(既定 on)は、`bake()` が(FOV 温存区間=ゆっくりズームを除く)整数フレームへ密キーを
焼いた後、その密キー列を共有エンジン `mmd_toolbox.vmd.reduce.reduce_camera_track` に通して aggressive 許容内の
疎ベジェへ削減する(以下 B-1)。削減対象は **30fps 整数フレームのサンプル**で、誤差判定も整数フレームで行う。

B-1 は手ぶれ振幅を整数フレームで許容内に保つ(平坦化しない)。一方で **キー間(60fps 等のサブ
フレーム再生位置)での真の揺れへの追従は保証しない**。本計画は、揺れの解析ソースを連続時刻で直接
フィットしてサブフレーム忠実度を高める改修(以下 B-2')を将来課題として記す。

## 2. 提案(B-2')

bake が合成する**解析揺れの全成分(ノイズ・モーション適応・呼吸ドリフト・歩調 gait・settle・フェード・
インパルス)を連続時刻の評価関数として扱い**、整数フレームのキー値にはその評価値を用いつつ、**フィットの
采否をサブフレーム(60fps 相当)での真の信号との誤差で制御**する。出力は B-1 同様、整数キー＋区間ベジェ。
連続化で一部成分(呼吸ドリフト・歩調・settle 等)を落とすと walking 等の挙動を失うため、bake の全成分を
漏れなく連続評価に載せる(対象成分は `shakevmd/bake.py` を正とする)。

リデュースエンジン(チャンネル評価器・分割ドライバ・ベジェフィット)は既に
`mmd_toolbox/vmd/{reduce.py,fit.py}` に共有済み。本改修は「整数キー列ソース」に加えて
**連続ソース(実数時刻の評価関数)をサブフレームで誤差評価する経路**をエンジンへ足し、shakevmd が
それを駆動する形になる。

## 3. B-1 比の具体的な優位と限界

優位(主に高周波・速いトランジェント・帯域上限 8Hz 付近で顕在):

- **サブフレーム誤差が真の信号に対して有界**。B-1 は整数フレームでしか誤差を見ないため、キー間で
  ベジェが真の揺れからずれうる(強インパルスではサブフレームで密出力から無視できない乖離が出る=
  実測で数度規模)。B-2' は 60fps 位置でも許容内に収める。
- **折返し(極値=速度0)近傍で端傾き(イーズ)を真の信号へ近づけうる**。B-1 は整数サンプルの離散差分しか
  持たず、折返しが整数上か中間かも区別できない。B-2' はサブフレーム誤差評価で連続信号に追従するので
  端傾きが整数差分ベースより真の傾きへ寄りうる。ただし**値残差の最小化だけでは端傾きは保証されない**
  (値が合っても傾きはずれうる)。確実に付けるには端傾きを微分制約として目的関数へ加える必要がある(§5 の未確定点)。
- **「サンプルの再フィット」二重損失を回避**(解析→整数化→再フィット ではなく 解析→直接フィット)。

限界(B-2' でも改善しない天井):

- VMD キーは整数フレームのみ、MMD のベジェは1区間=単調イーズ1本。**整数フレーム間に真の極値が
  あると B-1/B-2' とも表現できない**(キーが極値近傍に来ない限り)。ピーク振幅自体は上がらず、差は
  あくまで**キー間の追従**に出る。
- 低周波(既定 `--freq` 1.2Hz)では B-1 との差は小さい。
- 体感効果は未検証(§6)。「原理的に上」は「体感で有意」を意味しない。

## 4. 対象ファイルと規模(概算)

- `shakevmd/bake.py`(中核): 揺れを連続時刻評価へ作り替え、誤差制御フィットを駆動。
- `mmd_toolbox/vmd/reduce.py` ・ `fit.py`: 連続ソースをサブフレームで誤差評価する経路を追加。
- `shakevmd/cli.py`: `--smooth` 配線の変更(軽微)。
- テスト: shakevmd 側・mmd_toolbox reduce 側にサブフレーム経路の回帰。

概算 約 400〜700 行(中核は `bake.py` と `reduce.py`/`fit.py`)。

## 5. 設計上の未確定点(着手前に確定)

- **非整数極値の整数キー化**: サブフレーム極値を近傍整数へ寄せる / 両側整数を境界にする /
  誤差分割に委ねる、のいずれか。
- **連続化の範囲**: `motion_damp`・速度プロファイル・停止検出(settle)は現状、整数フレーム列から
  計算している。どこまで連続時刻化するか。
- **B-1 経路の扱い**: B-2' で置換するか、B-1 を残して切替にするか。
- **FOV**: 整数度保存のため、疎キー＋イーズで緩和しても完全解決ではない。視野角温存区間との整合。
- **端傾き(C1)の与え方**: サブフレーム誤差評価による値追従だけで十分か、折返し近傍で端傾きを
  微分制約として目的関数へ明示的に加えるか。現行 `fit.py` は値残差のみを最小化する(§3 の端傾きの優位は前者前提)。
- **サブフレーム誤差の判定基準**: 「60fps 位置でも許容内」(§2・§3)を判定するための評価点(各整数フレーム間の
  どのサブフレーム位置を見るか)・チャンネル別の誤差尺度と許容値・合格条件。現行 `reduce_camera_track()` の
  許容検証は整数フレーム対象なので、サブフレーム経路の判定基準を別途定義する必要がある(§6 の目視と併せて決める)。
- **連続信号(サブフレーム比較の「真の信号」)の定義**: bake() の出力は元カメラ軌道に揺れを合成した値で、
  元軌道は `interp.sample_camera()`(整数フレーム API)で得て `apply_gaze_shake()` で揺れと合成する。サブフレームで
  比較する真の信号を一意にするには、元カメラ軌道の実数時刻補間・揺れ全成分(§2)との合成方法・カット/FOV温存
  境界での扱いを定義する必要がある。モーション適応も元軌道のワールド位置・角速度に依存するため、その連続時刻化も含める。

## 6. 検証

効果は **MMD の 60fps / 無制限再生での目視確認が必須**。代表素材は「ほぼ静止〜緩いパン＋高周波の
揺れ」(極値が密に出る最悪条件)。判断軸はブルブルが減るか・質感が丸まりすぎないか・キー削減率。
比較は整数フレームだけでなくサブフレーム誤差でも B-1 と突き合わせる。
