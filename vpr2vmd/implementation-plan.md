## 1. 前提と依存

- 実装言語 Python 3.11+。
- 依存モジュール: [vpr_io](../vpr_io/vpr_io.md)(vpr 解析)、[lipsync](../lipsync/lipsync.md)(モーフ生成
  コア)、`mmd_toolbox.vmd.io`(VMD出力)。`vpr2vmd` はこれらを束ね、vpr 固有の入口処理を担う。
- 音声・認識・RMS には依存しない(入力が vpr のため。vpr2vmd.md §2)。

## 2. 実装ステップ(着手順)

各ステップは「テスト作成 → レビュー → 収束ならコミット」「実装 → レビュー → 収束ならコミット」を回す。

| ステップ | 内容 | 主な受入条件 |
|---|---|---|
| P-0 | CLI骨組み・引数パース・`--dry-run` の空実行 | CLIが起動し引数を解釈する |
| P-1 | vpr 読み込み: `vpr_io` で音符(時刻・ピッチ・歌詞・音素・強弱)・休符・テンポを取得 | 代表 vpr から音符・休符・テンポが取り出せる |
| P-2 | 口形イベント列の確定: 音素→母音(a/i/u/e/o)・両唇閉鎖・撥音(ん。`--no-n-morph` で無音)、促音/休符→無音、継続/母音なしは直前口形継続。テンポから時刻⇔フレーム変換 | 音素列から母音・両唇閉鎖・撥音「ん」(`--no-n-morph` 時は無音)・無音の口形イベント列(全時間軸被覆、口を不自然に開けない)が決定論的に得られる |
| P-3 | 開き量: vpr のベロシティ(0–127)→開き量。一様なら既定 | ベロシティがモーラ別開き量へ写像される。全ノート一様な vpr で既定開き量になる |
| P-4 | `lipsync` 接続・VMD出力: 口形イベント列＋開き量＋生成パラメータ→`lipsync`→モーフキー→`mmd_toolbox.vmd.io` | 1コマンドで vpr→口パクVMDを生成。モーフキーのみ・他セクション空 |
| P-5 | プリセット・レポート/診断(`--style`/`--report-json`/`--dry-run`)・公開時タスク | プリセットで開き量レンジ・タイミングが切り替わる。統計を出力 |

依存関係: P-2/P-3 は P-1(vpr_io 解析結果)に依存。P-4 は P-2/P-3 の出力を `lipsync` へ渡す。
`vpr_io` の write は不要(`vpr2vmd` は vpr を読むのみ)。

**公開時タスク**: ツール公開時に README のツール表へ `vpr2vmd` を追記する(README 本体は指示があるまで
変更しない)。

## 3. テスト方針

- `mmd_toolbox` のテスト規約(pytest・決定論・乱数シード固定・ネットワーク/GPU 不要)に従う。
- **入口処理の決定論テスト**: 口形イベント確定(音素→母音/両唇閉鎖、休符→無音、時刻変換)と開き量写像
  (強弱→開き量、既定)を、合成した vpr 解析結果(`vpr_io` のデータモデルのフィクスチャ、または `vpr_io`
  モック)を入力に決定論的に検証する。
- **共有コア回帰は既知値フィクスチャで担保**: モーフ生成コア(`lipsync`)の正しさ・回帰は、`vpr2vmd` と
  音声入力ツールの**ツール間比較では捉えられない**(同じ `lipsync` コアを通るため相殺される)。コアの回帰は
  [lipsync 仕様](../lipsync/lipsync.md) §7 の既知値フィクスチャで別途担保する(ツール間比較で
  代替しない)。
- **E2E**: 小さなサンプル vpr で vpr→VMD を通し、モーフキーVMDが生成されることを確認する。
- 出力VMDはラウンドトリップと既知値フィクスチャで検証する(モーフキーの値・フレーム・名称(Shift-JIS))。

## 4. サンプルデータと検証設計

- **vpr2vmd 用データは安い**: 音声と対の vpr(または vpr 単体)は比較的容易に用意でき、実在アセットを使える。
  口形イベントは vpr から確定的に得られ、正解の手作業を要さない。
- **E2E比較の用途**: `vpr2vmd` の出力(同じ vpr から作る口形イベント列・口パク)は、音声入力ツールの入口側
  誤差を見る**比較材料**として使える(同じ vpr を入れた両者の出力を突き合わせ、入口差を確認する)。
- **未監査 vpr は補助比較に限る**: vpr は書き起こしで実発音と食い違いうるため、未監査の vpr は厳密な正解
  ではなく**補助比較**に限る(正式な合否判定には監査済みデータを使う。本ツール単体の正しさは §3 の決定論
  テストと既知値フィクスチャで担保する)。
- **共有コア回帰の担保**: ツール間比較では共有コアの回帰を検出できないため、既知値フィクスチャ(§3)で
  別途担保する。

机上で確定できる入口処理(音素写像・時刻変換・ベロシティ写像)を §5.1〜§5.3 に確定する。実データ・実 vpr で

### 5.1 音素→口形イベントの写像(確定)

入力は `vpr_io` の各 `Note`(`phonemes: list[str]`(音符内の音素列。空可)・`start_tick`・`duration_tick`・
`velocity` 等)。休符(無音区間)は `vpr2vmd` が重複音符の解決後の採用音符列から再導出する(下記「解析範囲・休符の
再導出」。`vpr_io` も発音区間の補集合として休符を導出するが、`vpr2vmd` は自前の解決後区間を基準にする)。次の規則で
口形イベント列(母音 A/I/U/E/O・両唇閉鎖 BILABIAL・撥音「ん」 N・無音 SILENCE。
[lipsync 仕様](../lipsync/lipsync.md) §4.7)へ決定論的に写像する。

写像は**音素のカテゴリ**(母音 / 語頭両唇音 / 撥音 / 促音 / 継続 / その他子音 / 未知)で規則を定める。各音素記号が
どのカテゴリに
属するか(およびどの母音か)は `vpr_io` が確定する音素インベントリに従い(§5.4)、実装者が独自判断しない。
カテゴリ確定後の写像規則は記号集合に依存せず以下で確定する。

- **母音**: phonemes 中の母音音素を、その母音に対応する母音イベント(あ/い/う/え/お)にする。母音記号→
  `MouthShape` の対応は母音の同一性で一意に決まる(`vpr_io` インベントリで各記号がどの母音かが定まる。VOCALOID
  日本語では a→あ / i→い / u(M)→う / e→え / o→お が該当する見込みだが、正確な記号綴りは §5.4 の vpr_io 確定に
  従う)。1音符に複数母音があれば各母音を順に1モーラずつのイベントにする(時間配分は下記)。
- **両唇閉鎖**: 音符の語頭(phonemes 先頭)に両唇音があれば両唇閉鎖イベントにし、後続母音の開始までに閉口を
  完成させる(閉口完成のタイミングは `lipsync` 仕様 §4.10・§4.11)。語中・語末の両唇音は自前イベントを作らない。両唇音の
  記号集合(VOCALOID 日本語では m / b / p が該当する見込み)は §5.4 の vpr_io 確定に従う。
- **その他の子音**: 自前の口形イベントを作らず、隣接母音の協調調音へ委ねる([lipsync 仕様](../lipsync/lipsync.md) §4.3。
  両唇閉鎖以外の子音種別は `lipsync` が将来対応)。
- **休符**: 発音区間どうしの隙間を無音イベント(SILENCE)にする。休符区間は `vpr_io` の元発音区間ではなく、
  重複音符の解決後の**採用音符列の補集合**として再導出する(基準・範囲は下記「解析範囲(全時間軸)・休符の
  再導出」。切り詰めで生じた空白も SILENCE で埋める)。先頭休符(解析範囲先頭〜最初の音符)も無音とし、出力は
  閉口から始める。末尾の閉口は最後の母音のリリースで作る。
- **撥音「ん」**(後続母音を持たない単独の鼻音 `N\`): 既定では「ん」イベント(`MouthShape.N`)に、`--no-n-morph`
  (vpr2vmd.md §4.2)指定時は無音(閉口)イベントにする。撥音は閉じた鼻音なので母音「あ」へ倒して口を開けない。
- **促音「っ」**(`Q`): 無音(閉口)イベントにする(閉鎖・詰まりの見た目)。
- **未知音素**(`vpr_io` インベントリで母音・両唇音・撥音・促音・継続・その他子音のいずれの既知カテゴリにも該当しない記号): 自前イベントを作らず、
  母音と共起すれば「その他の子音」と同じく協調調音へ委ねる。診断に記録するが、それ自体では母音イベントを作らない。
- **母音が得られない音符**(継続記号のみ・その他子音のみ・未知音素のみ・`phonemes` 空、いずれも): 既定母音へ倒さず
  (歌詞 `lyric` からの母音推定もしない。歌詞→音素は `song2vpr`/認識側の責務)、採用音符列を時間順に組み立てる段階で
  **直前の確定口形を継続**する(直前が母音なら母音、撥音「ん」なら「ん」、閉口なら閉口)。直前の口形が無ければ
  無音(閉口)とする。これにより口が不自然に開かない。当該音符は `vpr2vmd` の診断(`--report-json`/`--dry-run`)に
  「母音未確定」として記録する。**既定母音『あ』へのフォールバックは行わない**(MMD の見た目で口を開けないため)。

**音符内の時間配分**(`MouthEvent.start`/`end` の決定): `vpr_io` の `Note` は音符単位の時刻(`start_tick`/
`duration_tick`)のみで音素ごとの時刻を持たないため、音符区間 `[s, e)`(フレーム。§5.2 で算出)を次の規則で
音素イベントへ割り当て、隙間なく・非重複でタイルする(`lipsync` §4.7 のイベント列契約)。音符間は採用音符列の
補集合として再導出した休符=SILENCE が埋め、全時間軸を被覆する(下記「解析範囲・休符の再導出」)。

- **語頭両唇閉鎖の取り分**: 語頭に両唇音があれば閉鎖イベント `[s, s + d_b)` を音符先頭に置く。
  `d_b = min(両唇閉鎖の公称長, (e − s) × 取り分上限)`。初期値は公称長 **3フレーム**・取り分上限 **0.5**(出発点。
  実データ調整は §5.4)。両唇音が無ければ `d_b = 0`。
- **母音の等分**: 残り区間(`[s + d_b, e)`)に含まれる母音 `k` 個を**区間長で均等分割**して順に割り当てる
  (`k = 1` なら残り区間全体)。母音を持たない音符(`k = 0`)は母音区間も語頭両唇閉鎖も作らず、音符区間全体を
  上記「撥音・促音・母音が得られない音符」の規則(「ん」/無音/直前口形継続)で埋める。語頭両唇閉鎖は母音を伴う
  音符にのみ作る(母音の無い両唇音だけの音符は実際に現れず、作っても後続母音が無いため)。これにより BILABIAL と
  重複せず、隙間なく非重複でタイルする。
- **ゼロ長・負長を作らない**: `d_b` は取り分上限でクランプし、母音区間は常に正の長さを持つ。極小区間の併合・
  間引きは `lipsync`(§4.4 最小保持)が行うため、`vpr2vmd` は等分結果をそのまま渡してよい。

**対象トラック・解析範囲・重複音符**(全時間軸の確定): `lipsync` の口形列は単一の口に対応するため、`vpr2vmd` は
単一の歌唱トラックを対象とする。`vpr_io` が「解析範囲(曲の総尺)は呼び出し側が定める」とする部分
([vpr_io.md](../vpr_io/vpr_io.md) §2)を、`vpr2vmd` は次で確定する。

- **対象トラック**: `VprProject.tracks` が複数ある場合、既定で先頭トラック(`tracks[0]`)を用い、`--track NAME|INDEX`
  で選択できる。複数トラックを混ぜない(同時発音は口形が重なるため)。**`--track` の解釈**: 引数が整数として
  解釈できれば **0-based の INDEX**(`tracks[INDEX]`。`tracks[0]` が先頭。範囲外はエラー)、そうでなければ
  `Track.name` 名と解釈する。**NAME が複数トラックに一致**したときは曖昧として**エラー**にし、INDEX 指定を促す
  (黙って先頭を選ばない)。一致無しもエラー。選択トラックの全パートの音符を統合し、`(start_tick 昇順, duration_tick
  降順, パート出現順, パート内の音符インデックス昇順)` を tie-break として安定整列して扱う。
- **解析範囲(全時間軸)・休符の再導出**: 重複音符の解決(下記)**後**の採用音符列を基準とする(`vpr_io` の元発音
  区間ではなく、`vpr2vmd` が切り詰め・除外した後の区間を基準にする)。先頭=フレーム `0`、末尾=採用音符列の最後の
  発音区間の終端(全 `note.end` の最大を §5.2 でフレーム化した値)。**休符(SILENCE)は採用音符列の発音区間の補集合**
  として `[0, 末尾]` 内で導出する(先頭〜最初の音符は先頭休符。切り詰めで生じた空白も補集合に含まれ SILENCE で
  埋まるため、被覆漏れを残さない)。末尾に追加の無音区間は設けず、出力末尾の閉口は最後の母音のリリース(`lipsync`)で
  作る。これにより `lipsync` の全時間軸被覆契約を満たす「全時間軸」を `vpr2vmd` 側で一意に定める。
- **重複音符**: 選択トラックは単音(monophonic)前提で、`vpr_io` が発音区間の重なりを `VprWarning` で報告する
  ([vpr_io.md](../vpr_io/vpr_io.md) §3.2)。`vpr2vmd` は上記の安定整列順に並べたうえで、次の2段階で
  非重複化する(`lipsync` の非重複契約を満たす)。`vpr_io` の警告を継承し、除外・切り詰めはいずれも診断に記録する。
  1. **同一 `start_tick` の重複除外**: 開始が等しい音符は整列順の先頭(=最長、次いでパート出現順)だけを残し、
     残りを重複として除外する。これで残った音符は `start_tick` が相異なる。
  2. **後続開始への切り詰め**: 残った音符(開始が相異なり昇順)について、各音符の終端を「開始が厳密に後ろの次の
     音符の開始」までに切り詰める(`end := min(end, 次音符の start)`)。切り詰めで長さが 0 以下になる音符は除外する。
  整列が決定的なので、採用・除外・切り詰め後の音符列は一意に定まる。
- **採用音符列が空のとき**: 対象トラックに音符が無い、または上記2段階で全件が除外された場合は、解析範囲を空
  (末尾=`0`)、口形イベント列も空とする。`lipsync` へ空列を渡してモーフキー 0 件の VMD を出力し(他セクションは
  空。§5 全体方針どおり)、診断に「対象トラックに有効な発音がない」と記録して警告する(エラーにはせず、空出力で
  決定的に終える)。

本節は写像の**規則**と音符内時間配分を確定するもので、各音素記号がどのカテゴリに属するかのみ `vpr_io` の
インベントリ確定(§5.4)に従う。

### 5.2 時刻⇔フレーム変換(tick→秒→フレーム)(確定)

`vpr_io` は時刻を tick(整数、`resolution`=tick/四分音符)で渡し、テンポは `tempos`(`list[TempoEvent{tick, bpm}]`)で
渡す。秒・フレームへの変換は持たない([vpr_io.md](../vpr_io/vpr_io.md) §2.1・§6)。

- **tick→秒**: テンポマップの区分積分。各テンポ区間 `[tick_i, tick_{i+1})` は `bpm_i` 一定とし、1 tick の秒数 =
  `60 / (bpm_i × resolution)`。tick `t` の絶対秒 = (各先行区間の tick 幅 × その区間の 1tick秒数)の総和 +
  `(t − tick_k) × 現区間の 1tick秒数`(`tick_k` は `t` を含む区間の開始)。最初の `TempoEvent.tick` が 0 で
  なければ、その bpm を tick 0 まで遡って適用する。
- **秒→フレーム**: `frame_float = 秒 × 30`(30fps、`mmd_toolbox` 規約)。各音符・休符の開始/終了 tick をこの式で
  float フレームに変換し、`lipsync` の `MouthEvent.start`/`end`(float)へ渡す([lipsync 仕様](../lipsync/lipsync.md) §4.7)。
- **整数フレーム量子化は `lipsync` が行う**(同 §4.5)。`vpr2vmd` 側では float フレームのまま渡し、量子化・キー
  衝突解決は持たない。
- **拍子は使わない**: `TimeSignature`(numerator/denominator)は小節・拍の構造であり、tick→秒の絶対時間変換には
  `resolution` と `tempos` のみで足りる。本変換で拍子は参照しない。

### 5.3 ベロシティ→開き量の写像・プリセット(確定)

`vpr_io` の `Note.velocity`(0–127、常在・int)を各モーラの開き量へ写像する。シンボリックな強弱指定で入力ゲインに
不変(RMS のような信号量ではない)。

- **写像式**: 正規化 `n = velocity / 127`、累乗 `γ`(初期 0.6。[song2vmd 実装計画](../song2vmd/implementation-plan.md) §4.4 の
  RMS→開き量と整合)で `open = lo + (hi − lo) × n^γ`、開き量レンジ `[lo, hi]`(プリセット)へクランプ、`--open-max`
  で上限。決まった開き量を `lipsync` へ渡す(合成プロファイルへの適用・合成総量の上限クランプは `lipsync` 側。
  [lipsync 仕様](../lipsync/lipsync.md) §4.1)。
- **`--default-open`**: 全ノートのベロシティが一様で強弱差(ダイナミックレンジ)が 0 のとき、写像式が定数に退化
  するため全モーラへ用いる既定開き量。既定はプリセット開き量レンジの中央 `(lo + hi)/2`。ベロシティが変化する
  通常入力では写像式を用い、`--default-open` は使わない(旧仕様の「強弱が無いとき」を、ベロシティ常在の事実に
  合わせ「ベロシティが一様で強弱差が無いとき」と確定)。
- **プリセット**(`--style`、既定 `pop`): 開き量レンジとタイミング/誇張を切り替える。[song2vmd 実装計画](../song2vmd/implementation-plan.md) §4.4
  のプリセット表と整合させた出発点(タイミング・誇張は `lipsync` の `GenerationParams` へ渡す。値の意味は
  [lipsync 仕様](../lipsync/lipsync.md) §4.8)。

  | 項目 | pop | ballad | powerful | whisper | rap |
  |---|--:|--:|--:|--:|--:|
  | 開き量レンジ(弱〜強) | 0.30–0.75 | 0.20–0.55 | 0.40–0.95 | 0.10–0.35 | 0.30–0.70 |
  | `--open-max` 既定 | 0.90 | 0.70 | 0.97 | 0.50 | 0.85 |
  | アタック | 2 | 3 | 1 | 2 | 1 |
  | リリース | 2 | 3 | 1 | 2 | 1 |
  | 協調調音 重なり(上限) | 2 | 3 | 2 | 2 | 1 |
  | 先行(anticipation) | 1 | 1 | 2 | 1 | 1 |
  | 最小保持 | 3 | 4 | 3 | 3 | 2 |
  | 合成誇張係数 | 1.0 | 0.8 | 1.3 | 0.7 | 1.0 |

### 5.4 リスクと未確定(実データ・実 vpr で確定)

- **プリセット具体値の調整**: §5.3 の開き量レンジ・タイミング・誇張・`γ`、および §5.1 の両唇閉鎖の公称長
  (3フレーム)・取り分上限(0.5)は出発点で、実データ(MMD/MMM 視覚確認)で調整する。`lipsync` の既定プロファイル・
  アルゴリズムは [lipsync 仕様](../lipsync/lipsync.md) §4 を用いる。
- **vpr 形式の確定**: `vpr_io` の read 実装(vpr レイアウト確定。[VPR_file_format.md](../docs/specs/vpr/VPR_file_format.md))が
  `vpr2vmd` の前提になる。§5.1 が用いる音素記号の具体集合・各記号のカテゴリ割当(母音/語頭両唇音/撥音/促音/継続/
  その他子音/未知)はこのインベントリ確定で定まる(写像規則自体は §5.1 で確定済みで、記号集合に依存しない)。
