# vpr2vmd 実装計画書

要求仕様 [vpr2vmd.md](vpr2vmd.md) を実装へ落とす計画。TDDで見出し単位のステップを進める。本書は仕様を
変更せず、仕様が実装での確定に委ねた詳細を定め、着手順序とテスト方針を決める。仕様と矛盾が生じた場合は
仕様(vpr2vmd.md)を正とし、本書を直す。

---

## 1. 前提と依存

- 実装言語 Python 3.11+。
- 依存モジュール: [vpr_io](../vpr_io/vpr_io.md)(vpr 解析)、[lipsync](../lipsync/lipsync.md)(モーフ生成
  コア)、`mmd_toolbox.vmd.io`(VMD出力)。`vpr2vmd` はこれらを束ね、vpr 固有の入口処理を担う。
- 音声・認識・RMS には依存しない(入力が vpr のため。vpr2vmd.md §2)。

---

## 2. 実装ステップ(着手順)

各ステップは「テスト作成 → レビュー → 収束ならコミット」「実装 → レビュー → 収束ならコミット」を回す。

| ステップ | 内容 | 主な受入条件 |
|---|---|---|
| P-0 | CLI骨組み・引数パース・`--dry-run` の空実行 | CLIが起動し引数を解釈する |
| P-1 | vpr 読み込み: `vpr_io` で音符(時刻・ピッチ・歌詞・音素・強弱)・休符・テンポを取得 | 代表 vpr から音符・休符・テンポが取り出せる |
| P-2 | 口形イベント列の確定: 音素→母音(a/i/u/e/o)・両唇閉鎖、休符→無音。テンポから時刻⇔フレーム変換 | 音素列から母音・両唇閉鎖・無音の口形イベント列(全時間軸被覆)が決定論的に得られる |
| P-3 | 開き量: vpr の強弱(ベロシティ/ダイナミクス)→開き量、無ければ既定 | 強弱がモーラ別開き量へ写像される。強弱が無い vpr で既定開き量になる |
| P-4 | `lipsync` 接続・VMD出力: 口形イベント列＋開き量＋生成パラメータ→`lipsync`→モーフキー→`mmd_toolbox.vmd.io` | 1コマンドで vpr→口パクVMDを生成。モーフキーのみ・他セクション空 |
| P-5 | プリセット・レポート/診断(`--style`/`--report-json`/`--dry-run`)・公開時タスク | プリセットで開き量レンジ・タイミングが切り替わる。統計を出力 |

依存関係: P-2/P-3 は P-1(vpr_io 解析結果)に依存。P-4 は P-2/P-3 の出力を `lipsync` へ渡す。
`vpr_io` の write は不要(`vpr2vmd` は vpr を読むのみ)。

**公開時タスク**: ツール公開時に README のツール表へ `vpr2vmd` を追記する(README 本体は指示があるまで
変更しない)。

## 3. テスト方針

- `mmd_toolbox` のテスト規約(pytest・決定論・乱数シード固定・ネットワーク/GPU 不要)に従う。
- **入口処理の決定論テスト**: 口形イベント確定(音素→母音/両唇閉鎖、休符→無音、時刻変換)と開き量写像
  (強弱→開き量、既定)を、合成した vpr 解析結果(`vpr_io` のデータモデルのフィクスチャ、または `vpr_io`
  モック)を入力に決定論的に検証する。
- **共有コア回帰は既知値フィクスチャで担保**: モーフ生成コア(`lipsync`)の正しさ・回帰は、`vpr2vmd` と
  音声入力ツールの**ツール間比較では捉えられない**(同じ `lipsync` コアを通るため相殺される)。コアの回帰は
  [lipsync 実装計画](../lipsync/implementation-plan.md) の既知値フィクスチャで別途担保する(ツール間比較で
  代替しない)。
- **E2E**: 小さなサンプル vpr で vpr→VMD を通し、モーフキーVMDが生成されることを確認する。
- 出力VMDはラウンドトリップと既知値フィクスチャで検証する(モーフキーの値・フレーム・名称(Shift-JIS))。

---

## 4. サンプルデータと検証設計

- **vpr2vmd 用データは安い**: 音声と対の vpr(または vpr 単体)は比較的容易に用意でき、実在アセットを使える。
  口形イベントは vpr から確定的に得られ、正解の手作業を要さない。
- **E2E比較の用途**: `vpr2vmd` の出力(同じ vpr から作る口形イベント列・口パク)は、音声入力ツールの入口側
  誤差を見る**比較材料**として使える(同じ vpr を入れた両者の出力を突き合わせ、入口差を確認する)。
- **未監査 vpr は補助比較に限る**: vpr は書き起こしで実発音と食い違いうるため、未監査の vpr は厳密な正解
  ではなく**補助比較**に限る(正式な合否判定には監査済みデータを使う。本ツール単体の正しさは §3 の決定論
  テストと既知値フィクスチャで担保する)。
- **共有コア回帰の担保**: ツール間比較では共有コアの回帰を検出できないため、既知値フィクスチャ(§3)で
  別途担保する。

---

## 5. 確定する詳細・リスクと未確定

- **音素→母音/両唇閉鎖の写像**: vpr の音素体系(発音表記)に対する母音(a/i/u/e/o)・両唇閉鎖への写像表は
  実装で確定する(`vpr_io` が返す音素表現に依存)。
- **時刻変換**: vpr のテンポ・拍子から30fpsフレームへの変換規則・量子化は実装で確定する。
- **vpr 形式の確定**: `vpr_io` の read 実装(vpr レイアウト確定)が `vpr2vmd` の前提になる
  ([vpr_io 実装計画](../vpr_io/implementation-plan.md))。
- **生成パラメータの初期値**: プリセットの具体値は実データ(MMD/MMM 視覚確認)で調整する。`lipsync` の
  既定プロファイル・アルゴリズムは [lipsync 実装計画](../lipsync/implementation-plan.md) を用いる。

---

## 6. 仕様への影響

- 仕様(vpr2vmd.md)の記述変更が必要な不整合は無い。本計画は仕様が実装での確定に委ねた詳細(5章)の置き場で
  あり、仕様の決定を覆さない。
- `vpr_io` のレイアウト確定や写像の確定で仕様の前提が変わる場合は、正本である vpr2vmd.md を先に更新してから
  本計画と実装を整合させる。
