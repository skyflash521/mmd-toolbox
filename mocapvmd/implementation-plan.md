# mocapvmd 実装計画書

[mocapvmd 要求仕様書](mocapvmd.md) に基づき、モーションキャプチャー由来のボーンVMDをクリーニングしてから疎化まで1コマンドで行う独立CLIツールを実装するための計画。

---

## 1. 実装方針

### 1.1 責務分離

`mocapvmd` はモーションキャプチャー由来のノイズ軽減・足IK安定化・信号整形(クリーニング)と、それに続くキーフレーム疎化を1プロセス内で行う。疎化の中核機構は `mmd_toolbox.vmd.reduce` の共通実装を再利用し、再実装しない。

クリーニングは内部で30fps整数フレームの密サンプル上に行い、その結果に共通の削減機構を適用して疎なVMDを出力する。`--no-reduce` 指定時のみ、原因分析や比較のためにクリーニング後の密キーを出力する。

### 1.2 共通化と括り出し

疎化の中核(区間分割・キー削減・継ぎ目処理・誤差検証・ベジェ採否)は既に `mmd_toolbox.vmd.reduce` にあり、`sparsevmd.reduce` は薄い再公開層である。mocapvmd も同じ `mmd_toolbox.vmd.reduce` を直接使う。

mocapvmd はボーン選択を行わず全ボーンを処理するため、ボーン選択機構は共有しない(`sparsevmd.selection` の括り出しは不要)。削減の許容誤差プリセットは運用ポリシーのため各ツール側に持ち(`sparsevmd.presets` / `mocapvmd.presets`)、値は `sparsevmd` と共有せず mocap向けに定める。削減機構は共通の `mmd_toolbox.vmd.reduce` を使う。共通の `Tolerances` はカメラ枠を含むため、カメラを扱わない mocapvmd 用に、ボーン専用のトレランス構築ヘルパを `mmd_toolbox.vmd.reduce` へ追加する(1.3)。

### 1.3 共通削減機構の呼び出し契約

`mmd_toolbox.vmd.reduce.reduce_bone_track` は `source_keys, ranges, tols` と、既定値の無いキーワード引数 `cut_thresholds / keep_frames / no_cut_detect / min_seg / max_seg / strict` を要求する(`curve_mode` / `diagnostics` のみ既定あり)。mocapvmd はこれらを次のように解決する。

- `source_keys`: **範囲内はクリーニング済みの密キー(線形補間)、範囲外は元キーを逐語**で合成した1本のトラックを渡す。共通機構は範囲外要素をそのまま返すため、この合成により要求仕様3.3の範囲外逐語保持を満たす。
- `tols`: ボーン種別ごとに解決する(要求仕様 5.3)。プリセット基準値(`--reduce-preset` / `--reduce-error-bone-*`)に種別スケールを掛けた `bone_pos` / `bone_rot` を、その種別のトラックに渡す。`reduce_bone_track` はトラック単位に呼ぶため、トラックの種別に応じた `tols` を都度与える。共通の `Tolerances` はカメラ4フィールド(`camera_pos` / `camera_rot` / `camera_distance` / `camera_fov`)も既定値なしで必須なので、mocapvmd 側でカメラ値を指定せずに済むよう、`mmd_toolbox.vmd.reduce` にボーン専用のトレランス構築ヘルパ(`bone_pos` / `bone_rot` だけ受け取り、未使用のカメラフィールドはヘルパ内部で埋めて `Tolerances` を返す)を追加し、mocapvmd はそれ経由で `tols` を作る。
- `cut_thresholds / keep_frames / no_cut_detect / min_seg / max_seg / strict`: 固定値(`cut_thresholds=(1.0, 30.0)`(POS, ROT)、`no_cut_detect=False`、`keep_frames` 空、`min_seg=1`、`max_seg=15`、`strict=False`)を `mocapvmd.reduce` 内で与える。CLI公開はしない。`max_seg` は1区間を短く抑えて手編集しやすくし、区間長探索を減らして疎化を速くするため小さくする。
- `ranges`: 各トラックに渡す範囲は、処理範囲(`--range` または全範囲)と**そのトラックの実在キー区間との積集合**にする(`sparsevmd` の `_reduce_bones` と同じく `ranges.intersect(global, first, last)`)。`reduce_bone_track` は与えた範囲全体をサンプリングし、トラック外の範囲には端値を延長した人工キーを作るため、トラック区間外を渡さない。
- キーが1個以下のトラックは疎化できないため、`reduce_bone_track` に渡さず逐語保持する(`sparsevmd` 同様)。
- `curve_mode`: `--curve-mode`(既定 `bezier`)。

### 1.4 パッケージ構成案

```text
mocapvmd/
  __init__.py
  cli.py
  classify.py
  denoise.py
  foot.py
  presets.py    # クリーニング強度と疎化許容誤差の解決
  reduce.py     # mmd_toolbox.vmd.reduce の起動・パラメータ束ね
  report.py
  tests/
```

- VMD入出力・サンプリング・削減は `mmd_toolbox.vmd` の共通機能を使う。
- ボーン種別ごとの効かせ方は初期値で固定せず、実データで調整する前提でプリセット・レポート・プレビューを設計する。

## 2. 処理パイプライン

1. VMDを `mmd_toolbox.vmd.io` で読み込む。
2. ボーン名ごとにトラック化する。
3. 標準名・準標準名・英語名のパターンからボーン種別を推定する。
4. 全ボーンを処理対象とする(ボーン選択は行わない)。
5. 入力の各整数フレーム(30fps)のキー値をトラックの処理入力とする。初期実装は入力が1フレームごとの密なキーであることを前提とし、密化はしない。
6. ボーン種別ごとのクリーニングパラメータを解決する。分類できないボーンは `unknown` として、クリーニングは保守的な弱設定で解決する(疎化スケールは標準1.0)。
7. フィルタ適用前に、不連続・カット・大きな動作アクセント・範囲端の保護マスクを確定する。以降の平滑化はこのマスクを越えて平均しない。
8. 一般ノイズ軽減を全ボーンに適用する(`--no-denoise` 指定時は適用しない)。保護マスクで区切られた区間内だけで平滑化する。
9. 分類で `foot_ik` / `toe_ik` と判定したボーンを足IK安定化対象とし、接地区間を検出して接地中の位置ぐらつきを重点的に抑える(`--no-foot-ik-stabilize` 指定時は適用しない)。
10. 範囲内はクリーニング済みの密キー(線形補間)、範囲外は元キー逐語、を合成した削減入力トラックを各ボーンで組み立てる(1.3 の呼び出し契約)。
11. 全ボーンのトラックを `mmd_toolbox.vmd.reduce.reduce_bone_track` で疎化する。各トラックの範囲は処理範囲とトラック実在区間の積集合とし、キー1個以下のトラックは逐語保持する(1.3 の呼び出し契約)。許容誤差は `--reduce-preset` / `--reduce-error-*`、曲線は `--curve-mode`。必須パラメータは 1.3 のとおり解決し、カット検出・継ぎ目処理は共通機構に従う。`--no-reduce` 指定時はこの段を飛ばし、合成トラックの密キーをそのまま出力する。
12. ボーン以外の対象外セクション(モーフ・カメラ・照明・セルフ影など)を無加工で透過する。
13. 出力VMDを `mmd_toolbox.vmd.io` で書き出す。
14. レポートに処理量、最大変位、最大回転差、接地区間、疎化のキー削減率・最大再生誤差、警告を出す。

## 3. 実装ステップ

### 3.1 Step 1: 基盤・診断

実装内容:

- `mocapvmd INPUT --dry-run --report-json report.json` を追加する。
- `pyproject.toml` を更新する: `[project.scripts]` に `mocapvmd = "mocapvmd.cli:main"`、`[tool.setuptools.packages.find]` の `include` に `mocapvmd*`、`[tool.pytest.ini_options]` の `testpaths` に `mocapvmd` を追加する(現状は3項目とも除外されている)。
- 入出力パス検証、上書きガード、dry-run、report-jsonを実装する。
- 全ボーンを処理対象として扱う(ボーン選択オプションは設けない)。
- ボーン一覧、分類結果、キー数、フレーム範囲を出す。
- 足IK候補、つま先IK候補を検出する。
- フレーム間速度、回転角速度、スパイク候補、接地候補をレポートする。

完了条件:

- 実VMDを変更せず、どのボーンにどの処理が適用される予定か確認できる。
- 対象外セクションを無加工で透過できる設計になっている。
- report-jsonに分類結果が出る。

### 3.2 Step 2: ボーン分類とプリセット解決

実装内容:

- ボーン名から `root` / `center` / `torso` / `arms` / `fingers` / `legs` / `foot_ik` / `toe_ik` を分類する。
- `light` / `balanced` / `stable-foot` / `strong` プリセットを定義する。
- 種別ごとの窓幅、強度、最大変更量を解決する。
- 分類不能ボーンは `unknown` とし、クリーニングは保守的な弱設定、疎化スケールは標準(1.0)にする。
- チューニング対象になる値をreport-jsonへ出す。

完了条件:

- 標準・準標準・英語名の代表パターンをテストできる。
- dry-runとreport-jsonで分類とパラメータを確認できる。
- ボーン種別ごとの効かせ方を比較できる。

### 3.3 Step 3: 一般ノイズ軽減

実装内容:

- 位置チャンネルの中央値フィルタとSavitzky-Golay平滑化を実装する。
- quaternion回転の同一半球化と局所平滑化を実装する。
- ボーン種別別の窓幅・強度を適用する。
- アクセントと判定したフレーム(同方向2フレーム以上の大変化、4.1)、カット、不連続、範囲端を保護する。単発往復のスパイクは速度が大きくても保護せず補正する。
- 元値からの最大変更量を制限する(要求仕様 5.5: 1フレーム 位置0.3 MMD単位 / 回転5度 でクランプ)。
- `--denoise` / `--no-denoise` を実装し、一般ノイズ軽減の有効・無効を切り替えられるようにする。

完了条件:

- `center`、`torso`、`arms`、`legs` で微小ノイズが減る。
- 大きな動作アクセントが鈍りすぎない。
- `--no-denoise` では一般ノイズ軽減が適用されない。
- クリーニング後の密キーが、後段の疎化に渡せる線形補間トラックとして組み立てられる。

### 3.4 Step 4: 足IK接地安定化

実装内容:

- 足IK・つま先IK候補を分類し、左右ごとに足IKとつま先IKを対応付ける。
- 分類済みの足IK・つま先IKを安定化対象にする。
- 速度・Y変化・継続長・足IKとつま先IKの相対位置急変から接地区間を検出する。対応するつま先IKが無いモデルでは相対位置条件をスキップし、速度・Y変化・継続長で判定する。
- 接地アンカーを中央値で求める。
- `foot_ik` は接地中央でX/Zを強く安定化し(プリセット別の直接値、4.3 / 5.4。端は 0.25 からフェード)、`toe_ik` はX/Zロックを弱め(0.30)、つま先の動き・回転を保つ。
- Yは完全固定せず弱めに安定化する(`foot_ik` 0.50 / `toe_ik` 0.30。4.3 / 5.4)。
- `--preset` は `foot_ik` の X/Z 接地ロック値を切り替える(`stable-foot` が最強。倍率ではなく直接値)。`toe_ik` ロックはプリセットによらず弱め。
- 最大補正量(要求仕様 5.5: 接地区間で 0.5 MMD単位)を超える場合は警告し、補正を弱める。
- `--foot-ik-stabilize` / `--no-foot-ik-stabilize` を実装する。

完了条件:

- 接地中の足IK水平ぐらつきが明らかに減る。
- 遊脚中の足運びやステップ位置は不自然に固定されない。
- dry-run/reportで接地区間と補正量を確認できる。

### 3.5 Step 5: インプロセス疎化の統合

実装内容:

- `mmd_toolbox.vmd.reduce` にボーン専用のトレランス構築ヘルパ(`bone_pos` / `bone_rot` だけ受け取り、未使用のカメラフィールドは内部で埋めて `Tolerances` を返す)を追加する。mocapvmd はこれを使い、カメラ許容値を指定しない。
- 正本ドキュメント `mmd_toolbox/mmd_toolbox.md` に共通の削減機構(`vmd.reduce`)と上記ヘルパを反映する。
- クリーニング後の全ボーンの密トラックを `mmd_toolbox.vmd.reduce.reduce_bone_track` で疎化する処理を `mocapvmd.reduce` に実装する。
- `--reduce-preset` / `--reduce-error-bone-pos` / `--reduce-error-bone-rot` / `--curve-mode` / `--no-reduce` を実装する。許容誤差は種別ごと(プリセット基準値 × 種別スケール、5.3)に `mocapvmd.presets`(mocap独自値、`sparsevmd` と非共有)で解決し、トレランス構築は上記ヘルパ。
- 元VMD、クリーニングのみ(`--no-reduce`)、クリーニング+疎化の3種類を比較する。
- キー削減率、最大再生誤差、足IK接地中の水平移動量をレポートする。
- 参考として、クリーニングなしで同じ許容誤差で疎化した結果とキー数・見た目を比較する。

完了条件:

- 1コマンドで疎なVMDが出力され、再生誤差が許容値以内に収まる。
- クリーニングなしで疎化した場合より、同等以上の見た目でキー数が減る。
- 足IKの見た目が改善し、氷上滑り感が軽減される。
- `mmd_toolbox.md` が共通化後の構成(`vmd.reduce` とボーン専用トレランスヘルパ)と一致する。

### 3.6 Step 6: 運用向け調整

実装内容:

- `light` / `balanced` / `stable-foot` / `strong` プリセットを実データで調整する。
- `--list-bones` を追加する。
- CSVプレビュー(`--preview-csv`)で各ボーンの入力/出力差分を確認できるようにする。これは診断出力であり、処理対象を絞る選択ではない(全ボーンを処理する方針は変えない)。
- READMEに推奨手順を追加する。
- ボーン種別ごとに、効かせすぎ・効き不足を判断するチューニング観点をREADMEまたは仕様へ反映する。

完了条件:

- ユーザーが分類、補正量、接地区間を事前確認できる。
- 代表的なmocap VMDで、クリーニング+疎化を1コマンドで行う推奨手順を説明できる。

### 3.7 Step 7: 種別別チューニング

実装内容:

- 実データで `root`、`center`、`torso`、`arms`、`fingers`、`legs`、`foot_ik`、`toe_ik` の効き方を比較する。
- 種別ごとの最大変更量、平均変更量、保護フレーム数、足IKロック適用率を集計する。
- 効かせすぎで演技が丸まるケースと、効き不足でノイズが残るケースを分類する。
- 必要に応じて `--preset` の値を調整し、将来の `--tuning-file` 追加要否を判断する。

完了条件:

- ボーン種別ごとの初期値が、少なくとも代表的なmocap VMDで説明可能な値になっている。
- `stable-foot` では足IKの接地安定が改善し、`light` では手首・指などの演技が過度に丸まらない。
- チューニング結果を再現できるレポート項目が揃っている。

## 4. アルゴリズム計画

本章はアルゴリズムの初期値・採用方式を確定値として示す(実データでチューニングする前提)。窓幅・閾値・フィルタ次数などは初期値を採用する。フィルタの数値計算の内部実装(平均の数値的な取り方、符号判定の内部表現、Savitzky-Golay の実装など)は、ここに示す挙動・初期パラメータ・テストを満たす範囲で各 Step の実装で決める。

### 4.1 一般ノイズ軽減

過度に複雑な周波数解析ではなく、決定論的で説明しやすいフィルタを採用する。

採用方式:

窓幅は中央値フィルタ・Savitzky-Golay とも種別表(5.2)の位置窓を、回転平滑化は回転窓を使う。

| チャンネル | 方式 |
|---|---|
| 位置 | 種別の位置窓で中央値フィルタ後、同じ位置窓で Savitzky-Golay(2次、端はミラー反射)。結果を種別の位置強度でブレンド |
| 回転 | quaternion を同一半球へ揃え、種別の回転窓内で成分平均してから正規化(slerp の近似)した値を回転強度でブレンド |
| 足IK接地中の位置 | 接地アンカーへ寄せるロック型平滑化(4.3 / 5.4) |

スパイク候補は、位置は各軸の `|位置 − 窓中央値|` の最大が 0.3 MMD単位、回転は窓内平均 quaternion との角度差が 5度 を超えるフレームとする(5.5 のクランプ閾値と同じ。0.3 / 5度 ちょうどは非スパイク)。位置スパイクは中央値フィルタ、回転スパイクは窓内正規化平均で抑える(回転は中央値を使わない)。

スパイクとアクセントは**別の量**で判定する。スパイクは窓基準からの逸脱(外れ値)で、アクセントはフレーム間変化量(速度)で捉える。一定速度の継続運動は窓中央値・窓内平均が注目値に一致して逸脱が出ないため、逸脱ではアクセントを検出できず速度で見る。

- スパイク候補: 窓基準からの逸脱が 位置 0.3 MMD単位(各軸)/ 回転 5度 を超えるフレーム(0.3 / 5度ちょうどは非候補)。位置は窓中央値、回転は窓内正規化平均を基準にする。
- スパイク(補正対象): スパイク候補のうち、速度がそのフレームで単発の符号反転(往復)をするもの。位置は該当軸のみ窓中央値で置換し、回転は窓内正規化平均へ寄せる(回転は中央値を使わない)。前のフレームとの差・次のフレームとの差の双方が要るので、区間端・カット隣接はスパイクにしない。
- アクセント(保護対象): フレーム間変化量(速度)が 位置 0.3 MMD単位(各軸)/ 回転 5度 を超え(スパイク閾値と同じ値を速度に適用)、符号が反転せず同方向に 2本以上連続する差分の区間(run)。その run が張るフレーム全体(位置は該当軸)を保護マスクに入れ、平滑化・スパイク補正の対象にしない。
- 競合時の優先: あるフレームが、片側に同方向 2本以上連続(アクセント run)を持ちつつ反対側で符号反転して往復に見える場合(run の終端の山・谷など)は、アクセント保護を優先する。すなわちスパイクは「スパイク候補かつ単発往復」のうち、アクセント run に属さず境界(カット・範囲端)でもないフレームに限る(最終スパイク = 候補 ∩ 往復 − アクセント − 境界)。アクセントとスパイクが同一フレームに当たっても取りこぼさないよう、アクセント run と境界を先に確定してからスパイクを差し引く。

速度は連続フレームの値の差とする(位置は各軸の差、回転は前フレームからの相対回転)。符号反転は、注目フレームの前後の差分の符号が逆転することを指す。位置は各軸ごとに差分の正負で判定する。回転は前後の相対回転を回転ベクトル(quaternion の log)で表し、その向きが反転(前後ベクトルの内積が負)することを往復、向きが揃う(内積が正)ことを同方向とみなす(角度距離は非負なので大小では向きを定義できない)。差分の大きさが実質ゼロ — 位置は各軸の絶対差、回転は相対回転ベクトルのノルム(ラジアン)が `1e-9` 以下 — のフレームは、往復にも同方向継続にも数えない(浮動小数の量子化ノイズを動きと誤認しないための下限)。

平滑化前の保護マスクで使う不連続・カットの検出は、疎化と同じカット閾値(位置 1.0 MMD単位 / 回転 30度。1.3 の `cut_thresholds`)を用いる。これを越える急変はカット境界として保護し、平滑化はこの境界をまたがない。

検出と平滑化は、各ボーンの密サンプルを 0 始まりの相対インデックスで扱い、レポートへ出すフレームのみ範囲開始フレームを足して絶対フレームへ戻す。カット境界は `detect_cuts_bone` の絶対フレーム集合を相対へ変換して用い、境界の両側(F-1 と F)を保護する(疎化の継ぎ目規約と同じ)。窓は奇数で中心フレームを含み、区間長が窓に満たない短区間では区間長以下の最大奇数へ縮め、実効窓が 3 未満なら平滑化しない。中央値フィルタ・Savitzky-Golay はカット区間ごとに適用する。

指数移動平均・双方向IIR は初期実装では使わず、効果不足時の代替候補とする。

### 4.2 足IK接地区間検出

初期閾値(初期値。実データで調整):

| 項目 | 値 |
|---|---:|
| 最小接地長 | 4 フレーム |
| 水平速度閾値 | 0.08 MMD単位/frame |
| 垂直速度閾値 | 0.04 MMD単位/frame |
| 接地Y局所窓 | ±5 フレーム |
| 接地Y許容幅 | 局所最小(上記窓内) + 0.08 MMD単位 |
| 相対位置急変閾値 | 足IKとつま先IKのVMD位置差分の1フレーム変化が 0.08 MMD単位以下 |

上記に加え、足IKとつま先IKの相対位置が急変するフレームは接地候補から除外する(要求仕様 4.3 の接地候補条件)。ここでの「相対位置」はPMX階層や基準姿勢を読まないモデル非依存の量として定義する。具体的には、同側の足IKとつま先IKのVMD位置値(チャンネル値)の差分ベクトルを取り、その1フレーム変化量を用いる。接地中は両IKが静止するため差分も静止し、差分が急変するフレームは少なくとも一方が動いている=非接地の指標になる。差分の絶対値は真の空間距離である必要はなく、変化量のみを判定に使う。

接地区間ごとに、足IK・つま先IKそれぞれの位置の代表値を各自のアンカーとして計算する。各IKは自身の中央値を使い、VMDチャンネル値は同一座標とは限らないためアンカーを共有しない。中央値を使うのは、外れ値に強く、片足を置いた瞬間の1フレーム跳ねに引っ張られにくいためである。

### 4.3 足IKロック

接地ロックは位置(X/Z/Y)のみを対象とし、`foot_ik` と `toe_ik` で分ける(要求仕様 4.3 / 5.4)。回転は接地ロックを求めず、つま先IKは回転保持を重視するため、接地中も一般回転ノイズ軽減のみを適用し、専用の接地回転ロックは初期実装に入れない。

ロック強度はブレンド係数(0〜1)で、基準が0.90付近と1.0に近いため、`--preset` の倍率ではなくプリセットごとの直接値で与える(倍率だと1.0を超えクランプで潰れるため)。

`foot_ik` の X/Z 接地中央ロック(接地端は 0.25 からフェード):

| プリセット | X/Z接地中央 |
|---|---:|
| `light` | 0.70 |
| `balanced` | 0.90 |
| `strong` | 0.93 |
| `stable-foot` | 0.97 |

`toe_ik` の X/Z はプリセットによらず弱め(0.30)で、`stable-foot` でも強く固定しない。Yロックは `foot_ik` 0.50・`toe_ik` 0.30 で弱めとし、プリセットでは変えない。接地端のフェード端値は要求仕様 5.4 のとおり(`foot_ik` X/Z 0.25、`foot_ik` Y 0.10、`toe_ik` X/Z・Y 0.10)。これにより `foot_ik` の接地固定は `stable-foot`(0.97) が最強・`strong`(0.93) が次点となり、`toe_ik` は一貫して弱い。

足IKを固定しすぎると、膝やセンターとの整合が崩れて脚が伸び縮みして見える場合がある。そのため、足IK単体で大きく移動させず、最大補正量を設ける。

### 4.4 種別別チューニング観点

チューニングでは、削減率だけでなく見た目の破綻と演技保持を確認する。

| 種別 | 効かせすぎの兆候 | 効き不足の兆候 |
|---|---|---|
| `center` | 重心移動が遅れる、上下動が平板になる | 全身が細かく震える |
| `torso` | 上半身の切り返しが鈍る | 肩・頭が細かく震える |
| `arms` | 手振りやポーズのアクセントが丸まる | 腕や手首がちらつく |
| `fingers` | 指の演技が潰れる | 単発スパイクが残る |
| `legs` | 踏み込みや蹴り出しが遅れる | 膝・足首が震える |
| `foot_ik` | 脚が伸び縮みする、足が吸い付く | 接地中に足が滑る |
| `toe_ik` | つま先上げが鈍る | つま先が接地中に震える |

### 4.5 初期チューニングの進め方

初期チューニングは、強い補正値を一度に当てるのではなく、破壊しにくい保守的な値から始めて、足元と全身揺れを優先的に詰める。

手順:

1. `light` 相当の弱い一般ノイズ軽減を全対象ボーンへ適用し、スパイク除去と大きな破綻がないことを確認する。
2. `center` の位置強度を上げ、全身の微振動が減る範囲と重心移動が鈍る境界を探す。
3. `foot_ik` / `toe_ik` の接地ロックを調整し、接地中の滑りが減る範囲と脚の伸び縮みが出る境界を探す。
4. `torso` と `legs` の回転平滑化を調整し、姿勢のちらつきと踏み込みの遅れを比較する。
5. `arms` と `fingers` は最後に調整し、演技が丸まらない範囲でスパイクだけを抑える。
6. 疎化まで通し、キー削減率だけでなく接地感と編集しやすさを確認する。

理由:

- 足IKとセンターは、少量のノイズでも視覚的な違和感が大きく、改善効果も見えやすい。
- 手首・指・頭は、ノイズと演技の境界が曖昧で、初期から強く効かせると重要なニュアンスを失いやすい。
- 足IKロックは効果が大きい反面、誤検出時に脚の伸び縮みや吸い付きが出るため、一般平滑化とは別に段階調整する必要がある。
- センターを強くしすぎると全身のタイミングが変わるため、足IKより先に強く固定しない。
- 疎化結果は入力信号の滑らかさに左右されるため、視覚上不要な揺れを減らすことと、疎化後に残すべきアクセントを守ることを同時に見る必要がある。

初期判断基準:

| 観点 | 優先する確認 |
|---|---|
| 足IK | 接地中のX/Z移動量、脚の伸び縮み、接地開始/終了の吸い付き |
| センター | 全身の震え、上下動の自然さ、重心移動の遅れ |
| 手首・指 | ジェスチャや指演技の丸まり、単発スパイク残り |
| 疎化後 | キー削減率、補間後の接地感、編集しやすさ |

## 5. テスト計画

### 5.1 単体テスト

- ボーン名分類が標準名・準標準名・英語名に一致する。
- 足IK・つま先IKが `legs` ではなく `foot_ik` / `toe_ik` に分類される(`右足ＩＫ`、全角ＩＫの `右つま先ＩＫ` を含む)。
- プリセット解決が 5.2 / 5.3 の表の確定値(代表種別の窓幅・位置強度・回転強度・疎化基準値・種別スケール)を返す。
- ボーン専用トレランス構築ヘルパが `bone_pos` / `bone_rot` だけから `Tolerances` を構築する。
- 疎化の許容誤差が種別ごとに解決される(プリセット基準値 × 種別スケール、`--reduce-error-*` の明示は基準値を上書き)。
- 位置フィルタが単発スパイクを軽減する。
- 位置スパイク判定が各軸の窓中央値差の最大で行われ、0.3 ちょうどは非スパイク・0.3超はスパイクになる。
- 同方向に2フレーム以上連続する大きな変化はアクセントとして保護され、1フレーム往復のスパイクのみ補正される。
- quaternion符号反転を連続回転として扱える。
- 回転スパイクが窓内平均quaternionとの角度差(5度ちょうどは非スパイク)で判定される(中央値を使わない)。
- 接地区間検出が確定閾値(最小接地長4・水平速度0.08・垂直速度0.04・Y局所窓±5・Y許容幅+0.08)で動作する。
- 接地区間検出が短すぎる停止を接地扱いしない。
- 足IKとつま先IKの相対位置差分の1フレーム変化が確定閾値 0.08 を超える区間を接地扱いしない。
- 接地アンカーが外れ値に引っ張られない。
- 全ボーンが処理対象になり、ボーン種別ごとに異なるパラメータが適用される。
- `--preset` の強度倍率が `light`=全種別0.5 / `balanced`=1.0 / `strong`=全種別1.4 / `stable-foot`=`foot_ik` 1.5・他1.0 として各種別のクリーニング強度に伝播する。
- 分類不能ボーンが除外されず、`unknown` で処理される(クリーニングは保守的な弱設定、疎化スケールは位置・回転とも 1.0 の標準)。
- `--range` 外のキーが変更されない。
- 不連続境界をまたいで平滑化しない。

### 5.2 回帰テスト

- ボーン以外の対象外セクション(モーフ・カメラ・照明・セルフ影)が逐語透過される。
- 既定では全ボーンが疎化され、出力キー数が入力より減る。疎化後の再生誤差が許容値以内に収まる(共通機構の検証に従う)。
- キーが1個以下のボーントラックは疎化せず逐語保持される。
- 各トラックの疎化範囲が処理範囲とトラック実在区間の積集合になり、トラック区間外に人工キーを作らない。
- `--no-reduce` では疎化されず、クリーニング後の密キーが出力され、その補間ブロックが `mmd_toolbox.vmd.reduce.BONE_LINEAR_INTERP` とバイト一致する。
- `--curve-mode linear` / `bezier` で出力補間曲線が切り替わる。
- `--reduce-preset`(既定 `balanced`)と `--reduce-error-*` の値が、種別スケールを掛けて各トラックの疎化許容誤差まで伝播する。
- `--range` 外の元キーが値と補間ブロックを逐語保持する。
- `--no-denoise` で一般ノイズ軽減が適用されない。
- `--no-foot-ik-stabilize` でも全ボーンの疎化は行われる(足IK安定化のみ無効)。
- `foot_ik` の接地X/Zロックがプリセット別の直接値で、`stable-foot`(0.97) > `strong`(0.93) > `balanced`(0.90) > `light`(0.70) の順に強い。
- `toe_ik` の接地X/Zロックがプリセットによらず確定値 0.30(`foot_ik` より小さい)で、`stable-foot` でも強く固定されない。
- 接地中のYロックが弱い指定値(`foot_ik` 0.50 / `toe_ik` 0.30)で適用される。
- 接地区間の開始・終了でロック強度が端値から接地中央値へフェードする(接地端値 `foot_ik` X/Z 0.25・`foot_ik` Y 0.10・`toe_ik` X/Z・Y 0.10)。フェード幅は端から3フレーム、接地長6フレーム未満では接地長の半分ずつに按分される。
- 一般ノイズ軽減の1フレーム変更量が上限(位置 各軸 0.3 MMD単位 / 回転 5度)でクランプされる。
- 足IK接地ロックの補正量が上限(0.5 MMD単位)を超えるとロックを弱め、警告を出す。
- 足IK接地ロック段階は接地中に回転を追加変更しない(回転は一般平滑化のみで、専用の接地回転ロックを持たない)。
- 同一入力・同一引数で同一出力になる。
- `dry-run` ではVMDを書き出さない。

### 5.3 合成データ

以下の合成VMDを用意する。

- 静止足IKに微小ノイズが乗ったデータ。
- 歩行で接地と遊脚が交互に出るデータ。
- ジャンプで両足が浮くデータ。
- 意図的に足を滑らせるデータ。
- ボーン名が日本語・英語・標準外のデータ。

- 膝の破綻や脚の伸び縮み。
- センターの重心移動。

- 疎化後の編集しやすさ。
- 種別ごとの効かせすぎ・効き不足が許容範囲か。
