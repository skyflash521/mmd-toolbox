# vpr_io 実装計画書

要求仕様 [vpr_io.md](vpr_io.md) を実装へ落とす計画。TDDで見出し単位のステップを進める。本書は仕様を
変更せず、仕様が実装での確定に委ねた詳細(vpr の直列化レイアウト・保持範囲)を定め、着手順序とテスト方針を
決める。仕様と矛盾が生じた場合は仕様(vpr_io.md)を正とし、本書を直す。

---

## 1. 前提と依存

- 実装言語 Python 3.11+。標準ライブラリ中心とし、重い依存を増やさない。
- `vpr_io` は形式I/Oに徹し、生成・判断ロジック(口形イベント化・ピッチ推定・音符分割)を持たない
  (vpr_io.md §1.2)。
- **読みを先行**する(`vpr2vmd`・S-1認識ゲートで先に必要)。**書きは `song2vpr` 着手時に拡張**する。

---

## 2. 実装ステップ(着手順)

各ステップは「テスト作成 → レビュー → 収束ならコミット」「実装 → レビュー → 収束ならコミット」を回す。

| ステップ | 内容 | 主な受入条件 |
|---|---|---|
| V-0 | 雛形・データモデル型: テンポ/拍子・トラック/パート・音符(時刻・ピッチ・歌詞・音素・ベロシティ)の型(vpr_io.md §2)。休符は専用型を持たず発音区間から導出する | データモデル型が定義され(休符は導出情報)、read/write の入出力境界が定まる |
| V-1 | read: vpr を解析しデータモデルへ変換(テンポ・拍子・トラック/パート・音符・歌詞・音素・ベロシティ)。休符は発音区間の補集合として導出 | 代表 vpr を読み、データモデルの各要素が取り出せ、休符区間が導出できる |
| V-2 | read のロスレス・エラー/警告: 解釈しないデータを保持する設計と保持範囲の明文化、構造異常の構造化エラー、続行可能事象の警告 | 未解釈データを保持し保持範囲が明文化される(実際の往復検証は write 実装の V-3 で行う)。異常入力で構造化エラー |
| V-3(song2vpr 時) | write: データモデル → vpr 直列化 | 書き出した vpr を read で読み戻せる(往復) |

依存関係: V-1/V-2 は V-0 の型に依存。V-3 は `song2vpr` 着手時に V-0〜V-2 の上へ拡張する。

---

## 3. テスト方針

- `mmd_toolbox` のテスト規約(pytest・決定論・乱数シード固定・ネットワーク/GPU 不要)に従う。
- **read のテスト**: 小さな代表 vpr を入力に、データモデルの各要素(テンポ・音符の時刻/ピッチ/歌詞/音素/
  強弱・休符)が期待値と一致することを検証する。テスト用 vpr の持ち方(コミットする実ファイルか、レイアウト
  確定後の合成フィクスチャか)は形式レイアウトの確定(4章)に合わせて決める。
- **ロスレス/往復**: V-2 では未解釈データを保持する設計と保持範囲を確認する。実際の往復(読み→書き→読み)の
  検証は write 実装(V-3、`song2vpr` 着手時)で行う。
- アダプタとしての形式変換に集中し、生成・判断ロジックを持ち込まない(持つべきテストは形式の読み書きの
  正しさ)。

---

## 4. 確定する詳細

机上で確定できる公開データモデル・関数(§4.1)と、実ファイル解析でしか決まらない形式レイアウト(§4.2)を
分けて扱う。

### 4.1 公開データモデル・関数(確定)

利用先(vpr_io.md §1.3)の必要から机上で確定する。型は Python の dataclass、公開関数はモジュール関数とし、
`mmd_toolbox.vmd`(`types.py` / `io.py`)の作法に倣う。時刻は vpr ネイティブの **tick(整数)** で保持し、
秒/フレーム/拍への変換は持たない(vpr_io.md §2・§6)。

- `VprProject`: `resolution: int`(tick/四分音符)、`tempos: list[TempoEvent]`、
  `time_signatures: list[TimeSignature]`、`tracks: list[Track]`。
- `TempoEvent`: `tick: int`、`bpm: float`。
- `TimeSignature`: `tick: int`、`numerator: int`、`denominator: int`。
- `Track`: `name: str`、`parts: list[Part]`。
- `Part`: `name: str`、`start_tick: int`(プロジェクト絶対 tick。パートの開始位置)、
  `notes: list[Note]`(`start_tick` の昇順)。
- `Note`: `start_tick: int`、`duration_tick: int`、`pitch: int`(MIDI ノート番号)、`lyric: str`(表示歌詞)、
  `phonemes: list[str]`(音符内の音素列。空可)、`velocity: int`(0〜127)。
  **時刻の座標系**: `Note.start_tick` は**プロジェクト絶対 tick**、`duration_tick` は **tick 長**で持つ(vpr が
  パート相対で格納する場合、read 時に `Part` 開始位置を `start_tick` へ加算して絶対化する。相対化は形式マッピングの
  責務で §4.2)。
- **休符**: 専用型を持たせない。同一 `Track` 内の**発音区間 `[start_tick, start_tick+duration_tick)` の和集合の
  補集合**を休符(無音区間)とする(隣接差分でなく和集合の補集合とすることで、万一区間が重なっても偽の休符を
  作らない)。先頭音符より前は先頭無音、解析範囲末尾までは末尾無音とし、**解析範囲(曲の総尺)は呼び出し側が
  定める**。歌唱トラックは単音想定で、発音区間が重なる入力は `read` が `VprWarning` で報告する(vpr_io.md §2)。
- **警告/エラー**: `VprWarning`(続行可能事象の構造化報告)、`VprFormatError`(構造異常)。
  `mmd_toolbox.vmd.types` の `VmdWarning`/`VmdFormatError` に倣う。
- **公開関数**(`mmd_toolbox.vmd.io` に倣う):
  - `read(src: str | Path | bytes) -> tuple[VprProject, list[VprWarning]]`(V-1)。
  - `write(project: VprProject) -> bytes` / `write_file(project: VprProject, path: str | Path) -> None`
    (V-3、`song2vpr` 着手時)。`write_file` は原子置換(同ディレクトリ一時ファイルへ書いて fsync し
    `os.replace`)で、書き込み途中の中断・ディスクフルでも既存の出力先を破損させない
    (`mmd_toolbox.vmd.io.write_file` に倣う)。
- 未解釈データ(ロスレス保持)を `VprProject`・各要素にどう持たせるかは §4.2(レイアウト確定後)。

### 4.2 形式レイアウト・ロスレス範囲(実装着手時に実ファイルから確定)

机上では決まらず、実 vpr の解析で確定する(決定方法は実ファイル解析と往復検証。受入は V-1〜V-3)。

- **vpr の直列化レイアウト**: コンテナ構造・フィールド配置・対応バージョンは実装着手時に実ファイルから確定し、
  形式仕様として記録する(vpr_io.md §5)。本実装はそれを実装する。
- **ロスレスの保持範囲**: 完全な往復一致を保証する範囲と、正規化により失われうる範囲、未解釈データの保持表現
  (生バイト/付随辞書等)を、レイアウト確定後に定める。

---

## 5. リスクと未確定

- **vpr 形式の確定**: 直列化レイアウト・バージョン差(VOCALOID のバージョンによる差異)が最大の未確定要素。
  レイアウト確定が read 実装の前提になる。
- **書きの妥当性**: `song2vpr` が出力する vpr が VOCALOID で正しく開けること(V-3 で確認)。

---

## 6. 仕様への影響

- 仕様(vpr_io.md)の記述変更が必要な不整合は無い。本計画は仕様が実装での確定に委ねた詳細(4章)の置き場で
  あり、仕様の決定を覆さない。
- レイアウト確定で仕様の前提(データモデル・責務)が変わる場合は、正本である vpr_io.md を先に更新してから
  本計画と実装を整合させる。
