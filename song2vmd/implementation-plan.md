# song2vmd 実装計画書

要求仕様 [song2vmd.md](song2vmd.md) を実装へ落とす計画。TDDで見出し単位のステップを進める。本書は仕様を
変更せず、仕様が実装での確定に委ねた詳細を定め、着手順序とテスト方針を決める。仕様と矛盾が生じた場合は
仕様(song2vmd.md)を正とし、本書を直す。

---

## 1. 前提と依存

- 実装言語 Python 3.11+。`mmd_toolbox` 本体の必須依存は `numpy`/`scipy` のまま保つ。
- `song2vmd` 固有の重い依存はツール側(パッケージのextra等)に閉じる:
  - S0: `soundfile`(BSD-3)。読めない形式のみ ffmpeg(自動検出・非再配布)。
  - S1: `demucs`(adefossez fork・MIT)を `demucs.api` で in-process。`torch`(BSD-3)。
  - S2: `transformers`(Apache-2.0)+ 音素モデル `facebook/wav2vec2-lv-60-espeak-cv-ft`(Apache-2.0)。`torch` は S1 と共有。
- VMD 書き出しは `mmd_toolbox.vmd.io`。生成するのはモーフキーのみ(汎用疎化は使わない。song2vmd.md §9)。
- アニメ的口パクのキーフレーム生成は共有モジュール [lipsync](../lipsync/lipsync.md) に委譲する。`song2vmd` は
  口形イベント列と開き量を作って `lipsync` へ渡す(モーフ生成コア・既定プロファイルは
  [lipsync 実装計画](../lipsync/implementation-plan.md))。
- 外部ツールはすべて song2vmd が内部で呼ぶ。利用者は `song2vmd INPUT` の1コマンドのみ。

## 2. 実装ステップ(着手順)

各ステップは「テスト作成 → レビュー → 収束ならコミット」「実装 → レビュー → 収束ならコミット」を回す
(自律開発の単位)。外部ツールに依存するステップは、ユニットテストではモックまたは短い小サンプルを使い、
ネットワーク・GPU・実モデルを必須にしない。

**ツール横断の着手順**: アニメ的口パクのモーフ生成コアは共有モジュール `lipsync` にあり、`vpr2vmd`(vpr
入力・認識不要)で先に実装・チューニングして見た目の品質を詰める。S2母音認識の成立可否(S-1ゲート)は
`vpr2vmd` と並行に早期評価する。`song2vmd` は、実証済みの `lipsync` コアへ音声フロント(S0–S3)と入口処理
(口形イベント確定・RMS→開き量)を接続する位置づけで、S-1ゲート合格後に進める。下表は `song2vmd` 内部の
ステップ。

| 区分 | ステップ | 内容 | 主な受入条件 |
|---|---|---|---|
| 基盤 | S-0 | パッケージ雛形・CLI骨組み(引数パース)・依存宣言・**モデルid/revision・推論条件の固定**・`--dry-run` の空実行 | CLIが起動し引数を解釈。モデル条件が固定され再現可能 |
| **ゲート** | **S-1** | **S2母音認識スパイク**。`facebook/wav2vec2-lv-60-espeak-cv-ft` で代表日本語歌唱サンプルの母音正解率・境界時刻ずれを測定し、受入基準(4章)を判定 | **受入基準を満たす。満たさなければ Julius 等を評価して認識器を確定してから先へ進む** |
| 段 | S-2 | S0 入力読み込み(`soundfile` 優先/ffmpeg フォールバック。ch/SR 保持)＋**入力レベル正規化**(斉次スカラ。6.1) | 各形式を読み、ch/SR を保持。mp3 も読める。正の一様ゲイン違いの入力で正規化後PCMが一致 |
| 段 | S-3 | S1 ボーカル抽出(`demucs.api`、`shifts=0`、Separator 抽象、`--separate-vocals`) | S0出力(正規化PCM・ステレオ)を入力しボーカルWAVを出力。決定論 |
| 段 | S-4 | S2 Recognizer(認識器でボーカルを16kHz monoへ変換 → 母音/子音/gap の全被覆セグメント列、Recognizer 抽象) | 全時間軸を重複・欠落なく被覆。母音は音素ラベルと任意信頼度 |
| 段 | S-5 | S3 強弱RMS(相対正規化=パーセンタイル、母音中央代表、無音ヒステリシス) | ミックス全体の一様ゲイン差では開き量が変わらない一方、曲内・モーラ間の相対強弱は開き量へ反映。境界の開閉反復が出ない |
| 中核 | S-6 | gap の無音/継続判定・閉鎖(両唇音)判定・あいうえお写像(S3 RMS 併用、日本語固有) | blank をそのまま無音化しない。責務は中核に集約 |
| 中核 | S-7 | S4 モーフ生成: 口形イベント列＋開き量＋プリセットを共有モジュール `lipsync` へ渡しモーフキーを生成([lipsync.md](../lipsync/lipsync.md) §4)。VMD出力は `mmd_toolbox.vmd.io` | lipsync.md §3 の品質基準を満たす疎なモーフキーVMDを出力 |
| 段 | S-8 | 長尺分割(無音区切り/無音なし時は最大チャンク長で強制分割、オーバーラップ・中央採用・継ぎ目結合・曲全体RMS正規化) | 継ぎ目でキーの重複・欠落がなく、境界母音が結合され(再アタック・保持値跳ねなし)、中央採用・曲全体RMS基準が保たれる |
| 仕上げ | S-9 | スタイルプリセット(8.1)とパラメータ確定 | プリセットで開き量レンジ・タイミングが切り替わる |
| 仕上げ | S-10 | レポート/診断(`--dry-run`/`--report-json`)・`--keep-intermediate` | 仕様6.7の統計を出力 |
| 仕上げ | S-11 | 統合・E2E(小サンプルで音声→VMD)。**公開時に README のツール表へ `song2vmd` を追記**(README 本体は指示があるまで触らない) | 1コマンドで口パクVMDを生成。**同一音源のゲイン違い入力(分離あり通し)で同一セグメント・同一VMD**(入力ゲイン不変性。6.1) |

依存関係: S-1(ゲート)は `vpr2vmd` と並行に早期確定し、合格後に S-2 以降の音声フロントへ進む。S-6 は
S-4/S-5 に依存し、S-7 は S-6 の口形イベント列・S-5 の開き量を `lipsync` へ渡す。S-8 はチャンク単位で
S0〜S2(認識)まで処理し、結合後に中核(S-6 相当)と S-7 の `lipsync` 生成を全曲へ1回適用する(4.5)。

## 3. テスト方針

- `mmd_toolbox` のテスト規約(pytest・決定論・乱数シード固定・ネットワーク/GPU 不要)に従う。
- 入出力のVMDはラウンドトリップと既知値フィクスチャで検証。モーフキーの値・フレーム・名称(Shift-JIS)を確認。
- S2/S1 など外部モデル依存は薄いアダプタ層に隔離する。中核の入口処理(S-6 の gap解決・あいうえお写像・閉鎖
  判定、および S-8 の継ぎ目結合の中核)は正規化中間形式(セグメント列・RMS)だけに依存させ、合成したセグメント
  列＋合成RMSのフィクスチャで決定論的にモックテストする。
- **共有モーフ生成コア(`lipsync`)の正しさ・回帰は、`song2vmd` と `vpr2vmd` のツール間比較では捉えられない**
  (両者は同じ `lipsync` コアを通るため相殺される)。lipsync コアの回帰は
  [lipsync 実装計画](../lipsync/implementation-plan.md) の既知値フィクスチャで担保する(ツール間比較で
  代替しない)。`song2vmd` 側は S-7 で口形イベント列・開き量を `lipsync` へ渡す接続を検証する。
- S-5(音声からのRMS算出)と S-8 のチャンク制御は音声・S1/S2 アダプタを扱うため、純関数の核(正規化・
  ヒステリシス・継ぎ目結合)を分離してテストし、アダプタ呼び出し部は小サンプルまたはモックで確認する。
- 実モデルを使う検証(S-1ゲート)は別途、手動または重テストとして分離し、通常の `pytest` には含めない。

## 4. 確定する詳細(初期値・手順)

仕様が実装での確定に委ねた項目を、初期値と手順としてここで確定する。値は出発点で、代表サンプルで
チューニングする(ただし §4.1 の S-1 ゲートの評価集合・閾値・集計規則は除く。下記のとおり採点前に固定する)。**時間単位**: 音声解析(4.1〜4.3)は秒/ms で扱う。出力キー生成(4.4)は30fps基準
(1秒=30フレーム)で、最終的にVMDキーを30fps整数フレームへ量子化する。

### 4.1 S2受入基準(S-1ゲート。客観的に判定)

- **代表データ**: 日本語歌唱5曲以上(ジャンル・テンポ・声質・男女に幅)の**伴奏込み音源**と、**ボーカル単体
  2点以上**。さらに**ペア音源**(同一歌唱のボーカルステムと、それを含むミックス)を**1組以上必須**で含める
  (分離の寄与の切り分けに使う)。数は初期目安だが、評価集合は対象モデルの出力を評価データで観測する前に確定・
  記録し、以後は固定する。
- **使い分けの理由(誤差の切り分け)**: ボーカル単体/ステムは分離をかけず S2 へ直入力(`--separate-vocals
  never`)し、**S2(音素認識)単独の精度**を測る。分離(S1)の寄与は、**同一歌唱のペア**で「ボーカルステム」対
  「そのミックスから分離したボーカル」を比べて測る(別音源どうしの差は歌唱内容・声質・録音条件が混じり、
  切り分けにならない)。ボーカルステムは**真にアカペラな音源**(公式ステム/アカペラ、または自録)を使い、
  本ツールで分離した出力を S2 単独測定には使わない(循環を避ける)。
- **ラベル(基準)**: 各音声に区間ラベルを人手で付与し、**全時間軸を被覆**する。ラベルは**対象ボーカルの内容**で
  判定する(伴奏の有無に依らない): **a/i/u/e/o**(母音)・**c**(対象ボーカルの子音・非母音有声区間)・
  **sil**(対象ボーカルが母音も子音も発していない区間。伴奏・残響があっても sil)。ペアの**ステムとミックスは
  同一歌唱なので同じラベルを使う**(これによりペア比較が成立する)。形式は **Audacity ラベル**(TSV: 開始秒・
  終了秒・ラベル)で、1音声につき同名の `.txt` を1つ。歌詞既知なら母音列の見当に使う。
- **音声形式**: 測定への符号化ノイズ混入を避けるため **WAV(可逆)** を使う(mp3 等の非可逆は使わない)。
  サンプルレート・チャンネルは原音のまま。
- **配置**: 評価データ(著作物の楽曲音声を含む)は**リポジトリに置かない**。利用者がローカルに用意し、S-1
  スパイクへ**パス指定で渡す**(ディレクトリ構成は任意。例: `vocals/`・`songs/`・`out/`)。リポジトリの管理外
  なので `.gitignore` での除外も不要。各音源の**役割**(伴奏込み/ボーカル単体/ステム/ミックス)と**ペア関係**
  (どのステムとどのミックスが同一歌唱か)は利用者がマニフェスト(または命名規約)で宣言し、スパイクが
  S2単独評価とペア比較・ミックス評価を一意に構成できるようにする。再現性のため、各音源・ラベルのダイジェスト
  (ハッシュ)をマニフェストまたは結果レポートに記録し、評価に用いた入力を後から再特定できるようにする
  (音源自体のリポジトリ保存は引き続き行わない)。
- **採点対象の段階**: S-1 は S2(認識)の品質を測る。アダプタ出力は CTC区間化(60ms吸収。4.2)済みの
  母音/子音/gap＋IPAラベルのセグメント列であり、採点対象はそれに評価用として中核と同一の **IPA→5母音写像**
  を適用したセグメント列とする(60ms吸収を採点時に再適用しない)。RMS補正・gap解決などの中核のRMS依存処理は
  **含めない**(写像自体は中核責務だが、ここでは同一規則を採点に流用する)。
- **母音正解率**: 上記の採点対象セグメント列を 10ms フレームへ展開し、**基準が母音(a/i/u/e/o)のフレーム**の
  うち母音種別が一致した割合(= 一致母音フレーム / 基準が母音のフレーム)。フレーム指標・区間指標とも同一の
  採点対象セグメント列から算出する。
- **過開口率(フレーム単位)**: 基準が c/sil のフレームのうち、予測が母音(口が開く)になったフレームの割合
  (= 母音と予測した c/sil フレーム / 基準が c/sil のフレーム)。母音区間が後続の c/sil へはみ出す過剰開口を
  捕捉する(区間対応付けの余剰では取りこぼすため、フレーム単位で別途数える)。
- **区間の対応付け**: 予測区間と基準区間を、母音種別が一致し**時間重なりが正(0より大)**の組に限り、
  **総重なり時間を最大化する全体最適割当**(ハンガリアン法等)で1対1対応させる(重なりゼロの組は対応に
  しない)。最適割当が複数あるときは一意化のため、基準区間・予測区間をそれぞれ開始時刻昇順(同時刻なら終了
  時刻昇順)で番号付けし、割当を(基準番号, 予測番号)の組の昇順リストとして辞書式比較した最小の割当を採る。
  基準にあって対応が無いものを未検出、予測にあって対応が無いものを余剰とし、いずれも除外せず失敗側に数える。
- **境界時刻ずれ**: 対応した区間の開始時刻差 |予測 − 基準| の中央値と95パーセンタイル(単位 ms)。対応区間が
  0件の曲は境界ずれが未定義なのでマクロ平均から除外し、そうした曲が1つでもあればゲート全体を不合格とする
  (認識器が代表曲で全面失敗しているため)。
- **集計と受入基準(初期値)**: 指標は**曲(サンプル)ごとに算出し、その曲数マクロ平均**で判定する(曲長で
  偏らないため)。基準: フレーム母音正解率 ≥ 80%、**過開口率 ≤ 10%**、境界ずれ中央値 ≤ 50ms かつ
  95パーセンタイル ≤ 120ms、かつ (未検出+余剰) / 基準区間数 ≤ 10%。未検出区間のフレームは母音正解率でも
  不一致として数える。
- **判定**: ゲートの合否は **S2単独**(ボーカルステム/単体)の基準で決める。S2単独が不合格なら
  Julius(phone-loop)等を同じ手順で評価し、認識器を確定してから S-2 以降へ進む。**ペア音源では、Demucs を
  アドホックに用いてミックス側(通し)も必ず評価する**(切り分けのため)。**S2単独は合格だがミックス側が悪い**
  ときは分離(S1)側の問題として S-3 で対処する(認識器は変えない)。合否そのものは S2単独で決め、ミックス側は
  S1 の課題の把握に使う。
- **再現性と客観性**: ゲートは固定したモデル(id・revision)と推論条件(4.2)で実施する。評価集合(マニフェスト)・
  受入基準の閾値・集計規則は、対象モデルの出力・指標を評価データ上で観測する前に固定して記録する(コミット等)。
  観測した出力・指標(暫定値・合否を含む)を見てから標本数や閾値を緩める変更は禁止。評価集合・規則の修正は
  観測結果と独立した事由(ラベル誤り・データ不備・固定条件の誤り等)に限り、修正後は最初から採点をやり直す。

### 4.2 認識器の固定とセグメント時刻

- **固定(S-1開始前)**: モデル `facebook/wav2vec2-lv-60-espeak-cv-ft` の revision、主要依存パッケージ版、
  入力16kHz mono と再サンプリング方式、実行デバイス/dtype、推論のバッチ/スレッド・乱数シードを固定する。
  ゲートはこの固定環境で実施し、実装も同条件を使う(同一環境・同一入力なら指標が再現する)。
- **CTC区間化(アダプタ側。RMS不要)**: 同一音素ラベルの連続フレームを1区間に連結。最小区間長 60ms(未満は隣接へ吸収。吸収先は
  より長い隣接(母音/子音)区間、同長なら直前。先頭/末尾で片側しか無ければその側。gap は吸収先にしない。
  非gapの隣接が無い(両隣gap、または端でgapのみ)場合は、その短区間自体を gap にする)。blank/未割当は
  gap とする(全時間軸を被覆。時間は秒で保持)。
- **IPA→あいうえお・閉鎖の写像(中核)**: 分類は一度だけ行う。アダプタは 母音/子音/gap と IPA ラベルを返す
  (7.2)。中核は **母音セグメントの IPA を5母音へバケット化**(a/ɑ/ʌ/æ→あ、i/ɪ/j→い、ɯ/u/ʊ/w→う、
  e/ɛ→え、o/ɔ→お)し、**子音セグメントのうち両唇音 m/b/p/ɸ/β を閉鎖**として扱う。表に無い母音IPAは最近接の
  5母音へ寄せ、判定不能は gap とする(初期表。実データで補正)。母音/子音の判別はアダプタ側で済んでいるため
  中核では再分類しない。
- **母音境界の精緻化**: 母音区間の開始を、前後 ±60ms 以内に RMS オンセット(立ち上がり)があればそれへ
  寄せる。無ければトークン境界を採用。
- **RMSオンセット検出**: 正規化RMSを ~30ms 移動平均で平滑化し、探索窓内で上昇の傾きがしきい値(初期
  +0.15/10ms)を超える最初の点をオンセットとする。複数候補があれば母音区間の元境界に時間的に最も近いものを選ぶ。
- **gap解決(中核)**: gap 区間の代表RMSが無音しきい値(4.3)以下なら無音(閉口)、以上なら直前母音を継続。
  ただし直前母音が無い先頭gap、および末尾gapは(RMSによらず)閉口とする(先頭・末尾は閉口で始終する。4.6)。

### 4.3 強弱・閉口(初期値)

- **RMS算出**: フレーム長 25ms・ホップ 10ms。**曲全体**の 10〜90 パーセンタイルで正規化し外れ値を除外
  (長尺分割時も曲全体基準。4.5)。母音中央代表は区間中央 60% の平均。
- **無音ヒステリシス**(正規化RMS): 開いている状態からは RMS が下降側しきい値 0.06 を下回ったら閉口へ入り、
  閉じている状態からは上昇側しきい値 0.10 を上回ったら開口へ戻る(下降側 < 上昇側。初期値)。
- **低ダイナミクス抑制**(song2vmd.md 6.4): 曲のダイナミックレンジ(例: 95〜5パーセンタイルRMSのdB差。比なので
  ゲイン不変)が下限(初期 12dB、実データで補正)未満なら、その曲は実質無音が無いとみなし、音量に基づく無音化
  (gap無音化・母音無音補正)を抑制する(音素由来の両唇閉鎖・先頭/末尾の閉口は対象外)。終始大音量の曲の閉口
  誤検出を防ぐ。絶対dBFSしきい値は使わない(入力ゲインに不変)。
- **母音区間の無音補正**: 母音セグメントでも代表RMSが無音(下降側しきい値 0.06)以下なら、信頼度によらず閉口に
  する(高信頼でも実RMSが無音の誤検出母音対策。仕様)。
- **両唇閉鎖**: 深さ=全母音0、長さ=子音区間長(上限 100ms)。

### 4.4 生成パラメータ(プリセット値)・開き量の決定

モーフ生成のアルゴリズム(母音合成・協調調音の遷移長・最小保持の併合/間引き・区間内競合短縮・連結区間内の
強弱節点・30fps量子化・伸び揺らぎ)と**既定の母音合成プロファイル**は共有モジュール `lipsync` が持つ
([lipsync 実装計画](../lipsync/implementation-plan.md) §4 が正本)。本節は `song2vmd` が `lipsync` へ渡す
**プリセットの具体値**と、`song2vmd` 入口の **RMS→開き量の写像・低信頼判定**を定める。時間はフレーム(30fps)。
`pop` を基準とし、他プリセットは開き量レンジと下表を調整する(値は `lipsync` のタイミング/誇張パラメータへ渡す)。

| 項目 | pop | ballad | powerful | whisper | rap |
|---|--:|--:|--:|--:|--:|
| 開き量レンジ(弱〜強) | 0.30–0.75 | 0.20–0.55 | 0.40–0.95 | 0.10–0.35 | 0.30–0.70 |
| アタック | 2 | 3 | 1 | 2 | 1 |
| リリース | 2 | 3 | 1 | 2 | 1 |
| 遷移 | 2 | 3 | 1 | 2 | 1 |
| 協調調音 重なり(上限) | 2 | 3 | 2 | 2 | 1 |
| 先行(anticipation) | 1 | 1 | 2 | 1 | 1 |
| 最小保持 | 3 | 4 | 3 | 3 | 2 |
| 合成誇張係数 | 1.0 | 0.8 | 1.3 | 0.7 | 1.0 |

- **強弱→開き量(入口。RMS→開き量の写像)**: 区間代表RMSを 0〜1 に正規化し、累乗指数 0.6(初期)で写像、
  開き量レンジへクランプ、`--open-max` で上限。`--open-max` 既定はプリセット値(pop 0.90 / ballad 0.70 /
  powerful 0.97 / whisper 0.50 / rap 0.85。各プリセットの開き量レンジ上限以上)。こうして決めたモーラ別開き量を
  `lipsync` へ渡す(合成プロファイルへの適用・合成総量の上限クランプは `lipsync` 側。lipsync 実装計画 §4.1)。
- **`--vowel-gain`**: 既定 1:1:1:1:1(a:i:u:e:o)。母音別の開き量倍率として `lipsync` へ渡す(適用順は
  lipsync 実装計画 §4.1)。
- **合成誇張係数**: 上表の値を `lipsync` の母音合成プロファイルの補助重みへ掛ける誇張係数として渡す(適用は
  `lipsync` 側)。
- **低信頼・無声母音(入口判定)**: 認識器が信頼度を出す場合、信頼度 < 0.5 かつ 正規化RMS < 0.3 の母音区間を
  「弱い」と判定し、開き量を 0.5 倍に弱めて `lipsync` へ渡す(区間長が最小保持未満なら `lipsync` の最小保持で
  前後へ吸収される)。信頼度を出さないバックエンドでは正規化RMS のみで判定する(< 0.2 を弱いとみなす)。

### 4.5 長尺分割(初期値)

- 最大チャンク長 = `--max-duration`(既定300秒)。チャンク境界は、目標境界の前後 ±5秒で最も静かな点(無音)を
  探す。無音が無ければ目標境界で強制分割。隣接チャンクは前後 1.0秒 オーバーラップさせる。
- 継ぎ目は**セグメント段階で結合してからキー生成する**(キー生成はチャンク単位でなく結合後の全体で1回行う):
  1. 各チャンクを S0〜S2(認識)まで個別処理し、母音/子音/gap のセグメント列を得る。
  2. オーバーラップ区間は、チャンク中央に近い側のセグメントを採用して重複を除く(中央区間採用)。
  3. チャンク境界をまたぐ同一母音セグメントは1区間へ結合する(再アタック・閉口を挟まない)。
  4. 結合した全曲セグメント列に中核の処理順序(4.6)を適用し、`lipsync` でキー生成を1回行う。
- RMS の相対正規化(4.3)は曲全体を基準にし、チャンクごとに基準がずれないようにする。

### 4.6 中核の処理順序(決定論)

アダプタ(Recognizer)は、CTC出力を連結・60ms未満吸収して 母音/子音/gap の全被覆セグメント列(IPAラベル付き)
を返す(4.2前半。RMS不要)。中核はそのセグメント列に次の順で適用し、結果を一意にする(S3のRMSを使う):

1. IPA→あいうえお写像・両唇音→閉鎖判定(4.2)。
2. gap解決: RMS で gap を無音(閉口)/直前母音継続に確定。母音区間の無音補正も行う(4.3)。ただし低ダイナミクス
   曲(4.3)では、この音量に基づく無音化・無音補正を抑制する(音素由来の両唇閉鎖・先頭/末尾の閉口は対象外)。
3. 同母音連結: 連続する同一(あいうえお)母音区間を1つの口形イベントへまとめる。
4. 母音境界の RMS オンセット補正(4.2)。境界はここで確定する。
5. 低信頼・無声判定: 弱い母音を抽出し開き量を弱める(4.4)。
6. ここまでで確定した口形イベント列(母音・両唇閉鎖・無音)とモーラ別開き量・プリセットを `lipsync` へ渡す。
   最小保持未満の併合/間引き、キー配置(アタック・保持・遷移・閉口・先行)、30fps整数フレームへの量子化
   (同一モーフ・同一フレームのキー衝突解決を含む)は `lipsync` が行う(lipsync 実装計画 §4)。

- 先頭は閉口から始め、末尾は閉口で終える。判定が同値(RMS等)で割れる場合は連結(直前優先)側に倒す。

## 5. リスクと未確定

- **S2品質(最大リスク)**: 歌唱での母音認識が受入基準に届くか。S-1ゲートで先に潰す。届かなければ認識器を差し替える。
- 依存の重さ・速度: `transformers`+モデル取得(ダウンロード・キャッシュ・メモリ・初回ネットワーク)。モデルの
  版(revision)は S-0 で固定(4.2)。キャッシュ先・オフライン挙動・必要ディスク/RAM・CPU実行時間は S-4 で確定する。
- 決定論: 外部ツール(分離・認識)の非決定性。Demucs `shifts=0`、スレッド/シード固定で可能な範囲に収める。
- Demucs 保守終了: adefossez fork を版固定。将来、保守活発な audio-separator への切り替え余地。

## 6. 仕様への影響

本計画の作成で判明した、要求仕様(song2vmd.md)の変更要否:

- 仕様の記述変更が必要な不整合は無い(責務・パイプライン・中間形式・ライセンスは確定済み)。本計画は仕様が
  実装での確定に委ねた詳細(4章)の置き場であり、仕様の決定を覆さない。
- 実装着手後、4章の数値確定や S-1 ゲートの結果で仕様の前提が崩れた場合(例: 認識器の差し替え)は、
  正本である song2vmd.md を先に更新してから本計画と実装を整合させる。
