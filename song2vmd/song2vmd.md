# song2vmd 要求仕様書

日本語の歌の音声ファイルから、標準表情モーフ(あ・い・う・え・お)による口パクVMDを
自動生成する独立CLIツールの要求仕様。

---

## 1. 位置づけ

### 1.1 結論

本機能は `song2vmd` という独立CLIツールとして提供する。

`song2vmd` は、日本語の歌の音声ファイル(BGM込み可)を入力に、ボーカル抽出・音素/母音認識・
声の強弱解析を経て、標準表情モーフによる口パクVMDを **1コマンドのフル自動**で出力する。

```text
入力 音声ファイル(歌, mp3/wav 等)
  -> song2vmd(ボーカル抽出 → 音素/母音認識 → 強弱 → モーフ生成)
  -> 口パクVMD
  -> MMD/MMMで確認・編集
```

ボーカル抽出と音素/母音認識は外部ライブラリ(必要時のみサブプロセス)に委譲し、song2vmd が内部で呼ぶ。
外部ツールは固定せず、あとで差し替えられる構成とする(7章)。

口パクに必要なのは「時刻ごとの母音(口形)と強弱」であって歌詞の単語ではないため、歌詞の書き起こし
(意味のあるテキスト化)は行わない。歌唱では書き起こしの誤りが多く、母音の取り違えに伝播するため、
音声から母音・音素そのものを時刻付きで認識する方式を採る。

### 1.2 設計境界

CLAUDE.md の設計境界に従う。

- フォーマット層(VMDの読み書き)は `mmd_toolbox` に置く。
- アニメ的口パクのキーフレーム生成(標準口モーフの選択・母音合成プロファイル・生成方針)は共有モジュール
  `lipsync` に委譲する([lipsync.md](../lipsync/lipsync.md)。3章・6.5)。
- `song2vmd` 入口の判断(音声から口形イベント列を確定する処理＝母音→母音種別の写像・両唇閉鎖判定・無音/閉口
  判定・境界補正、声の強弱→開き量の写像、外部ツール連携、CLI引数、プリセットの具体値)は `song2vmd` 側に置く。

### 1.3 独立ツールとする理由

- 既存ツール(`shakevmd`・`sparsevmd`・`mocapvmd`)はいずれもVMDを入力に取る。
  `song2vmd` は音声を入力に取り、外部の音声解析CLIを束ねる点で系統が異なる。
- 音声解析(分離・音素認識)はドメイン固有で、外部ツールへの依存と差し替えが本質。
  この依存管理を既存ツールへ混ぜない。

## 2. 目的

### 2.1 解きたい問題

MMDで歌に口パクを手付けするのは手間が大きい。自動生成したいが、フレーム単位で音声スペクトルを
追従して母音を推定する素朴な自動化は、次の問題を起こしやすい。

- モーフ値がフレームごとに細かく揺れ、口の動きが小刻みでせわしなく見える。
- フレームごとのスペクトル推定に任せて母音モーフが無制御に混ざり、口形が定まらず締まらない。
- 声の強弱をフレーム単位で連続追従するため、開き量が常に微振動する。

これらは、MMDの手付けやアニメで見られる「はっきり開閉し、1拍ごとに口形を保持する」口パクとは
かけ離れた見た目になる。なお、綺麗な口形のために複数の口モーフを組み合わせること自体は必要であり
有効である。避けるべきは「フレームごとの無制御な混在」であって、「設計された合成」ではない(3章)。

### 2.2 目標

- 日本語の歌の音声から、**アニメ的(MMD的)な、はっきり開閉する口パク**を自動生成する。
- 母音をモーラ単位で1つの主母音モーフとして保持し、フレーム単位の小刻みな揺れを避ける(3章)。
- 声の強弱を、各モーラの口の開き量(モーフ最大値)に反映する。
- ボーカル抽出・音素/母音認識の外部ツールを、あとで差し替えられる構成にする。
- 処理結果を数値レポートで確認できるようにする。

### 2.3 非目標

- 口モーフ(あ・い・う・え・お)以外の表情(まばたき、眉、目、感情表現)は生成しない。
  声から表情の感情までは判定しない。
- 日本語以外の言語は対象外とする。母音写像・特殊モーラ処理は日本語前提とする。
- 解剖学的な口形合成や、子音ごとの精密な口形再現は行わない。あくまで標準母音モーフによる口パク。
- 汎用キーフレーム疎化器は作らない。アニメ的な疎なキーは生成段階で直接置く(9章)。

## 3. アニメ的口パクの定義(品質基準)

本ツールが満たすべき口パクの質(アニメ的・MMD的な、はっきり開閉する口パク)の品質基準は、共有モジュール
`lipsync` の [lipsync.md §3](../lipsync/lipsync.md) を正本とする。設計された母音合成・開きすぎない・保持と
最小保持・協調調音・同母音連結・口形の先行準備・きびきびした遷移・子音と無音の口形・疎なキーといった要件は
そちらで定義し、本書では重複定義しない。

`song2vmd` は、音声から確定した口形イベント列(6.3)と開き量(6.4・6.5)を `lipsync` に渡して、この品質基準を
満たす口パクを得る。母音の単位はフレームごとのスペクトルではなく、音素/母音認識で得た時刻付き音素(から
束ねたモーラ)に置く(4章)。

---

## 4. 処理パイプライン

各ステージは正規化された中間形式でつながる。外部委譲ステージ(S1・S2)は差し替え可能(7章)。
音声の読み込みは soundfile を優先し、soundfile で読めない形式のみ ffmpeg を内部で用いる
(6.1)。

```text
入力 音声ファイル(歌, BGM込み可)
  ├─[S0] 入力読み込み(復号・レベル正規化。ch/SR保持) soundfile優先/ffmpegフォールバック → 正規化PCM
  ├─[S1] ボーカル抽出(正規化PCM→ボーカル)         ライブラリ(差し替え可)→ ボーカルWAV
  ├─[S2] 音素/母音認識(ボーカルを16kHz monoへ変換) ライブラリ(差し替え可)→ 時刻付きセグメント列
  ├─[S3] 強弱エンベロープ(ボーカルのRMS)          song2vmd側(numpy/scipy)→ 時刻ごとの音量(RMS)
  └─[S4] モーフ生成(口形イベント+開き量→lipsync)  lipsync(共有)+ mmd_toolbox→ あ・い・う・え・お の口パクVMD
```

- すべてのステージは `song2vmd` の1コマンド内で完結する。外部ツールはツールが内部で呼ぶ(ライブラリAPI、
  または内部管理のサブプロセス)。利用者が demucs / ffmpeg 等のコマンドを手で叩くことはない(7章)。
- S1(Demucs 等)は**ステレオ原音のまま分離する方が品質が高い**ため、S0 では mono化・低レート化をせず
  チャンネル数・サンプルレートを保持する(復号に加え入力レベル正規化を行う。6.1)。S2 が要求する 16kHz mono
  化は、S1 で得たボーカルに対して S2 の前段で行う。
- S2は歌詞テキストを介さず、ボーカルから母音・子音・gap を時刻付きで認識する。無音/閉口の確定・あいうえお
  写像は中核(入口)がS3のRMSと音素ラベルを併せて行い、口形イベント列(母音・両唇閉鎖・無音)を作る(6.3)。
  3章の口パク(保持・閉口キー)の生成は `lipsync` が行う(6.5)。
- S2の時刻精度はバックエンド依存で粗いことがある。母音の立ち上がりはS3のRMS立ち上がり(オンセット)へ
  寄せて補正する(6.3・6.4)。
- S3は外部ツールを使わず、ボーカルのRMSエンベロープを `numpy/scipy` で算出する。各区間の保持値
  (口の開き量)を決めるのに使う(6.5)。
- S0は復号と入力レベル正規化(斉次スカラ。6.1)を行い、チャンネル数・サンプルレートを保持する(16kHz mono 化は S2 前段で行う)。

## 5. コマンドライン仕様

### 5.1 書式

```text
song2vmd INPUT [options]
```

`INPUT` は音声ファイル(wav/mp3 等、外部ツールが扱える形式)。既定出力:

```text
<入力名>.vmd
```

### 5.2 主なオプション(初期案)

| 引数 | 既定 | 説明 |
|---|---:|---|
| `INPUT` | 必須 | 入力音声ファイル |
| `-o, --output PATH` | `<入力名>.vmd` | 出力VMD |
| `--overwrite` | off | 既存出力の上書きを許可 |
| `--model-name NAME` | 空 | VMDに格納するモデル名(最大20バイト, Shift-JIS) |
| `--style NAME` | `pop` | 歌い方スタイルプリセット(8.1)。開き量レンジ・タイミングを切り替える |
| `--separate-vocals MODE` | `auto` | ボーカル分離 `auto` / `always` / `never` |
| `--separator NAME` | 採用ツール固定 | S1バックエンド選択(7章)。初期は固定、選択は段階導入 |
| `--recognizer NAME` | 採用ツール固定 | S2音素/母音認識バックエンド選択。初期は固定、選択は段階導入 |
| `--vowel-gain a:i:u:e:o` | プリセット値 | 母音別の開き量倍率(口形バランス調整) |
| `--open-max V` | プリセット値 | 口の開き量の上限(開けすぎ防止) |
| `--coarticulation FRAMES` | プリセット値 | 隣接母音の協調調音の重なり長(上限) |
| `--anticipation FRAMES` | プリセット値 | 母音口形を音より先行させる最大フレーム数 |
| `--min-hold FRAMES` | プリセット値 | 最小保持フレーム。これより短いモーラは併合/間引き |
| `--intensity-curve P` | プリセット値 | 強弱→開き量の非線形指数(累乗則) |
| `--silence-threshold ON:OFF` | プリセット値 | 無音(閉口)判定のヒステリシス開始/終了しきい値 |
| `--max-duration SEC` | `300` | 長尺の自動分割境界(処理資源対策。0で無効。6.6) |
| `--report-json PATH` | なし | モーラ・音素・強弱・キー数の処理統計を出力 |
| `--dry-run` | off | 出力せず処理計画と診断を表示 |
| `--keep-intermediate` | off | 中間生成物(正規化PCM・分離WAV・認識結果)を残す(診断用) |

外部ツールは song2vmd が内部で呼ぶ(7章)。モデル等の細かな呼び出し設定は設定で与え、CLIには
バックエンドの「選択」と、口パクの「効かせ方」のみを置く。

### 5.3 入出力要件

- 出力VMDの書き出しは `mmd_toolbox.vmd.io` に委譲する。生成するのはモーフキーのみ。
- ボーン・カメラ・照明・セルフ影セクションは空で出力する。
- 文字列(モーフ名・モデル名)はShift-JIS(cp932)で格納する。
- フル自動のみとし、中間生成物を入力に取ってステージをスキップする運用は設けない。中間生成物は
  一時作業ディレクトリに置き、既定では処理後に破棄する(`--keep-intermediate` で保持)。
- 外部ツールの非決定性(モデル・スレッド)に注意し、可能な範囲で決定論にする(10章)。

## 6. 機能要求

### 6.1 入力読み込み(S0)

- 入力音声を読み込み、後段が扱えるPCMにする。読み込みは `soundfile`(現行の同梱 libsndfile は
  WAV/FLAC/OGG/mp3 に対応)を優先し、読めない形式(一部の m4a/aac 等)のみ ffmpeg にフォールバックする。
  ffmpeg はリポジトリに同梱・再配布せず自動検出して内部で呼ぶ(7.1)。
- S0 では**チャンネル数・サンプルレートを保持**する(S1 はステレオ原音の方が分離品質が高いため、ここで
  mono化・低レート化しない)。S2 が要求する 16kHz mono への変換と再サンプリングは、S1 で得たボーカルに
  対して S2 の前段で行う(numpy/scipy 等)。
- **入力レベル正規化**: 入力全体の音量を一定の基準レベルへ正規化してから S1 以降へ渡す。正規化係数は入力に
  対して斉次(正の一様ゲイン g に対し正規化後PCMが不変。例: ピーク値、または絶対ゲート無しの全体RMSで割る)
  とし、絶対ゲートを持つ測定(ゲート付きラウドネス)は使わない。これにより分離・認識・強弱算出が入力の全体
  ゲインに依存しない(同一音源のゲイン違いで口パク結果が変わらない。6.3・6.4)。基準値は実装で確定。

### 6.2 ボーカル抽出(S1)

- S0 の出力(入力レベル正規化済み。ステレオ・元サンプルレート)からボーカルを分離し、ボーカルWAVを得る
  (出力形式は分離器に従う)。`--separate-vocals` で挙動を選ぶ。
  - `auto`(初期): 常に分離する(初期実装ではBGM有無の自動判定を持たず `always` と同義)。BGM有無の
    自動判定は別の判定問題のため将来対応とする。
  - `always`: 常に分離する。
  - `never`: 分離せず入力をそのままボーカルとして扱う(既にボーカル単体の入力向け)。
- 分離は外部ライブラリで内部実行し(必要時のみサブプロセス)、Separator 抽象の背後で差し替え可能とする(7章)。

### 6.3 音素/母音認識(S2)

- S1 のボーカルを認識器が要求する形式(16kHz mono)へ変換したものから、歌詞テキストを介さずに母音・音素を
  時刻付きで認識する(文字列なしの音素認識)。口パクに必要なのは母音の時刻であり単語ではないため、意味の
  ある書き起こしは行わない。
- 認識器は **母音・子音・gap(未割当区間)** を区別したセグメントとおおまかな時刻を返す(7.2)。母音→モーフ
  写像は a→あ, i→い, u→う, e→え, o→お。**無音・閉口の確定は中核が S3 のRMSと音素ラベルを併せて行う**。
  CTC の blank はそのまま無音にせず、gap として中核が RMS で無音/継続を判定する。
- **入力ゲインへの頑健性**: 入力の全体ゲイン差は S0 の入力レベル正規化(6.1)で吸収し、パイプライン全体
  (分離・認識・強弱)が入力音量に依存しない。これは分離器(代替 Separator を含む)のゲイン依存も断つ。
  加えて認識器自身も入力振幅を内部正規化することが多く(wav2vec2 の特徴抽出など)、強弱(S3)は曲ごとに相対
  正規化する(6.4)。口パク強弱用の別途ラウドネス正規化は不要。
- **時刻の確定**: CTC系の認識はトークン単位の粗いオフセットを返すため、各母音区間の境界は認識のトークン
  境界を一次情報とし、S3のRMSの立ち上がり(オンセット)が近傍にあるときだけそれへ寄せて精緻化する。
  オンセットが無い(レガートで同程度の音量が続く等)場合はトークン境界をそのまま用いる。境界の確定規則・
  補正窓・信頼度の扱いは実装で確定する。
- **観測できる音響イベントで規則を書く**: 文字列が無いため、字面上の特殊モーラ(撥音・促音・語末など)を
  音響だけから一般には確定できない。よって口形イベントの確定は次の観測可能なイベントに基づく(口パク生成は
  lipsync。6.5):
  - **連続した同一母音区間**: 同一母音が続く区間は、字面の長音・同母音連続を区別せず、観測上の連続同一母音
    区間として一つの口形イベントにまとめる。異なる母音は別の口形イベントとして渡す(保持区間化・同母音連結・
    境界の協調調音は lipsync が行う。6.5)。
  - **閉鎖・無音区間**: 子音セグメントが両唇音(ま行・ば行・ぱ行)なら一瞬の閉口にする。gap 区間は中核が
    S3 のRMSで判定し、RMSが無音しきい値以下なら無音(閉口)、発声が続いていれば直前母音を継続する
    (低ダイナミクス曲ではこの音量に基づく無音化を抑制。6.4)。促音か無音かを字面で区別せず、観測した
    無音/閉鎖の長さで扱う。
  - **弱い/無声の母音区間**: 認識信頼度とRMSが低い母音区間は、開き量を弱めて `lipsync` に渡す
    (短すぎる区間は lipsync の最小保持で前後へ吸収される。6.5)。初期実装は簡易判定でよい。
- **無音・閉口判定の責務**: 無音/閉口の確定は中核が、S2 のセグメント(母音/子音/gap)と S3 のRMSヒステリシス
  (`--silence-threshold`、6.4)を併せて行う。gap かつ RMS が無音しきい値以下なら無音(閉口)、母音セグメント
  でも RMS が無音しきい値以下の区間は閉口寄りに補正する(無声・誤検出対策)。ただし低ダイナミクス曲では、
  この音量に基づく無音化・無音補正を抑制する(音素由来の両唇閉鎖・先頭/末尾の閉口は対象外。6.4)。
- 子音は標準母音モーフで視覚的に表せるものに限定する。両唇閉鎖は閉口の口形イベントにし、その他の子音は
  独立した口形イベントにしない(前後母音の協調調音は lipsync が扱う。6.5)。舌位置が主体の子音は標準母音
  モーフで無理に再現しない。
- 認識は外部ライブラリで内部実行し(必要時のみサブプロセス)、Recognizer 抽象の背後で差し替え可能とする
  (7章)。日本語の歌での母音認識品質が本方式の品質を直接左右するため、採用は実現可能性ゲート(7.5)で
  確定する。音素→母音への写像と上記イベント規則の判断は日本語固有処理として song2vmd 側に置く。

### 6.4 強弱エンベロープ(S3)

- ボーカルWAVのRMSエンベロープを `numpy/scipy` で算出する。
- **相対正規化**: 絶対音量を直接モーフ値へ変換せず、曲またはフレーズ内の相対強度へ正規化する。
  正規化は外れ値の影響を抑えたパーセンタイル範囲を使い、瞬間的なピークを除外する。ミックスの音量差で
  口の開き量が変わらないようにする。
- **低ダイナミクス曲での閉口抑制**: 相対正規化は曲内に十分な強弱(無音と発声の差)がある前提のため、終始
  大音量で実質的な無音が無い曲では相対的に最も静かな部分を無音(閉口)と誤検出しうる。曲のダイナミックレンジ
  (発声部と最静部のレベル差。比なのでゲインに不変)が小さい曲では、**音量に基づく無音(閉口)判定**(発声が
  続く区間の無音化・母音区間の無音補正)を抑制する。音素に基づく両唇閉鎖や、先頭・末尾の構造的な閉口は抑制
  対象外。絶対レベルのしきい値は使わない(入力ゲインで結果が変わらないようにするため)。判定規則は実装で確定。
- **母音中央代表値**: 各モーラの保持値には、子音区間を除いた母音中央部の代表RMSを使う。子音トランジェントで
  開き量が乱れるのを防ぐ(母音区間は音素認識から得る)。
- **無音判定のヒステリシス**: 開始しきい値と終了しきい値を分け、境界付近の開閉反復(小刻み)を防ぐ。
- **低信頼区間**: 認識・発声の信頼度が低い区間は、既定の最小開き量を保証せず閉口寄りに抑える。信頼度は
  認識器が出せる場合に用い、出せないバックエンドでは音量のみで代替する。
- 各モーラ区間のRMSから、そのモーラの口の開き量(保持値)を決める(6.5)。
- 外部ツールに依存しない。新たな重い依存を増やさない。

### 6.5 開き量の決定とモーフ生成への受け渡し

キーフレーム生成そのもの(3章の品質基準を満たすアニメ的口パク)は共有モジュール `lipsync` の
[lipsync.md §4](../lipsync/lipsync.md) のモーフ生成コアに委譲する。`song2vmd` は入口処理として開き量を決定し、
口形イベント列(6.3)・開き量・生成パラメータを `lipsync` に渡す。

- **開き量の決定(song2vmd 入口。RMS→開き量の写像)**: 各モーラ区間のRMS(6.4)を `--intensity-curve` の
  累乗則で写像し、`--open-max` とスタイルプリセットの開き量レンジ(強声/弱声の目安。8章)へクランプして、
  そのモーラの開き量(保持値スケール、0〜1相当)を決める。声が強いモーラほど大きく、ただし上限を超えて
  開かない。**このRMS→開き量の写像は `song2vmd` 側に残し、`lipsync` へは確定した開き量を渡す**
  (lipsync.md §2.2・§6)。
- **lipsync へ渡す入力**: 6.3 で確定した口形イベント列(母音 a/i/u/e/o・両唇閉鎖・無音/休符)、上記の
  モーラ別開き量、およびスタイルプリセット(8章)が与える生成パラメータ(アタック/リリース・遷移・協調調音・
  先行・最小保持・誇張など)。母音合成プロファイル・各生成パラメータの意味・キーフレーム生成方針
  (母音合成・保持・協調調音・先行準備・最小保持・きびきび遷移・疎キー配置・伸び表現)は lipsync.md を
  正本とし、本書では重複定義しない。
- **無音/閉口・両唇閉鎖の確定は入口で行う**: 無音・休符の区間や両唇閉鎖は、6.3・6.4 の観測イベント規則
  (RMSヒステリシス・両唇音判定)で口形イベントとして確定してから `lipsync` に渡す。`lipsync` 内では音量判定を
  しない。

### 6.6 長尺の分割

- 処理資源(メモリ・分離/認識の計算コスト)に配慮し、長尺音声を自動分割して処理する(`--max-duration`)。
  VMDのフレーム番号は十分大きい(u32)ため、分割はフレーム数上限対策ではなく資源対策である。
- 分割は歌唱の途中で切らないよう、無音区間で区切る。探索範囲内に無音が無い場合(ロングトーン・ライブ音源
  等)は最大チャンク長で強制分割し、継ぎ目はオーバーラップで補う(無音探索範囲・最大チャンク長は実装で確定)。
- 継ぎ目で品質を落とさないため、隣接チャンクは前後にオーバーラップを持たせて分離・認識し、各チャンクは
  中央区間のみ採用する。境界をまたぐ連続母音区間は結合し、キーの重複・欠落を避ける。強弱の相対正規化
  (6.4)は曲全体を基準に行い、チャンク単位で基準がずれないようにする。継ぎ目処理の具体手順は実装で
  確定する。

### 6.7 レポートと診断

`--dry-run` と `--report-json` は以下を出力する。

- 選択した各バックエンドと主要パラメータ。
- 分離の有無、認識音素数、検出モーラ数、音素認識の被覆率。
- モーラごとの母音・保持値・保持長、併合/間引きしたモーラ数。
- 閉口区間、最大開き量、生成キー数。

## 7. 外部ツール連携機構

利用者に外部コマンドを叩かせず、`song2vmd` が内部で外部ツールを呼ぶ。各委譲ステージはアダプタ
interfaceと正規化中間形式で疎結合にし、あとで差し替え可能にする。

### 7.1 内部呼び出し方針(ユーザーにコマンドを叩かせない)

- 利用者は `song2vmd INPUT` の1コマンドだけを実行する。入力読み込み・復号(ffmpeg)・ボーカル抽出・音素認識
  などの外部ツールは、すべて song2vmd が内部で呼ぶ。利用者が demucs / ffmpeg 等を手で実行することはない。
- 呼び出しは **ライブラリAPI(Python)を優先**し、ライブラリが無いものだけ内部管理のサブプロセスで呼ぶ。
  一時ファイル・出力の受け渡し・エラー処理・後始末はすべてツールが面倒を見る。
- これらの外部ツールは song2vmd の依存として導入する(パッケージのextra等)。`mmd_toolbox` 本体の必須依存
  は `numpy/scipy` のまま保ち、重い依存は song2vmd 側に閉じる。
- ffmpeg はライセンス(LGPL/GPL)上、**バイナリを本リポジトリに同梱・再配布しない**。実行時に自動検出
  (PATH/既知パス)して内部で呼ぶ(方針A・確定)。再配布しないため ffmpeg ビルドのライセンスは我々の義務に
  ならない。音声の読み込みはまず `soundfile` で試し(現行の同梱 libsndfile は 1.1.0 以降で WAV/FLAC/OGG に
  加え mp3 も復号できる)、`soundfile` で扱えない形式のみ ffmpeg へフォールバックする(再サンプリングは
  numpy/scipy でも可)。ffmpeg を同梱配布する別配布パッケージ(imageio-ffmpeg 等)への依存は採らない。
  いずれも利用者にffmpegコマンドを叩かせない。

### 7.2 アダプタinterface

- **Separator**: `separate(vocal_source, mode) -> vocal_wav_path`(内部でライブラリ/サブプロセスを呼ぶ)
- **Recognizer**: `recognize(vocal_wav_path) -> [Segment{type, start_sec, end_sec, phoneme?, confidence?}]`(文字列なしの音素認識)。`type` は **母音/子音/gap** の3種で、出力は全時間軸を重複・欠落なく被覆する。母音・子音セグメントは音素ラベル(IPA等)と任意の `confidence` を持つ。**gap** は認識器が音素を割り当てなかった区間(CTC の blank 等。発声の継続中にも出るため、ここで無音とは断定しない)。**無音/閉口の確定・あいうえお母音への写像・閉鎖(両唇音)判定は中核が行う**(S3 のRMSと音素ラベルを併用。6.3・6.4)。アダプタは言語非依存の音素分割(母音/子音/gap)までに責務を限定し、RMS を必要としない。

各ステージは抽象interfaceの背後に実装を隠す。**ボーカル抽出は Separator 抽象**の背後にあり、将来の抽出
ツール切り替えは Separator 実装の追加だけで行える(中核・他ステージは無変更)。Separator は入力に音声、
出力に「ボーカルWAVのパス」だけを約束し(出力形式は分離器に従う)、内部で用いるライブラリ・モデル・分離トラック構成・
一時ファイルの扱いは各実装に閉じる。`mode`(`auto`/`always`/`never`)もこの抽象が解釈する。

音素→母音への写像、gap の無音/継続判定、閉鎖(両唇音)判定、音響イベント規則(連続母音区間・閉鎖・無音。
6.3)は、S3 のRMSも使う日本語固有の中核処理であり、アダプタの外(song2vmd 中核側)に置く。これにより
アダプタは「音声→母音/子音/gap のセグメント列」だけに責務を限定でき、RMS を必要としない(RMS は S3 で
算出し中核が使う)。

### 7.3 正規化中間形式(差し替えの契約)

- S0出力: 復号・入力レベル正規化したPCM(チャンネル数・サンプルレートは保持。mono化・再サンプリングはしない。6.1)。
- S1出力: ボーカルWAVのパス(分離器の出力形式。S2向け 16kHz mono 化は S2 前段で行う)。
- S2出力: 全時間軸を被覆する時刻付きセグメント列(母音/子音/gap の区別・音素ラベル・任意の信頼度を含む。無音/閉口の確定は中核)。

各アダプタは、対応する外部ツールのネイティブ出力をこの中間形式へ変換する責務を持つ。中核ロジック
(S3・S4)は中間形式だけに依存し、特定の外部ツールに依存しない。

### 7.4 段階方針(初期は1ツール、のち引数で選択)

- **初期実装**: 各ステージに採用ツールを1つだけ組み込む(7.5)。アダプタinterface(7.2)と正規化中間
  形式(7.3)は初期から用意し、中核ロジックは特定ツールに依存しないようにする。
- **以降**: 各ステージに2つ目以降のアダプタを追加し、引数(`--separator` / `--recognizer`)で適用ツールを
  選択可能にする。中核ロジックは変えず、アダプタの追加だけで切り替えられる構造とする。特にボーカル抽出は
  この方針で複数の Separator 実装を切り替えられるようにする。

### 7.5 初期実装で採用するツールと将来の代替

いずれもツールが内部で呼ぶ(ライブラリAPI優先)。採用理由は下表のとおり。

| ステージ | 初期実装の採用ツール | 主な採用理由 | 将来の代替候補 |
|---|---|---|---|
| S0 入力読み込み | soundfile(現行 libsndfile は mp3 も可)優先 + 自動検出ffmpegへフォールバック(リポジトリに同梱しない) | 標準入出力を内部処理。soundfileで読めない形式のみffmpeg。ffmpegを再配布せずライセンス義務を避ける | —(方針B/imageio-ffmpeg は不採用) |
| S1 ボーカル抽出 | Demucs v4(`demucs.api`。元repo保守終了→限定bugfixの adefossez/demucs fork を版固定・`shifts=0`) | 高品質・MIT・ライブラリでin-process呼び出し可・GPU不要でも動作 | audio-separator(保守活発・Python API) / Spleeter / 分離なし(`never`) |
| S2 音素/母音認識 | wav2vec2 音素認識(transformers + 許諾モデル, in-process) | 歌唱頑健性(自己教師あり)・純Pythonでin-process・torchはDemucsと共有・ライセンス清浄(Apache/BSD+許諾モデル) | Julius 音素認識(phone-loop構成が必要・高精度時刻)。Allosaurusは GPL-3.0 で不可 |

初期採用は実装の出発点であり、品質・導入性の評価で見直す。

- **S2は実現可能性ゲート(必須)**: S2の母音認識品質は本方式の品質を直接左右する(成立しなければ製品全体が
  成立しない)。実装着手前に技術スパイクで、代表となる日本語歌唱サンプルの母音正解率・境界時刻ずれを測り、
  あらかじめ定めた受入基準を満たすことをゲートにする。満たさなければ Julius(phone-loop 音素認識の構成が
  必要)や他の認識器を評価する。受入基準・代表データ・指標は実装で確定する。
- **wav2vec2の依存**: torch は Demucs と共有するが、transformers 本体とモデル取得(ダウンロード・キャッシュ・
  メモリ・初回ネットワーク)は新規に必要。モデルの版(revision)固定・キャッシュ先・オフライン時の挙動・
  必要ディスク/RAM を依存仕様に含める。時刻はCTCで近似のため母音の立ち上がりをRMSオンセットへ寄せて
  精緻化する(6.3・6.4)。
- **Demucsの保守と再現性**: 元リポジトリは保守終了(archive)。限定的なbugfix対応の fork(adefossez/demucs)を
  版固定で使う。再現性のため `shifts=0` など非決定要素を固定する。保守活発な audio-separator も代替候補。
- 本リポジトリは MIT であり、GPL-3.0 の Allosaurus は採用しない。差し替えは7.4の構造に従いアダプタ追加で行う。

## 8. プリセットとパラメータ

口パクの効かせ方はプリセット(`--style`)で与え、実データでチューニングする。プリセットは「歌い方」に
よって口の開け方が変わることを反映する(8.1)。母音ごとの口形は合成プロファイルで定義する(8.2)。
共通の調整パラメータは 8.3 に置く。

### 8.1 歌い方スタイルプリセット

歌い方(しっとり・元気・力強い・ささやき・早口など)によって、適切な口の開き量・遷移の速さ・誇張の
強さが変わる。これをプリセットとして用意し、主に**開き量レンジ**(弱声〜強声で取り得る開きの範囲)と
**タイミング**(アタック/リリース・最小保持・遷移・誇張)を切り替える。

| プリセット | 想定する歌い方 | 開き量レンジ(弱〜強, 目安) | タイミング・誇張の方針 |
|---|---|---:|---|
| `pop`(既定) | 標準的・はっきりした歌唱 | 0.30 〜 0.75 | 中庸。はっきり開閉し保持を効かせる |
| `ballad` | しっとり・落ち着いた歌唱 | 0.20 〜 0.55 | 開き控えめ。アタック/リリース長め、伸ばしの揺らぎやや多め |
| `powerful` | 力強い・ロック・シャウト | 0.40 〜 0.95 | 大きく開く。誇張強め、アタック速い |
| `whisper` | ささやき・静かな歌唱 | 0.10 〜 0.35 | 開き小さく閉じ気味。遷移も控えめ |
| `rap` | 早口・テンポの速い歌唱 | 0.30 〜 0.70 | 最小保持を短く、遷移を速く、きびきび |

開き量レンジは各モーラのRMS(強弱)を写像する下限・上限であり、`--open-max` で上限をさらに抑えられる。
プリセットは出発点で、`--open-max` などの個別オプション(8.3)で上書きできる。値は実データで調整する。

### 8.2 母音合成プロファイル

各母音の口形を、標準口モーフの重みの組として定義する(3章の「設計された母音合成」)。素のモーフ単独では
不自然になりやすい母音(特に う・お の丸め、い の横開き)を、補助の口モーフを少量重ねて整える。
初期プロファイル(実データで調整。値は保持値=1.0時の相対重み):

| 母音 | 主モーフ | 補助の合成(初期案) |
|---|---|---|
| あ | あ | 単独主体 |
| い | い | 必要に応じ あ をごく少量(開き確保) |
| う | う | お を少量(丸めの安定) |
| え | え | あ・い を少量(中間開き) |
| お | お | う を少量(丸め) |

補助の重みはプリセットの誇張方針に応じて増減する。複数モーフを合成しても口形が破綻しないよう、合成後の
総量が `--open-max` を超えないようにクランプする。初期実装で使う口モーフは標準口母音モーフ
(あ・い・う・え・お)と閉口を基本とし、感情・口角などの表情モーフ付与は初期非対象とする(2.3)。

### 8.3 共通パラメータ

各プリセットが持つ初期パラメータ(実データで調整):

- 開き量レンジ(弱声・強声の目安)と上限(`--open-max`)。口を開けすぎない上限の主役。
- 強弱→開き量の非線形指数(`--intensity-curve`)。弱い声を持ち上げすぎない累乗則。
- 最小保持フレーム(`--min-hold`)。小刻み抑制の主役。
- アタック/リリースのフレーム数、遷移フレーム数(きびきび感)。
- 協調調音の重なり長(`--coarticulation`)と母音口形の先行フレーム数(`--anticipation`)。
- 母音合成プロファイル(8.2)と母音別の開き量倍率(`--vowel-gain`)。
- 無音判定のヒステリシス開始/終了しきい値(`--silence-threshold`)、両唇音の閉口の深さ・長さ。
- 長い伸ばし音に許す揺らぎの量(既定は控えめ)。

初期値は固定とせず、歌唱内容・ミックス・モデルにより適切値が変わる前提で、レポート(6.7)と
MMD/MMM上の視覚確認で調整する。特に開き量レンジ・最小保持・アタック/リリース・強弱指数は、
小刻み感・開きすぎ・口の生き生きさのトレードオフに直結するため重点的に調整する。

## 9. mmd_toolbox との関係

- VMDの読み書きは `mmd_toolbox.vmd.io` に委譲する。`song2vmd` はVMDのバイナリ構造を直接扱わない。
- 生成するのはモーフキーのみ。モーフキーがキー間で線形評価される事実(補間曲線を持たない)は
  [vmd-interp.md](../mmd_toolbox/vmd-interp.md) を正本とする。
- アニメ的な疎なキーは生成段階で直接置く(キーフレーム生成は 6.5 で共有モジュール `lipsync` に委譲)。
  ボーン/カメラ用のベジェ疎化のような汎用疎化器は作らず、`mmd_toolbox` にモーフ用の疎化機能も追加しない
  (設計境界どおり、アニメ的口パクの生成判断は共有モジュール `lipsync` 側、フォーマット入出力は
  `mmd_toolbox` 側)。
- 既知の制約: 既存の `mmd_toolbox.vmd.reduce` はボーン/カメラ専用(`Tolerances` も `bone_*`/`camera_*` のみ)で、
  モーフ(スカラー)キーの疎化には対応していない。song2vmd は汎用疎化を使わず生成段階で直接疎キーを置くため、
  この非対応は本ツールの障害にならない。将来モーフ疎化を共通機能として持たせる場合は、`mmd_toolbox` 側に
  モーフ対応の追加(修正)が必要になる。
- 時間軸は30fps基準(`mmd_toolbox` 規約)に従う。

## 10. 制約と考慮事項

- 日本語の歌のみを対象とする。母音認識の誤り(歌唱の崩れ・ロングトーン・無声化・コーラス混入など)は
  そのまま口形に出る。
- 母音認識は歌唱で誤ることがある。歌詞テキストを介さず母音そのものを認識することで、単語誤り・幻聴の
  伝播は避ける。認識の時刻が粗い場合はRMSオンセットへ寄せて補正する(6.3・6.4)。将来、より高精度な
  認識器や、任意の歌詞テキスト指定による精度向上の余地を残す。
- 処理資源に配慮し、長尺は自動分割する(6.6。VMDフレーム番号は u32 で十分大きく上限対策ではない)。
- 音声の読み込みは soundfile を優先し、読めない形式のみ ffmpeg(自動検出・非再配布)にフォールバックする。
  ffmpegバイナリはリポジトリに同梱せず、利用者にffmpegコマンドは叩かせない(7.1)。
- 外部ツール・モデルの取得失敗や実行失敗の場合は、どのステージで失敗したかを明示して停止する。
- 出力の再現性: 外部ツール(分離・認識)が非決定的な場合があるため、モデル指定・シード固定・スレッド
  設定で可能な範囲の決定論を目指す。完全な決定論は外部ツール依存であることを明記する。
- 将来拡張(初期非対象): 感情・表情モーフの付与、英語等の多言語対応、歌詞テキスト指定による高精度化。
