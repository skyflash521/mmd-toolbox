# song2vmd 要求仕様書

日本語の歌の音声ファイルから、標準表情モーフ(あ・い・う・え・お)による口パクVMDを
自動生成する独立CLIツールの要求仕様。

---

## 1. 位置づけ

### 1.1 結論

本機能は `song2vmd` という独立CLIツールとして提供する。

`song2vmd` は、日本語の歌の音声ファイル(BGM込み可)を入力に、ボーカル抽出・音素/母音認識・
声の強弱解析を経て、標準表情モーフによる口パクVMDを **1コマンドのフル自動**で出力する。

```text
入力 音声ファイル(歌, mp3/wav 等)
  -> song2vmd(ボーカル抽出 → 音素/母音認識 → 強弱 → モーフ生成)
  -> 口パクVMD
  -> MMD/MMMで確認・編集
```

ボーカル抽出・音素/母音認識・強弱RMS算出の音声前段は共有モジュール
[vocal_analysis](../vocal_analysis/vocal_analysis.md) に委譲し(外部ツールは vocal_analysis が内部で呼び、固定
せず差し替えられる)、`song2vmd` はその共有出力から口形イベント列と開き量を作って `lipsync` へ渡す(4章・7章)。

口パクに必要なのは「時刻ごとの母音(口形)と強弱」であって歌詞の単語ではないため、歌詞の書き起こし
(意味のあるテキスト化)は行わない。歌唱では書き起こしの誤りが多く、母音の取り違えに伝播するため、
音声から母音・音素そのものを時刻付きで認識する方式を採る。

### 1.2 設計境界

CLAUDE.md の設計境界に従う。

- フォーマット層(VMDの読み書き)は `mmd_toolbox` に置く。
- 音声前段(ボーカル抽出・音素/母音認識・強弱RMS算出)と IPA→5母音写像規則・S-1認識ゲートは共有モジュール
  `vocal_analysis` に委譲する([vocal_analysis.md](../vocal_analysis/vocal_analysis.md)。7章)。
- アニメ的口パクのキーフレーム生成(標準口モーフの選択・母音合成プロファイル・生成方針)は共有モジュール
  `lipsync` に委譲する([lipsync.md](../lipsync/lipsync.md)。3章・6.5)。
- `song2vmd` 入口の判断(vocal_analysis の出力から口形イベント列を確定する処理＝IPA→母音写像の適用・両唇閉鎖
  判定・無音/閉口判定・境界補正、声の強弱→開き量の写像、CLI引数、プリセットの具体値)は `song2vmd` 側に置く。

### 1.3 直経路の採用(vpr を中間に挟まない)

`song2vmd` は音声から VMD への**直経路**を採り、vpr を中間に挟まない(音声→vpr→vmd と二段にしない)。

- 二段にすると、音声由来の**連続的な開き量(RMS)が音符のベロシティ/休符へ落ち、時刻も音符単位へ量子化される**
  ため、口パクの開き量と境界が鈍る。直経路はフル自動・音声→VMD の要件(1.1)とも整合する。
- 共有するのは**音声前段(vocal_analysis)とモーフ生成コア(lipsync)**であって vpr ではない。各CLIは2入力抽象
  (口形イベント列＋開き量)を別々の入口で用意して同じコアへ渡すので([lipsync.md](../lipsync/lipsync.md) §2)、
  コア再利用による効率と直経路による品質を両立できる。
- この劣化評価は設計上の判断であり、`vpr_io` の読み書きが整えば(vpr 経路を実際に通して)実測で確かめる。

### 1.4 独立ツールとする理由

- 既存ツール(`shakevmd`・`sparsevmd`・`mocapvmd`)はいずれもVMDを入力に取る。
  `song2vmd` は音声を入力に取り、共有モジュール(`vocal_analysis`・`lipsync`)を束ねる点で系統が異なる。
- 音声解析(分離・音素認識)はドメイン固有で、外部ツールへの依存と差し替えが本質。
  この依存管理を既存ツールへ混ぜない。

## 2. 目的

### 2.1 解きたい問題

MMDで歌に口パクを手付けするのは手間が大きい。自動生成したいが、フレーム単位で音声スペクトルを
追従して母音を推定する素朴な自動化は、次の問題を起こしやすい。

- モーフ値がフレームごとに細かく揺れ、口の動きが小刻みでせわしなく見える。
- フレームごとのスペクトル推定に任せて母音モーフが無制御に混ざり、口形が定まらず締まらない。
- 声の強弱をフレーム単位で連続追従するため、開き量が常に微振動する。

これらは、MMDの手付けやアニメで見られる「はっきり開閉し、1拍ごとに口形を保持する」口パクとは
かけ離れた見た目になる。なお、綺麗な口形のために複数の口モーフを組み合わせること自体は必要であり
有効である。避けるべきは「フレームごとの無制御な混在」であって、「設計された合成」ではない(3章)。

### 2.2 目標

- 日本語の歌の音声から、**アニメ的(MMD的)な、はっきり開閉する口パク**を自動生成する。
- 母音をモーラ単位で1つの主母音モーフとして保持し、フレーム単位の小刻みな揺れを避ける(3章)。
- 声の強弱を、各モーラの口の開き量(モーフ最大値)に反映する。
- ボーカル抽出・音素/母音認識の外部ツールを、あとで差し替えられる構成にする。
- 処理結果を数値レポートで確認できるようにする。

### 2.3 非目標

- 口モーフ(あ・い・う・え・お)以外の表情(まばたき、眉、目、感情表現)は生成しない。
  声から表情の感情までは判定しない。
- 日本語以外の言語は対象外とする。母音写像・特殊モーラ処理は日本語前提とする。
- 解剖学的な口形合成や、子音ごとの精密な口形再現は行わない。あくまで標準母音モーフによる口パク。
- 汎用キーフレーム疎化器は作らない。アニメ的な疎なキーは生成段階で直接置く(9章)。

## 3. アニメ的口パクの定義(品質基準)

本ツールが満たすべき口パクの質(アニメ的・MMD的な、はっきり開閉する口パク)の品質基準は、共有モジュール
`lipsync` の [lipsync.md §3](../lipsync/lipsync.md) を正本とする。設計された母音合成・開きすぎない・保持と
最小保持・協調調音・同母音連結・口形の先行準備・子音と無音の口形・疎なキーといった要件は
そちらで定義し、本書では重複定義しない。

`song2vmd` は、音声から確定した口形イベント列(6.3)と開き量(6.4・6.5)を `lipsync` に渡して、この品質基準を
満たす口パクを得る。母音の単位はフレームごとのスペクトルではなく、音素/母音認識で得た時刻付き音素(から
束ねたモーラ)に置く(4章)。

## 4. 処理パイプライン

音声前段(S0–S3: 入力読み込み・ボーカル分離・音素/母音認識・強弱RMS算出)は共有モジュール
[vocal_analysis](../vocal_analysis/vocal_analysis.md) に委譲する。`song2vmd` はその共有出力(ボーカルWAV・音素
セグメント列・RMS・IPA→5母音写像)から、入口処理で口形イベント列と開き量を作り、共有モジュール
[lipsync](../lipsync/lipsync.md) へ渡して口パクVMDを生成する。

```text
入力 音声ファイル(歌, BGM込み可)
  ├─[S0–S3] 音声前段        vocal_analysis(共有)→ ボーカルWAV・音素セグメント列・RMS・IPA→5母音写像
  ├─[入口]  口形イベント確定 song2vmd側 → 写像適用・両唇閉鎖判定・gap解決・無音/閉口確定・オンセット補正(6.3)
  ├─[入口]  開き量の決定     song2vmd側 → RMS→開き量(6.4・6.5)
  └─[S4]    モーフ生成       lipsync(共有)+ mmd_toolbox → あ・い・う・え・お の口パクVMD
```

- すべての処理は `song2vmd` の1コマンド内で完結する。音声前段の外部ツール(分離・認識・復号)は
  `vocal_analysis` が内部で呼ぶ。利用者が外部ツールのコマンドを手で叩くことはない(vocal_analysis.md §8)。
- S0–S3 の責務(入力読み込み・ch/SR保持・入力レベル正規化・ボーカル分離・音素/母音認識・RMS算出・相対正規化)と
  正規化中間形式・IPA→5母音写像規則は **vocal_analysis.md §2〜§7 を正本**とする。`song2vmd` はその共有出力を
  消費する(6.1)。
- **口形イベント確定(`song2vmd` 入口)**: vocal_analysis の音素セグメント列に IPA→5母音写像(規則は
  vocal_analysis 提供)を適用し、両唇閉鎖判定・gap解決・無音/閉口の確定・母音境界のRMSオンセット補正を行って
  口形イベント列(母音・両唇閉鎖・無音)を確定する(6.3)。
- **開き量の決定(`song2vmd` 入口)**: 各モーラのRMSから開き量を決める(6.4・6.5)。
- 確定した口形イベント列と開き量を `lipsync` へ渡し、3章の口パク(保持・閉口キー等)を生成する(6.5)。

## 5. コマンドライン仕様

### 5.1 書式

```text
song2vmd INPUT [options]
```

`INPUT` は音声ファイル(wav/mp3 等、外部ツールが扱える形式)。既定出力:

```text
<入力名>.vmd
```

### 5.2 主なオプション(初期案)

| 引数 | 既定 | 説明 |
|---|---:|---|
| `INPUT` | 必須 | 入力音声ファイル |
| `-o, --output PATH` | `<入力名>.vmd` | 出力VMD |
| `--overwrite` | off | 既存出力の上書きを許可 |
| `--model-name NAME` | 空 | VMDに格納するモデル名(最大20バイト, Shift-JIS) |
| `--style NAME` | `pop` | 歌い方スタイルプリセット(8.1)。開き量レンジ・タイミングを切り替える |
| `--separate-vocals MODE` | `auto` | ボーカル分離 `auto` / `always` / `never` |
| `--separator NAME` | 採用ツール固定 | S1バックエンド選択(7章)。初期は固定、選択は段階導入 |
| `--recognizer NAME` | 採用ツール固定 | S2音素/母音認識バックエンド選択。初期は固定、選択は段階導入 |
| `--vowel-gain a:i:u:e:o` | プリセット値 | 母音別の開き量倍率(口形バランス調整) |
| `--open-max V` | プリセット値 | 口の開き量の上限(開けすぎ防止) |
| `--coarticulation FRAMES` | プリセット値 | 隣接母音の協調調音の重なり長(上限) |
| `--anticipation FRAMES` | プリセット値 | 母音口形を音より先行させる最大フレーム数 |
| `--min-hold FRAMES` | プリセット値 | 最小保持フレーム。これより短いモーラは併合/間引き |
| `--intensity-curve P` | プリセット値 | 強弱→開き量の非線形指数(累乗則) |
| `--silence-threshold ON:OFF` | プリセット値 | 無音(閉口)判定のヒステリシス開始/終了しきい値 |
| `--max-duration SEC` | `300` | 長尺の自動分割境界(処理資源対策。0で無効。6.6) |
| `--report-json PATH` | なし | モーラ・音素・強弱・キー数の処理統計を出力 |
| `--dry-run` | off | 出力せず処理計画と診断を表示 |
| `--keep-intermediate` | off | 中間生成物(正規化PCM・分離WAV・認識結果)を残す(診断用) |

音声前段の外部ツールは vocal_analysis が内部で呼ぶ(7章)。モデル等の細かな呼び出し設定は設定で与え、CLIには
バックエンドの「選択」と、口パクの「効かせ方」のみを置く。

### 5.3 入出力要件

- 出力VMDの書き出しは `mmd_toolbox.vmd.io` に委譲する。生成するのはモーフキーのみ。
- ボーン・カメラ・照明・セルフ影セクションは空で出力する。
- 文字列(モーフ名・モデル名)はShift-JIS(cp932)で格納する。
- フル自動のみとし、中間生成物を入力に取ってステージをスキップする運用は設けない。中間生成物は
  一時作業ディレクトリに置き、既定では処理後に破棄する(`--keep-intermediate` で保持)。
- 外部ツールの非決定性(モデル・スレッド)に注意し、可能な範囲で決定論にする(10章)。

## 6. 機能要求

### 6.1 入力読み込み(S0)

入力読み込み(復号・入力レベル正規化・チャンネル数/サンプルレート保持)は共有モジュール
[vocal_analysis](../vocal_analysis/vocal_analysis.md) の S0(vocal_analysis.md §3)に委譲する。`song2vmd` は
正規化PCMを直接扱わず、後段の共有出力を消費する。

- **入力ゲインへの頑健性**: 入力の全体ゲイン差は vocal_analysis の入力レベル正規化(S0)で吸収され、分離・
  認識・RMS算出が入力音量に依存しない(同一音源のゲイン違いで口パク結果が変わらない。6.3・6.4)。

### 6.2 ボーカル抽出・音素認識・強弱RMS(S1–S3)

ボーカル抽出(S1)・音素/母音認識(S2)・強弱RMS算出(S3)は共有モジュール
[vocal_analysis](../vocal_analysis/vocal_analysis.md) に委譲する(vocal_analysis.md §4〜§6)。`song2vmd` は共有
出力(ボーカルWAV・音素セグメント列・RMS)を消費する。

- **ボーカル抽出(S1)**: vocal_analysis.md §4。分離の挙動 `auto`/`always`/`never` の選択は `song2vmd` の CLI
  (`--separate-vocals`、5.2)で公開する。
- **音素/母音認識(S2)**: vocal_analysis.md §5。母音/子音/gap の全被覆セグメント列＋IPAラベル(任意の信頼度)を
  得る。バックエンド選択は CLI(`--recognizer`、5.2)で公開する。
- **強弱RMS算出(S3)**: vocal_analysis.md §6。相対正規化したRMSを得る。RMS を使う判断(無音/閉口・開き量)は
  `song2vmd` 入口(6.3・6.4)。

### 6.3 口形イベント列の確定(入口)

[vocal_analysis](../vocal_analysis/vocal_analysis.md) の音素セグメント列(母音/子音/gap＋IPAラベル)と RMS から、
`song2vmd` 入口で口形イベント列(母音・両唇閉鎖・無音)を確定する。母音認識そのもの・IPA→5母音写像規則・
認識器の採用と実現可能性ゲートは vocal_analysis.md(§5・§7・§9)を正本とする。確定処理は次のとおり(確定した
口形イベント列からの口パク生成は lipsync。6.5):

- **あいうえお写像の適用**: vocal_analysis の IPA→5母音写像規則(vocal_analysis.md §7)を母音セグメントへ適用し、
  a→あ, i→い, u→う, e→え, o→お とする。
- **時刻の確定(オンセット補正)**: 認識のトークン境界を一次情報とし、近傍に S3 のRMS立ち上がり(オンセット)が
  あるときだけそれへ寄せて精緻化する。無い(レガートで同程度の音量が続く等)場合はトークン境界を用いる。
  補正窓・規則は実装で確定する。
- **観測できる音響イベントで規則を書く**: 文字列が無いため、字面上の特殊モーラ(撥音・促音・語末など)を音響
  だけから一般には確定できない。よって口形イベントの確定は次の観測可能なイベントに基づく:
  - **連続した同一母音区間**: 同一母音が続く区間は、字面の長音・同母音連続を区別せず、観測上の連続同一母音
    区間として一つの口形イベントにまとめる。異なる母音は別の口形イベントとして渡す(保持区間化・同母音連結・
    境界の協調調音は lipsync が行う。6.5)。
  - **閉鎖・無音区間**: 子音セグメントが両唇音(ま行・ば行・ぱ行)なら一瞬の閉口にする。gap 区間は RMS で
    判定し、RMSが無音しきい値以下なら無音(閉口)、発声が続いていれば直前母音を継続する(低ダイナミクス曲では
    この音量に基づく無音化を抑制。6.4)。促音か無音かを字面で区別せず、観測した無音/閉鎖の長さで扱う。
  - **弱い/無声の母音区間**: 認識信頼度とRMSが低い母音区間は、開き量を弱めて `lipsync` に渡す(短すぎる区間は
    lipsync の最小保持で前後へ吸収される。6.5)。初期実装は簡易判定でよい。
- **無音・閉口判定の責務**: 無音/閉口の確定は入口が、vocal_analysis のセグメント(母音/子音/gap)と S3 のRMS
  ヒステリシス(`--silence-threshold`、6.4)を併せて行う。gap かつ RMS が無音しきい値以下なら無音(閉口)、母音
  セグメントでも RMS が無音しきい値以下の区間は閉口寄りに補正する(無声・誤検出対策)。ただし低ダイナミクス
  曲では、この音量に基づく無音化・無音補正を抑制する(音素由来の両唇閉鎖・先頭/末尾の閉口は対象外。6.4)。
- 両唇閉鎖は閉口の口形イベントにし、その他の子音は独立した口形イベントにしない(前後母音の協調調音は lipsync
  が扱う。6.5)。舌位置が主体の子音は標準母音モーフで無理に再現しない。
- あいうえお写像の適用・閉鎖判定・gap解決・観測イベント規則・口形イベント確定は日本語固有の入口処理として
  `song2vmd` 側に置く(vocal_analysis は写像規則と音素セグメント列・RMS を提供するまで)。

### 6.4 強弱(RMS)に基づく入口処理(S3の消費)

RMSエンベロープの算出と相対正規化は [vocal_analysis](../vocal_analysis/vocal_analysis.md) の S3
(vocal_analysis.md §6)に委譲する(入力ゲインに不変)。`song2vmd` 入口は、その相対正規化済みRMSを使って
無音/閉口判定と開き量決定を行う。

- **低ダイナミクス曲での閉口抑制**: 相対正規化は曲内に十分な強弱(無音と発声の差)がある前提のため、終始
  大音量で実質的な無音が無い曲では相対的に最も静かな部分を無音(閉口)と誤検出しうる。曲のダイナミックレンジ
  (発声部と最静部のレベル差。比なのでゲインに不変)が小さい曲では、**音量に基づく無音(閉口)判定**(発声が
  続く区間の無音化・母音区間の無音補正)を抑制する。音素に基づく両唇閉鎖や、先頭・末尾の構造的な閉口は抑制
  対象外。絶対レベルのしきい値は使わない(入力ゲインで結果が変わらないようにするため)。判定規則は実装で確定。
- **母音中央代表値**: 各モーラの開き量には、子音区間を除いた母音中央部の代表RMSを使う。子音トランジェントで
  開き量が乱れるのを防ぐ(母音区間は vocal_analysis の音素セグメントから得る)。
- **無音判定のヒステリシス**: 開始しきい値と終了しきい値を分け、境界付近の開閉反復(小刻み)を防ぐ。
- **低信頼区間**: 認識・発声の信頼度が低い区間は、既定の最小開き量を保証せず閉口寄りに抑える。信頼度は
  認識器が出せる場合に用い、出せないバックエンドでは音量のみで代替する。
- 各モーラ区間のRMSから、そのモーラの口の開き量を決める(6.5)。

### 6.5 開き量の決定とモーフ生成への受け渡し

キーフレーム生成そのもの(3章の品質基準を満たすアニメ的口パク)は共有モジュール `lipsync` の
[lipsync.md §4](../lipsync/lipsync.md) のモーフ生成コアに委譲する。`song2vmd` は入口処理として開き量を決定し、
口形イベント列(6.3)・開き量・生成パラメータを `lipsync` に渡す。

- **開き量の決定(song2vmd 入口。RMS→開き量の写像)**: 各モーラ区間のRMS(6.4)を `--intensity-curve` の
  累乗則で写像し、`--open-max` とスタイルプリセットの開き量レンジ(強声/弱声の目安。8章)へクランプして、
  そのモーラの開き量(保持値スケール、0〜1相当)を決める。声が強いモーラほど大きく、ただし上限を超えて
  開かない。**このRMS→開き量の写像は `song2vmd` 側に残し、`lipsync` へは確定した開き量を渡す**
  (lipsync.md §2.2・§6)。
- **lipsync へ渡す入力**: 6.3 で確定した口形イベント列(母音 a/i/u/e/o・両唇閉鎖・無音/休符)、上記の
  モーラ別開き量、およびスタイルプリセット(8章)が与える生成パラメータ(アタック/リリース・遷移・協調調音・
  先行・最小保持・誇張など)。母音合成プロファイル・各生成パラメータの意味・キーフレーム生成方針
  (母音合成・保持・協調調音・先行準備・最小保持・疎キー配置・伸び表現)は lipsync.md を
  正本とし、本書では重複定義しない。
- **無音/閉口・両唇閉鎖の確定は入口で行う**: 無音・休符の区間や両唇閉鎖は、6.3・6.4 の観測イベント規則
  (RMSヒステリシス・両唇音判定)で口形イベントとして確定してから `lipsync` に渡す。`lipsync` 内では音量判定を
  しない。

### 6.6 長尺の分割

- 処理資源(メモリ・分離/認識の計算コスト)に配慮し、長尺音声を自動分割して処理する(`--max-duration`)。
  VMDのフレーム番号は十分大きい(u32)ため、分割はフレーム数上限対策ではなく資源対策である。
- 分割は歌唱の途中で切らないよう、無音区間で区切る。探索範囲内に無音が無い場合(ロングトーン・ライブ音源
  等)は最大チャンク長で強制分割し、継ぎ目はオーバーラップで補う(無音探索範囲・最大チャンク長は実装で確定)。
- 継ぎ目で品質を落とさないため、隣接チャンクは前後にオーバーラップを持たせて分離・認識し、各チャンクは
  中央区間のみ採用する。境界をまたぐ連続母音区間は結合し、キーの重複・欠落を避ける。強弱の相対正規化
  (6.4)は曲全体を基準に行い、チャンク単位で基準がずれないようにする。継ぎ目処理の具体手順は実装で
  確定する。

### 6.7 レポートと診断

`--dry-run` と `--report-json` は以下を出力する。

- 選択した各バックエンドと主要パラメータ。
- 分離の有無、認識音素数、検出モーラ数、音素認識の被覆率。
- モーラごとの母音・保持値・保持長、併合/間引きしたモーラ数。
- 閉口区間、最大開き量、生成キー数。

## 7. 外部ツール連携(vocal_analysis への委譲)

音声前段(S0–S3)の外部ツール連携機構——内部呼び出し方針(利用者にコマンドを叩かせない)、アダプタ
interface(Separator / Recognizer)、正規化中間形式、段階方針、初期採用ツールと将来の代替、S2 実現可能性
ゲート——は共有モジュール
[vocal_analysis](../vocal_analysis/vocal_analysis.md)(§2・§8・§9)を正本とし、候補比較は
[vocal_analysis/external-tools.md](../vocal_analysis/external-tools.md) を補助資料とする。本書では重複定義しない。

- 利用者は `song2vmd INPUT` の1コマンドだけを実行する。音声前段の外部ツール(分離・認識・復号)は
  `vocal_analysis` が内部で呼び、利用者がそれらを手で実行することはない。
- バックエンドの選択(`--separator` / `--recognizer` / `--separate-vocals`)は `song2vmd` の CLI で公開する
  (5.2)。アダプタの追加・切り替えは vocal_analysis 側で行い、`song2vmd` はその選択肢を引数として見せる。
- 音声前段の重い依存(分離・認識のライブラリやモデル取得)は `vocal_analysis` 側に閉じ、`mmd_toolbox` 本体の
  必須依存は `numpy/scipy` のまま保つ。

## 8. プリセットとパラメータ

口パクの効かせ方はプリセット(`--style`)で与え、実データでチューニングする。プリセットは「歌い方」に
よって口の開け方が変わることを反映する(8.1)。母音ごとの口形は合成プロファイルで定義する(8.2)。
共通の調整パラメータは 8.3 に置く。

### 8.1 歌い方スタイルプリセット

歌い方(しっとり・元気・力強い・ささやき・早口など)によって、適切な口の開き量・遷移の速さ・誇張の
強さが変わる。これをプリセットとして用意し、主に**開き量レンジ**(弱声〜強声で取り得る開きの範囲)と
**タイミング**(アタック/リリース・最小保持・遷移・誇張)を切り替える。

| プリセット | 想定する歌い方 | 開き量レンジ(弱〜強, 目安) | タイミング・誇張の方針 |
|---|---|---:|---|
| `pop`(既定) | 標準的・はっきりした歌唱 | 0.30 〜 0.75 | 中庸。はっきり開閉し保持を効かせる |
| `ballad` | しっとり・落ち着いた歌唱 | 0.20 〜 0.55 | 開き控えめ。アタック/リリース長め、伸ばしの揺らぎやや多め |
| `powerful` | 力強い・ロック・シャウト | 0.40 〜 0.95 | 大きく開く。誇張強め、アタック速い |
| `whisper` | ささやき・静かな歌唱 | 0.10 〜 0.35 | 開き小さく閉じ気味。遷移も控えめ |
| `rap` | 早口・テンポの速い歌唱 | 0.30 〜 0.70 | 最小保持を短く、遷移を速く、きびきび |

開き量レンジは各モーラのRMS(強弱)を写像する下限・上限であり、`--open-max` で上限をさらに抑えられる。
プリセットは出発点で、`--open-max` などの個別オプション(8.3)で上書きできる。値は実データで調整する。

### 8.2 母音合成プロファイル

各母音の口形を、標準口モーフの重みの組として定義する(3章の「設計された母音合成」)。素のモーフ単独では
不自然になりやすい母音(特に う・お の丸め、い の横開き)を、補助の口モーフを少量重ねて整える。
初期プロファイル(実データで調整。値は保持値=1.0時の相対重み):

| 母音 | 主モーフ | 補助の合成(初期案) |
|---|---|---|
| あ | あ | 単独主体 |
| い | い | 必要に応じ あ をごく少量(開き確保) |
| う | う | お を少量(丸めの安定) |
| え | え | あ・い を少量(中間開き) |
| お | お | う を少量(丸め) |

補助の重みはプリセットの誇張方針に応じて増減する。複数モーフを合成しても口形が破綻しないよう、合成後の
総量が `--open-max` を超えないようにクランプする。初期実装で使う口モーフは標準口母音モーフ
(あ・い・う・え・お)と閉口を基本とし、感情・口角などの表情モーフ付与は初期非対象とする(2.3)。

### 8.3 共通パラメータ

各プリセットが持つ初期パラメータ(実データで調整):

- 開き量レンジ(弱声・強声の目安)と上限(`--open-max`)。口を開けすぎない上限の主役。
- 強弱→開き量の非線形指数(`--intensity-curve`)。弱い声を持ち上げすぎない累乗則。
- 最小保持フレーム(`--min-hold`)。小刻み抑制の主役。
- アタック/リリースのフレーム数、遷移フレーム数(きびきび感)。
- 協調調音の重なり長(`--coarticulation`)と母音口形の先行フレーム数(`--anticipation`)。
- 母音合成プロファイル(8.2)と母音別の開き量倍率(`--vowel-gain`)。
- 無音判定のヒステリシス開始/終了しきい値(`--silence-threshold`)、両唇音の閉口の深さ・長さ。
- 長い伸ばし音に許す揺らぎの量(既定は控えめ)。

初期値は固定とせず、歌唱内容・ミックス・モデルにより適切値が変わる前提で、レポート(6.7)と
MMD/MMM上の視覚確認で調整する。特に開き量レンジ・最小保持・アタック/リリース・強弱指数は、
小刻み感・開きすぎ・口の生き生きさのトレードオフに直結するため重点的に調整する。

## 9. mmd_toolbox との関係

- VMDの読み書きは `mmd_toolbox.vmd.io` に委譲する。`song2vmd` はVMDのバイナリ構造を直接扱わない。
- 生成するのはモーフキーのみ。モーフキーがキー間で線形評価される事実(補間曲線を持たない)は
  [vmd-interp.md](../mmd_toolbox/vmd-interp.md) を正本とする。
- アニメ的な疎なキーは生成段階で直接置く(キーフレーム生成は 6.5 で共有モジュール `lipsync` に委譲)。
  ボーン/カメラ用のベジェ疎化のような汎用疎化器は作らず、`mmd_toolbox` にモーフ用の疎化機能も追加しない
  (設計境界どおり、アニメ的口パクの生成判断は共有モジュール `lipsync` 側、フォーマット入出力は
  `mmd_toolbox` 側)。
- 既知の制約: 既存の `mmd_toolbox.vmd.reduce` はボーン/カメラ専用(`Tolerances` も `bone_*`/`camera_*` のみ)で、
  モーフ(スカラー)キーの疎化には対応していない。song2vmd は汎用疎化を使わず生成段階で直接疎キーを置くため、
  この非対応は本ツールの障害にならない。将来モーフ疎化を共通機能として持たせる場合は、`mmd_toolbox` 側に
  モーフ対応の追加(修正)が必要になる。
- 時間軸は30fps基準(`mmd_toolbox` 規約)に従う。

## 10. 制約と考慮事項

- 日本語の歌のみを対象とする。母音認識の誤り(歌唱の崩れ・ロングトーン・無声化・コーラス混入など)は
  そのまま口形に出る。
- 母音認識は歌唱で誤ることがある。歌詞テキストを介さず母音そのものを認識することで、単語誤り・幻聴の
  伝播は避ける。認識の時刻が粗い場合はRMSオンセットへ寄せて補正する(6.3・6.4)。将来、より高精度な
  認識器や、任意の歌詞テキスト指定による精度向上の余地を残す。
- 処理資源に配慮し、長尺は自動分割する(6.6。VMDフレーム番号は u32 で十分大きく上限対策ではない)。
- 音声前段の入力読み込みの方式(対応形式・復号のフォールバック・復号器を再配布しない方針・利用者にコマンドを
  叩かせない方針)は vocal_analysis.md §3・§8 を正本とする(7章)。
- 外部ツール・モデルの取得失敗や実行失敗の場合は、どのステージで失敗したかを明示して停止する。
- 出力の再現性: 外部ツール(分離・認識)が非決定的な場合があるため、モデル指定・シード固定・スレッド
  設定で可能な範囲の決定論を目指す。完全な決定論は外部ツール依存であることを明記する。
- 将来拡張(初期非対象): 感情・表情モーフの付与、英語等の多言語対応、歌詞テキスト指定による高精度化。
