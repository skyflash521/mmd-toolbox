# cli_progress 仕様書

CLI ツールの進捗ライブ表示(人間向け、標準エラーへの1行上書き表示)を提供する共有基盤ライブラリ。

層: **共有ドメイン層**([../../docs/conventions/layering.md §1](../../docs/conventions/layering.md#1-層タクソノミー))。形式層でも単一ツール固有でもない
ドメイン処理として共有ドメイン層に置く。[cli_events](../../libs/cli_events/cli_events.md)(機械モードの
JSON Lines イベント送出)とは関心事が別(本モジュールは人間向け stderr ライブ表示)なので同一モジュールへ
同居させず独立させる。

依存: Python 標準ライブラリのみ(`sys` / `threading` / `time` / `unicodedata` / `contextlib`)。
フォーマット層・他の共有ドメイン層(`vocal_analysis` / `cli_events`)へは依存しない。

正本関係: 進捗ライブ表示の外部契約(TTY判定での既定有効・`--quiet` による抑制・機械モードでの
progress イベント代替・1本の行への改行なし上書き・進行カウンタが更新されない間も経過時間表示を
進め続けて停滞と誤認させないこと・副作用専用・外部出力との競合時の一時停止)は
[CLIインターフェース規約
§6](../../docs/conventions/cli-interface.md#6-横断的な一貫性) が正(**以下、本書で「規約」はこの CLI インターフェース規約を指す**)。本書はその契約を実装する
共有モジュールの API・挙動を定める(規約が正、本書は実装ビュー)。

---

## 1. 公開API

`ProgressReporter(stream=None, *, enabled=None, now=None, interval=0.15, write_lock=None)`

- `stream`: 書き込み先(既定 `sys.stderr`)。
- `enabled`: 省略時は `stream.isatty()` で自動判定する(規約の「TTY判定での既定有効」を実装する)。
- `now`: 経過時間の計測に使う時刻関数(既定 `time.monotonic`)。
- `interval`: ハートビートの再描画間隔秒(既定 `0.15`)。
- `write_lock`: 構築時に注入する排他ロック(コンテキストマネージャプロトコルを満たすもの。[§2](#2-write_lock-契約))。

### メソッド

- `stage(label)`: 段を開始/切り替える。同じライブ行を使い、改行しない。旧段のハートビートを止めてから
  新しい段のハートビートを起こす(単一描画所有者。規約の停滞回避の実装)。
- `update(done, total, note="")`: 進行を通知する(描画はしない)。`total` が `None`(未確定)のときは
  カウントを出さず経過のみ表示する。`note` は描画行の末尾へ併記する(用途は呼び出し側が定める)。
- `close()`: 進捗を終える。ハートビートを止め join してから、ライブ行を消す(規約の「終了時はライブ行を
  消す」を実装する)。書き込み失敗で無効化された後でも、残存スレッドを防ぐため必ずハートビートを
  停止・join する。
- `summary(message)`: 完了行を1行残す(有効時のみ)。

### 副作用専用の保証

表示の `stream` 書き込みが失敗(端末のエンコード不能・閉じたストリームへの書き込み等)しても例外を
外へ漏らさず、以後の表示を `enabled=False` で無効化するだけで処理は止めない(規約の副作用専用を実装する)。

## 2. write_lock 契約

呼び出し元が同じ標準エラーへ別の仕組みで OS レベルの fd 操作(`os.dup2` によるリダイレクト等)を行う
場合、そのロックを構築時に `write_lock` として注入すると、ライブ行の描画・ライブ行の消去(`close`)・
完了行(`summary`)の各書き込みがそのロックを保持している間に行われる(呼び出し元の fd 操作と競合
しないようにするため)。未指定時は
`contextlib.nullcontext()` で no-op となり、ロックなしで動作する。どのツールがどんなロックを注入するかは
そのツール自身の仕様書が定める(本書は注入機構のみを規定する)。

## 3. テスト

`pytest libs/cli_progress` で単体検証する(テスト方針は [../vmd/vmd.md §4](../vmd/vmd.md#4-テスト方針) に準ずる。決定論的・外部依存なし)。
stream・clock・有効化・再描画間隔を注入で差し替え、デーモンスレッドの実時間スケジューリングには
依存しない。
