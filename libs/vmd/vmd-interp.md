# vmd-interp 仕様書

vmd.interp — MMD互換の補間曲線評価・サンプリング

親仕様: [vmd.md](vmd.md)
補間ブロックのバイトレイアウト: [`../../docs/specs/vmd/VMD_file_format.md`](../../docs/specs/vmd/VMD_file_format.md)

---

## 1. 目的

VMDの補間曲線をMMD本体と同一挙動で評価し、任意フレームでの
モーション値のサンプリング(ベイクの基礎)を提供する。

---

## 2. 補間曲線の定義

- 各チャンネルは制御点2つの3次ベジェ曲線:
  始点 `(0,0)`、終点 `(127,127)` 固定、制御点 `(x1,y1)`, `(x2,y2)` ∈ [0,127]。
  評価時は127で割って [0,1] に正規化する
- 線形(MMDデフォルト)は `(20,20), (107,107)`
- **補間パラメーターは区間の到達側(後側)キーに格納される**:
  区間 [k0, k1] の補間には k1 の補間パラメーターを使用する
- チャンネル構成:
  - カメラ: 6チャンネル(X/Y/Z位置・回転・距離・視野角)。
    **回転は1チャンネルをオイラー3軸すべてに共通適用する**
  - ボーン: 4チャンネル(X/Y/Z位置・回転)
- **モーフキーは補間ブロックを持たない**([vmd-io.md §2.2](vmd-io.md#22-キーフレーム))ため、ベジェ曲線を持たない。
  MMDはキー間のウェイトを線形補間で評価する。このキー間線形評価の意味論は本仕様を正とする
  (モーフ値のサンプリングAPIは現状提供しない。本仕様が提供するサンプリングAPIの対象は
  カメラ・ボーンのベジェ補間)

---

## 3. 評価

区間 [k0, k1] とサンプルフレーム f(k0.frame ≤ f ≤ k1.frame)について:

1. `x = (f - k0.frame) / (k1.frame - k0.frame)`
2. ベジェの時間成分 `X(s) = x` を逆解きして媒介変数 s を得る:
   ニュートン法(初期値 s=x、収束閾値 1e-6 程度)。
   非収束または s が [0,1] を外れた場合は二分法にフォールバック
3. `y = Y(s)` を補間係数とする

チャンネル別の値の算出:

- スカラー値(位置・距離・視野角): `v = v0 + (v1 - v0) × y`
- ボーン回転: クォータニオンの球面線形補間(slerp)に y を適用。
  **返り値は正規化済みクォータニオン**。VMD格納値は float32 でノルムが厳密に1とは限らないため、
  キーフレーム上の評価でも格納値とは正規化ぶんの差(~1e-8 水準)が生じうる(位置はキーフレーム上で
  格納値と厳密に一致する)
- カメラ回転: **オイラー各軸の線形補間に y を適用**(3軸とも共通の補間曲線で独立補間)。
  クォータニオンへの一般化は行わない(MMD互換のため)

境界の扱い:

- 最初のキー以前・最後のキー以後: 端キーの値で一定
- フレーム差1の区間: 30fps整数フレームのサンプルでは中間点が存在しない
  (両端キーの値のみが現れ、値ジャンプはそのまま保持される)
- 視野角(格納は整数度)は実数として評価・返却する。整数への丸めは呼び出し側の責任
  (丸め規則の既定は四捨五入。[§5](#5-mmd互換性の検証)参照)

## 4. API

    sample(keys, channel, frame) -> float | quaternion
    sample_range(keys, channel, frame_start, frame_end) -> numpy配列(1フレーム間隔)
    sample_camera(keys, frame) -> カメラ全チャンネルの評価値
    bake_bone_track(keys, frame_start, frame_end) -> (positions, rotations)

- 入力キー列はフレーム昇順を前提とする([vmd-io.md §5](vmd-io.md#5-正規化明示操作) の正規化済みであること)
- `sample_range` はベイク用途の一括評価。30fps・1フレーム間隔固定
- `bake_bone_track` はボーントラック全チャンネルの密ベイク。`[frame_start, frame_end]` を
  1フレーム間隔(両端含む)で評価し、positions は `(x, y, z)` の列、rotations はクォータニオンの列を返す。
  評価は `sample` と同一意味論([§3](#3-評価) の境界規約・到達側キーの補間曲線・回転の正規化)で、
  キー間隔の一様性を仮定せず区間 `[k0, k1]` ごとに独立に評価する。区間を単調に掃引する
  O(フレーム数+キー数) の実装とし、`sample_range` のフレームごとの区間探索を避ける。次の2つの
  ファストパスを持つ(いずれも一般解と同じ結果を返す高速化であり、評価の意味論は変えない):
  - 線形ファストパス: 到達側キーの制御点が X側とY側で一致する区間(MMD既定の線形
    `(20,20), (107,107)` を含む)は補間係数 `y = x` としてニュートン法を省く
  - 定数ファストパス: 区間両端の値が一致するチャンネルは端値の評価値で充填する
    (位置は端値そのもの、回転は正規化後の端値。一般解も同じ値を返すため)

## 5. MMD互換性の検証

MMD本体には中間フレームの補間値を機械可読に出力する機能がないため
(補間値の目視転記は実施不可能)、互換性は以下の2本立てで担保する:

1. **数値クロスバリデーション(自動・pytest内)**:
   補間ベジェのアルゴリズム自体は複数の互換実装で確立している
   ([../../docs/specs/vmd/VMD_file_format.md](../../docs/specs/vmd/VMD_file_format.md) の参照元)。リスクは数式の選択ではなく
   自前実装のミスにあるため、独立した実装(純Pythonのサードパーティ実装を
   テスト専用依存として利用するか、仕様から独立に書いた素朴な第2実装)との
   数値一致をテストする
2. **視覚A/Bスモーク(人間・一度きり)**:
   揺れ強度0でベイクしたVMDと元VMDをMMDで再生し、見た目に差がないことを
   確認する。数値の読み取りは行わない。pytest外の受け入れチェックとして
   手順を [`tests/data/README.md`](tests/data/README.md) に記す。補間誤りはカメラの動きの差として
   現れるため、全フレームベイクはこの確認の感度を高める方向に働く

視野角の丸め規則([§3](#3-評価))は確定手段がないため、**既定を四捨五入**とし、
視覚A/Bで差が顕在化した場合にのみ再調査する(誤差は最大±0.5度・
中間フレームのみで、実用上知覚されにくい)。

本体との実装差異が発見された場合は本体挙動を正として本仕様を更新する。

## 6. テスト要件

1. 線形の補間曲線(20,20)/(107,107)で解析解(線形補間)と一致すること
2. 極端な制御点((0,127)/(127,0) など)でニュートン法が収束、
   または二分法フォールバックが正しく動作すること
3. 区間の補間に後側キーのパラメーターが使われること
4. カメラ回転が3軸独立・共通の補間曲線で評価されること(クォータニオン化しない)
5. 範囲外フレームで端キーの値を返すこと
6. 独立実装との数値クロスバリデーション([§5](#5-mmd互換性の検証))
7. `bake_bone_track` が gap=1 の密キー列で位置を厳密にキー値と一致させ、回転を正規化差を除いて
   一致させること(単位ノルムのテストデータでは厳密一致)
8. 不等間隔トラック(同一トラックに gap 1・2・10・60 等を混在)の全フレームで `bake_bone_track` と
   `sample` が一致すること(線形・非線形の補間曲線の両方)
9. 線形ファストパスの結果が一般解(ニュートン法)と一致すること(ニュートン法は近似解のため
   許容差 1e-8 以内で比較する)
10. `bake_bone_track` の境界: 単一キー、フレーム差1の値ジャンプ保持、範囲端
