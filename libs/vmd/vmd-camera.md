# vmd-camera 仕様書

vmd.camera — MMDカメラモデルの座標変換・符号規約

親仕様: [vmd.md](vmd.md)
カメラキーのフィールド定義: [`../../docs/specs/vmd/VMD_file_format.md`](../../docs/specs/vmd/VMD_file_format.md)

---

## 1. 目的

MMDカメラの「カメラ中心+距離+角度」表現と、ワールド座標表現
(カメラ位置+視線方向+ロール)の相互変換を提供する。
視線揺れ変換、カット検出のカメラ位置ジャンプ判定など、
カメラモーションを幾何的に扱うすべての処理の基礎となる。

---

## 2. カメラモデル

キーフレームの構成要素(格納値):

- カメラ中心 `position` (X, Y, Z)。MMD UIの「カメラ中心」。
  カメラ本体の位置ではなく、カメラが向く中心点
- 距離 `distance`(**通常は負値** = カメラはカメラ中心の後方)
- 角度 `rotation` (X, Y, Z) ラジアン。MMD UIの「角度」(表示は度)
- 視野角(整数度)、パースペクティブフラグ(**0=ON, 1=OFF** — 値が直感と反転)

変換の定義([§4](#4-規約の確定と検証)で確定):

- **角度は格納値の全3成分を反転**して回転行列を構成する。
  適用順は Y→X→Z: `R = Ry(-ry) · Rx(-rx) · Rz(-rz)`
- カメラワールド位置 = `カメラ中心 + R · (0, 0, distance)`
  (distanceが負のため、視線の手前側にカメラが置かれる)
- カメラの前方軸(視線方向)= `R · (0, 0, 1)`。
  カメラ位置からカメラ中心へ向かう向きと一致する(distance<0のとき)
- 上方向 = `R · (0, 1, 0)`

---

## 3. 符号・規約の注意点

- `distance` は負値が標準(正値はカメラ中心の前方=通常使われない)
- 回転行列の構成時、格納角度 (rx, ry, rz) は全成分を反転して用いる([§2](#2-カメラモデル)・[§4](#4-規約の確定と検証))
- パースペクティブフラグは 0 が ON
- 視野角は整数度でしか格納できない
- `distance = 0` のキーではカメラ位置=カメラ中心となり、視線方向は角度のみで決まる

---

## 4. 規約の確定と検証

MMDは格納値を固定の規則で表示するだけであり、規則そのものは確立した互換実装の
照合で机上で確定できる事実である。以下の2実装の照合で確定した([§2](#2-カメラモデル)):

- **babylon-mmd** `MmdCamera`: `Matrix.RotationYawPitchRoll(-ry, -rx, -rz)` で
  回転行列を構成し、`カメラ位置 = カメラ中心 + R·(0,0,distance)`。MMD忠実再現を
  目的とした実装で、本仕様の座標系(カメラ中心まわりの公転モデル)と一致する
- **three.js** `MMDLoader.buildCameraAnimation`: `euler.set(-rot[0],-rot[1],-rot[2])`
  で全角度成分を反転。fps=30。回転オフセットの構造も中心+距離方向で一致

両実装が一致する確定事実: 角度の全3成分を反転、距離はそのまま、
カメラ中心まわりに回転オフセットを適用。適用順は babylon の YXZ を採用する。

検証:
- テストは独立実装との数値クロスバリデーション(自動・pytest内)で行う:
  既知のカメラキーに対するワールド位置・前方軸の一致を、[§2](#2-カメラモデル)の式を別実装で
  書き直したものと照合する(コーディングミスの検出。[vmd-interp.md §5](vmd-interp.md#5-mmd互換性の検証) と同方式)
- 絶対的なMMD一致の最終確認は視覚A/Bスモーク(人間・一度きり、揺れ0ベイクの
  再生比較)で行う。規約を取り違えると揺れ適用結果がカメラの公転・平行移動として
  明白に破綻するため判別できる
- 本体との差異が発見された場合は本体挙動を正とする

## 5. API

    to_world(camera_key) -> CameraPose
        # CameraPose: カメラワールド位置, 視線方向, ロール(またはupベクトル),
        #             fov, perspective
    from_world(pose, distance, prev_key=None) -> カメラキーのフィールド値
        # カメラ中心・角度を逆算する

逆変換 `from_world` の要件:

- **オイラー角のアンラップ**: 連続フレーム列を逆変換する際、前フレーム
  (`prev_key`)の角度に最も近い表現を選び、±180°ジャンプを起こさない。
  ベイク用途では必須の要件
- **ジンバル対策**: ピッチ±90°近傍ではヨー/ロールの分解が不定になるため、
  前フレームの値を優先して解決する
- **往復一致**: `to_world → from_world` で元のキー値と一致すること(数値誤差の範囲)
- `distance = 0` では変換は恒等(角度がそのまま視線方向を表す)

---

## 6. テスト要件

1. 往復一致: `to_world → from_world` が元のキー値に一致(各種角度・距離・距離0)
2. 角度連続性: 滑らかなポーズ列の逆変換で角度列に±180°ジャンプがないこと
3. ジンバル近傍(ピッチ±90°付近)での安定性
4. 独立実装との数値クロスバリデーション([§4](#4-規約の確定と検証))
