## 方針

- このディレクトリに置くのは**MMD本体で作成したファイルのみ**。
  その価値は「MMD本体が実際に書き出したバイト列であること」にある
- 既知値が必要なテストデータ(カット入り・順不同・切り詰め・v1形式・
  混在セクション・ベイク済み・物理フラグ等)はファイルとして置かず、
  テストコード内のフィクスチャとして用意する
- フィクスチャは宣言的なリテラルに限る: io層のテストには手書きのバイト列、
  ロジックのテストには直接記述したキー列・文書。解析・オフセット計算・
  ファイルの加工といった、実行しないと出力が分からないロジックを含めてはならない。
  テストコードには「それ自体はテストされない底」が必ず残るため、その底には
  読んだだけで仕様書・期待値と突き合わせて正誤を判定できる記述しか
  置けない、という原則による
- MMD産ファイルを使うテストは内容の事前知識を必要としないものに限る:
  - ラウンドトリップ(read→write のバイト一致。任意の内容で成立)
  - 補間・カメラ変換のクロスバリデーション入力
    (ファイルから読んだキーを評価して独立実装と比較。事前知識不要)
  - 内容の多様性チェック(下記の条件は「位置」ではなく「存在」の条件なので、
    テストがファイル自身を読んで確認できる。テストデータ検査のテストが
    1条件=1テストとして検査し、満たさない場合は
    「テストデータの作り直しが必要」であることを明示して失敗する)
- したがって**作成手順に正確なフレーム番号・数値の指定はない**。
  自由に作ってよく、下記の条件を満たしていればよい
- 作成・配置後に `pytest libs/vmd/tests` を実行すると、
  満たしていない条件がテスト名と失敗メッセージで列挙される。
  すべて成功すればデータは完成

## camera_basic.vmd

カメラ・照明モードで作成し、カメラ・照明モーションとして保存する
(カメラ・照明・セルフ影セクションが1ファイルに入る)。

条件は、保存されたファイルの内容が満たすべき性質として記述する。
条件にない事項(キーの位置、個々の値)は任意。

| 条件 | 必要とする理由 |
|---|---|
| カメラキーが3個以上ある | 補間曲線の検証に複数の区間が必要なため |
| 2個目以降のカメラキーに、補間曲線がデフォルト値のキーが1個以上ある | デフォルトの補間曲線の評価を検証するため |
| 2個目以降のカメラキーに、補間曲線がデフォルト値でないキーが1個以上ある | デフォルト以外の補間曲線の評価を検証するため |
| 距離の値が2種類以上ある | 距離チャンネルの補間評価を実データで行うため |
| カメラ中心の座標(X・Y・Zの組)が2種類以上ある | 位置チャンネル(X・Y・Z)の補間評価を実データで行うため |
| 角度(X・Y・Zの組)が2種類以上ある | 回転チャンネルの補間評価を実データで行うため |
| 視野角の値が2種類以上ある | 視野角チャンネルの透過テストのため |
| パースONのキーとOFFのキーの両方がある | パースペクティブフラグ両値の透過テストのため |
| 照明キーが1個以上ある | 照明セクション構造のラウンドトリップのため |
| セルフ影キーが1個以上ある | セルフ影セクション構造のラウンドトリップのため |

- 補間曲線のデフォルト値: 全6チャンネルが (20, 107, 20, 107)(MMDがキー登録時に設定する線形の値)
- 補間曲線の条件が「2個目以降」なのは、区間の補間曲線が到達側(後側)キーに
  格納され、先頭キーの補間曲線はどの区間にも使われないため([vmd-interp.md §2](../../vmd-interp.md#2-補間曲線の定義))

テストでの用途:

- vmd-io: カメラ系実ファイルのラウンドトリップ
- vmd-interp: クロスバリデーションの入力
- shakevmd: 統合テストの入力(ベイク忠実性、視野角・パース透過、境界連続性)、
  視覚A/Bスモークの元データ

## model_motion.vmd

任意のモデルで作成し、モデルモーションとして保存する。

条件は、保存されたファイルの内容が満たすべき性質として記述する。
条件にない事項(キーの位置、個々の値)は任意。

| 条件 | 必要とする理由 |
|---|---|
| ボーンキーが1個以上ある | ボーン111バイトキー(補間ブロック64バイトの実パディング・Shift-JISボーン名)のラウンドトリップのため |
| モーフキーが1個以上ある | モーフ23バイトキー構造のラウンドトリップのため |

注: 本ファイルはvmdの「全セクションのロスレス読み書き」保証と、ボーン・モーフを扱う
ツールのためのもの。カメラモーションだけを扱うテストはボーンセクションを
フィクスチャで代替できるため、本ファイルを要さない。

## テスト要件との対応

| テスト | 使用データ |
|---|---|
| vmd-io 1(ラウンドトリップ) | camera_basic, model_motion, 手書きバイト列(後方セクション欠落・物理フラグ) |
| vmd-io 2(v1拒否) | 手書きバイト列(v1のmagic) |
| vmd-io 3(正規化) | データモデル直接構築(順不同・重複・混在セクション) |
| vmd-io 4(エラー) | 手書きバイト列(セクション途中切り詰め・magic不正) |
| vmd-io 5(物理フラグ) | 手書きバイト列。model_motion に実例があればそれも使う |
| vmd-io 6(フィールドassert) | 手書きバイト列 |
| vmd-interp 1–5 | データモデル直接構築(キー列) |
| vmd-interp 6(クロスバリデーション) | camera_basic +データモデル直接構築 |
| vmd-camera 1–4 | データモデル直接構築(キー列) |
| shakevmd 1–6 | camera_basic |
| shakevmd 7・9–11(カット) | データモデル直接構築(既知位置のカット入りキー列) |
| shakevmd 8(正規化) | データモデル直接構築(順不同・重複) |
| shakevmd 12(透過) | データモデル直接構築(カメラ+ボーン/モーフを含む文書) |
