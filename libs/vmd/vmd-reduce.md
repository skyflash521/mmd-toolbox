# vmd-reduce 仕様(キーフレーム疎化エンジン)

`vmd.reduce`(支援: `vmd.cuts`・`vmd.fit`・`vmd.sample`)が担う、VMD キーフレーム疎化
(区間分割・キー削減・補間曲線フィット・誤差評価・継ぎ目・出力後検証)のアルゴリズム仕様。
複数の利用ツールが共有するこのエンジンの**正本**であり、各ツール仕様はここを参照して結論を二重に持たない。

`vmd` はフォーマット層モジュール([../../docs/conventions/layering.md](../../docs/conventions/layering.md) §1)。
本書は形式の事実と疎化アルゴリズムを扱い、ツール固有の判断(CLI 引数名・既定値・プリセット・終了コード・
レポート表示)は持たない(それらは各ツール仕様が持つ)。許容誤差・区間長・カット閾値などのパラメータは
**意味(役割)**で記述し、その引数名・既定値・検証は利用側に委ねる。性能特性と棄却済み最適化の正本は
[vmd.md](vmd.md) §6。

## 1. 削減の単位とチャンネルグループ

- **トラック**: カメラは VMD 内のカメラキー列全体を1トラック、ボーンはボーン名ごとに独立トラックとして扱う。
- **チャンネルグループ**: 1つの VMD キーは複数チャンネルを同時に持つため、削減後のキー時刻は
  チャンネルごとの要求分割点の和集合になる。
  - カメラ: 位置 X/Y/Z(各軸個別の補間曲線)・回転(Euler X/Y/Z に共通の1本)・距離(個別)・
    視野角(個別。保存時は整数度へ丸める。丸めは vmd 既定の四捨五入=0.5切り上げで決定論的に行い、
    Python の `round` の偶数丸めは使わない。[vmd-interp.md](vmd-interp.md) §5)・
    perspective(透視投影フラグ 0=ON/1=OFF。補間対象外の離散値で、区間内は値を変えず、出力キーには
    そのフレーム時点で有効な直近キーの値を設定する。値が切り替わるフレームは §7.1 の不連続境界として
    常に保持し、カット自動検出を無効化しても保持する)。
  - ボーン: 位置 X/Y/Z(各軸個別)・回転(quaternion slerp に適用する1本の補間曲線)。
- **共有曲線の制約**: カメラ回転は3軸に1本の曲線しか持てないため、3軸すべての誤差が許容値以下になる
  曲線を探索する。ボーン回転は端点間 slerp に1本の曲線を適用し、サンプル回転が端点間の大円弧から
  外れる場合は区間を分割する。

## 2. 許容誤差の意味

各チャンネルは「位置・回転・距離・視野角」ごとの最大許容誤差を受け取る。各値は0以上の有限小数。

- 視野角以外の許容値 `0` は、整数フレーム上での完全一致(§8.1 のとおり出力キーを再サンプリングした値との
  一致)を要求する。ただし VMD が位置・回転・距離を float32 で保存する(`io.py`)ことによる量子化誤差
  (float32 epsilon 程度)は、視野角の整数丸めと同様に分割不能な量子化誤差として扱い、`0` 許容でも
  超過理由にしない。すなわち `0` は「曲線フィット由来の誤差を残さない(float32 格納誤差のみ許容)」を意味する。
  入力が既に密(整数フレームごとの元キーを持つ)なら、その区間は元キーをそのまま保持する密フォールバック
  (§4・§8.3)で float32 往復しても値が変わらず量子化誤差も生じない。入力が疎で補間サンプルをソースと
  する場合は、密フォールバックでも内部フレーム値が float32 へ丸められるため float32 量子化誤差までは残りうる
  (上記のとおり許容)。
- 視野角の許容値は、VMD の視野角キーが整数度保存であるため0.5度以上に制限する。0.5未満は不正。
- 誤差は出力 VMD を再サンプリングして検証する最終基準であり、補間曲線フィット中の目的関数より優先される。

## 3. 区間化の制御

- **最小区間長**(1以上): これ以上は分割しない下限。誤差を満たせる範囲でこの長さより短い区間に分割しない。
  最小区間長まで分割しても誤差を満たせない区間は、§4 の破綻回避(元の密なキー数の保持)を優先し、
  下限を無視して元のフレーム単位キー(区間長1)まで分割して保持する。strict 指定では分割せず失敗とする。
- **最大区間長(sliding 上限)**: 未指定なら上限なし(無制限)で、上限維持(§4 の maxspan-cap)を一切行わず
  滑らかな長区間を長いまま残す。有限値を指定したときは、誤差と無関係な等分点を無条件の出力キーにはせず
  (機械的な等分 grid キーを生まない)、間隔の上限維持は区間処理で、確定キーから次キーまでが上限を超える
  非定数区間に限って行う。**全チャンネルが定数(無変化)の区間は sliding 上限の対象外**で、上限を超える間隔の
  まま残す(定数区間には編集すべき曲がりが無く、上限維持の追加キーはキー過多とフィット評価増を招くだけのため)。
  定数判定は各チャンネルが自分の値型・単位で、区間内サンプルが量子化下限相当のしきい値以下しか動かないかを
  見る。定数判定手段を持たないチャンネルが1つでもあれば定数扱いにしない。
- **strict**: 指定誤差を満たせないとき、高密度キー保持で続行せず失敗とする(非 strict は §4 の破綻回避で密化)。

## 4. 全体手順

各トラックについて:

1. 入力モーションを対象範囲内で 30fps 整数フレームにサンプリングする(`vmd.interp` の `sample_range` /
   `sample_camera` に委譲)。
2. 範囲端、先頭/末尾、不連続境界、保持指定フレームを必須キーとして登録する。
3. 最大区間長(sliding 上限)が無制限なら上限維持(step 6 の maxspan-cap)を行わない。有限値のときは、
   誤差と無関係な等分点を無条件キーにせず、上限維持は区間処理で非定数区間に限って行う(§3)。
4. 各区間について、全チャンネルグループが VMD 補間曲線で表現可能か試す。
5. 量子化済み補間曲線で出力候補を作り、整数フレームで再サンプリングして誤差を測る。
6. すべての誤差が許容値以下で、かつ区間長が最大区間長以下(または全チャンネル定数、または上限が無制限)なら
   区間を採用する。誤差は許容内でも区間長が上限を超える非定数区間は(上限が有限のときに限り)、上限を守るため
   `maxspan-cap` キーを足して分割する(誤差駆動でない sliding 上限維持の分割)。分割点は原則、直前に確定した
   キーから最大区間長の位置(sliding 上限位置)に置く。品質と収束のために誤差駆動点で分けた方がよい場合は、
   その内部フレームを選んでよい。
7. 許容値を超えた場合、最大誤差フレームで区間を `error-split` として分割し、再帰的に処理する。
8. これ以上分割できない場合は隣接キーとして保持する。

この方式により、削減不能な高周波モーションやノイズを含む場合でも、元の密なキーフレーム列に近い形で安全に
出力できる。

## 5. 曲線フィット

### 5.1 スカラー曲線フィット

スカラー値 `v` の区間 `[f0, f1]` について:

1. 端点値を `v0`, `v1` とする。
2. `abs(v1 - v0) > 1e-9` の場合、内部サンプルを `y = (v - v0) / (v1 - v0)` に正規化する。
3. VMD 補間曲線 `BezierX(s), BezierY(s)` に対して `BezierX(s) = x` を満たす `s` を求め、`BezierY(s)` が
   `y` に近くなるよう制御点 `(x1,y1),(x2,y2)` を最小二乗で探索する。
4. 制御点を `[0,127]` 整数へ量子化する。
5. 量子化後の曲線で再評価し、元単位の最大誤差を検証する。

`abs(v1 - v0) <= 1e-9` で内部サンプルも許容誤差以内なら線形曲線で採用する。内部サンプルが許容誤差を超えて
動いている場合、その区間は1本の VMD 曲線では表現できないため分割する。

### 5.2 回転曲線フィット

カメラ回転:
- `CameraKey.rotation` はラジアン格納で `sample_camera` もラジアンを返す(`types.py`・`interp.py`)。
  unwrap はラジアン上で行い、許容誤差・カット閾値との比較は度へ換算した角度誤差で行う。
- 3軸共通の補間係数 `y` を使って各軸を `r0 + (r1 - r0) * y` で評価する。
- 目的関数は3軸の角度誤差の重み付き和とし、最終判定は最大角度誤差で行う。

ボーン回転:
- quaternion は同一半球に揃えて符号反転の不連続を除去する。
- 端点 `q0`, `q1` の slerp に補間係数 `y` を適用する。
- 誤差はサンプル回転との角度距離(度)で測る。
- サンプルが端点間 slerp から外れる場合、1本の曲線では表現できないため分割する。

### 5.3 制御点探索

- 最適化変数は `(x1,y1,x2,y2)`。実行可能領域は `0 <= x1 <= x2 <= 1`, `0 <= y1 <= 1`, `0 <= y2 <= 1`。
  `x1 <= x2` はボックス境界ではないため `least_squares` のボックス境界だけでは保証できない。X を単調増加に
  保つ(評価側 `_solve_factor` の前提、[vmd-interp.md](vmd-interp.md) §3)ため、
  `x2 = x1 + (1 - x1) * t`(`t in [0,1]`)と再パラメータ化し、最適化変数 `(x1, t, y1, y2)` をすべて
  ボックス境界 `[0,1]` で扱う。
- 初期値は線形曲線 `(20,20),(107,107)` を正規化した値とする。`scipy.optimize.least_squares` を使う。
  複数初期値を使う場合は、線形/ease-in/ease-out/ease-in-out の固定リストから決定論的な順序で試す。
  `least_squares` を呼ぶ前に固定 ease 制御点で許容内に収まるか試す安価採用(cheap accept)もこの固定順で行う。
- linear モードの場合は探索を行わず、線形曲線だけで検証する。
- 制御点を `[0,127]` 整数へ量子化したあと、`x1 <= x2` と X 単調増加を再検査する。量子化で `x1 > x2` に
  なった場合や §8 の再サンプリング誤差が許容値を超える場合はフィット失敗として扱い、§6 に従って分割する。
- 最終的な採否は必ず量子化後の曲線で行う。

## 6. 分割点の選択

区間が許容誤差を満たさない場合:

1. 全チャンネルの正規化誤差を比較し、最大誤差フレームを候補にする。正規化誤差は、各チャンネルの §8.2 の誤差を
   そのチャンネルの許容誤差で割った無次元量とし、単位やスケールの異なるチャンネル間で比較可能にする。許容誤差が
   0のチャンネルは、誤差0なら正規化誤差0、誤差が正なら正規化誤差を無限大として扱い、最優先の分割候補とする
   (ゼロ除算は行わない)。
2. 分割点は必ず内部フレーム `f0 < f < f1` から選ぶ。最大誤差が端点に出た場合は、内部フレームのうち誤差最大の
   ものを選ぶ。
3. 値の局所極値、速度符号反転、回転方向反転が検出されている場合は優先候補にする。

これにより、山・谷・切り返し・停止点をキーとして残しやすくする。

分割・キー追加の理由は診断で次の4種に区別する:
- `cut`: §4 step2 で登録する必須キー(範囲端・不連続検出・perspective 切替・保持指定フレーム)。不連続検出は §7.1/§7.2。
- `error-split`: 正規化誤差が許容を超えたため内部フレームで追加した分割キー(本節, §4 step7)。
- `verification-add`: 出力後検証(§8.3)で許容超過したため追加したキー。
- `maxspan-cap`: sliding 上限(§4 step3/step6)を守るため追加したキー。

`maxspan-cap` は誤差駆動でない上限維持の分割なので `error-split` とは別フィールドで数える。

## 7. 不連続・境界処理

### 7.1 不連続検出

- 隣接サンプル `F-1` と `F` の差がカット閾値を超えた場合、`F` から新しい区間が始まる境界として扱う。
- カメラはカメラ中心位置(ユークリッド距離)・回転角度(§8.2 と同じ軸別角度誤差の最大値,度)・
  距離(絶対値)を検出対象にし、各々のカット閾値と比較する。
- ボーンは位置差(ユークリッド距離)・回転角度差(§8.2 と同じ quaternion 角度距離,度)を検出対象にし、
  各々のカット閾値と比較する。
- カメラの perspective が切り替わるフレームは、閾値によらず常に境界とする(§1)。カット自動検出を無効化
  しても保持し、フラグ切り替えをまたいで補間曲線を作らない。

### 7.2 境界の保存

- 不連続境界をまたいで補間曲線を作らない。
- 境界直前と直後のキー値は入力サンプル値をそのまま使用する。
- フレーム差1のジャンプは、出力でも同じ隣接フレームのジャンプとして保持される。

### 7.3 範囲端・継ぎ目

- 範囲端は必須キーとして保持する。
- **範囲外のキーは変更不可**とする。範囲外の対象キーは値・補間曲線ともに逐語保持し、書き換えや範囲外への
  境界キー追加は行わない。
- 範囲端の到達側補間曲線が範囲外区間に影響する継ぎ目のうち、**書き換えてよいのは範囲内にある側のキーのみ**:
  - 下側継ぎ目: 範囲開始キー(範囲内)の到達側曲線を元サンプルから再フィットし、手前の範囲外キーから範囲開始
    までの動きを忠実に保つ。曲線が乗るキーは範囲内なので変更可。書き換えたフレームは診断 `seam_rewrites` に明示する。
  - 上側継ぎ目: 範囲終了直後の範囲外キーに到達側曲線が乗るため、**範囲外キー変更不可の原則に従い書き換えない**。
    範囲外キーは逐語保持し、前キーが範囲終了に変わることによる継ぎ目の不整合は許容する。

## 8. 誤差評価

### 8.1 評価タイミング

各採用候補区間は、補間曲線を `[0,127]` 整数へ量子化したあと、出力予定キー列として再サンプリングして評価する。

### 8.2 評価指標

- 位置: 採否判定はユークリッド距離。軸別の最大絶対誤差は診断値として返す(表示の判断は利用側)。
- カメラ距離: 絶対誤差。
- 視野角: 保存時丸め後の整数度を再評価し、元サンプルとの差を測る。VMD 上の視野角は整数度保存のため、丸めだけで
  最大0.5度の誤差が発生する。視野角許容は0.5度以上に制限し、分割によって丸め誤差を消そうとしない。丸め由来の
  0.5度までは量子化誤差として扱い、曲線フィット由来の誤差で許容を超える場合は通常通り分割対象とする。
- カメラ回転: unwrap 後の軸別角度誤差の最大値。
- ボーン回転: quaternion 角度距離。

### 8.3 出力後検証

書き出し直前に、各削減範囲を1フレーム間隔で再サンプリングし、範囲内のすべてのフレームが許容誤差以内であることを
検証する。非 strict で誤差超過が残る場合は、超過フレームを必須キーに加えて該当区間をさらに分割して再試行する。
超過フレームは出力キー上にはない(出力キー上は元値を格納するためフィット誤差0)ので、再試行のたびに必須キーは
厳密に増え、最悪1フレーム間隔まで密化すれば元値を逐語保持するため必ず収束する。ただし視野角の整数丸め誤差は
分割不能な量子化誤差として扱い、§8.2 の視野角判定を満たしている限り追加分割の理由にしない。strict ありで誤差
超過が残る場合は失敗とする。

検証と再分割の許容保証は削減範囲(範囲内フレーム)に対して成立する。範囲外のキーは §7.3 のとおり値・補間曲線とも
逐語保持するため誤差は生じない。範囲開始キーの到達側曲線(下側継ぎ目, §7.3)は範囲外区間に乗るが、§7.3 が範囲外
へのキー追加を禁じるため分割による許容保証の対象外とし、元サンプルからの単一区間ベジェ再フィットによる最善努力
(残差は整数量子化が下限)として扱う。この継ぎ目曲線は範囲開始キーの到達側のみに作用し、範囲内フレームの補間には
影響しない。

再試行ループの反復実態は診断 `verify` に記録する。範囲ごとに1レコードを持ち、処理範囲(`range`)・検証回数
(`iterations`)・各反復の許容超過フレーム数(`bad_counts`)と追加フレーム数(`added_counts`)・密化で追加した
総フレーム数(`added_total`)からなる(`bad_counts`/`added_counts` の長さは `iterations` に一致し、正常収束時は
末尾が0)。

### 8.4 端点速度平滑化(C1近似)

`bezier` モードでは、出力後検証(§8.3)のループ内で、出力キーを構築したあとに**ボーン位置チャンネルの補間制御点へ
端点速度平滑化ポストパスを適用する**(カメラ位置は対象外)。疎化は区間ごとに独立にフィットするため内部キーで補間速度が不連続になりがちで、
再生時にキー境界が速度のカクつき(コーナー)として見える。これを軽減するため、各内部キー `k` で、到達側区間
`[k-1,k]` の終端と出発側区間 `[k,k+1]` の始端のベジェ端点速度を、ソースの中心差分速度(キー `k` 前後フレームの
値差/2)へ近づける。両隣を同じ速度へ揃えるとキーで速度が連続(C1)になる。

制御点は §5.3 と同じく `[0,127]` へクランプする。クランプにより、必要な速度が大きい区間や正味変位と逆符号の
(局所極値付近の)区間では端点速度を合わせきれず実現可能範囲への射影にとどまるため、これは厳密な C1 保証では
なく **C1 近似**である。クランプは曲線の単調性(X・Y とも単調)を保つので出力は常に MMD 補間曲線として適合する。

許容契約は破らない:
- 非 strict: C1 適用後に §8.3 の検証を行い、許容超過があれば `verification-add` で密化して収束させる。
- strict: C1 適用後に許容超過する範囲では C1 を適用せず元フィットを残す(C1 が strict の許容失敗を新たに誘発しない)。

`linear` モードはベジェ制御点で接線を調整できないため対象外。回転チャンネルの C1(slerp 係数を端点間角度で
重み付けした角スピード連続)は検討したが、実データ計測で出力キーが増える割に効果が乏しく不採用とした([vmd.md](vmd.md) §6)。

## 9. 出力キーの再構築・量子化・格納

- 削減後のキー列は再構築して書き出す(対象セクションのバイト一致・元のキー順・元の補間ブロック保持は保証しない)。
  削減せず保持するトラック(選択対象外・削減不能=キー1件以下)も、値と補間曲線は保持するが、セクション全体は
  再構築・再ソートするためバイト一致は保証しない。
- 出力キーはトラックごとにフレーム昇順で書き出す。ボーンキーはボーン名(`name_raw` の生バイト)・フレーム番号の
  順に安定ソートする。比較は vmd の規約どおり生バイトで行い([vmd.md](vmd.md) §3、`io.normalize` と同じ
  `(name_raw, frame)` キー)、デコード後の表示名では並べない。
- 補間曲線は MMD 互換の制御点範囲 `[0,127]` の整数に量子化して保存する。量子化は決定論的に行う: 各制御点の実数値を
  四捨五入(0.5は切り上げ)で最近傍整数へ丸めたあと `[0,127]` にクリップする(丸め→クリップの順)。量子化後の
  `x1 <= x2` 単調性は §5.3 で再検査する。
- 補間曲線は区間の到達側(後側)キーに格納する([vmd-interp.md](vmd-interp.md) §2)。
- 区間長1フレームでは整数フレーム上の中間サンプルが存在しないため、補間曲線は線形に設定する。

## 10. テスト要件(エンジン契約)

テストフレームワーク・実行方法・テストデータの扱いは [vmd.md](vmd.md) §4 の方針に従う。共有エンジンの契約として
次を検証する(CLI 表示・終了コード・ファイル入出力など利用側の挙動は各ツール仕様のテスト要件で扱う)。

1. 線形モーション: 連続フレームの線形移動が先頭/末尾キーと線形補間曲線に削減され、再サンプリング誤差が0になること。
2. 既知ベジェ再現: 既知の VMD 補間曲線で生成した密サンプルから、量子化誤差内の補間曲線と少数キーが得られること。
3. 局所極値: 山・谷を含むスカラー列が極値付近で分割され、端点同値の区間を1本の曲線で誤表現しないこと。
4. カメラ回転共有曲線: 3軸回転を1本の補間曲線で評価し、最大角度誤差が許容以下になること。
5. ボーン回転: quaternion slerp と角度距離で誤差判定し、回転方向反転や大円弧外のサンプルで適切に分割されること。
6. 不連続保存: カット/ワープを含む入力で、ジャンプが補間によりなまらず、同じ隣接フレーム間に保持されること。
7. 視野角量子化: 整数丸め誤差(0.5度)が分割不能な量子化誤差として扱われ、追加分割を誘発しないこと。
8. strict: 許容誤差を満たせないケースで strict が失敗となること。
9. 再現性: 同一入力・同一パラメータで出力が一致すること。
