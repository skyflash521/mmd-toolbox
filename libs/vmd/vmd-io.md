# vmd-io 仕様書

vmd.types / vmd.io — VMD読み書き・データモデル・正規化

親仕様: [vmd.md](vmd.md)
バイナリレイアウトの正: `../../docs/specs/vmd/VMD_file_format.md`(本書では重複記載しない)

---

## 1. 対応フォーマット

- v2(magic `"Vocaloid Motion Data 0002"`)のみ対応する(読み書きとも)
- v1(magic `"Vocaloid Motion Data file"`)は非対応。v1のmagicを検出した場合は
  「v1形式は非対応」であることを明示したメッセージの `VmdFormatError` とする
  (単なる「magic不正」と区別し、ユーザーが原因を特定できるようにする)
- magicが両者いずれでもない場合も `VmdFormatError`

---

## 2. データモデル(types)

### 2.1 VmdDocument
- ヘッダ: バージョン、model_name(生バイト+表示用デコード文字列)
- セクション: bone / morph / camera / light / self_shadow / ik_property の
  各キーフレームリスト
- **セクション有無の記録**: 旧版VMDで省略された後方セクション
  (Self Shadow以降)は「不存在」として記録し、書き出し時に再現する。
  「キー0件で存在」と「セクション不存在」を区別する

### 2.2 キーフレーム
- 各フィールドはフォーマット仕様書の定義に従う。数値はファイル格納値を
  そのまま保持する(距離の負値、セルフ影distanceのエンコード値などの
  意味的解釈は行わない。解釈は interp / camera / 呼び出し側の領分)
- **補間ブロックは生バイトを必ず保持する**(ボーン64バイト、カメラ24バイト)。
  制御点の読み書きは生バイト上のビューとして提供する
- ボーン補間の制御点読み出しは、物理演算フラグによる先頭バイト上書き
  (Byte[2], Byte[3])を考慮し、シフトコピー側から復元する
  (フォーマット仕様書「物理演算フラグ」参照)。書き戻しは生バイト保持が原則
- 名前フィールド(ボーン名・モーフ名・IKボーン名)は固定長の生バイトを保持し、
  null終端後の残バイトも書き出しで再現する
- **モーフキーフレームは補間ブロックを持たない**(ボーン・カメラと異なり
  morph_name＋frame＋weight のみ。フォーマット仕様書「Morph Keyframes」)。
  キー間ウェイトの評価意味論は解釈であり vmd-interp.md の領分

---

## 3. 読み込み

    read(path | bytes) -> (VmdDocument, warnings)

- セクションは Bone → Morph → Camera → Light → Self Shadow → IK/Property の順に読む
- EOFが**セクション境界に一致**する場合: 旧版として残りセクションを
  「不存在」と記録し、警告を返して正常終了
- **セクション途中**でのEOF・サイズ不整合: `VmdFormatError`
- キーフレーム配列は無加工で読み込む(ソート・重複除去をしない。
  正規化は§5の明示操作)
- デコード不能な文字列など、続行可能な事象はすべて警告で報告する

---

## 4. 書き出し

    write(doc) -> bytes
    write_file(doc, path) -> None

- v2形式で書き出す
- セクション不存在の記録を再現する(不存在セクションはキー数も書かない)
- フィールド値・生バイト(補間ブロック、名前、null終端後の残バイト)を
  そのまま書き出す
- `write_file` は**原子的に書き出す**: 同ディレクトリの一時ファイルへ書いて
  fsync し、`os.replace` で原子置換する。書き込み途中の中断・ディスクフルでも
  既存の出力先(入力と同一パスへの上書きを含む)を破損させない

---

## 5. 正規化(明示操作)

    normalize(doc, sections=None) -> (VmdDocument, warnings)

読み込みとは分離された明示操作とする(正規化はバイト一致を壊すため)。
`sections` で対象セクションを限定できる(例: カメラのみ)。
指定外のセクションは無加工で保持される(透過用途: shakevmdはカメラのみを正規化し、
混入した他セクションをバイト単位で透過する)。

1. 各セクション内をフレーム番号昇順で安定ソートする
   (ボーン・モーフ・IKは名前→フレーム番号の順)
2. 同一性キーの重複(カメラ等: 同一フレーム/ボーン・モーフ: 同一名+同一フレーム)は
   **ファイル内で後に現れたキーを採用**し、先行キーを破棄する

実施したすべての操作(並べ替えの有無、破棄したキーの位置)を警告として返す。

### 5.1 frame-0 中立キー補完(明示操作)

    ensure_frame0_neutral_keys(doc, sections=("morph",)) -> VmdDocument

出力VMDで使用キー(モーフ、一般化でボーンも)を frame=0 に中立値で登録しておく MMD 互換・編集上の規約。
`normalize` とは別の独立した明示操作で、`write` は与えた `VmdDocument` をそのまま書く低レベルI/Oのまま
(自動でキーを増やさない)とし、CLI が出力前に本関数を呼ぶ。

- 対象セクションは**名前付きセクション(`morph`/`bone`)のみ**。`camera`/`light`/`self_shadow`/`ik_property` は
  名前付き使用集合でないので指定するとエラー。
- 使用名集合は対象セクション内のキー名から導出し、**frame-0 キーを持たない名前にだけ**中立キーを挿入する
  (既存の frame-0 は尊重して値を保つ)。中立値はモーフ=`weight 0.0`、ボーン=identity 回転 `(0,0,0,1)`・
  ゼロ位置・既定リニア補間。
- 挿入キーは末尾に追加するので、続けて `normalize`(§5)でソート・重複後勝ちを適用してよい。

中立キー(モーフの weight、ボーンの identity 回転・既定補間)の構築は MMD 互換知識として本モジュール(形式層)が
持ち、「この出力に規約を適用するか」は呼び出し側CLIの出力ポリシーとして CLI が本関数を呼ぶかで決める。

---

## 6. ラウンドトリップ保証

- **正規化なし**: `read → write` の結果は入力とバイト一致する。
  これは本ライブラリの最重要保証であり、全テストVMDで検証する
- 正規化適用後は保証対象外

---

## 7. エラー・警告一覧

| 種別 | 事象 |
|---|---|
| VmdFormatError | magic不正 / v1形式(専用メッセージ) / セクション途中のEOF / サイズ不整合 |
| 警告 | 後方セクション欠落 / 文字列デコード不能 / 正規化: 並べ替え発生 / 正規化: 重複キー破棄 |

---

## 8. テスト要件

1. ラウンドトリップ: v2のVMD(全セクションあり / 後方セクション欠落 /
   カメラ専用 / モデル専用 / 物理フラグ付きボーンキー)で読み→書きのバイト一致
2. v1拒否: v1形式のVMDで、v1非対応を明示したメッセージの `VmdFormatError` となること
3. 正規化: 順不同キー・重複キーを含むVMDの並べ替え・後勝ち採用と警告報告。
   `sections` で対象を限定した場合、指定外セクションが無加工であること
4. エラー: セクション途中欠損・magic不正で `VmdFormatError`
5. 物理フラグ付きボーン補間: 制御点がシフトコピーから正しく復元され、
   かつ生バイトが無加工で書き戻されること
6. フィールド単位assert: フォーマット仕様書のレイアウトからテストコード内に
   手書きしたバイト列フィクスチャを読み込み、各フィールドが期待値と一致すること。
   逆方向(データモデル→write→バイト列比較)も検証する
   (reader/writerが対称に間違う解釈誤りの検出。vmd.md §4.2)
