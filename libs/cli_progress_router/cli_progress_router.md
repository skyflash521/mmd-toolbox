# cli_progress_router 仕様書

進捗の報告先を、機械モードのイベント送出と人間向けライブ表示へ1か所で振り分ける共有基盤ライブラリ。

層: **共有ドメイン層**([../../docs/conventions/layering.md §1](../../docs/conventions/layering.md#1-層タクソノミー))。複数の CLI ツールが共有する進捗報告の振り分けを、
特定形式の入出力でも単一ツール固有でもないため共有ドメイン層に置く。

依存: [cli_progress](../cli_progress/cli_progress.md)(人間向けライブ表示へ委譲する)。機械モードの送出先は
[cli_events](../cli_events/cli_events.md) のエミッタで、構築時に受け取る。同層内の一方向依存だけを持ち、
フォーマット層・CLIツール層へは依存しない。

正本関係: 進捗表示の外部契約(TTY判定での既定有効・静音指定による抑制・機械モードでは progress
イベントで代替すること・副作用専用)は
[CLI インターフェース規約 §6](../../docs/conventions/cli-interface.md#6-横断的な一貫性) が正。本書は
その契約の振り分け側を実装する共有モジュールの API・挙動を定める。

---

## 1. 責務

1回の進捗報告を、実行モードに応じて別々の出力へ振り分ける。呼び出し側は機械モードかどうかを意識せず、
工程の進行だけを報告する。

- **機械モード**: 端末かどうかに関わらず progress イベントを送出する(静音指定は送出へ影響しない。
  進捗表示の抑制は人間向け表示の話であり、機械利用側が読むイベントは抑制対象でないため)。**受け取った
  段 id・完了数・総数・補足・経過秒の5つをすべて**、`stage`・`done`・`total`・`note`・`elapsed` の
  フィールドへ載せ、どれも落とさない。**各値が何を表すか**(どの段 id があるか・何を数えるか・補足に何を
  書くか)は各ツールが決めることであり、この振り分けを使うツールは、この5フィールドを自分の progress
  イベントの公開契約として自身の仕様書に明記する。
- **非機械モード**: 端末であり静音指定が無いときだけライブ表示を有効にし、段 id を利用者向けの工程名へ
  変換して表示へ渡す。
- **送出失敗の区別**: 機械モードのイベント送出は、外部処理の進捗コールバックからも呼ばれる。送出の失敗を
  素の例外のまま返すと、呼び出し元が工程そのものの失敗と区別できないため、専用の例外型で返す。

段 id の集合と、それに対応する利用者向けの工程名は各ツールが持ち、構築時に対応表として渡す
(工程名の正記法は [用語規約の処理工程の利用者向け名称](../../docs/conventions/terminology.md#処理工程の利用者向け名称)が正)。

## 2. 公開API

`ProgressRouter(*, machine, quiet, emitter, stream, labels, write_lock=None, now=None, interval=0.15)`

- `machine`: 機械モードかどうか。真ならイベント送出、偽ならライブ表示になる。
- `quiet`: 静音指定。非機械モードのライブ表示だけを無効にする。
- `emitter`: 機械モードの送出先(`progress` を受けるエミッタ)。非機械モードでは使わない。
- `stream`: 非機械モードのライブ表示の書き込み先。端末判定にも使う。
- `labels`: 段 id から利用者向け工程名への対応表。表に無い id は id をそのまま表示に使う。
- `write_lock`: ライブ表示へ渡す排他ロック([cli_progress の write_lock 契約](../cli_progress/cli_progress.md#2-write_lock-契約))。
  同じ標準エラーへ fd レベルの操作を行う呼び出し元が注入する。
- `now` / `interval`: ライブ表示の時刻関数と再描画間隔。既定はライブ表示側の既定に従う。

### メソッド

- `stage(stage_id, *, done=0, total=None, note="", elapsed=0.0)`: 工程の開始・進行を報告する。
  機械モードでは、受け取った5つの値をすべて載せた progress イベントを送出する。非機械モードでは、
  **段 id が前回と変わったときだけ**表示の段を切り替え、同じ段 id での再呼び出しは進行の更新だけを
  行う(段を切り替え直さないので、同一段のライブ行が途切れない)。
- `close()`: 進捗を終える。ライブ表示ではライブ行を消す。**この呼び出しの後に同じ段 id で `stage()` を
  呼ぶと、新しい段として報告が再開する**(モードに依らず同じ扱いとし、呼び出し側がモードで分岐しなくて
  済むようにする)。冪等で、何度呼んでもよい。
- `summary(message)`: 完了行を1行残す(非機械モードのライブ表示が有効なときのみ)。

### 例外

`ProgressEmitError`: 機械モードの progress イベント送出に失敗したことを表す。送出中に上がった例外の
型名と文言を持ち、元の例外を原因として保持する。**変換するのは通常の例外だけで、協調的な中断は変換せず
そのまま通す**(中断を送出失敗へ化けさせると、呼び出し側の中断の扱いと終了コードが働かなくなるため)。
呼び出し元はこれを工程の失敗と区別し、想定外の失敗の経路へ落とす。

## 3. テスト

`pytest libs/cli_progress_router` で単体検証する(テスト方針は [../vmd/vmd.md §4](../vmd/vmd.md#4-テスト方針) に準ずる。決定論的・外部依存なし)。

- 機械モードで、端末かどうか・静音指定に関わらず progress イベントが送出され、人間向けライブ表示へは
  何も出力しないこと。
- 非機械モードで、端末判定と静音指定からライブ表示の有効・無効が決まること。
- 同一段 id の連続呼び出しが段を切り替えず進行だけを更新し、別の段 id で切り替わること。
- `close()` の後に同じ段 id で報告すると新しい段として再開すること。
- 対応表に無い段 id が id のまま表示へ渡ること。
- 送出の失敗が専用の例外になり、元の失敗の型名と文言を保つこと。
