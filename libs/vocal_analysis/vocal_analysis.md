# vocal_analysis — 音声前段

層: **共有ドメイン層**([../../docs/conventions/layering.md §1](../../docs/conventions/layering.md#1-層タクソノミー))。

音声(歌。伴奏込みでもよい)から、複数の CLI が後段で共有する前段出力——分離したボーカル WAV、母音・子音・gap を
区別した時刻付きの音素セグメント列、相対正規化した強弱 RMS——を作る。入力読み込みから RMS 算出までを1回で通す
実行(長尺の自動分割と診断用中間生成物の書き出しを含む)、音素記号から日本語5母音への写像、日本語テキストの
かな読み、認識品質を測る S-1 測定の採点もあわせて提供する。

## 対象範囲

- 無音・閉口の確定、gap が無音か発声の継続かの判定、母音境界のオンセット補正、口形イベントと開き量の決定は
  行わない。RMS を使うこれらの判断は利用先が持つ。
- ピッチ推定・音符分割・歌詞と音素の対応付けは行わない。
- 書き起こしテキストは共有出力に含めず、歌詞テキストの入力も要求しない。

## 前提と制約

- 前段の依存(torch・transformers・pyopenjtalk-plus・audio-separator など)は `vocal-analysis` extra に閉じ、
  本体の必須依存は numpy・scipy のまま保つ。
- 外部ツールとモデルの同梱・利用条件は [外部ツールの制約](external-tools.md) に従う。
- 歌唱では音素モデル(wav2vec2 CTC)の出力の大半が blank になり、音素を自由に認識させても母音がほとんど出ない
  (S-1 測定で確認)。
- 音素モデル・内容認識モデルの既定のモデル id と revision、音素モデルの数値精度を変えるときは、S-1 測定で
  現行と比べて品質の退行が無いことを確かめてから変える。
- 分離の作業ディレクトリと、長尺分割時に書き出す曲全体のボーカル WAV は、
  [一時ファイル・中間生成物の配置規約 §2.2](../../docs/conventions/temporary-and-intermediate-files.md#22-非公開の内部一時領域)
  の非公開の内部一時領域として扱う。

## 既知の限界

- 実行デバイス(GPU の有無)・スレッド数・数値精度が変わると、書き起こしと音素境界の時刻がわずかに変わりうる。
- 歌唱では音素モデルが音素の時刻を裏付ける手がかりをほとんど出さないので、内容認識が返す単語タイムスタンプの
  誤差が、フレーズ内の音素位置のずれとして残る。
- 漢字を含む書き起こしの読みは G2P の辞書が単語単独の文脈で決めるので、歌詞特有の当て字や読みを誤ることがある。
  助詞「は」「へ」や長音のように、かなでも単語の切れ目しだいで読みが変わることがある。常にかなを返す
  内容認識モデルを指定すれば、漢字に由来する読み違いは起きない。
- `tinyllama-katakana-converter` は、英字語に対して発音として不適切なかなを生成することがある。
- SOFA 経路は単語の境界で音声を切り分けるので、単語をまたぐ発声を gap にしてしまうことがあり、極端に短い
  音素を既定の経路より多く出す。

## 認識品質の測定(S-1)

- S-1 は、音素認識の構成を選ぶ・改めるときに、参照ラベル付きの日本語歌唱データで構成どうしを比べ、明らかに
  成立しない構成を除くための開発時の測定とする。合否を決める関門ではなく、品質の合否は利用先での調整と MMD 上の
  視聴確認で決める。
- 測定データ(楽曲音声を含む)はリポジトリに置かない。実モデルを使う測定は pytest のスイートに含めず、手動で
  実行する。
- 構成どうしを比べるときは、モデル id と revision・測定データ・採点規則・実行環境(マシンと GPU の有無)を揃える。
- 分離の寄与を切り分けるときは、同じ歌唱のアカペラとミックスを組にして比べる。
- 過開口率は利用先の閉じ側の処理を設計する材料として測り、構成の採否には使わない。
- 曲をまたぐ集計は測定側で行い、本モジュールは曲ごとの採点だけを提供する。
