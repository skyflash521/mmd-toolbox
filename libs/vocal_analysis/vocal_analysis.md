# vocal_analysis 要求仕様書

音声前段(入力読み込み・ボーカル分離・音素/母音認識・強弱RMS)を担う共有ドメインモジュールの要求仕様。
複数のCLIが共有する、音声から後段が使う正規化出力を作る前段処理を提供する。

---

## 1. 位置づけ

### 1.1 目的

音声(歌, BGM込み可)から、後段が必要とする共有の前段出力を作る。後段の用途は次のとおり。

- リップモーション生成系: 音素セグメント列＋RMS(→入口処理で口形イベント列と開き量を作る)。
- 採譜系: ボーカルWAV(→F0ピッチ推定)＋音素セグメント列(→音符分割・歌詞/音素対応)。
- S-1 認識測定: 認識品質の測定(構成間の比較・破綻検出。採点に IPA→5母音写像を使う)。

共有出力は **分離済みボーカルWAV＋音素ラベル付きセグメント列＋RMS**(2章)。**IPA→5母音写像**も
`vocal_analysis` が提供する(S-1測定の採点とリップモーション生成系の口形イベント確定の双方が使う)。

### 1.2 設計境界

[../../docs/conventions/layering.md](../../docs/conventions/layering.md) §1 の**共有ドメイン層**に属する共有モジュール(形式層でも単一ツール固有でもない、複数ツールが共有するドメインロジック)。

- **`vocal_analysis` が持つ**: 入力読み込み(S0)・ボーカル分離(S1)・音素/母音認識(S2)・強弱RMS算出(S3)、
  IPA→5母音写像、認識品質を測る S-1測定(9章)。外部ツール(分離・認識)はアダプタの背後で差し替え可能(8章)。
- **利用先(各CLI)に残る**: RMS を消費する判断(無音/閉口の確定・gap解決・母音境界のオンセット補正・
  口形イベント確定・開き量の決定)、ピッチ推定、音符分割・歌詞対応、CLI引数・プリセット。`vocal_analysis` は
  共有出力(2章)を作るところまでを担い、その消費判断は持たない。
- VMD・vpr の形式入出力は持たない(VMDは `vmd`、vprは `vpr`)。

### 1.3 利用先

| 利用先 | 使う共有出力 |
|---|---|
| リップモーション生成系 | 音素セグメント列・RMS・IPA→5母音写像(→入口で口形イベント列・開き量を作る) |
| 採譜系 | ボーカルWAV(→ピッチ推定)・音素セグメント列(→音符分割・歌詞/音素対応) |
| S-1 認識測定 | 音素セグメント列・IPA→5母音写像(採点)。vpr由来の参照ラベルを使う場合は [vpr](../vpr/vpr.md) を読む |

採譜系は口形イベントを要さないため、共有出力は**音素粒度**で持つ(口形イベント確定はリップモーション生成系の入口)。

## 2. 共有出力(正規化中間形式)

各ステージは正規化中間形式でつながる。外部委譲ステージ(S1・S2)は差し替え可能(8章)。

```text
入力 音声ファイル(歌, BGM込み可)
  ├─[S0] 入力読み込み(復号・レベル正規化。ch/SR保持) → 正規化PCM
  ├─[S1] ボーカル抽出(正規化PCM→ボーカル)         → ボーカルWAV
  ├─[S2] 音素/母音認識(ボーカルを16kHz monoへ変換) → 時刻付きセグメント列(母音/子音/gap)
  └─[S3] 強弱エンベロープ(ボーカルのRMS)          → 時刻ごとのRMS
```

- **S0出力**: 復号・入力レベル正規化したPCM(チャンネル数・サンプルレートは保持。mono化・再サンプリングは
  しない。3章)。
- **S1出力**: ボーカルWAVのパス(分離器の出力形式。S2向け 16kHz mono 化は S2 前段で行う)。
- **S2出力**: 全時間軸を被覆する時刻付きセグメント列(母音/子音/gap の区別・音素ラベル(IPA等)・任意の
  信頼度)。**無音/閉口の確定・あいうえお母音への写像・閉鎖(両唇音)判定は含まない**(写像は7章で提供するが、
  適用と無音/閉口確定は利用先)。
- **S3出力**: RMSエンベロープ(相対正規化。6章)。RMSを使う判断(無音判定・開き量)は利用先。

中核ロジック(利用先)は中間形式だけに依存し、特定の外部ツールに依存しない。各中間形式の公開型は §2.1 で
確定する(時刻は秒)。

### 2.1 公開データ型

各ステージをつなぐ正規化中間形式の公開型。S1出力(ボーカルWAV)以外は Python の dataclass、S1出力は
`pathlib.Path`。時刻は**秒(float)**。numpy 配列は `np.ndarray`。

- `AudioPcm`(S0出力 正規化PCM): `samples: np.ndarray`(形状 (フレーム数, チャンネル数)、float32、値域 [-1, 1])、
  `sample_rate: int`。チャンネル数は `samples.shape[1]`(ch/SR 保持。mono化・再サンプリングしない。3章)。
- **S1出力(ボーカルWAV)**: `pathlib.Path`(分離器が書き出したボーカルWAVのパス。専用 dataclass は設けない。
  出力形式は分離器に従う。4章・8.1)。
- `Segment`(S2出力の要素): `type: Literal["vowel", "consonant", "gap"]`、`start_sec: float`、`end_sec: float`、
  `phoneme: str | None`(IPA。母音/子音のみ。gap は None)、`confidence: float | None`(任意。0〜1)。
  セグメント列は時間順・隙間なく連続・非重複で全時間軸を被覆する(5章・8.1)。
- `RmsEnvelope`(S3出力): `times_sec: np.ndarray`(各フレーム中心時刻、秒)、`values: np.ndarray`(相対正規化済み
  RMS、6章)、`dynamic_range_db: float`(曲全体のダイナミックレンジ = 95/5 パーセンタイル RMS の dB 差。比なので
  ゲイン不変)。`dynamic_range_db` は正規化済み `values`(クリップ済み)からは復元できないため別フィールドで持つ。
- `AnalysisResult`(共有出力コンテナ): `vocal_wav: Path`、`segments: list[Segment]`、`rms: RmsEnvelope`。
  利用先は必要な部分集合だけを使う(1.3)。
- 音素→5母音写像は公開関数として提供する(7章)。S-1測定とリップモーション生成系の入口が同一規則で使う。

## 3. 入力読み込み(S0)

- 入力音声を読み込み、後段が扱えるPCMにする。読み込みは `soundfile`(現行の同梱 libsndfile は
  WAV/FLAC/OGG/mp3 に対応)を優先し、`soundfile` で読めない形式のみ ffmpeg にフォールバックする。
  ffmpeg はリポジトリに同梱・再配布せず、実行時に自動検出して内部で呼ぶ(8章)。
- **ffmpeg はオプション(必須ではない)**。ffmpeg 無しでも `soundfile`(同梱 libsndfile)が読める
  **WAV/FLAC/OGG/mp3** を最低保証として読む。これ以外の形式(一部の m4a/aac 等)は ffmpeg を検出できた
  ときのみ読み、検出できなければ `AudioLoadError`(「ffmpeg を導入してください」と分かるメッセージ)で
  失敗する(黙って別形式に化けさせない)。最低保証の形式だけで使う利用者は ffmpeg を導入しなくてよい。
- **読み込み失敗の分類(`AudioLoadError`)**: `AudioLoadError(message, *, reason)` はキーワード専用の
  必須引数 `reason` を公開契約として持ち、例外インスタンスの `reason` 属性として読み出せる(呼び出し側が
  原因を区別できるようにする)。値は次の2つ: `"decoder_missing"`(フォールバック復号器=ffmpegが未検出の
  ため復号を試みられない)、`"not_audio"`(入力ファイルが存在しない、または利用可能な復号経路を
  いずれも実際に試みたが失敗した。ffmpeg変換自体の失敗、変換後ファイルの再読み込み失敗を含む)。
- 公開関数は `load_audio(path) -> AudioPcm`(`vocal_analysis.io`)。
- S0 では**チャンネル数・サンプルレートを保持**する(S1 はステレオ原音の方が分離品質が高いため、ここで
  mono化・低レート化しない)。S2 が要求する 16kHz mono への変換は S2 の前段で行う。
- **入力レベル正規化**: 入力全体の音量を一定の基準レベルへ正規化してから S1 以降へ渡す。正規化係数は入力に
  対して斉次(正の一様ゲイン g に対し正規化後PCMが不変。例: ピーク値、または絶対ゲート無しの全体RMSで割る)
  とし、絶対ゲートを持つ測定(ゲート付きラウドネス)は使わない。これにより分離・認識・RMS算出が入力の全体
  ゲインに依存しない(同一音源のゲイン違いで結果が変わらない)。
- **正規化方式(確定・ピーク正規化)**: `peak = max(|samples|)`(全チャンネル・全フレームの絶対値の最大)。
  `peak > 0` なら `samples_out = samples * (target_peak / peak)`、`target_peak = 0.95`。`peak == 0`(完全無音)は
  0除算を避けて入力をそのまま返す。正の一様ゲイン g に対し peak も g 倍になり `target_peak / peak` で相殺される
  ため、正規化後PCMは g に不変(斉次)。`target_peak` は 0.95 に確定し、実装が独自に変えない(変更が要れば
  本書を先に更新する)。
- **実際の到達精度(浮動小数点誤差)**: 上記の斉次性は実数演算では厳密に成立するが、実装は有限精度浮動
  小数点で計算するため、ビット厳密な不変性までは保証しない。異なる入力ゲインから得られる最終的な連続値
  (S3のRMSエンベロープ・呼び出し側の開き量等)には、正規化(S0)またはボーカル抽出(S1)の段階で生じる
  微小な残差(絶対誤差でおおむね1e-4オーダー)が生じうる。音素/口形イベントの種別・境界といった離散
  判定はこの残差の影響を受けず不変である(分離込みの実パイプラインで確認済み)。残差の根本原因は未特定。

## 4. ボーカル抽出(S1)

- S0 の出力(入力レベル正規化済み。ステレオ・元サンプルレート)からボーカルを分離し、ボーカルWAVを得る
  (出力形式は分離器に従う)。分離の挙動(`always`/`never`)は利用先がCLI等で選ぶ。
  - `always`: 常に分離する(既定)。
  - `never`: 分離せず入力をそのままボーカルとして扱う(既にボーカル単体の入力向け)。
  - BGM有無の自動判定は持たない。判定コストが実運用の主要ケース(BGM込み入力)では常に純オーバーヘッド
    になり、判定を追加する価値が無いと判断したため。
- 分離は外部ライブラリで内部実行し(必要時のみサブプロセス)、Separator 抽象の背後で差し替え可能とする(8章)。
  公開関数は

  ```python
  def separate(
      pcm: AudioPcm,
      mode: Literal["always", "never"],
      *,
      on_progress: Callable[[str], None] | None = None,
  ) -> Path: ...
  ```

  (`vocal_analysis.separator`)。`on_progress`(進捗通知。既定`None`)は Recognizer の同名引数と
  同じ契約(実際にネットワークダウンロードを要した区間だけ進捗文言を渡して呼ぶ)に加え、分離処理
  (Demucs推論)が実際に進行している区間も文言を渡して呼ぶ(8.1)。
  ライブラリ未導入時は `SeparationError` で失敗する。
- `separate()` は分離前後の一時WAVを格納する作業ディレクトリをOSの一時領域に作る。このディレクトリは
  呼び出し元に公開せず、プロセスの正常終了時に削除を試みる(強制終了時や削除失敗時は残置を許容する)。
  呼び出し元は戻り値の `Path` を読み終えたタイミングを`vocal_analysis`側へ伝える手段を持たず、
  削除タイミングを制御できない。この一時領域は
  [一時ファイル・中間生成物の配置規約](../../docs/conventions/temporary-and-intermediate-files.md) §2.2
  の非公開の内部一時領域に従う。

## 5. 音素/母音認識(S2)

- S1 のボーカルを認識器が要求する形式(16kHz mono)へ変換したものから、母音・音素を時刻付きで認識する。
  リップモーション・音符分割に必要なのは母音・音素の時刻であり単語ではないため、書き起こしテキストは共有出力に
  含めず、歌詞テキストの入力も要求しない。認識構成がアダプタ内部で内容認識(文字起こし)を音素列の情報源
  として使うことは、この契約に反しない(認識構成の選定・比較は9章、候補比較は
  [external-tools.md](external-tools.md))。
- 認識器は **母音・子音・gap(未割当区間)** を区別したセグメントとおおまかな時刻を返す(8章)。**gap** は認識器
  が音素を割り当てなかった区間(CTC の blank 等。発声の継続中にも出るため、ここで無音とは断定しない)。
  母音・子音セグメントは音素ラベル(IPA等)と任意の `confidence` を持つ。
- **S2の責務はここまで**(言語非依存の音素分割=母音/子音/gap＋音素ラベル)。無音/閉口の確定・あいうえお
  母音への写像・閉鎖(両唇音)判定・gap の無音/継続判定は、S3のRMSも使う日本語固有の処理であり、利用先
  (リップモーション生成系の入口)に残る。`vocal_analysis` は写像規則(7章)を提供するが、その適用と無音/閉口確定は利用先。
- **時刻の粗さ**: CTC系の認識はトークン単位の粗いオフセットを返す。母音区間の境界の精緻化(RMSオンセットへ
  寄せる)は利用先が行う(S3のRMSを使う)。`vocal_analysis` はトークン境界を一次情報として渡す。
- 認識は外部ライブラリで内部実行し(必要時のみサブプロセス)、Recognizer 抽象の背後で差し替え可能とする
  (8章)。日本語の歌での母音認識品質が本方式の品質を直接左右するため、採用は S-1 認識測定(9章)で
  確定する。公開関数は

  ```python
  def recognize(
      vocal_wav_path: Path,
      content_recognizer_model: ContentRecognizerModel = ...,
      *,
      retry: bool = True,
      forced_aligner: ForcedAlignerId = "wav2vec2-ctc-forcedalign",
      sofa_aligner: SofaAlignerConfig | None = None,
      english_katakana_method: EnglishKatakanaMethod = "arpakana",
      on_progress: Callable[[str], None] | None = None,
  ) -> list[Segment]: ...
  ```

  (`vocal_analysis.recognizer`。`content_recognizer_model`は5.2・8.3、`retry`は5.2「トリガ式
  リトライ」)。強制アライメント段は
  `forced_aligner`で選択可能(既定`wav2vec2-ctc-forcedalign`。5.3・8.1・8.2・8.3)で、
  `forced_aligner="sofa-forcedalign"`のときのみ`sofa_aligner`(`SofaAlignerConfig`。8.3)が必須になる。
  `english_katakana_method`で英語カタカナ化フォールバック(5.2手順4)の変換方式を選択
  できる(既定`arpakana`。選択式`tinyllama-katakana-converter`)。
  `content_recognizer_model`は既存どおり第2位置引数のままとし、`retry`・`forced_aligner`・
  `sofa_aligner`・`english_katakana_method`・`on_progress`はキーワード専用引数とする。
  ライブラリ未導入時、またはモデル取得に失敗した場合は `RecognitionError` で失敗する(8.3章)。
  `forced_aligner="sofa-forcedalign"`で`sofa_aligner`が`None`の場合も同様に`RecognitionError`とする。
  `on_progress`はモデル(内容認識モデル・音素モデル・`english_katakana_method=
  "tinyllama-katakana-converter"`選択時のカタカナ生成モデルのいずれも)の初回取得が実際にネットワーク
  ダウンロードを要した区間だけ、進捗文言(`f"ダウンロード中: {model_id} {percent}%"`。
  `percent`は取得済みバイト数の百分率)を都度渡して呼ぶ。取得済みモデル(キャッシュ済み)を使う場合や
  `on_progress`省略時は一切呼ばない。加えて、いずれのモデルもロード開始時(ダウンロードの有無に
  関わらず、キャッシュ済みでディスクから読み込むだけの場合を含む)に`f"{モデル種別}読み込み中:
  {model_id}"`(モデル種別は内容認識モデル・音素モデル・カタカナ生成モデル)を1回呼び、ロード完了までの
  区間を無通知にしない。ダウンロードが発生した場合、そのモデルのロードが完了した時点で空文字列を
  渡して1回呼び、通知を終える。加えて、区間ごとの実処理が進行する区間(ダウンロードとは独立)でも、
  区間の時刻範囲と区間番号を含む進捗文言(書き起こし段は`f"歌詞書き起こし中: {開始}-
  {終了}({区間番号}/{区間数})"`、wav2vec2 CTC強制アライメント段は`f"音素アライメント中: {開始}-
  {終了}({区間番号}/{区間数})"`。時刻は`m:ss`形式)を都度渡して呼ぶ(こちらはダウンロードの有無に
  関わらず呼ぶ)。呼び出し元(利用先)はこれらの文言をそのまま利用者向け表示へ使ってよい。

### 5.1 母音/子音の判定基準とフレーム時間(RMS不要)

**母音/子音の判定基準(言語非依存・アダプタ共通)**: 下記の母音記号基準集合とNFD基底文字判定による
分類規則は、`forced_aligner`の選択(5.3・8.1)に関わらず、確定済みの1つのIPA記号を**母音/子音**へ
分類する共通規則である(SOFA経路は写像を経た後のIPA記号へ、この規則をそのまま適用する。5.3)。
規則を**IPA母音チャート(標準的な言語学的分類。7章の日本語5母音バケット表とは別物)**を使って確定する。
7章の写像表(15記号)は「識別済みの母音をどの日本語5母音へ割り当てるか」の表であり網羅的でないため、
母音か否かの一次判定にそのまま転用できない(採用モデルの音素インベントリは多言語対応で392記号あり、
`iː`・`uː`・`eɪ`・`ɜː` 等7章の表に無い母音記号を多数含む)。

**wav2vec2 CTC経路(5.2)でのIPA記号の確定**: CTC出力の各フレームは音素インベントリ中の1記号(または
blank)に対応し、この1記号へ上記の分類規則を適用する。SOFA経路(5.3)はCTCフレームを持たず、SOFAの
出力セグメントが直接1記号を確定するため、フレーム単位の分類という手順自体を経ない(確定した記号への
分類規則自体は共通。上記)。

- **母音記号の基準集合**: IPA母音チャートの基本母音(前舌/中舌/後舌 × 狭/半狭/半広/広の各段、円唇・
  非円唇を問わない)`i y ɨ ʉ ɯ u ɪ ʏ ʊ e ø ɘ ɵ ɤ o ə ɛ œ ɜ ɞ ʌ ɔ æ ɐ a ɶ ɑ ɒ` に、R音性母音
  `ɚ ɝ`、および採用モデルの語彙に現れる拡張母音記号 `ᵻ`(reduced central vowel の表記)を加えた集合。
- **判定手順**: 記号を Unicode 正規化形式 NFD(結合文字分解)にし、先頭の1文字(基底文字。長音記号
  `ː`・鼻音化記号(結合チルダ)等の修飾記号は正規化により基底文字の後ろに分離される)が上記の母音記号
  基準集合に含まれれば母音、そうでなければ子音とする。この「先頭基底文字が母音記号か」という判定は、
  単一母音(`aː`=長音・`ɑ̃`=鼻音化 等の修飾付き含む)だけでなく、採用モデルの語彙に現れる下降二重母音
  (`aɪ`・`eɪ`・`oʊ`・`aʊ` 等。母音記号で始まる)や母音+R音性子音の連続(`ɑːɹ`・`ɔːɹ` 等。米語のr音化
  母音表記)も正しく母音側に判定する。中国語声調番号付き表記(`a1`・`e2` 等)も同じ理由で母音側になる。
  一方、採用モデルの語彙には `j`・`w` 等の接近音で始まる上昇二重母音的な記号(`ja`・`ju` 等)もあり、
  これらは先頭が母音記号基準集合に無いため子音側になる(音節主音は後続母音だが、先頭の接近音自体は
  IPAの子音チャートに属するため、この判定基準と整合する)。空文字列は子音側(母音記号基準集合に
  一致しないため)。
- gapはこの母音/子音判定の対象外で、母音/子音のいずれでもない出力は常に gap とする(wav2vec2 CTC経路の
  blankトークン、SOFA経路のAP/SP/pau/cl相当の出力。5.2・5.3)。時間は秒で保持する(8.1 の Recognizer 契約)。

**フレーム時間(確定・wav2vec2 CTC経路専有)**: §8.3 で固定した採用モデル(`facebook/wav2vec2-lv-60-espeak-cv-ft`)の畳み込み
層の総ストライドは 320 サンプルで、S2 の入力サンプルレート 16kHz(§5.1)における1フレームは
**20ms**(`320/16000`)に固定される(モデル・revision を固定する限り不変の値。§8.3)。フレーム中心では
なくフレーム開始位置を基準に、フレーム `i` の区間は `[i*0.02, (i+1)*0.02)` 秒とする。**この20ms
フレーム時間は`forced_aligner="wav2vec2-ctc-forcedalign"`(5.2)専用の値である。`forced_aligner=
"sofa-forcedalign"`(5.3)はCTCフレームを持たず、出力の時刻粒度はSOFA自身の出力形式に由来する
100ナノ秒単位であり、20msフレームへの量子化を経ない。**

**実行条件**: 音素モデル(強制アライメント用)・内容認識モデル(Whisper系。5.2手順3)のいずれも、
実行デバイスは環境依存で自動選択する(GPU(CUDA)が利用可能ならGPUを使う。CPU実行時のスレッド数も
環境既定のまま制限しない)。内容認識モデルの数値精度(dtype)はこの自動選択に連動し、GPU実行時と
CPU実行時で異なる値を使う(具体値は実装が保持する)。音素モデルのdtypeのみ、モデル id・revision
(8.3)と同じ固定値として残す: dtypeはモデル id・revisionと同様に認識結果(数値)に影響する推論条件
であり、採用構成の品質はこの値でS-1測定(9章)により検証済みのため、変更する場合はrevision変更と
同じ手順(8.3)を要する。内容認識の貪欲デコード(ビーム幅1・サンプリング無し)は乱数由来の非決定性
(サンプリング・ビームサーチの分岐)を持ち込まない。実行デバイス(CPU/GPU)やスレッド数・数値精度が
異なると浮動小数点演算の丸め誤差の出方が変わるため、内容認識モデルでは貪欲デコードの僅差のトークン
選択が割れて書き起こし・単語タイムスタンプが、音素モデルでは対数確率のわずかな差から強制アライメントが
確定するセグメント境界の時刻が、それぞれわずかに変わりうる。

### 5.2 wav2vec2 CTC経路: 複合構成(内容認識+G2P+強制アライメント)の区間化

本節は`forced_aligner="wav2vec2-ctc-forcedalign"`(既定。8.1・8.2・8.3)を選んだ場合の区間化を定める。
`forced_aligner="sofa-forcedalign"`を選んだ場合は5.3を見る(内容認識・G2Pの前段(下記手順1〜4)は
両経路で共通。強制アライメント段(手順5以降)だけが経路ごとに異なる)。

§8.3 で採用する複合構成は、単段の自由CTC構成(フレームごとに独立分類してから区間化する方式。歌唱で
母音をほぼ出力せず不採用)ではなく、**既知の音素列を
音声へ強制的に対応付ける(強制アライメント)**方式で区間化する。CTCの blank が歌唱で支配的になり
フレーム単位の自由分類が母音をほぼ出力しない(9章の測定で確認済み)ことへの対処であり、音素の**種類**を
内容認識由来の文字列から G2P で得て既知にすることで、強制アライメントは blank 支配の影響を
受けずに音素の**位置**(開始時刻)を正確に出せる。

**内容認識モデルの指定(既定値・任意指定)**: 内容認識(手順3)に使うモデルは
`ContentRecognizerModel`(`model_id`・`model_revision`の組。8.3)で指定する。`recognize()`は
`content_recognizer_model`引数(既定値は下記「既定値」)を受け取り、内容認識には常に同じ手順
(パイプライン読み込み→かな限定プロンプト(8.3)でprompt_ids取得→単語タイムスタンプ付き貪欲デコード)を
適用する。モデルによる分岐は持たない(かな限定プロンプトと単語タイムスタンプ取得の併用は既定値で
実測確認済み。本節手順7の単語窓制約に使う)。単語タイムスタンプが取得できないモデル・区間は、
手順5の窓の対応付けを行わず、手順7では単語窓制約を使わずフォールバック(位置バンド制限)で直接
整列する(認識自体は失敗させない)。

- **既定値**: `openai/whisper-medium`(revisionは8.3に固定)。かな化される場合とされない場合が
  ある(手順4の既知の限界)。
- **任意指定**: `ContentRecognizerModel(model_id=..., model_revision=...)` で既定値以外の
  モデルも指定できる(常にかなを返すモデル等。external-tools.md §2.2)。`model_revision` を
  省略した場合は最新リビジョンを使う(8.3。任意指定でもこの挙動自体は同じ)。既定値のみ
  実測・検証済みの組み合わせとして `model_revision` を固定しており、任意指定はこの実測検証の
  対象外(利用者の自己判断)。

**トリガ式リトライの有効/無効**: `recognize()` は `retry` 引数(`bool`。既定`True`)を受け取り、
手順3の**トリガ式リトライ**(エコー幻覚・反復幻覚)の有効/無効を切り替える。`False` を渡すと
無効化する(この場合もgap確定・反復救済(手順4)自体は働く。リトライだけを行わない)。リトライは
別モデルを使わず**主モデル自身**をプロンプト無しで再認識する(手順3参照)。

任意指定で常にかなを返すモデルへ切り替える場合の選定理由・トレードオフは
[external-tools.md](external-tools.md) §2 を正とする(重複記載しない)。

ボーカルWAV全体を単一の Whisper 呼び出し・単一の強制アライメントで処理すると、次の2つの実測済みの
不具合が生じる。**(a) 長尺入力での書き起こし破綻**: Whisper は数分規模の入力で反復幻覚(同一文の
繰り返し)や、無音・低エネルギー区間での定型句幻覚(動画配信由来の学習データに起因する「ご視聴
ありがとうございました」等)を起こす(9章の測定で確認済み)。**(b) blank 支配下での押し込み崩壊**:
`pau` にマップされる状態(列の先頭・末尾)は blank 支配下でほぼゼロコストで留まり続けられるため、
制約の無い強制アライメントは実際の音素列全体をごく短い窓へ押し込み、残りの大半を `pau` に割り当てて
しまう(9章の測定で確認済み)。この2つに対処するため、複合構成は**無音検出による区間分割**・
**区間の有声スパンへのトリム**・**アライメントの単語窓制約**(内容認識モデル自身が返す単語
タイムスタンプに基づく制約。取得できない場合のフォールバックとして位置バンド制限も持つ)を
併せ持つ。

**パイプライン**:

1. **区間分割(無音検出)**: ボーカルWAVを 100ms 幅の連続フレームに分け、各フレームの RMS を求める。
   全フレームの RMS の95パーセンタイル値を「ピーク」とし、ピークから **30dB** 下回る値を無音しきい値と
   する(曲ごとの音量差に対して相対的に定まり、絶対値の較正を要しない。ピークが0(全フレームRMSが0)の
   場合はしきい値も0になり、この場合は「RMSがしきい値以下」の判定(次文・手順2)がRMS0のフレーム・
   区間を過不足なく無音と判定する)。しきい値**以下**のフレームが連続 **0.6秒以上** 続く区間を無音区間と
   し、その中点を分割点とする。分割点(0秒・音声終端を含む)で
   区切られた各区間を、左から順に長さを累積し、**1.5秒未満**の区間は次の分割点まで結合を続ける
   (音声終端まで結合しても1.5秒に満たない場合はそのまま採用する)。結合後、**25秒を超える**区間は
   等分割して25秒以下の区間へ均等に分ける。
   この無音検出は、S3(6章)のRMSエンベロープ(百分位相対正規化・強弱表現用)とは別の、本手順専用の
   単純なフレームRMS計算であり、S3への依存は持たない。母音/子音/gapの種別判定(5.1・本節手順9)には
   一切使わず、**内容認識呼び出しの可否を決める前段フィルタ**に責務を限定する(次項)。
2. **区間の無音判定と有声スパンへのトリム**: 各区間について区間全体のRMSを求め、手順1のしきい値
   **以下**の区間は無音区間として扱い、内容認識呼び出し・G2P・強制アライメントを行わず
   `type="gap"`・`phoneme=None` のSegmentを区間全体に対して直接確定する(不要な認識呼び出しを避け、
   無音入力に対する内容認識モデルの定型句幻覚を構造的に防ぐ)。無音でない区間は、手順3以降へ渡す前に
   **有声スパンへトリム**する: 区間内を手順1と同じ100msフレームでRMS化し、しきい値を上回る最初の
   フレームの開始から最後のフレームの終了までを有声スパンとし、その外側へ余白 **100ms**(手順1の
   フレーム1枚分。しきい値未満の子音の助走を切り落とさないため)を加えた範囲だけを手順3以降(内容認識・
   G2P・強制アライメント)の入力とする。しきい値を上回るフレームが1つも無い場合(区間全体RMSは
   しきい値超だが、有声成分が末尾の不完全フレーム(フレーム化で切り捨てられる100ms未満の端数)にのみ
   ある場合など)は、トリムせず区間全体を入力とする。トリムで除いた先頭・末尾は `type="gap"` の
   Segmentとして直接確定する(手順9の結合で全時間軸の被覆を保つ)。区間の境界は無音区間の**中点**(手順1)のため、区間は
   端に最大で無音区間の半分(数秒に及びうる)を含み、トリム無しでは (i) 先頭の無音が単語窓制約・
   フォールバックの位置バンド制限(手順7)いずれの起点も実際の発声位置からずらし(単語タイムスタンプ・
   均等割り当てとも手順3以降の入力範囲を基準とした相対時刻のため)、先頭のトークンを無音上へ置いて
   以降の口形の時刻を実際の歌唱からずらす、(ii) 末尾の無音が内容認識モデルの幻覚(実際にはその区間で
   歌われていない歌詞の生成)を誘発しその音素が無音上へ散布される、という2つの実測済みの不具合を生む。
3. **内容認識**: 無音でない各区間の音声(手順2でトリムした入力範囲)を、指定された
   `content_recognizer_model`(前掲「内容認識
   モデルの指定」。モデル固定は8.3)へ個別に入力し、テキストと**単語タイムスタンプ**(各単語の
   開始・終了時刻。トリムした入力範囲内の相対時刻)を得る(区間ごとに独立呼び出しとし、
   他区間の文脈を引き継がない。これにより長尺入力特有の反復幻覚を避ける)。かな限定プロンプト
   (8.3)を渡した書き起こしを返す(既定値`openai/whisper-medium`はかな化される場合とされない
   場合がある。任意指定で常にかなを返すモデルへ切り替えることもできる。external-tools.md §2.2)。
   **単語タイムスタンプの単調化**: 歌唱では単語タイムスタンプの順序が乱れる(前の単語より
   後退する、トリムした入力範囲外の値を返す等)ことがあるため、まず開始・終了をトリムした
   入力範囲 `[0, 範囲長]`(秒)へクランプし、続けて開始時刻を直前の単語の開始時刻以上へ、終了
   時刻を自身の開始時刻+最小長(50ms)以上へ、単語の時系列順にクランプする。単語タイムスタンプを
   返さないモデル・区間は「単語タイムスタンプが取得できない場合」として扱い、手順4のG2Pは区間の
   書き起こし全体を1回で変換し(単語ごとに分割しない)、手順5の窓の対応付けを行わず、手順7では
   単語窓制約を使わずフォールバック(位置バンド制限)で直接整列する。書き起こしが空文字列(単語
   0個)の区間は、手順4のG2Pを行わず区間全体を `type="gap"`・`phoneme=None` の Segment として
   直接確定する(手順2の無音確定・手順4の音素密度超過確定と同様の扱い。整列しても全区間が blank
   になるだけの区間に対し、強制アライメントを試みない)。得られたテキスト・単語タイムスタンプは
   強制アライメントの入力にのみ使い、共有出力(2章)には含めない(5章)。
   **プロンプト文エコーの除去(常時適用)**: 内容認識は、かな限定プロンプトの指示文そのものを
   「歌詞」として出力する幻覚(エコー)を起こすことがある(実際に歌唱がある区間でも起きる)。
   書き起こしを句点で文に分割し、空白・句読点を除いて正規化した各文がプロンプトの構成文と一致する
   ものを除去する。1文以上除去した場合、残りの末尾の文がプロンプト構成文と**5文字以上**の共通
   接頭辞を持つならば、区間末尾で切れたエコーの断片として同様に除去する(エコーを除去していない
   書き起こしの通常文には適用しない。実際の歌詞がプロンプト文と偶然一致する確率は無視できるため、
   この照合の誤除去は実質発生しない)。除去でテキストが変化した区間の単語タイムスタンプは、残った
   文と単語の対応が保証できないため破棄する(手順5の窓対応なし・手順7フォールバックの扱い)。
   **内容認識のリトライ(トリガ式・区間あたり1回)**: エコー除去の直後、次のいずれかが成立した
   区間は、**主モデル(`content_recognizer_model`)自身で**同じ音声をプロンプト無し・
   タイムスタンプ無し(テキストのみ)に1回だけ再認識し、そのテキストを主モデルの1回目の結果の
   代わりに採用する(単語タイムスタンプは破棄する。手順5の窓対応なし・手順7フォールバックの
   扱い):
   **(i)** エコー除去の結果テキストが空になった(エコーしか無かった。手順2を通過済みの有声区間で
   ある)、**(ii)** 手順4の音素密度が **20音素/秒**(下記「音素密度による反復幻覚の検出と救済」)を
   超えた。トリガはこの2つのみで、漢字・ASCII英字を含む単語の残存はリトライ条件に含めない
   (漢字は下記手順4の既知の限界として残る)。
   エコーはかな限定プロンプト起因の幻覚のため、同じモデルでもプロンプトを外すだけで実際の
   歌詞を回復できる。このリトライに別モデルを使う構成は採らない: 別モデルを主モデルと同時に
   GPUへ常駐させるとVRAMを圧迫し推論が不安定になり、処理時間を有界にできないため。
   リトライ結果にもエコー除去(プロンプト無しのため通常は無変化)と手順4の密度検査・反復救済を
   適用してから採用する。回復テキストは漢字を含みうるため、その区間の読みはG2P辞書に依存する
   (下記の既知の限界)。`retry`が`False`の場合はリトライを行わず、主モデルの結果のまま手順4の
   反復救済・gap確定へ進む。
4. **G2P**: 手順3で単語タイムスタンプが取得できた場合、各単語のテキストを**単語ごとに個別に**
   `pyopenjtalk-plus`(8.3)で音素記号列(下記の記号集合)へ変換する(単語境界をまたぐ文脈は
   使わない)。取得できなかった場合は、区間の書き起こし全体を1回の変換にかける(単語単位に
   分割しない。前掲)。テキストがかな(既定値はかな化された区間。任意指定で常にかなを返す
   モデルを使えば常にこれに該当する)であれば、単語ごとに独立して変換しても、
   多くの場合は全体を一括変換した場合と同じ結果になる(かなの音素は概ね一意に決まるため)。ただし
   助詞「は」「へ」の読み(わ/え と は/へ の対応)や長音の解釈など、ごく一部は文脈(前後の品詞・
   文節境界)に依存し、内容認識モデルの単語分割の切り方次第で一括変換と異なる読みになることが
   ある(下記の既知の限界に含める)。文中の句読点は `pau`(無音)記号として現れる。
   **英語カタカナ化フォールバック**: `pyopenjtalk-plus`へ渡す前に、各形態素ノードの表層形を
   NFKC正規化(全角英数字・記号を半角相当へ変換する)した上で、文中でASCII英字のみの1形態素ノード
   として完結し品詞がフィラーと判定される語(`pyopenjtalk-plus`が正しい読みを持たない英単語)を
   検出し、CMUdict(発音記号辞書)で発音記号(ARPAbet)を引ける場合は変換方式(既定値`arpakana`。
   ARPAbet音素をルールベースでカタカナへ変換する、生成モデル・GPU不要のライブラリ。選択式
   `tinyllama-katakana-converter`。生成モデルによる変換)でカタカナへ補完変換し、対象語をカタカナへ
   置き換えたテキスト全体をあらためて`pyopenjtalk-plus`へ渡す(全文再解析)。CMUdictで同じ語に
   複数の発音表記がある場合は先頭の表記を使う。CMUdictに未収録の語・変換結果がひらがな/カタカナ
   以外を含む場合・変換方式自体が失敗した場合は、その語を変換せず元のテキストのまま`pyopenjtalk-plus`
   へ渡す(安全側フォールバック)。CMUdict本体は他の学習済みモデルと同様に初回使用時に自動取得し、
   利用者に手動コマンドを要求しない。
   **既知の限界(対象範囲・CMUdict網羅率。未軽減)**: 対象は1形態素ノードで完結する語に限る。
   アポストロフィ・ハイフンを含み複数ノードへ分裂する語(`dog's`・`rock-and-roll`等)は対象外
   で、現行のpyopenjtalk-plus既定動作(アルファベット名の1文字読み)のまま残る。また、CMUdict
   (1993〜2008年収録)は近年の固有名詞・俗語を収録しておらず、該当語も同様に変換されず現行の
   既定動作のまま残る。
   **既知の限界(対象語の言語判定を持たない。未軽減)**: 対象語の判定(ASCII英字のみ・品詞
   フィラー)は言語を区別しないため、英語以外のASCII語(フランス語`bonjour`等)も対象語として
   検出されうる。CMUdictは英語以外の語(英語圏で定着した外来語等)も収録している場合があり、
   該当すればその語は英語話者の発音に基づいてカタカナへ変換される(実機確認: `bonjour`は
   CMUdictに`B AH0 N ZH UH1 R`として収録され「バンジュア」に変換される。フランス語の発音
   「ボンジュール」にはならない)。
   **既知の限界(`tinyllama-katakana-converter`選択時の発音精度。未軽減)**: 出力妥当性検査は
   生成結果がひらがな・カタカナのみで構成されるかだけを見るため、子音の脱落・別の音への置換・
   原語をたどれない変換であっても、出力自体がかなのみで構成されていれば検査を通過し採用される。
   既定値`arpakana`はルールベースのため機械的な発音対応が保たれるが、`tinyllama-katakana-converter`
   は生成モデルであるため、発音として不適切なかな出力を生成する場合がある。
   **既知の限界(漢字の読み・一部のかなの文脈依存の読み。未軽減)**: かな化されず漢字を含む
   書き起こしになった単語は、漢字の読みを `pyopenjtalk-plus` 自身の辞書・形態素解析が(単語単独の
   文脈で)決定するため、歌詞特有の当て字・非標準的な読み(歌唱でのみ使われる読み方)を誤ることが
   ある(同字異音の読み違い)。単語単独の文脈は文全体の文脈より読みの手がかりが少なく、この
   読み違いは全体を一括変換する場合より起きやすい。前掲のかなの文脈依存の読み(助詞・長音)も
   同様に、単語分割の切り方次第で一括変換と異なる読みになりうる。いずれの場合も、その語の音素列
   自体が実際の発声と異なり、強制アライメントにもその誤りが伝播する。読み違いの回避がなお必要な
   曲では、曲単位で内容認識モデル自体を任意指定で常にかなを返すモデル(漢字由来の限界を持たない。
   入力に漢字が現れないため。かなの文脈依存の読みの限界は他の内容認識モデルと同様に残る。
   external-tools.md §2.2)へ切り替えることができる(前掲「内容認識モデルの指定」。時刻誤差の
   安定性は既定値に劣るトレードオフがある)。
   対象語だけを別モデルで読み直す構成は採らない: 別モデルを主モデルと同時にGPUへ常駐させると
   VRAMを圧迫し推論が不安定になるため(前掲手順3のトリガ式リトライと同根)。
   **音素密度による反復幻覚の検出と救済**: 手順3の内容認識は、区間の実際の発声より著しく多い
   内容を生成する反復幻覚(同一文・同一フレーズの繰り返し。実在する反復歌唱の過剰増幅を含む)を
   起こすことがある(手順2でトリムした入力範囲は無音でないため、この幻覚は手順2の無音判定では
   防げない)。この場合、区間のG2P結果(単語ごとに個別変換した場合は全単語分を合わせた)音素
   記号列の要素数を区間の実効長(トリムした入力範囲の秒数)で割った**音素密度**が、日本語の高速な
   歌唱・発話でも通常到達しない **20音素/秒** を超える。超えた区間は次の順で処理する:
   **(1) リトライ**(手順3の「内容認識のリトライ」トリガ(ii)。未実施かつ有効な場合)。
   **(2) 反復救済**(リトライ後もなお密度超過の場合、またはリトライが無効の場合): 書き起こし
   末尾の反復 `単位×k`(単位は末尾から検出した最長一致の繰り返し。繰り返し数 k≧3 かつ総長8文字
   以上)を検出し、(2a) 反復を除いた先頭部が空でなければ**先頭部だけを採用**する(実在の歌詞に
   幻覚の反復が付随した形。反復部分の音声は多くの場合、後続の区間で独立に認識される)。
   (2b) 全文が反復(先頭部が空)ならば、繰り返し数を「区間の実効長 × **3.5モーラ/秒** ÷ 単位の
   モーラ数」へ正規化して採用する(実在する反復歌唱(ラララ等)の過剰増幅を実時間に見合う個数へ
   戻す。3.5モーラ/秒は参照ラベル付き歌唱コーパス(9.1)を基準に定めた値)。
   救済でテキストが変化した区間の単語タイムスタンプは破棄する(手順7フォールバックの扱い)。
   この救済は密度超過の区間だけに適用し、密度が正常な書き起こし(実在の歌詞の3回程度の反復等)には
   一切触れない。**(3) gap確定**: 救済後もなお密度が20音素/秒を超える(または救済後のテキストが
   空の)区間は、書き起こし・G2P・後続の強制アライメントの結果を用いず、区間全体を
   `type="gap"`・`phoneme=None` の Segment として直接確定する(誤った音素列・タイミングを確定
   させるより、利用先の gap 解決(無音/継続判定)へ委ねる)。しきい値(20音素/秒)は、正常な
   書き起こし(歌唱・発話とも)の実測値に対して十分な余裕を持ち、かつ反復幻覚時の実測値を確実に
   下回るよう固定した値である(値・反復検出の条件(k≧3・総長8文字)・正規化レート(3.5モーラ/秒)を
   変える場合は本書を先に更新する)。
5. **音素列の組み立てと単語窓の割り当て**: 手順3で単語タイムスタンプが取得できた場合、手順4で
   得た単語ごとの音素記号列を、単語の時系列順に `pau` で連結する(単語境界にも `pau` を挿入する。
   先頭の前と末尾の後にも `pau` を1つずつ補い、トリムした入力範囲の端に残る無音・息継ぎ(トリム
   余白等)を吸収できるようにする)。各音素記号(および挿入した各 `pau`。単語内の句読点由来の
   `pau` はその単語自身の窓を、単語境界に挿入した `pau` は前後2単語の窓を共有する)に、その
   由来する単語の**時間窓**を対応付ける: 単語内の音素記号は、その単語の
   `[開始時刻 - 余白, 終了時刻 + 余白]` を窓とする。単語間の `pau` は隣接する2単語の
   `[前の単語の終了時刻 - 余白, 次の単語の開始時刻 + 余白]`、先頭の `pau` は
   `[0, 最初の単語の開始時刻 + 余白]`、末尾の `pau` は
   `[最後の単語の終了時刻 - 余白, トリムした入力範囲の終端]` を窓とする。窓の下端が上端を上回る
   場合(単調化は単語の開始時刻の順序だけを保証するため、前の単語の終了時刻が次の単語の開始時刻を
   余白の2倍(1.5秒)を超えて上回る=重なる場合に生じうる)は、小さい方を下端・大きい方を上端として
   扱う(空窓にしない)。**余白は0.75秒に固定する**(手順7「単語窓制約の余白の決定」)。
   手順3で単語タイムスタンプが取得できなかった場合は、この窓の対応付けは行わず、手順4で得た
   (単語分割していない一括の)音素記号列の前後に `pau` を1つずつ補うだけにする(手順7では単語窓
   制約を使わずフォールバックで直接整列する)。
6. **記号→アライメント用トークンへの変換**: 組み立てた記号列の各要素を、`pau`・`cl`(促音の閉鎖。無音と
   同じ扱い。下記の写像表)は音素モデルの blank トークンへ、それ以外は下記の**G2P記号→音素モデル語彙の
   写像表**で対応する語彙記号のトークンIDへ変換する(写像表に無い記号が現れたら `RecognitionError` で
   停止する。黙って捨てない)。各トークンは手順5で対応付けた時間窓を保持したまま次の手順へ渡す。
7. **強制アライメント(単語窓制約Viterbi)**: 手順2でトリムした入力範囲に対する音素モデル(8.3の
   モデル・revision固定。CTC出力)の対数確率行列(入力範囲内フレーム数 T)に対し、変換したトークン列を
   **その順序どおりに単調に
   (スキップ無し)**対応付ける動的計画法で最尤経路を求める。blankトークン(`pau`・`cl` 由来)は
   1状態、非blankトークン(音素)は最小滞在制約(下記)による連鎖サブ状態で表し、状態
   遷移は「同一状態に留まる」「次の状態へ進む」の2種のみ(トークンの読み飛ばしは禁止)。
   各状態の対数確率にはそのトークンの語彙IDの列を使う(`pau`・`cl` 由来の状態は blank の列を使う)。
   **最小滞在制約**: 非blankトークン(音素)は最小滞在フレーム数(上限 **6フレーム=120ms**)の連鎖
   サブ状態で表し(各サブ状態に1フレーム以上滞在)、音素の状態に合計その滞在フレーム数以上滞在
   しなければ次のトークンへ進めない形にする。blank優勢の歌唱では、音素状態に1フレーム(20ms)だけ
   滞在して通過する経路が最尤になりやすく、モーラの区間が数十msへ潰れて位置も実際の発声からずれる
   (バンドの下限側に極小モーラが並ぶ)実測済みの不具合への対処で、歌唱のモーラの実長の下限相当を
   強制する。
   **局所適応(単語タイムスタンプ取得時)**: 手順5で単語窓が対応付けられている場合、最小滞在フレーム数は
   単語ごとに個別に決める: その単語の実時間(終了時刻-開始時刻をフレーム数へ換算)を、その単語の
   音素記号列の要素数(`pau`・`cl`由来のblank記号を含む)で割った値を四捨五入し6フレームに切り詰めた
   もの(1未満にはしない)とする(単語間・先頭・末尾の `pau` は常に1フレーム)。四捨五入は
   実装が固定した真の四捨五入(0.5は常に切り上げ。言語処理系の実装依存な偶数丸めは使わない)で、
   実時間/要素数がちょうど.5になる商を偶数丸めが切り捨てること、およびちょうど整数になる商が
   浮動小数点誤差で1フレーム低く丸まることの両方を避けるための決定論的な丸めであり、確率的要素は
   持たない。
   歌唱ではフレーズ内でテンポが不均一なことがあり、チャンク全体の平均(下記フォールバック側の算出)では
   十分な余裕があっても、テンポの速い一部の単語群(モーラ実長が120ms未満)だけが局所的に逼迫し、
   単調遷移と単語窓を同時に満たす経路が消える(理論上到達不能になる)ことが実測で確認された。単語ごとの
   実時間に応じて最小滞在を短縮することで、この逼迫を解消する。単語窓制約は使うが最小滞在をチャンク
   全体で1つとする構成と、単語ごとに最小滞在を局所適応させる構成(本実装。
   `recognize()`を直接呼び出した実測)を比べると、参照ラベル付き歌唱コーパス(9.1)のマクロ平均で
   母音開始時刻誤差の中央値は約120ms→約95msへ、95パーセンタイルは約597ms→約409msへ縮小し、参照
   ラベルとの母音一致率(手順7「単語窓制約の余白の決定」で定義)に退行は無かった(実測で確認済み)。
   テンポが不均一な区間ほど改善が大きい(90秒規模の曲2件では中央値が約233ms→約87ms・約90ms→約52ms
   へ縮小)。局所適応を用いない構成の値は、手順7「単語窓制約の余白の決定」が引用する値(位置バンド制限
   のみとの比較。472ms→116ms等)とは別の測定走行によるものであり、単語窓制約を含む構成同士の比較
   として本段落の値を参照すること。値(除算に切り詰め上限として使う6フレーム)を変える場合は本書を
   先に更新する。
   **フォールバック側の算出(単語タイムスタンプ非取得時、または局所適応でも単語窓制約が失敗した場合)**:
   入力範囲のフレーム数 T をサブ状態の総数(このチャンクの全非blankトークンに一律の滞在数を仮定した値)で
   割った比から、チャンク全体で1つの最小滞在フレーム数を決める。フレーム数がサブ状態の総数に足りない
   場合(密な歌詞・短い入力範囲)は、その入力範囲に限り成立する最大の滞在数へ引き下げる(1未満にはしない)。
   **有声フレームのblank抑制**: 対数確率行列のblank列に対し、有声フレーム(入力範囲を手順1の
   しきい値と同じ基準で 20msフレームRMS化し、しきい値を上回るフレーム)では固定ペナルティ **7**
   (対数確率)を引いてからアライメントする。blank優勢の歌唱では、声が出ているフレームでも
   blank(`pau`)に留まる経路が最尤になりやすく、フレーズ先頭のモーラが実際の発声より数百ms
   (実測で約0.8秒)遅れて置かれる実測済みの不具合への対処。ペナルティ値は、フレーズ先頭の遅延
   (有声オンセットに対する最初の非blankセグメント開始の遅れ)を実測で数十msまで抑える最小の
   値として固定した(値を変える場合は本書を先に更新する)。
   **単語窓制約**: 手順5で窓が対応付けられている場合、状態 `l`(サブ状態展開後)が遷移できる
   フレーム `t` を、その状態が属するトークンの窓 `[lo, hi]`(秒)と交差するフレームに限る(5.1で
   確定したフレーム区間 `[t*0.02, (t+1)*0.02)` を用い、`lo < (t+1)*0.02` かつ `hi > t*0.02` を
   満たすフレームを到達可能とする。窓は手順3で単調化・クランプ済みの値をそのまま使う)。交差しない
   フレームは到達不能として扱う。単語内の全音素サブ状態・前後の `pau` はいずれも由来する単語
   (または隣接2単語間)の窓を共有する(手順5)。窓は内容認識モデル自身が返す単語タイムスタンプ
   (手順3)に基づき単語ごとに個別のため、フレーズ内の語順・語長の違いに追従でき、句全体を単一の
   均等割り当てへ押し込む下記フォールバックより、実際の発声位置への近さを保てる(下記「単語窓
   制約の余白の決定」の実測で確認済み)。**開始・終端条件**: フレーム0は状態0(先頭トークン)に
   固定する(他の状態は到達不能として除外する)。最終フレーム T-1 では状態 L-1(末尾トークン)に
   **到達している経路の中で**最尤のものを採る(未到達の経路は採らない)。
   **早期遷移ボーナス**: 単語窓制約は「窓内のどこでもよい」というハード制約のみで窓内の位置選好を
   持たないため、blank優勢の歌唱では手順7の有声フレームのblank抑制だけでは覆いきれず、窓の遅い側
   (上端寄り)へ配置が偏ることが実測で確認された(有声区間が長く続く場合、blankに留まり続ける
   経路の対数確率は有声抑制ぶんが引かれるだけで、それ以上の不利が無いため)。この偏りを抑えるため、
   状態 `l` の対数確率に、その状態の窓内での相対位置 `rel = (t*0.02 - lo) / (hi - lo)`(0〜1に
   クランプ)に応じた加算項 `2.0 * (1 - rel)` を加える(窓の下端で最大2.0、上端で0。ハード制約
   である到達可能フレームの範囲は変えない)。局所適応(前掲)を用いた構成のうち、早期遷移ボーナスを
   含まない構成と含む構成を比較すると、参照ラベル付き歌唱コーパス(9.1)のマクロ平均で母音開始時刻
   誤差の中央値は約95ms→約92msへ、95パーセンタイルは約409ms→約373msへ縮小し、参照ラベルとの
   母音一致率に退行は無かった(実測で確認済み)。加えて、単語窓制約のみでは残る「有声区間が
   長く続く単語の直前で、窓の遅い側まで配置が押し込まれる」個別の不具合事例(内容認識モデル自身の
   単語タイムスタンプに対し、VMDの30fpsフレーム換算で実測約22フレーム=0.74秒遅れていたもの)は、
   早期遷移ボーナスを含む構成でVMDの30fpsフレーム換算で約6〜9フレーム(約0.2〜0.3秒)の差まで
   縮小することを確認した。値(加算項の最大値2.0)を変える場合は本書を先に更新する。
   **フォールバック(位置バンド制限)**: 次の**いずれか**に該当する場合、単語窓制約を使わず、
   この位置バンド制限で整列する(書き起こしが空文字列の区間は手順3でgap確定済みのため、
   ここには到達しない): **(i)** 手順3で単語タイムスタンプが取得できなかった場合、**(ii)** 単語窓
   制約の下で最終フレームに到達する経路が無い場合(窓の対応付け自体は行ったが整列が破綻した場合)。
   状態 `l` の**期待フレーム位置**を
   `(l / (L-1)) * (T-1)`(サブ状態展開後の状態列全体を入力範囲内へ均等割り当てした場合の位置。L は
   サブ状態展開後の状態数。L=1 なら0)とし、フレーム `t` が状態 `l` に遷移できるのは
   `|t - 期待フレーム位置| <= バンド幅` を満たす場合に限る。バンド幅は **1.0秒に相当するフレーム数**
   で固定する(blank 支配下でも均等割り当てから大きく外れた押し込み崩壊を構造的に防ぐ。9章の測定で
   確認済み)。これにより、既知の音素列全体を手順2でトリムした入力範囲の全時間軸へ過不足なく
   対応付ける(トークン列の要素数と入力範囲の長さの兼ね合い、または単語窓制約・バンド制限の
   いずれでも理論上到達不能な場合を除く。この場合は `RecognitionError` で停止する)。

   **単語窓制約の余白の決定**: 余白は、参照ラベル付き歌唱コーパス(9.1)を用いた時刻精度の
   開発時比較(9章のS-1測定とは別の指標を使う。**参照ラベルとの母音一致率**: 予測のSegment列と
   参照ラベルを母音種別列の編集距離で対応付け、対応した母音のうち種別が一致した割合。9.4の
   母音正解率とは算出方法が異なる開発時比較指標であり、9章のS-1測定の代わりにはならない)で、
   0.2秒・0.5秒・0.75秒の3値を比較し、0.75秒が最も母音開始時刻誤差を抑えた(参照ラベルとの母音
   一致率は3値でほぼ同等)ため採用した。位置バンド制限のみの構成と比べ、
   同じ測定データで母音開始時刻誤差の中央値は平均約472ms→約116msへ、95パーセンタイルは平均約
   1104ms→約485msへ縮小した(参照ラベルとの母音一致率は平均約87%→約88%でほぼ同等)。値を変える
   場合は本書を先に更新する。
8. **区間内の区切りの確定**: 各トークンの区切りは「そのトークン自身の状態が最尤経路上で最初に現れる
   フレーム」から「次のトークンの状態が最尤経路上で最初に現れるフレーム」まで(最後のトークンは
   トリムした入力範囲の終端まで)とする。隣接する区切りが同一の出力記号(次項の写像後の記号。`pau`・`cl`
   由来はいずれも blank 扱いで同一視する)を持つ場合は1つへ結合する。結果は手順2でトリムした入力範囲の
   全時間軸を重複・欠落なく被覆する(状態機械がその範囲内の全フレームをちょうど1つの状態へ割り当てるため)。
9. **Segment化と結合**: `pau`・`cl` 由来の区切り(blank 扱い)は `type="gap"`・`phoneme=None`。それ以外は
   5.1 の母音/子音判定基準(IPA母音チャート)を写像後の記号へ適用し `type` を定め、`phoneme` にその記号を
   入れる。`confidence` は算出せず常に `None`。手順1で分割した各区間(手順2で無音確定した区間・手順2の
   トリムで gap 確定した先頭・末尾・手順3で書き起こしが空文字列のため gap 確定した区間・手順4の
   音素密度で gap 確定した区間を含む)の Segment列を時刻順に
   連結し、隣接する同一 `type`・同一
   `phoneme` のSegment(区間境界をまたいで隣接するgap同士など)は1つへ融合して、ボーカルWAV全体の
   時間軸を重複・欠落なく被覆する1本のSegment列とする。

**G2P記号→音素モデル語彙の写像表(確定)**: `pyopenjtalk-plus` の音素記号のうち母音・子音36種(無声化母音
`I`/`U` を含む)を、8.3で固定した音素モデルの語彙(espeak表記)へ1対1で対応付ける。母音の無声化(`I`→`i`,

**既知の限界(歌唱でのフレーズ内時刻ずれ)**: 音素モデル(8.3)の放出は歌唱でblankが支配的になり
(実測では、時刻ずれが観測されたフレーズのほぼ全フレームがblank確率0.98〜1.00で、非blankの
スパイクは76フレーム中3つ)、個々の音素の時刻を裏付ける音響証拠が乏しい。手順2のトリム・手順7の
有声blank抑制・最小滞在(単語ごとの局所適応を含む)・単語窓制約・早期遷移ボーナスは、モーラ長の
下限を保証し、フレーズ先頭・フレーズ内部いずれの時刻ずれも実測で抑える(早期遷移ボーナスを含む
構成での母音開始時刻誤差は、参照ラベル付き歌唱コーパスのマクロ平均で中央値約92ms・95パーセンタイル約
373ms。手順7)。ただし単語窓制約は内容認識モデル自身が返す単語タイムスタンプの精度に依存するため、
フレーズ内部の位置ずれが完全に無くなるわけではない。**次の緩和策は実測で効果が無いことを確認済みで、
再試行しない**: (a) アライメント区間ごとにCTC確率(日本語5母音に限定した区間平均確率)で母音記号を
上書きする方式は、人手作成のリップシンクVMDを参照とした母音一致の開発時比較(9章のS-1測定とは別)を
悪化させた(blank以外の確率
質量は歌唱では残差ノイズで、母音種別の信号にならない)。(b) 書き起こしの語境界(空白)に `pau` を
挿入して息継ぎをアンカーする方式(内容認識モデル自身の単語タイムスタンプではなく、書き起こし
テキストの空白から機械的に単語境界を推定する方式)は、フレーズ内の時刻を改善しなかった(挿入した
`pau` は無音の谷には吸着するが、その間の有声区間内の音素位置には依然として証拠が無く、時刻の
矯正力を持たない。息継ぎ区間を無音として検出する効果自体はあり、副作用も観測されていないため、
無音化目的での採用は妨げない)。(c) 強制アライメント用の音素モデル自体を、語彙をひらがな単位に
持つ既製の日本語かな認識CTCモデルへ差し替える方式は、参照ラベルとの母音一致率(手順7「単語窓制約
の余白の決定」で定義)が現行構成の平均87%から71%へ悪化した(時刻誤差の一部指標は改善したが、
母音種別自体の識別精度が現行の音素モデル+G2Pの組み合わせを下回った)。(d) 有声フレームのblank
抑制ペナルティ(手順7)を強化する(7→10→15)方式は、密集した歌詞区間の特定の実例では改善したが、
参照ラベル付き歌唱コーパスのマクロ平均では母音開始時刻誤差が悪化した(中央値約95ms→約103ms→
約107ms)。ペナルティは元々別の目的(フレーズ先頭の遅延抑制)で校正した値であり、増強は特定の
実例以外の区間で過剰な早期遷移を誘発する副作用が優った。(e) 利用先の口形イベント確定処理での
RMSオンセット補正の探索窓を、直前の母音的口形が一定時間(0.25秒)を超えて長い場合にだけ拡張する
方式は、全曲でのモーフキー比較により、実際に長く伸ばして歌っている正当な長母音(1秒近く持続する
実例を含む)を、探索窓の拡張が誤って別の母音の立ち上がりと取り違え、当該母音をほぼ消失させる
実測済みの重大な副作用を持つことが確認された(直前の母音が長いこと自体は、blank支配による
未検出区間と正当な長音発声を区別する手がかりにならない)。(a)〜(e)と異なり、手順7の単語窓制約・
早期遷移ボーナスは書き起こしの文字列や別モデルへの差し替え、既存の校正値の変更、直前区間の長さの
みに基づく推測のいずれでもなく、**現行構成の内容認識モデル自身が内部的に持つ時刻情報(単語
タイムスタンプ)とその窓内での一様な早期側選好**を強制アライメントの制約に転用するため、上記の
失敗の機構(残差ノイズ・矯正力の欠如・母音識別精度の悪化・他区間への副作用・正当な長音の誤検出)の
いずれも当てはまらず、実測で有効性を確認できた(採用済み)。残る約373ms(95パーセンタイル)規模の
位置ずれは、単語窓制約が内容認識モデル自身の単語タイムスタンプ精度に依存する構造に起因する。
さらなる低減には、単語タイムスタンプ自体の精度向上(内容認識モデル側)、または歌唱で音素証拠を
出せる音響モデル/アライナーへの差し替え(強制アライメント側)のいずれかを検討する余地があり、
候補は9章の測定(参照ラベル付き歌唱データによる時刻精度の比較)で評価してから採用する。

### 5.3 SOFA経路: 単語単位アライメント

本節は`forced_aligner="sofa-forcedalign"`(8.1・8.2・8.3)を選んだ場合の強制アライメント段を定める。
内容認識・G2P(5.2手順1〜4)は経路共通のまま変更しない。**利用者は`SofaAlignerConfig`(8.3)で
SOFA実行環境(専用Python実行ファイル・SOFAリポジトリのルート・チェックポイント)を指定する必要が
あり、本モジュールはこれらの既定値・同梱チェックポイントを一切持たない**(8.3のライセンス方針)。
`sofa_aligner`省略時(`None`)は`RecognitionError`にする(§5本文)。

- **単語単位アライメント(確定)**: SOFAの強制アライメントは、5.2手順7の単語窓制約(内容認識が返す
  単語ごとの時刻範囲に余白(マージン)0.75秒を加えた到達可能フレーム範囲で、強制アライメントの状態
  遷移を制約する仕組み)に相当する外部からの時間的制約注入を持たない。区間全体を
  一括でSOFAへ渡すと、歌唱表現(メリスマ・崩れた発音)がある箇所で音素境界が単語の意味的区切りと
  無関係な位置にずれる。そこで、5.2手順3で単語タイムスタンプが取得できた区間では、**単語ごとに
  音声チャンクを`[単語開始秒, 単語終了秒)`で切り出し、その単語のG2P結果(音素記号列)とペアにして
  個別にSOFAへ渡す**(1回の`recognize()`呼び出しの中で、対象区間・対象単語全体をまとめてSOFAへ
  一括処理させる。1曲あたりSOFA呼び出しが複数回になる場合(長尺曲の分割処理)があっても、この
  単語単位分割自体は各回の入力内で同じ規則を適用する)。単語タイムスタンプが取得できなかった区間
  (5.2手順3のフォールバック対象)は、区間全体を1つのSOFA対象とする(単語窓制約が無い場合の
  wav2vec2経路と同じフォールバック)。
- **有効な単語列の確定(SOFA経路専用の追加サニタイズ)**: 5.2手順3の単語タイムスタンプ単調化は
  開始時刻を「直前の単語の開始時刻以上」にクランプするに留まり、ある単語の終了時刻が次の単語の
  開始時刻を超える重複を解消しない。wav2vec2経路はこの重複があっても、単語窓は音声全体に対する
  単一のアライメント計算における状態遷移可能フレームの制約であって音声を物理的に分割しないため
  実害が無いが、SOFA経路は各単語の音声チャンクを物理的に切り出すため、重複があると同じ音声
  区間が2つの単語チャンクへ二重に含まれ、Segment契約(2章・8.1「隙間なく連続・非重複で全時間軸を
  被覆」)を破る。これを防ぐため、単語列の先頭から末尾へ次の**cursorベースの逐次クランプ**を1回
  だけ適用し、「有効な単語列」を確定する: (1) 各単語の終了時刻をトリム後区間の全長以下へ再クランプ
  する。(2) `cursor`をトリム後区間の先頭(相対時刻`0.0`)で初期化し、単語を時系列順に処理する。
  各単語の開始時刻を`max(元の開始時刻, cursor)`へクランプし、クランプ後の区間長が5.2手順3の最小
  単語長未満(ゼロ・負長を含む)、または当該単語の音素記号列(5.2手順4のG2P結果)が空の場合は、
  その単語を無効とし(`cursor`は更新せず、次の単語も同じ`cursor`を基準にクランプする)、
  そうでなければ有効として`cursor`をそのクランプ後の終了時刻へ更新する。この
  `cursor`は「これまでに確定した有効な単語チャンクの終端」を表すため、無効化された単語を何個挟んでも、
  次に処理する単語は常にこの`cursor`を下限にクランプされ、確定済みの単語チャンクと重複しない。
- **gapの確定**: SOFA対象として個別に音声チャンクを渡すのは「有効な単語列」だけである。gapは、
  この有効な単語列を時系列順に並べたときの隙間(先頭から最初の有効単語まで・有効単語同士の間・
  最後の有効単語からトリム後区間の終端まで)に対してのみ確定する。無効化された単語の元の時間範囲が
  隣接する有効単語に完全に包含される場合は、その範囲は既に有効単語の結果に含まれているため、個別の
  gap Segmentを重ねて生成しない(Segment契約の非重複性を保つ)。単語タイムスタンプ自体は取得できたが
  全ての単語が上記(2)の判定により無効化され「有効な単語列」が0件になった場合は、トリム後
  区間全体を単一のgap Segmentとして確定する(5.2手順3の空文字列判定・手順4の音素密度判定と同じ
  「強制アライメントを試みず区間全体をgap確定する」パターンに揃える)。
- **SOFA対象が0件の場合**: 無音・空の書き起こし・幻覚判定(5.2手順2〜4)や上記の有効な単語列0件が
  重なり、渡された音声全体でSOFAへ渡す区間・単語が1つも無い場合、SOFAサブプロセスの起動自体を省略し、
  既に確定済みのgap Segmentだけから成るSegment列をそのまま返す。
- **AP/SPラベルの扱い**: SOFAは`force`モードでも、与えた音素記号列に含まれない"AP"(吸気音・呼吸音)
  ラベルを後処理で追加挿入することがある。APは無音ではないが、本モジュールの母音/子音/gapの3分類
  (8.1のRecognizer契約)に「呼吸音」の区分は無いため、母音・子音のどちらとも判定できないものとして
  gap側へ倒す(閉口/無音と同一視するのではなく、3分類インベントリ外の音響イベントを利用先のRMS
  解決へ委ねる扱い)。SOFA自身の学習データ形式にある"SP"(無音)も同様にgap相当として扱う。
- **音素記号の写像**: SOFAへ渡す音素記号列・SOFAが返す音素記号列は、G2P(5.2手順4)が出力するのと
  同じ記号系(pyopenjtalk-plus由来。AP/SP挿入を除く)を基本とする。ただし、SOFA自身の語彙(チェック
  ポイント学習時の音素セット)は無声化母音の専用記号を持たず通常の母音記号(i/u)のみを認識するため、
  SOFAへ渡す直前に無声化マーカーI→i・U→uへ正規化する(5.2手順6の「G2P記号→音素モデル語彙の写像表」
  が元々I→i・U→ɯのIPA記号へ集約している対応関係と同じであり、正規化してもSegmentの最終的な
  phoneme値には影響しない)。7.1のespeak IPA→5母音写像・5.1の母音/子音判定基準はいずれもIPA記号を
  前提にするため、SOFA出力を`Segment`へ入れる前に、5.2手順6の「G2P記号→音素モデル語彙の写像表」と
  同じ写像規則でIPA記号へ変換する(wav2vec2経路とSOFA経路は同じ写像表を共有し、独自の表を新設
  しない)。写像表に無い記号が来た場合は黙って捨てず`RecognitionError`にする(5.2手順6と同じ方針)。
  両経路とも同じ`Segment`型を返すため、利用先はどちらのアライナーが使われたかを意識しない。
- **失敗契約(外部プロセス境界。確定)**: SOFAサブプロセスの終了コードが0であることだけを成功の条件に
  せず、出力ファイルの存在・非空も検証する(黙って空のSegment列を返さない)。`SofaAlignerConfig`の
  `timeout_sec`(8.3)を超えて完了しない場合、およびサブプロセスが異常終了した場合は、いずれも
  `RecognitionError`にする(黙って劣化させず、原因が特定できるエラーで失敗させる。
  cli-interface.md §10の外部プロセス連携の例外規定が要求する「失敗時の挙動の明記」に対応する)。
- **相対パスの絶対化(確定)**: `SofaAlignerConfig`の`sofa_python`・`sofa_root`・`checkpoint_path`
  (いずれも8.3)が相対パスで与えられた場合、呼び出し時のプロセスの作業ディレクトリ基準で絶対化して
  から、起動前検証(実在検証・非ASCIIパスの拒否)とサブプロセス起動に使う。SOFAサブプロセスは
  作業ディレクトリを`sofa_root`にして動くため、相対パスをそのまま渡すと、起動前検証(呼び出し元の
  作業ディレクトリ基準)と実行時(`sofa_root`基準)で解決先が食い違い、検証を通過したパスが実行時に
  見つからない失敗になる——絶対化はこの食い違いを断つ。
- **非ASCIIパスの拒否(確定)**: SOFAサブプロセスに渡す一時ディレクトリの絶対パス・`sofa_root`・
  `checkpoint_path`(いずれも8.3)のいずれかに非ASCII文字が含まれる場合は、SOFAを起動せず
  `RecognitionError`にする(SOFA自身が非ASCIIパスを扱えない技術的制約による。cli-interface.md §10の
  外部プロセス連携の例外規定に基づく)。判定は上記の絶対化後のパスに対して行う。
- **時刻の変換**: SOFAのHTK出力は100ナノ秒単位の整数値であり、`start_sec = 値 / 1e7`で秒へ変換する
  (5.1「フレーム時間」)。
- **Segment契約の検証(確定)**: パース後のSegment列が2章・8.1のSegment契約(隙間なく連続・非重複で
  全時間軸を被覆)を満たすか、次の4点を検証し、いずれか1点でも満たさなければ`RecognitionError`にする:
  (a) 各セグメント自身の開始時刻が終了時刻以前、(b) 隣接するセグメントの終了時刻と次の開始時刻が
  一致、(c) 先頭セグメントの開始時刻がトリム後区間の先頭(`0.0`)と一致、(d) 末尾セグメントの終了時刻が
  トリム後区間の全長と一致。(b)(c)(d)の一致判定は許容誤差50ミリ秒以内の絶対差で行う(SOFAの100ナノ秒
  整数からの変換誤差の経路がトリム後区間の全長の算出経路と異なるため、浮動小数点の完全一致を要求
  しない。加えて、SOFAはチェックポイントの学習時サンプルレートへ入力音声を内部でリサンプリングして
  から音声全長を再計算するため、この内部リサンプリングに起因する丸め誤差が末尾時刻に数ミリ秒〜
  十数ミリ秒規模で生じうる。境界値が実装依存の量子化点に一致する場合にこの丸め誤差が拡大する
  ケースも実測で確認されており、実測で観測された最大値に対して十分な余裕を持たせた値として
  50ミリ秒に確定した)。検証を通過したSegment列は、返す前に許容誤差を残さない厳密値へ正規化する(先頭の開始時刻を
  `0.0`へ、末尾の終了時刻をトリム後区間の全長へ、各隣接ペアの後続の開始時刻を先行の終了時刻へ
  それぞれ上書きする)。正規化後のSegment列に対し(a)〜(d)を許容誤差なしの厳密な等号/不等号で
  再検証し、1件でも満たさなければ`RecognitionError`にする(一次検証の許容誤差設定がその音声には
  不適切だったとみなし、値を調整して通さず失敗として扱う。極端に短い隣接セグメントが正規化の上書き
  により新たな逆順を生む場合がある)。
- **既知のトレードオフ(未解消)**: 単語境界はマージン無しの物理的な音声チャンク境界のため、wav2vec2
  経路の余白(マージン)付き到達可能窓(5.2手順7「単語窓制約の余白の決定」。窓の外側0.75秒分まで
  状態遷移を許す制約)より、単語境界での協調調音・語尾の伸びを吸収する柔軟性が低い。単語境界を
  またぐ発声がある箇所で、実際には有声の区間を誤って
  gap確定してしまう副作用が実データ検証で確認されている。SOFA経路は15ms未満の極端に短い音素
  セグメントをwav2vec2経路より多く出力する傾向もある(利用先の後処理(同母音連結・最小保持フレーム)
  である程度吸収されるが、完全に無害とは確認できていない)。品質を懸念する利用者は既定の
  wav2vec2経路を使い続けられる。

## 6. 強弱エンベロープ(S3)

- ボーカルWAVのRMSエンベロープを `numpy/scipy` で算出する。外部ツールに依存しない。公開関数は
  `compute_rms(pcm: AudioPcm) -> RmsEnvelope`(`vocal_analysis.rms`)。
- **相対正規化**: 絶対音量を直接値へ変換せず、曲またはフレーズ内の相対強度へ正規化する。正規化は外れ値の
  影響を抑えたパーセンタイル範囲を使い、瞬間的なピークを除外する。ミックスの音量差で結果が変わらないように
  する(入力ゲインに不変)。絶対レベルのしきい値は使わない。
- RMS を使う判断(無音/閉口判定のヒステリシス、低ダイナミクス曲での閉口抑制、モーラ代表RMSによる開き量、
  低信頼区間の扱い)は利用先(リップモーション生成系の入口)に残る。`vocal_analysis` は相対正規化したRMSを共有出力として
  渡すところまでを担う。

### 6.1 RMS算出(確定)

- **フレーム化**: フレーム長 **25ms**・ホップ **10ms** を対象サンプルレートでサンプル数へ換算(`round()`)し、
  時刻0から信号長を超えない範囲でホップ幅ずつずらしてフレームを生成する(末尾の不完全フレームは切り捨て、
  ゼロ詰めしない)。信号長がフレーム長未満でフレームが1つも取れない場合は、`times_sec`・`values` を空配列、
  `dynamic_range_db` を `0.0` とする(算出不能をエラーにせず空の結果で表す)。フレーム中心時刻(`times_sec`)は
  `フレーム開始時刻 + フレーム長/2`。ボーカルWAVが複数チャンネルの場合、フレーム内の全チャンネル・全サンプル
  をまとめて二乗平均平方根(RMS)を取る(3章のピーク正規化と同じ全チャンネル・全フレームの扱いに揃え、
  チャンネルごとの独立計算・平均はしない)。
- **パーセンタイルの補間方式**: `p10`・`p90`・`p5`・`p95` はいずれも線形補間(`numpy.percentile` 既定の
  `method="linear"`)で算出する。
- **曲全体**のフレームRMSから 10パーセンタイル `p10`・90パーセンタイル `p90` を取り、各フレームを
  `values = clip((rms - p10) / (p90 - p10), 0.0, 1.0)` で正規化する(`p10`→0・`p90`→1、範囲外はクリップで
  外れ値を除外)。`p90 == p10`(無音・定常)は0除算を避け全フレーム 0.0。差の比なので入力ゲインに不変。
- 共有出力には相対正規化したRMS(`values`)と、曲全体の `dynamic_range_db`(95/5 パーセンタイル RMS の dB 差。
  ゲイン不変)を渡す(`dynamic_range_db` は正規化済み値からは復元できないため別に持たせる。利用先の低
  ダイナミクス抑制がしきい値判定に使う)。
- **`dynamic_range_db` の算出**: 曲全体のフレームRMSから 5パーセンタイル `p5`・95パーセンタイル `p95` を取り、
  `dynamic_range_db = 20 * log10(p95 / p5)`(RMS は振幅なので 20*log10)。線形補間で得た `p95` の値自体が
  `0`(比の基準が無い)場合は比が定義できないため `dynamic_range_db = 0.0` とする。`p95 > 0` かつ `p5 == 0`
  の場合は 0除算・log(0) を避け、`p5` を `p95 * 1e-6` に置き換えて算出する(`p95` に対する相対フロアなので
  入力ゲインに不変のまま保たれる)。

## 7. 音素→5母音写像

認識器・vpr が返す音素記号を日本語の5母音 a/i/u/e/o へ写像する規則を提供する。系統の違う**2つの入力記号系**を
扱うため写像も2つに分ける。いずれも**複数CLIが共有するドメインロジック**なので共有ドメイン層の本モジュールに置く([../../docs/conventions/layering.md](../../docs/conventions/layering.md) §1。特定のCLIツール内に置かない)。

### 7.1 espeak IPA → 5母音(S2出力用)

- wav2vec2(espeak音素)が返す母音セグメントの IPA を5母音へ**完全一致のテーブル参照**でバケット化する
  (a/ɑ/ʌ/æ→あ、i/ɪ/j→い、ɯ/u/ʊ/w→う、e/e̞/ɛ→え、o/o̞/ɔ→お)。公開関数は
  `espeak_ipa_to_vowel(symbol: str) -> str | None`(`vocal_analysis.phonemes`。マッチすれば母音文字
  a/i/u/e/o、テーブルに無ければ None)。テーブルは**採用認識器の音素インベントリ
  (espeak)から S-1測定の採点前に確定・固定**する(測定データの出力を見てからの変更は §9 の比較条件の規定で禁止。
  写像表は採点規則の一部)。テーブルは認識器が出力する母音IPAを網羅するよう作り、取りこぼしを表の網羅で防ぐ。
- **テーブルに無い母音IPA・判定不能なラベルはいずれも gap とする**(「最近接」のような曖昧な距離判定は使わず
  決定論的に。安全側=誤った母音を立てない)。この gap フォールバックは想定外ラベル向けの稀な経路で、S-1測定
  では gap は母音不一致として数える(=取りこぼしは表の網羅で防ぐ前提)。
- この写像は **S-1測定の採点**と **リップモーション生成系の口形イベント確定**の双方が同一規則で使う。母音/子音の判別は
  アダプタ(S2)側で済んでいるため、写像は母音セグメントのIPAを5母音へバケット化するだけで再分類しない。
  **閉鎖(両唇音)判定や無音/閉口の確定は写像に含めない**(利用先の入口処理)。
- **`forced_aligner`の選択(8.1・8.2)に関わらず不変**: SOFA経路(5.3)もwav2vec2 CTC経路(5.2)と同じ
  espeak IPA記号を`Segment.phoneme`へ入れるため、本節の写像表はどちらの経路にもそのまま適用でき、
  経路ごとに表を分けない。

### 7.2 VOCALOID(X-SAMPA)→母音/カテゴリ(vpr由来ラベル生成用)

- vpr の音素は **espeak IPA ではなく VOCALOID の X-SAMPA 表記**であり、7.1 の IPA 表は適用できない。S-1測定の
  参照ラベルに vpr由来のものを使う場合(9章)は、VOCALOID 日本語の音素インベントリ(X-SAMPA)から確定した、
  X-SAMPA を母音(a/i/u/e/o)・子音(c)・休符(sil)へ写像する別系統の規則を使う。
- この X-SAMPA→母音/カテゴリ写像も**共有モジュールが提供**し、vpr を読む CLI と S-1測定が同一規則で使う(写像表の
  二重管理を避ける)。公開関数は `xsampa_vowel_letter(symbol: str) -> str | None`(`vocal_analysis.phonemes`。
  母音記号テーブルに一致すれば母音文字 a/i/u/e/o、一致しなければ None)。母音記号テーブルに無い記号(子音・
  vpr の継続記号「-」等)を子音 c・休符 sil へ確定する処理は、この写像の外側(vpr由来ラベルを使う場合の
  生成側。9章)が文脈(直前音符の継承等)を見て行う。

## 8. 外部ツール連携機構

利用者に外部コマンドを叩かせず、各委譲ステージはアダプタinterfaceと正規化中間形式で疎結合にし、あとで
差し替え可能にする。詳細な候補比較は [external-tools.md](external-tools.md) を補助資料とし、本書を正本とする。

### 8.1 アダプタinterface

- **Separator**: `separate(vocal_source, mode, *, on_progress) -> vocal_wav_path`(内部でライブラリ/
  サブプロセスを呼ぶ)。出力は「ボーカルWAVのパス」だけを約束し、内部のライブラリ・モデル・分離
  トラック構成・一時ファイルは各実装に閉じる。`mode`(`always`/`never`)もこの抽象が解釈する。
  `on_progress`(進捗通知)はキーワード専用の省略可能引数(既定`None`)で、Recognizer の同名引数と
  基本契約(実際にネットワークダウンロードを要した区間だけ進捗文言を渡して呼ぶ)は同じだが、
  文言の内訳は委譲先ライブラリの取得単位に従う: Recognizer 側はモデル1件ぶんの取得を単一の割合で
  示すのに対し、Separator 側(audio-separator)はモデルが複数ファイルで構成される場合、ファイルごとに
  実ファイル名付きで 0%→100% を示す(1モデルの取得中に複数回の 0%→100% サイクルが起こりうる)。
  Separator 側はさらに、モデルのロード開始時(ダウンロードの有無に関わらず、キャッシュ済みで
  ディスクから読み込むだけの場合を含む)に`f"モデル読み込み中: {ファイル名}"`を1回呼び、ロードが
  完了するまでの区間(ダウンロードが発生すればその間は上記の取得済み割合の文言で上書きされる)を
  空白にしない。加えて、モデル取得後の分離処理(Demucs推論)が実際に進行している区間でも、
  ダウンロードの有無に関わらず進捗文言(`f"分離中: {percent}%"`)を都度渡して呼ぶ。
- **Recognizer**: `recognize(vocal_wav_path, content_recognizer_model, *, retry, forced_aligner, sofa_aligner,
  english_katakana_method, on_progress) -> [Segment{type, start_sec, end_sec, phoneme?, confidence?}]`
  (文字列なしの音素認識)。
  `content_recognizer_model`(`ContentRecognizerModel`。5.2・8.3)は既定値を持つ省略可能引数。
  `retry`(内容認識のトリガ式リトライの有効/無効。`bool`。既定`True`。5.2)はキーワード専用の
  省略可能引数。`forced_aligner`(強制アライメント段の選択。`ForcedAlignerId`。既定
  `wav2vec2-ctc-forcedalign`。5.2・5.3・8.2・8.3)はキーワード専用の省略可能引数で、
  `forced_aligner="sofa-forcedalign"`を選ぶときのみ`sofa_aligner`(`SofaAlignerConfig`。8.3)が
  必須になる(それ以外では無視する)。`english_katakana_method`(英語カタカナ化
  フォールバックの変換方式選択。`EnglishKatakanaMethod`。既定`arpakana`。5.2手順4)は
  キーワード専用の省略可能引数。`on_progress`(モデル初回取得の進捗通知。5章)もキーワード専用の
  省略可能引数(既定`None`)。
  `type` は **母音/子音/gap** の3種で、出力は全時間軸を重複・欠落なく被覆する。
  アダプタは言語非依存の音素分割(母音/子音/gap)までに責務を限定し、RMS を必要としない(IPA→母音写像の
  適用・無音/閉口確定は利用先)。この契約(引数・戻り値の型・責務範囲)は`forced_aligner`の選択に
  関わらず不変。
- **標準エラーへの出力の抑制**: 各アダプタは委譲先ライブラリ(audio-separator/Demucs・transformers・
  huggingface_hub・tqdm等)自身のログ・進捗バーを抑制し、標準エラーは呼び出し側の進捗表示にのみ
  使わせる。抑制はプロセス内で一度行えば以後も有効な広域設定(ログレベル・tqdmの既定disable化)で、
  `separate`/`recognize`系の初回呼び出し時に適用する。pyopenjtalk(open_jtalk)のネイティブ拡張が
  発する警告はPython側のログ設定を経由しないため、該当呼び出しをOSレベルで一時的に標準エラーを
  抑える形で個別に囲む(SOFA経路はサブプロセスの出力を`communicate()`で完全キャプチャし成功時は
  捨てるため、この抑制の対象外)。このOSレベル抑制(`vocal_analysis.quiet.suppress_native_stderr`)は
  標準エラーのfdを一時的に差し替えるため、呼び出し元(利用先)が別スレッドから同じ標準エラーへ書く
  場合(進捗表示のライブ更新等)は、同モジュールが公開する`STDERR_WRITE_LOCK`を取ってから書く必要が
  ある(取らずに書くと、実コンソール環境でOS由来の書き込み失敗が起こりうる)。

### 8.2 アダプタの登録と選択

- 各ステージの採用ツール(**既定アダプタ**)は 8.3 の表を正本とする。アダプタを追加・変更する場合は
  本書(8.3)を先に更新する。
- 中核はアダプタinterface(8.1)と正規化中間形式(2章)だけに依存し、特定の外部ツールに依存しない。
  差し替えはアダプタの実装追加だけで行える構造とする。
- 各アダプタは、利用先 CLI がバックエンド選択引数の値・既定値・選択肢(自己記述)に使う**安定 id**
  (小文字・ハイフン区切り)を持つ。現行の id は 8.3 の表のとおり(S1 `audio-separator-htdemucs-ft`・
  S2 `wav2vec2-ctc-forcedalign`・`sofa-forcedalign`)。S2 の内容認識モデルは id ではなく
  `content_recognizer_model` 引数(`ContentRecognizerModel`。5.2)で選ぶ。
- 同一ステージに複数のアダプタがあるときは、引数で適用ツールを選択可能にする(選択肢の公開は利用先
  CLIが行う)。アダプタと id の追加・変更は本書(8.3)を先に更新する。**S2は複数アダプタを持つステージで
  あり(`forced_aligner`引数。8.1)、S1の分離モード(`always`/`never`。4章)とは異なり、同一ステージ
  内で複数の実装(強制アライメント手法)から選ぶパターンにあたる。**

### 8.3 採用ツールと代替候補

| ステージ | 採用ツール | 主な採用理由 | 代替候補 |
|---|---|---|---|
| S0 入力読み込み | soundfile(現行 libsndfile は mp3 も可)優先 + 自動検出ffmpegへフォールバック(リポジトリに同梱しない) | 標準入出力を内部処理。soundfileで読めない形式のみffmpeg。ffmpegを再配布せずライセンス義務を避ける | —(imageio-ffmpeg 等は不採用) |
| S1 ボーカル抽出 | Demucs v4 htdemucs_ft を audio-separator 経由で実行(アダプタ id: `audio-separator-htdemucs-ft`。shift平均(複数回の追加フォワードパスを伴う)を無効化する設定で既定の分離処理を軽くする) | 高品質・MIT・ライブラリでin-process呼び出し可・GPU不要でも動作。生 `demucs.api`(adefossez fork)は `torchaudio<2.2` 固定で新しい Python(3.13等)向けビルドが無く採用しない(§8.3後注) | audio-separator の他モデル(MDXC系Roformer等。ライセンス個別確認要) / Spleeter / 分離なし(`never`) |
| S2 音素/母音認識(既定アダプタ) | 複合構成(内容認識 + `pyopenjtalk-plus` G2P + 音素モデルの CTC 強制アライメント。5.2。アダプタ id: `wav2vec2-ctc-forcedalign`)。内容認識モデルは `content_recognizer_model` 引数で指定する(既定値 `openai/whisper-medium`・任意指定も可。5.2)。**単段の自由音素認識(`wav2vec2-espeak`)は歌唱で母音をほぼ出力しないことが S-1 測定で確認済みのため不採用**([external-tools.md](external-tools.md) §2) | すべて純Pythonでin-process・torch/transformersは既存と共有・ライセンス清浄。内容認識モデルの選定理由は [external-tools.md](external-tools.md) §2 を正とする | Julius 音素認識(phone-loop構成が必要・高精度時刻)。Allosaurusは GPL-3.0 で不可。`kana-whisper`(常にかなを返す)は任意指定で利用可能であり、名前付き定数としては提供しない |
| S2 音素/母音認識(選択制アダプタ) | 内容認識+G2Pは既定アダプタと共通、強制アライメント段をSOFA(Singing-Oriented Forced Aligner。MIT)の単語単位アライメントへ置き換える構成(5.3。アダプタ id: `sofa-forcedalign`。`forced_aligner="sofa-forcedalign"`で選択)。利用者提供の専用Python実行環境・SOFAリポジトリ・チェックポイント(`SofaAlignerConfig`。下記補足)をサブプロセスとして呼ぶ | 単独指標(母音一致率・境界時刻精度)だけでは実曲のフルパイプラインを通した最終的なリップモーション品質の優劣を判定できないため、両アダプタを選択可能とし既定はwav2vec2 CTC経路のまま維持する(下記補足) | ―(SOFA自体が代替候補。単段自由CTC等は上記と同じ理由で不採用) |

採用ツールは品質・導入性の評価で見直しうる(候補比較は [external-tools.md](external-tools.md)。見直す場合は
本書を先に更新する)。**モデル本体を変えずrevisionだけを更新する場合も同様の手順を踏む**: 新しい
revisionで9章のS-1測定を実行し、現行revisionと比べて品質退行が無いことを確認してから、本書の
revision値を更新する(revisionが変わればモデルの重み・挙動が変わりうるため、事前検証を経ずに
値だけ書き換えない)。重い依存(`torch`・`transformers`・
`pyopenjtalk-plus`・モデル取得)は `vocal_analysis`
側に閉じ、本リポジトリ本体の必須依存は `numpy/scipy` のまま保つ。モデル重み(分離・認識)は各ライブラリの
標準キャッシュへ取得して使い、専用のキャッシュ機構は設けない。モデルが未キャッシュでネットワークからも
取得できない場合は、モデル取得が必要と分かるエラーで失敗する(黙って劣化させない)。

S2 の音素モデル(強制アライメント用。5.2)は `facebook/wav2vec2-lv-60-espeak-cv-ft`
(revision `ae45363bf3413b374fecd9dc8bc1df0e24c3b7f4`)に固定する。S2 の内容認識モデル(`ContentRecognizerModel`。5.2)は、既定値が `openai/whisper-medium`
(revision `abdf7c39ab9d0397620ccaea8974cc764cd0953e`)に固定する。既定値以外を指定する
場合、`model_revision` を省略すると最新リビジョンを使う(5.2)。かな限定プロンプト(5.2)の文字列は
「すべて ひらがなだけで こたえてください。かんじは つかわないでください。」に固定する。

**S1 実行ライブラリの補足**: 生 `demucs.api`(adefossez fork)は依存 `torchaudio` を `<2.2` に固定しており、
この上限を満たす `torchaudio` のビルドが無い新しい Python(3.13等)では導入できないため採用しない。
`audio-separator`(MIT)経由で同じ Demucs v4 の重み(`htdemucs_ft`。
ボーカル SDR≈10.8。`audio-separator` が示すモデル一覧の値)を、この
`torchaudio` 上限に縛られない形で in-process 実行する。ボーカル stem 以外は書き出さない設定にし
(stem名の比較は大文字小文字を区別しない)、shift平均(複数回の追加フォワードパスを伴う)を無効化する設定で既定の分離処理を軽くする。

**S2 複合構成の補足**: 無音検出による区間分割・内容認識・G2P(`pyopenjtalk-plus`)・強制アライメント
(5.2)の各段は1つの Recognizer アダプタ(id `wav2vec2-ctc-forcedalign`)としてまとめて実装し、
外部から見た契約は他の Recognizer 実装と同じ `recognize()`(8.1のRecognizer契約。引数・戻り値は
`forced_aligner`の選択に関わらず不変)のみとする(内部の中間結果(書き起こしテキスト・音素記号列・
区間境界)はアダプタ内部にとどめ、外部へ公開しない。5章)。追加依存(`transformers` のWhisper系実行・
`pyopenjtalk-plus`)は `vocal_analysis` の optional dependency に加える。

**S2 SOFA経路(`sofa-forcedalign`)の補足**: SOFA(github.com/qiuqiao/SOFA、MIT)は自由音素認識(ASR)
機能を持たない強制アライナーであり、内容認識(Whisper系)+G2Pが供給する既知の音素記号列を音声へ
時刻合わせする段(5.2手順5以降に相当)だけを置き換える(5.3)。

- **チェックポイント・実行環境は利用者提供・既定値なし(確定)**: `SofaAlignerConfig`は
  `sofa_python`(専用venvのPython実行ファイルパス)・`sofa_root`(SOFAリポジトリのルート)・
  `checkpoint_path`(SOFAチェックポイント)の3フィールドをいずれも既定値なしの必須値として持つ
  (`timeout_sec: float = 300.0`のみ既定値を持つ、SOFA呼び出し1回あたりのサブプロセスタイムアウト秒数。
  5.3の失敗契約)。本モジュールはSOFA本体のコードもチェックポイント
  (モデル重み)もいずれも同梱・配布・埋め込みしない。入手可能な日本語SOFAチェックポイントは
  商用利用が制限されているものしかなく、これを既定値にすると素の状態でツールを動かした利用者が
  制限に気づかないままライセンス違反を犯しうるため、既定値を持たない設計にした(利用者保護の
  方針判断であり、本リポジトリ自身のライセンスの都合ではない)。
- **依存分離(専用venv・サブプロセス)**: SOFAのPython依存(固定版のnumpy・librosa等)は
  `vocal_analysis`の実行環境と非互換のため、同一環境に同居させず、利用者が用意する専用venvを
  サブプロセスとして呼ぶ。
- **既定アダプタを置き換えない理由**: 参照ラベル付き歌唱コーパスでの単独比較の数値指標(母音一致率・
  境界時刻精度)だけでは、フルパイプライン(内容認識→G2P→強制アライメント→VMD生成)を通した最終的な
  リップモーション品質の優劣を判定できない(9章冒頭「リップモーションの最終品質はMMD上の視聴確認でしか判定できない」と
  同じ理由による)。数値指標上の優劣とMMD視聴確認上の優劣が常に一致するとは限らないため、採用判断を
  一方に固定せず、両アダプタを選択可能なまま維持し、既定は`wav2vec2-ctc-forcedalign`のまま変更しない
  (SOFAは利用者が用途ごとに選ぶ・比較する選択肢として提供する)。

## 9. 認識品質の測定(S-1)

S2の母音認識品質は本方式の品質を直接左右する(成立しなければ後段の製品が成立しない)。ただしリップモーションの
最終品質は MMD 上の視聴確認でしか判定できず、数値の代理指標だけで合否を確定することはできない。そこで
S-1 は合否ゲートではなく**開発時の測定手順**とする: 認識構成(認識器とその使い方。単段の自由認識に限らず、
内容認識と強制アライメントを組み合わせる複合構成等も含む)の選定・改良・差し替えの際に、参照ラベル付きの
日本語歌唱データで認識品質を測り、**構成間の相対比較**と**破綻検出**(明らかに不成立な構成の除外)に使う
(「作る」ではなく「測る」)。認識構成の最終確定と品質の合否は、利用先の実装時調整と MMD 上の視聴確認が担う。

- 測定は認識(S2)の品質を測るため、`vocal_analysis` の責務とする。採点は espeak IPA→5母音写像(7.1)を使う。
  S2 の品質はリップモーション生成系(母音)・採譜系(音素セグメント)の双方に効くため、本測定は両系統共通の品質確認で
  ある。
- **測るのは S2 の供給責務の範囲**: 後段の品質を左右する S2 の供給物は「母音の種類」「(開始)時刻」「検出の
  過不足」である(2章・8.1)。母音区間の終端(閉じ側)のタイミングと無音/閉口の確定は S2 の供給責務ではなく、
  利用先の調整可能な入口処理(RMS併用の無音/閉口判定・閉じの先行等。10章)が最終確定する。よって構成の
  比較はこの3点に対応する主指標(9.4)で行い、閉じ側の指標(過開口率)は利用先の調整設計の材料として測る。

### 9.1 測定データ

- **クリーン音源(S2単独測定用)**: 参照ラベル付きの日本語歌唱データを分離せず S2 へ直入力し、**S2(認識)単独**の
  品質を測る。男女を含む声種の幅と、マクロ平均(9.5)が意味を持つ曲数を確保する。
- **ペア(S1=分離の寄与切り分け用)**: クリーン音源のうち一部を、同一歌唱のミックス(同じボーカル＋伴奏)と
  ペア化する。「アカペラ→S2」対「ミックス→S1→S2」を比べて分離の寄与を測る(別音源どうしの差は歌唱内容・
  声質が混じり切り分けにならないため、同一歌唱で比べる)。S2単独は良いがミックス側が悪いときは分離(S1)側の
  問題として切り分ける(認識構成のせいにしない)。
- **配置**: 測定データ(著作物の楽曲音声を含む)は**リポジトリに置かない**。測定者がローカルに用意しパス指定で
  渡す(本測定は利用先CLIが公開する機能ではなく、開発時の手順のため)。
- **実行形態**: 実モデル(分離・認識)を使う測定は、ネットワーク・GPU を要さない通常の `pytest` スイートには
  含めず、開発時に手動実行する使い捨てスクリプトで行う(9.5の集計と同様)。

### 9.2 参照ラベル

- 各音声に区間ラベルを付与し**全時間軸を被覆**する。ラベルは**対象ボーカルの内容**で判定する(伴奏の有無に
  依らない): **a/i/u/e/o**(母音)・**c**(対象ボーカルの子音・非母音有声区間)・**sil**(対象ボーカルが母音も
  子音も発していない区間。伴奏・残響があっても sil)。
- **参照ラベルの扱い**: 参照ラベルは**完全な正解ではなく誤りを含みうるもの**として扱う。個別のランダムな
  誤りは多数曲のマクロ平均(9.5)で影響を抑えるが、記号が未知・時刻が無効など**ラベル自体が成立しない**
  区間は、薄めるのではなく測定対象から除く。ペアのステムとミックスは同一歌唱なので同じラベルを使う
  (ペア比較が成立する)。

### 9.3 採点対象の段階と比較条件

S-1 は S2(認識)の品質を測る。採点対象は、採用構成(8.3)の Recognizer アダプタが Segment 契約(2章・8.1)
どおりに出力する母音/子音/gap＋音素ラベルのセグメント列に、**espeak IPA→5母音写像**(7.1)を適用した
セグメント列とする(アダプタ内部の区間化規則——採用構成では複合構成の強制アライメント=5.2——を採点時に
再適用・上書きしない。RMS補正・gap解決などの利用先のRMS依存処理は**含めない**)。構成間の比較は、
各構成のモデル id・revision(8.3)を揃え、かつ同一の実行環境(同一マシン・同一のGPU可用性)で実行して
得た結果どうしを、同一の測定データ・同一の採点規則の下で比較する(実行環境が異なると実行デバイスの
自動選択(5.1)の結果や浮動小数点演算の丸め誤差の出方が変わり、条件を揃えたことにならない)。この
「同一の実行環境で実行する」は、S-1測定という開発時の作業自体が満たすべき前提であり、`vocal_analysis`
自体が製品として保証する性質ではない。

### 9.4 指標

主指標(S2の供給責務に対応する。構成の比較・破綻検出に使う):

- **母音正解率**: 採点対象セグメント列を 10ms フレームへ展開し、**基準が母音(a/i/u/e/o)のフレーム**のうち母音
  種別が一致した割合(= 一致母音フレーム / 基準が母音のフレーム)。未検出区間のフレームは不一致として数える。
- **区間の対応付け(未検出・余剰)**: 予測区間と基準区間を、母音種別が一致し**時間重なりが正(0より大)**の組に
  限り、**総重なり時間を最大化する全体最適割当**(ハンガリアン法等)で1対1対応させる。最適割当が複数あるときは、
  基準区間・予測区間をそれぞれ開始時刻昇順(同時刻なら終了時刻昇順)で番号付けし、割当を(基準番号, 予測番号)の
  組の昇順リストとして辞書式比較した最小の割当を採る。対応の無い基準は未検出、対応の無い予測は余剰とし、
  いずれも失敗側に数える。
- **境界時刻ずれ**: 対応した区間の開始時刻差 |予測 − 基準| の中央値と95パーセンタイル(ms)。対応区間が0件の
  曲は境界ずれが未定義なのでマクロ平均から除外し、その事実を測定結果に明記する(対応が取れない曲が出る
  こと自体が構成の破綻のサイン)。

参考指標(閉じ側。利用先の調整設計の材料):

- **過開口率**: 基準が c/sil のフレームのうち、予測が母音(口が開く)になったフレームの割合。母音区間が後続の
  c/sil へはみ出す度合いを表す。閉じ側のタイミングは利用先の入口処理が最終確定する(本章冒頭・10章)ため
  構成の採否には使わず、利用先の閉じ側処理(無音/閉口判定・閉じの先行)の初期値設計の材料として報告する。

### 9.5 集計

指標は**曲ごとに算出し、その曲数マクロ平均**で構成間を比較する。単一構成の数値に対する固定の合否閾値は
設けない(数値は相対比較と破綻検出に使い、品質の合否は利用先の実装時調整と MMD 上の視聴確認が担う。
本章冒頭)。マクロ平均などの集計は S-1 測定を実行する開発時の使い捨て手順が担い、`vocal_analysis` は
これを公開APIとして提供しない(測定はライブラリの公開面を増やす対象ではない。曲ごとの採点関数(9.4)
だけを公開する)。

## 10. 利用先に残る責務(含まないもの)

次は `vocal_analysis` の責務ではなく、利用先(各CLI)に残る。

- **口形イベント確定(リップモーション生成系の入口)**: 無音/閉口の確定、gap解決(RMS で無音/継続)、両唇閉鎖判定、母音境界
  のRMSオンセット補正、観測イベント規則(連続母音区間・閉鎖・無音)、口形イベント列の確定。
- **開き量の決定(リップモーション生成系の入口)**: RMS→開き量の写像、低信頼区間・低ダイナミクス曲の扱い。
- **ピッチ・音符(採譜系)**: F0ピッチ推定、音符分割、歌詞/音素対応付け。
- **形式入出力・CLI**: VMD(`vmd`)・vpr(`vpr`)の入出力、CLI引数・プリセット。
