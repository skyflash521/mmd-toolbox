# cli_options 仕様書

CLI ツールの引数検証と自己記述の制約公開を、同一の定義から導くための共有基盤ライブラリ。

層: **共有ドメイン層**([../../docs/conventions/layering.md §1](../../docs/conventions/layering.md#1-層タクソノミー))。複数の CLI ツールが共有する CLI 入力契約
(引数の定義・検証・設定への解決)を、特定形式の入出力でも単一ツール固有でもないため共有ドメイン層に
置く。

依存: Python 標準ライブラリのみ(`argparse` / `math`)。フォーマット層・他の共有ドメイン層へは依存しない。

正本関係: 引数エラーの終了コード・`code`・人間向けエラー行の書式は
[CLI インターフェース規約](../../docs/conventions/cli-interface.md)が正
(**以下、本書で「規約」はこの CLI インターフェース規約を指す**)。自己記述イベントのペイロード全体の
形と、どの引数を公開するかは各ツールの仕様書が定める。本書が定めるのは、値の受理範囲を1か所で決め、
その範囲を検証と公開の双方へ供給する仕組みである。

---

## 1. 責務

- **受理範囲の単一定義**: 数値引数の範囲・複合トークン引数の書式を1つのオブジェクトが持ち、argparse の
  型検証と自己記述で公開する制約の双方をそこから導く。制約を help や自己記述へ手書きで複製すると、
  実際に通る値と公開している値が別管理になって食い違うため。
- **理由の言語化**: 解析できない値・範囲外の値を、利用者が読める1行の理由へ変換する。argparse は
  `type` が関数でない場合に理由の代わりにオブジェクトの表現を出すため、検証子自身が理由を作る。
- **自己記述の機械導出**: 自己記述で公開するオプション定義の配列を、parser の登録内容から組み立てる。

本モジュールは**値の形**(型・範囲・書式)だけを担い、**引数の意味**(何を指定するオプションか・
既定値・組み合わせの制約)は呼び出し側が持つ。

## 2. 範囲付き数値の検証子

`RangeValidator(*, value_type, minimum=None, maximum=None, exclusive_min=False)`

- `value_type`: `"int"` または `"float"`。自己記述で公開する型名でもある。
- `minimum` / `maximum`: 下限・上限(省略で無制限)。
- `exclusive_min`: 真なら下限を含まない(`0` 超などを表す)。

**呼び出し**: 文字列を受け取り、`value_type` の数値へ変換して返す。**受理する字句は Python の `int` /
`float` の変換規則そのもの**とし(符号・指数表記・前後の空白の扱いを含む)、独自の字句規則を定義しない
(利用者が既に書ける形を実装ごとに狭めないため)。次のいずれかに当たる入力は
`argparse.ArgumentTypeError` を送出する。理由は日本語1行で、期待する型または範囲と、受理できなかった
入力を示す。**理由に引数名を入れない**(argparse が理由の前へ引数名を付けるため、入れると二重になる)。

- その型として解析できない。
- `value_type` が `"float"` で、値が有限でない(無限大・非数は大小比較をすり抜けるため、範囲判定より
  前に弾く)。
- 範囲外(`exclusive_min` が真なら下限と等しい値も範囲外)。

**制約の公開**: `constraint` は `min`(下限)・`max`(上限)・`exclusive_min`(下限を含まないか)の3キーを
**常に持つ**オブジェクトで、自己記述へそのまま載せる。無制限の下限・上限は `null` とする。検証に使う値と
同一のものを公開するので、公開制約と実際に通る値がずれない。

## 3. 複合トークンの検証子

`CompoundValidator(*, format, elements, relation=None, separator=":")`

- `format`: 利用者へ見せる書式(`a:i:u:e:o` など)。自己記述の制約にもこの文字列を載せる。
- `elements`: 要素名と要素検証子([§2](#2-範囲付き数値の検証子))の対の列。要素数は書式の要素数と一致する。
- `relation`: 要素間の関係の制約。**説明の文字列と判定関数の対**で与える。判定関数は要素検証子を通した
  後の値の列を書式の順で受け取り、制約が成立するとき真を返す。省略可。
- `separator`: 要素の区切り文字(既定 `:`)。書式が別の区切りを使う引数はここで指定する。

**呼び出し**: 文字列を `separator` で分割し、要素数が `elements` と一致しなければ書式を示して拒否する。
各要素は対応する要素検証子で検証し、失敗した要素は**どの要素が違反したか**を理由へ含める。`relation` を
持つ場合は全要素の検証後に判定し、成立しなければその説明を理由にする。すべて通れば、**要素値を書式の順に
並べたタプル**を返す(呼び出し側は添字で各要素を取る)。

**制約の公開**: `constraint` は `format`(書式の文字列)と `fields`(要素ごとの制約の配列)を持つ。
`fields` の各要素は `name`(要素名)・`type`(その要素の数値型名)と、[§2](#2-範囲付き数値の検証子) が定める3キーを**同じ階層へ
平坦に**並べたオブジェクトとする(範囲を入れ子にしない)。要素間の関係は自己記述の制約に載せる場所が
無いため公開せず、help 文で示す(公開形を増やすより、機械利用側が扱う語彙を小さく保つ)。

## 4. 自己記述の options 配列の導出

`describe_options(parser, type_table)`

parser へ登録済みの引数から、自己記述の `options` 配列を組み立てて返す。要素の順序は登録順とする。

- `type_table` は引数の格納先名から**型名と制約の対**への対応表で、**この表に載る引数だけ**を配列に
  入れる。メタ操作・モード指定(ヘルプ・バージョン・自己記述・機械モード)は表に載せないことで除外する。
- 対の**型名と制約がどちらも空**の引数は、その引数に設定された検証子から型と制約を取る([§2](#2-範囲付き数値の検証子)・[§3](#3-複合トークンの検証子))。
  型名は、複合トークンの検証子なら `"compound"`、範囲付き数値の検証子ならその `value_type`
  (`"int"` または `"float"`)とする。
- 名前は、位置引数ならその格納先名、オプションなら**肯定形の長形式**を採る。真偽フラグの否定形だけを
  持つ登録は、肯定形が同じ格納先で既に載るため配列に入れない。
- 各要素は `name`・`type`・`constraint`・`default`・`help` の**5キーを常に持つ**(該当しない値は `null`)。
  `default` と `help` は parser の登録内容から取る。

配列の各要素をこの形にすること自体は本モジュールが定めるが、**自己記述イベント全体のペイロード**
(この配列をどのキーへ載せるか、他に何を載せるか)は各ツールの仕様書が定める。

## 5. テスト

`pytest libs/cli_options` で単体検証する(テスト方針は [../vmd/vmd.md §4](../vmd/vmd.md#4-テスト方針) に準ずる。決定論的・外部依存なし)。

- 範囲付き数値の受理集合(境界値・下限を含む/含まない・上限)と、解析できない値・非有限値の拒否。
- 複合トークンの要素数不一致・要素の範囲外・要素間の関係違反の拒否と、区切り文字を変えた場合の分割。
- 拒否の理由に引数名が含まれないこと。
- 公開する制約が、検証に使う範囲・書式と一致すること。
- 自己記述の導出が、登録順・除外規則(表に無い引数・否定形のみの登録)・位置引数の名前・検証子からの
  型と制約の取得を規則どおり行うこと。
