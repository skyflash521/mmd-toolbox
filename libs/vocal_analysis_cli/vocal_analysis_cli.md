# vocal_analysis_cli 仕様書

音声前段([vocal_analysis](../vocal_analysis/vocal_analysis.md))を CLI から駆動するための共通引数群を定義し、
検証と設定への解決までを担う共有基盤ライブラリ。

層: **共有ドメイン層**([../../docs/conventions/layering.md §1](../../docs/conventions/layering.md#1-層タクソノミー))。複数の CLI ツールが共有する CLI 入力契約
(引数の定義・検証・設定への解決)を、特定形式の入出力でも単一ツール固有でもないため共有ドメイン層に置く。
音声前段の実行そのものは持たず、[vocal_analysis](../vocal_analysis/vocal_analysis.md) へ渡す設定を作るところまでを担う。

依存: [vocal_analysis](../vocal_analysis/vocal_analysis.md) の**最上位から公開されている設定型と定数**
(既定値・アダプタ id・分割の実行ポリシー)、[cli_options](../cli_options/cli_options.md)、Python 標準ライブラリ。
音声前段の重い依存を要する取り込みは行わない。フォーマット層・CLIツール層へは依存しない。

正本関係: **本書は共通引数群の名前・意味・既定・検証の正本**である。各引数が選ぶバックエンドの中身
(アダプタの登録・既定値・挙動)は [vocal_analysis](../vocal_analysis/vocal_analysis.md) が定める。共通の起動
フラグ・終了コード・エラーイベントの基底は [CLI インターフェース規約](../../docs/conventions/cli-interface.md)が定める。

---

## 1. 責務と境界

- **共有する**: 共通引数群の定義と一括登録、組み合わせ検証、設定オブジェクトへの解決、実行デバイス指定の
  適用、自己記述のための型情報、追加依存が未導入のときの理由1行。
- **各ツールに残す**: この共通引数群を公開するかどうかの判断(音声前段を使うかどうか)、ツール固有の
  オプション、自身の仕様書に書く利用者向けの公開契約、追加依存を要する取り込み文とガードの評価。

**共通引数群は一括で登録し、一部だけを非公開にする機構は持たない**。ツール側の選択は「この共通引数群を
使うか使わないか」の粒度とする。部分的な取捨選択を許すと、登録・自己記述・組み合わせ検証・設定解決が
それぞれ別の引数集合を前提にすることになり、同じ引数集合を前提にできなくなるため。共通引数群に含まれる
引数を公開するツールは、その名前・意味・検証を独自に定義しない([../../docs/conventions/layering.md §1](../../docs/conventions/layering.md#1-層タクソノミー))。

**本モジュールは追加依存を要さない**。引数の定義・検証・自己記述は、追加依存の未導入ガードより前に
成立していなければならないため、それを提供する側がガードの内側にあってはならない。

## 2. 共通引数群

`add_arguments(parser)` が下表を parser へ一括登録する。真偽フラグは規約の対の様式に揃える。

| 引数 | 型 | 既定 | 意味 |
|---|---|---|---|
| `--separate-vocals MODE` | 選択肢 | `always` | ボーカル分離の実施方針(`always` / `never`)。各値を選んだときに何が起きるかは音声前段が定める |
| `--separator NAME` | 選択肢 | 音声前段の既定分離アダプタ | ボーカル分離バックエンドの選択。選択肢は音声前段の登録アダプタの安定 id |
| `--recognizer-model-id ID` | 文字列 | 未指定 | 内容認識モデルの指定。未指定なら音声前段の既定モデルを使う |
| `--recognizer-model-revision REV` | 文字列 | 未指定 | 内容認識モデルのリビジョン指定。`--recognizer-model-id` と組で使う |
| `--recognizer-retry` / `--no-recognizer-retry` | 真偽の対 | 有効 | 内容認識のトリガ式リトライの有効・無効 |
| `--forced-aligner NAME` | 選択肢 | 音声前段の既定アライメント段 | 強制アライメント段のバックエンド選択。選択肢は登録アダプタの安定 id |
| `--sofa-python PATH` | 文字列 | 未指定 | SOFA 専用環境の Python 実行ファイル。SOFA 経路の選択時のみ必須 |
| `--sofa-root PATH` | 文字列 | 未指定 | SOFA のルートパス。SOFA 経路の選択時のみ必須 |
| `--sofa-checkpoint PATH` | 文字列 | 未指定 | SOFA のチェックポイントファイル。SOFA 経路の選択時のみ必須 |
| `--sofa-timeout SEC` | 浮動小数(0 超の有限値) | SOFA 設定型の既定 | SOFA サブプロセス1回あたりのタイムアウト秒数 |
| `--english-katakana-method NAME` | 選択肢 | 音声前段の既定方式 | 英語カタカナ化フォールバックの変換方式選択 |
| `--device MODE` | 選択肢 | `auto` | 実行デバイスの選択。`cpu` は GPU を使わず CPU で実行し、`auto` は環境をそのまま使う(GPU が利用できる環境なら GPU が使われる) |
| `--max-duration SEC` | 浮動小数(0 以上の有限値) | `300` | 長尺の自動分割で狙うチャンクの目標長(秒)。`0` で分割しない |

**音声前段が公開する定数・設定型に対応物を持つ引数**(分離アダプタ・強制アライメント段・英語カタカナ化
方式・SOFA のタイムアウト)は、選択肢も既定も手書きで複製せず音声前段の登録・設定型・既定値から取る
(音声前段側の追加・変更へ自動的に追随させるため)。

**分離の実施方針と実行デバイスは、選択肢と既定を本モジュールが上表のとおり定める**。音声前段はどちらに
ついても選択肢の一覧や既定を公開していない(分離の実施方針は分離を呼ぶかどうかの指定でアダプタの選択では
なく、実行デバイスはプロセスの環境をどう整えるかの指定で音声前段の処理内容を選ぶものではないため)。
ただし**分離の実施方針の各値を選んだときに何が起きるか**は音声前段が定めるので、値の意味を本書では
定義しない。

数値引数の範囲検証と、その範囲を自己記述へ公開する仕組みは
[cli_options](../cli_options/cli_options.md) の範囲付き数値の検証子を用いる。

**解析結果からの取り出し**: 各引数の格納先名は、**長形式のフラグ名から先頭のハイフンを取り除き、残りの
ハイフンをアンダースコアへ置き換えた名前**とする(真偽の対は肯定形の名前を共有する)。音声前段の実行へ
そのまま渡る5つ(分離の実施方針・分離アダプタ・リトライ・強制アライメント段・英語カタカナ化方式)は、
[§4](#4-設定への解決) の設定を組み立てる関数を通さないので、ツールがこの名前で解析結果から直接読んで渡す。

`describe_type_table()` は、この共通引数群についての自己記述の型情報
([cli_options.md §4](../cli_options/cli_options.md#4-自己記述の-options-配列の導出) が受け取る対応表と同じ形)を返す。
ツールは自分の固有引数の型情報と併せて自己記述の組み立てへ渡す。各引数が載る型名と制約は次のとおり。

| 上表の型 | 自己記述の型名 | 制約 |
|---|---|---|
| 選択肢 | `"enum"` | `{choices: [...]}` |
| 文字列 | `"str"` | 無し |
| 真偽の対 | `"flag"` | 無し |
| 浮動小数 | 対応表を空にして検証子から導く | 同左 |

## 3. 組み合わせ検証

`validate(args) -> tuple[str, str] | None` は、単独の引数の型・範囲では表せない組み合わせの誤りを検出する。
違反があれば**対象の引数名(長形式)と理由の本文**の2要素タプルを返し、違反が無ければ `None` を返す。
ツールはこれを引数エラー(規約が定める終了コード)として報告する。検証は次の順に行い、**1回の呼び出しに
つき最初に見つかった1件だけ**を返す(複数を並べても利用者はどれから直すか選べないため)。

1. **SOFA 経路の必須3項目**: 強制アライメント段に SOFA 経路を選んだとき、SOFA 専用環境の Python・
   ルートパス・チェックポイントがそろっていること。欠落は `--sofa-python` → `--sofa-root` →
   `--sofa-checkpoint` の順に走査し、最初に見つかった1件を返す。
2. **リビジョン単独指定**: 内容認識モデルの指定なしにリビジョンだけを指定するのは、対象が無く無意味な
   ため違反とする。返す引数名は `--recognizer-model-revision`。

## 4. 設定への解決

いずれも検証済みの引数を入力に取る。前の3つは音声前段が受け取る設定を組み立てて返し、最後の1つは
プロセスの環境へ適用する。

- `resolve_recognizer_model(args) -> ContentRecognizerModel`: 内容認識モデルの設定を返す。モデル指定が
  無ければ音声前段の既定モデルをそのまま返す。
- `resolve_sofa_config(args) -> SofaAlignerConfig | None`: SOFA 経路の設定を返す。SOFA 経路を選んで
  いなければ `None` を返す(選んでいない経路の設定を作ると、指定されていない値を既定で埋めることに
  なるため)。
- `resolve_chunking_policy(args) -> ChunkingPolicy | None`: 長尺分割の実行ポリシー
  ([vocal_analysis.md §11.1](../vocal_analysis/vocal_analysis.md#111-長尺の自動分割))を返す。目標長が `0` のときは `None`(分割しない)を返す。
  探索窓の幅とオーバーラップ長は利用者へ公開せず、ポリシーの既定値を使う。**音声前段の API は CLI の
  引数を直接受けず、分割しないことか実行ポリシーかを受ける**(引数からポリシーを決めるのは本モジュール、
  ポリシーに従って分割を実行するのは音声前段、という分担にするため)。
- `apply_device(args) -> None`: 実行デバイスの選択をプロセスへ適用する。`cpu` を選んだときは環境変数
  `CUDA_VISIBLE_DEVICES` を `-1` にして、プロセスから GPU を隠す。`auto` では何もしない(利用者が外から
  与えた設定を上書きしないため)。**最初の GPU 照会より前に呼ばなければ効かない**(利用できるデバイスの
  集合はプロセス内の最初の照会以降固定されるため)。環境変数は子プロセスへ継承されるので、音声前段が
  起動するサブプロセスにも同じ選択が効く。

## 5. 追加依存の未導入

音声前段の実行は配布物の追加依存(`vocal-analysis` extra)を要する一方、コンソールスクリプトは追加依存
なしの導入でも登録されるため、依存が揃わない環境からも起動されうる。`missing_dependency_message(exc) -> str`
は、取り込みに失敗した例外から**不足しているモジュール名と、その extra を導入する pip のコマンドを示す
1行の文字列**を組み立てて返す。不足モジュール名を持たない例外では、例外の文言をそのまま不足の箇所に使う。
文字列に**ツール名は入れない**(どのツールから呼ばれても同じ追加依存を指すため)。この文字列をどの
`code`・どの終了コードで報告するかは各ツールの仕様書が定める。

取り込み文そのものは各ツールが持つ(どの取り込みが追加依存を要するかは各エントリポイントが宣言する)。
ガードを評価する位置は、**引数の検証をすべて終えた後・処理を開始する直前**とする。これによりメタ操作
(ヘルプ・バージョン・自己記述)と引数エラーは、追加依存の有無に依らずそれぞれの終了コードで成立する。

## 6. テスト

`pytest libs/vocal_analysis_cli` で単体検証する(テスト方針は [../vmd/vmd.md §4](../vmd/vmd.md#4-テスト方針) に準ずる。決定論的・外部依存なし)。

音声前段の重い依存は取り込まないので、実モデル・GPU・ネットワークを要さない。

- 共通引数群が一括で登録され、13個すべてが解析後の値として取り出せること。
- 音声前段に対応物を持つ引数の選択肢と既定が、音声前段の登録・設定型・既定値に一致すること。
- 数値引数の受理集合と、自己記述の型情報が検証子と同一定義から導かれること。
- 組み合わせ検証が、走査順どおりに最初の1件だけを引数名とともに返し、違反が無ければ何も返さないこと。
- 設定への解決が、指定あり・指定なしのそれぞれで期待する設定を作ること(目標長 `0` が分割しないことを
  含む)。
- 実行デバイスの適用が、選択に応じて環境を変える・変えないこと。
- 追加依存の未導入の理由1行が、不足モジュール名を持つ例外と持たない例外の双方で組み立てられること。
