# shakevmd 仕様書

MMDカメラモーション(VMD)に手ぶれを焼き込むCLIツール

依存: vmd(同リポジトリのフォーマット層ライブラリ、../../libs/vmd/vmd.md), cli_events(同リポジトリの
共有ドメイン層ライブラリ、機械モードのイベント送出、../../libs/cli_events/cli_events.md),
cli_progress(同リポジトリの共有ドメイン層ライブラリ、進捗ライブ表示、../../libs/cli_progress/cli_progress.md),
numpy, scipy, click または argparse

---

## 1. 概要

### 1.1 目的
既存のカメラVMDの指定範囲に、手持ちカメラ風の揺れを加算した新しいVMDを生成する。
レンダリング品質を損なわない「3Dカメラ方式」の揺れを、VMDベイクによって実現する。

### 1.2 基本方針
- 元モーションの補間曲線を毎フレームサンプリング(ベイク)し、揺れを加算して
  高密度キーとして出力する。適用範囲外のキーは無傷で保持する。
- 揺れは回転主体(Pitch/Yaw/Roll)+控えめな位置成分。Rollはデフォルトで弱める。
- 揺れと元モーションを相関させる(モーション適応振幅・停止過渡)ことで
  「貼り付けた揺れ」ではなく「人が持っている」質感を目指す。
- カット(シーンチェンジ)はベイク範囲を独立セグメントに分割する境界として扱い、
  ノイズ位相・速度解析・停止過渡のすべてに波及させる(§5.3)。
- 同一入力・同一引数からは常に同一出力(シードはデフォルト固定)。
- ベイクは30fps・1フレーム間隔固定。VMDのキーフレームは30fps整数のみであり、
  間隔を変えるオプションは提供しない。

### 1.3 非目標
- スクリーンスペース(ポストエフェクト)方式の揺れ → MMEエフェクト側の領分
- 視野角への揺れ → VMDの視野角は整数度のみのため表現不可(§10)
- ボーン・モーフモーションの加工(入力に含まれる場合はカメラキーのみ処理し警告)
- GUI(スコープ外。コアとCLIを分離し、追加可能な構造に留める)

## 2. コマンドライン仕様

### 2.1 書式

    shakevmd <入力ファイル名>.vmd [オプション]

### 2.2 入出力・範囲

| 引数 | 型 / 書式 | デフォルト | 説明 |
|---|---|---|---|
| `<入力ファイル名>` | パス | (必須) | 入力カメラVMD |
| `-o, --output` | パス | `<入力ファイル名>_shake.vmd` | 出力先 |
| `--overwrite` | flag | off | 出力先の既存ファイルへの上書きを許可。未指定で出力先に既存ファイルがあるとエラー |
| `--range START:END` | フレーム番号(整数) | 全範囲 | 揺れ適用範囲。START/ENDは各々省略可(省略側は先頭/末尾まで)。両方省略(`:`)は全範囲と同義。`START>END`(逆順)は引数エラー。複数指定可(カット単位の運用を想定)。範囲端は常に既存キーへスナップされる(§5.2)。重複はスナップ適用後に判定しエラー |

入出力の受け渡し(入力=positional パス、出力=`--output`)・挙動パラメーターの取り回し・移植性は規約 §9・§10
に従う(同一入力・同一引数から常に同一出力になることは1.2の基本方針による)。

### 2.3 揺れ生成(基本)

| 引数 | 型 / 単位 | デフォルト | 説明 |
|---|---|---|---|
| `--amp-rot` | 度 | 0.8 | 回転振幅の基準値 |
| `--amp-pos` | MMD距離単位 | 0.05 | 位置振幅。控えめ推奨 |
| `--rot-weights P,Y,R` | 比率 | 1.0,1.0,0.3 | Pitch/Yaw/Roll個別重み |
| `--freq` | Hz | 1.2 | ノイズ基本周波数 |
| `--seed` | int | 1 | ノイズシード。固定値がデフォルト(再現性) |

ノイズはC1連続なパーリン/シンプレックス系の多オクターブ合成を使用し、最高オクターブの
実効周波数を8Hzに帯域制限する(§6.1)。オクターブ数およびオクターブ重み構成
(静止/移動プロファイル、§6.2)は内蔵値とし、プリセットおよびコアAPIでのみ変更可能(§8)。

### 2.4 強度制御

| 引数 | 書式 | デフォルト | 説明 |
|---|---|---|---|
| `--impulse` | `F:S:D`(複数可) | なし | フレームFに強さS、減衰時間D秒の衝撃を加算。指数減衰(§6.3) |
| `--fade` | 秒 | 0.7 | 範囲端の自動フェードイン/アウト時間(§5.1) |

### 2.5 モーション適応(§6.2)

| 引数 | 型 | デフォルト | 説明 |
|---|---|---|---|
| `--motion-damp` | float | 1.0 | 元モーション速度に応じた振幅減衰係数(動くほど揺れを弱める)。0で無効 |
| `--settle` | 度 | 0.0 | 停止検出時のオーバーシュート減衰振動の初期振幅。0で無効(既定=無効)。収束時間は内蔵値(プリセット/コアAPIで変更可) |

静止時/移動時プロファイル(振幅・オクターブ重み構成)は内蔵値とし、
プリセットおよびコアAPIでのみ変更可能(§6.2、§8)。

### 2.6 カット制御

| 引数 | 書式 | デフォルト | 説明 |
|---|---|---|---|
| `--cut-threshold` | `位置,角度` | 5.0,20.0 | カット自動検出の感度。位置ジャンプ(カメラ中心またはカメラワールド位置、MMD距離単位)と角度ジャンプ(度)のいずれか超過で検出(§5.3) |

カット位置のフレーム単位の手動指定(追加・打ち消し)はコアAPIでのみ提供する(§5.3)。

### 2.7 プリセット・運用

| 引数 | 説明 |
|---|---|
| `--preset NAME` | `handheld` / `telephoto` / `walking` / `earthquake`。公開引数を一括設定し、個別引数の明示指定が優先。`walking`は乱数ノイズに歩調周期成分(左右=歩調f、上下=2f)を混合し gait_freq/gait_amp も設定する。静止/移動プロファイル・オクターブ構成はプリセット未設定で bake() 既定値を継承する(転送機構はコアAPI/プリセット定義で設定可能だが、プリセット別のチューニングは未対応。§8) |
| `--dry-run` | 出力せず統計表示(適用範囲、スムージング前のカメラキー総数(`--smooth` による整理はこの表示の後に行うため、出力 VMD のキー数とは別の値)、最大振幅、カット検出位置、警告)。VMD の書き込みは抑制するが、引数検証(入出力パス衝突など)は dry-run でも実施し、衝突があれば終了コード2を返す(本実行と一致した fail-fast。§9) |
| `--smooth` / `--no-smooth` | ベイク後の密キーをプロセス内で疎ベジェへ削減し、30fps超再生の微振動(キー間速度の不連続)を低減する。**既定 on**。`--no-smooth` で無効化し密キー＋線形のまま出力する。固定設定と整合基準は §3.3 |
| `-v, --verbose` | 詳細ログ |
| `--quiet` | 進捗表示を抑制する(進捗表示節)。警告・統計・終了コードは抑制しない |
| `--version` | バージョンを表示して終了する |

### 2.7.1 進捗表示

工程はベイク(常に実行)と、`--smooth` 指定時のみのスムージング。有効条件・表記・停滞回避・副作用専用等の
一般契約は[CLIインターフェース規約](../../docs/conventions/cli-interface.md) §6が正。

スムージング段の進捗通知(処理済みフレーム数・全範囲フレーム総数・出力後検証区間の注記)は共有疎化
エンジンが持つ契約で、[vmd-reduce.md](../../libs/vmd/vmd-reduce.md) §11 を正とする
(本書では重複記述しない)。ベイク段は note を持たない。

### 2.8 機械モードとメタ操作(機械可読インターフェース)

他のソフトウェアが子プロセスとして呼ぶ機械利用のために、機械可読の起動フラグを持つ。共通の契約
(チャネル固定・イベント種別の語彙・終端規則・終了コードの基底・標準出力の UTF-8 固定)は
[CLI インターフェース規約](../../docs/conventions/cli-interface.md)が正で、共通のイベント送出基盤は
[cli_events](../../libs/cli_events/cli_events.md)を用いる。shakevmd 固有のイベントペイロード・`code` 値は §12 が定める。

| 引数 | 説明 |
|---|---|
| `--machine` | 出力を JSON Lines のイベントストリームにする(§12)。標準出力はイベント専用、標準エラーは人間向けログ・警告、終了コードは §9。既定(非指定)の人間向け表示・終了コードは変えない |
| `--describe` | VMD を読まずにオプション定義とプリセット一覧の result イベント(§12.4)を出して終了する。`--version`/`--help` と同じ独立メタ操作で、`--machine` を要さず単独で起動でき、入力 positional も要求しない |

- **入力検査**: `--machine --dry-run` は VMD を書かず、入力メタ情報の result イベント(§12.2 の `mode:"inspect"`)を
  出す。既存 `--dry-run`(書かない統計表示)の意味を機械モードへ写したもの。
- **`--help`/`--version` の機械モード挙動**: `--machine` と併用しても両者は従来どおり人間向けテキストを出して
  終了コード0で終わり、イベントストリームには載せない(処理を起動しないメタ操作のため。規約 §3 のメタ操作の例外)。
- **`--help` の説明**: 各オプション・引数の役割(§2.2–§2.7 の説明)を人間向けに出す。機械向けの自己記述
  `--describe` とは別軸で、対話利用者が `--help` だけで使い方を把握できる。
- 真偽フラグは `--x`/`--no-x` の様式に揃える(現状 `--smooth`/`--no-smooth`)。

## 3. VMD入出力

VMDの読み書き・データモデル・正規化は共通ライブラリ vmd に委譲する
(仕様: ../../libs/vmd/vmd-io.md。バイナリレイアウトの正は ../../docs/specs/vmd/VMD_file_format.md)。
本章はshakevmdとしての利用要件のみ規定する。

### 3.1 入力
- カメラキーは元のレコードを**原本(無加工)として保持**する。実際のカメラVMDは
  ファイル内でフレーム順に並んでいない(順不同)ため、これは前提となる
- サンプリング・範囲解決(`--range`スナップ)・カット検出・セグメント分割には、
  vmdの正規化(フレームソート・同一フレーム重複は後勝ち)を適用した
  **内部作業ビューのみ**を使う。この正規化は原本を変更せず、出力バイトを決めない
  (正規化警告はユーザーに表示する)
- カメラキー0件: エラー終了(終了コード1)
- ボーン/モーフ/照明/セルフ影/IKキーが含まれる場合: カメラキーのみ処理し、
  他セクションは無加工で透過。警告を表示
- VMDヘッダ(`model_name`)は入力の値をそのまま出力に引き継ぐ(変更しない)
- 視野角は揺れの対象外。**視野角が一定の区間**はベイク時に元の補間曲線をサンプリングし、
  整数度へ丸めて各フレームに設定する(丸め規則は ../../libs/vmd/vmd-interp.md §3 の既定=四捨五入)
- **視野角が複数フレームにわたって変化する区間(隣接する元キーで視野角が異なり、かつその
  フレーム間隔が2以上=ゆっくりズーム)は密キーを焼かず、その区間の元キーをバイト単位で温存する**。
  視野角は整数度でしか格納できないため(§10)、毎フレーム密キーで整数化するとゆっくりズームが
  1°刻みの階段になる。元のスパースキーを残して MMD の補間(実数評価、../../libs/vmd/vmd-interp.md §3)に委ねる
  ことで滑らかなズームを保つ。温存区間は密ベイクの対象から外れ密キーを生成しないため、
  揺れは構造的に乗らない(motion_damp の速度抑制とは無関係。位置・回転が静止したまま視野角だけ
  変化する純粋なズームでは速度が0で motion_damp は働かないが、それでも密ベイクを行わないので
  揺れは生じない)
- **隣接フレーム(間隔1)での瞬間的な視野角変化(カット等のショット切替で視野角も変わる場合)は
  階段にならないため通常どおり密ベイクする**(温存すると短いショット内で揺れが急にオン/オフして
  不連続=ガクつきになるため)。瞬間ジャンプは1フレームで完結し、密キーでもそのまま再現される
- パースペクティブフラグは補間曲線を持たないため、各ベイクフレームには
  当該フレーム以前で最も近いキーの値をホールドして設定する(ステップ)

### 3.2 出力
- ベイク範囲: 1フレーム間隔の高密度キー。キー間補間曲線は線形(MMDデフォルト値)を設定。
  ただし**視野角が変化する区間は密キーを焼かず、その区間の元キーをバイト単位で温存**する(§3.1)。
  なお既定ではこの密キーをさらにプロセス内で疎ベジェへ削減して出力する(§3.3。`--no-smooth` で
  この削減を無効化すると本節の密キー出力のままになる)
- 範囲外: **原本のカメラレコードをバイト単位でそのまま出力**する(正規化後の
  作業ビューではなく原本を使い、各レコードの重複・補間パラメーターを改変しない)。
  出力リスト全体はフレーム昇順に整列するため範囲外キーもフレーム順に並ぶが、各レコードの
  バイト内容は不変である。VMD のカメラキーはフレーム番号で時刻が定まり、ファイル内の格納順は
  揺れ加工の対象ではない(順不同格納が常態という前提は §3.1)
- 範囲端スナップの結果、同一フレーム重複や順不同キーがベイク区間と範囲外の
  境界をまたいで分割が一意に定まらない場合はエラー終了(終了コード2)
- 揺れ強度0・範囲指定なしの場合でも、密ベイクされた区間がある限り出力は「ベイクされたVMD」であり
  元ファイルとバイナリ一致はしないが、再生結果はフレーム時刻上で一致すること(§7テスト)。
  なお全区間が視野角変化区間の場合は密キーが一切焼かれず元キーのみが温存されるため(§3.1)、
  結果的に原本と一致しうる(密ベイク区間が無い退化ケース)

### 3.3 スムージング(`--smooth` / `--no-smooth`)
- 密キー＋線形補間は、キー間の速度が各フレームで不連続になり(角)、30fpsを超える
  再生(60fps・無制限)で微細な振動として見えることがある。スムージングは**既定 on** で、
  ベイク後の密キーを**プロセス内で**疎なベジェキーへ削減し、区間内をベジェ補間にして角を
  減らすことでこの微振動を低減する(区間ごとに独立フィットするため疎キー境界の速度連続性は
  保証せず、完全な解消ではない)。`--no-smooth` を指定すると削減を行わず、密キー＋線形補間のまま出力する。
- 削減は共通ライブラリ `vmd.reduce` のカメラキー削減機構を**ベイク出力のキー列へ直接適用**する。
  中間VMDは書かず、最終出力を1回だけ書き出す。
- 固定設定: 曲線モード=ベジェ、許容=aggressive 相当(位置 0.10 / 回転 0.25° / 距離 0.10 /
  視野角 1.00°)、最大セグメント 5 フレーム。これは sparsevmd CLI の
  `--curve-mode bezier --preset aggressive --max-segment-frames 5` と同設定であり、両経路の
  出力は aggressive 許容内で整合する(§7。直接経路は倍精度・パイプラインは単精度ソースのため
  バイト完全一致は前提にしない)。
- カット境界: カットとして境界化するのは**ベイクが確定したカットだけ**とし、reduce 側のカット
  再検出は無効化する(パースペクティブ切替・最大セグメント・範囲端による境界化は別途行われる)。
  カット F は F-1→F の不連続なので両側(F-1, F)を必須キーにして境界をまたぐ曲線を作らない。
- 手ぶれ品質の保持: 位置・回転・距離・視野角は**整数フレーム**で密ベイクに対し許容内に保たれる
  (reduce の出力後検証が整数フレームで許容超過を検出してキー化するため)。代表素材では
  サブフレーム(60fps超)でも許容内に収まることをテストで確認している(§7)。
- 実ベジェフィットの強制: `--smooth` は共有疎化エンジンを `force_bezier=True` で呼び、
  線形ファストパス(線形・固定 ease への短絡)を無効化して実ベジェ曲線を強制する。
  ファストパスは「許容・キー数は不変だが曲線形状を線形へ寄せる」ため、滑らかさ
  (速度不連続の角を消すベジェ化)を契約とする smooth では退化になる。滑らかさ契約は整数フレーム
  許容適合とは別物であり、許容内でも線形に退化させない(共通ライブラリ側のファストパス・
  オプトアウト機構は [vmd.md](../../libs/vmd/vmd.md) §6)。sparsevmd 等は
  `force_bezier=False` 既定でファストパスを温存する。

## 4. ベイク仕様

### 4.1 補間曲線評価
- vmd.interp(../../libs/vmd/vmd-interp.md)を使用する。
  MMD互換のベジェ評価(逆解き、カメラ回転のオイラー軸独立補間など)は
  ライブラリ側の仕様・テストで担保される
- shakevmdは適用範囲(セグメント)を30fps・1フレーム間隔でサンプリングしてベイクする

### 4.2 視線揺れ変換
MMDカメラは「カメラ中心+距離+角度」表現のため、角度への素朴な加算はカメラ中心の周りの公転になる。
本ツールはカメラ位置を固定して視線を揺らす変換を常に適用する。
座標変換(ワールド位置・視線方向の算出と逆算、符号規約、逆変換の角度連続性・
ジンバル対策)は vmd.camera(../../libs/vmd/vmd-camera.md)を使用する。
各フレームについて:
1. 元のカメラ中心・距離・角度からカメラのワールド位置と視線方向を算出
2. 視線方向に回転ノイズを適用(カメラ位置は固定)
3. 新しい視線方向と元の距離から、新しいカメラ中心位置を逆算してキーに書き戻す
4. 位置ノイズはカメラ位置への加算として同様に逆算

実現: 回転ノイズは角度への**成分ごとのオイラー加算**(揺れ角度 = 元の角度 + 回転ノイズ。
ラップ・正規化はしない)とし、カメラのワールド位置が固定(位置ノイズ指定時はその分
ワールドでシフト)されるよう新しいカメラ中心を `中心 = カメラ位置 − R(揺れ角度)·(0,0,距離)`
で逆算する。角度を直接加算するため、姿勢の再分解・ジンバル対策は不要。

距離0のキーでは本変換は素朴な角度加算と一致する。
素朴な角度加算(カメラ中心の周りの公転、特殊演出用)はコアAPIでのみ選択可能とし、
CLIには公開しない。

## 5. 境界・カット処理

### 5.1 範囲端の連続性
- 範囲端で揺れ強度は必ず0でなければならない。範囲端には `--fade` 秒の
  自動フェードを常に挿入する
- フェードはイーズイン/アウト(滑らかな0接続)とし、位置と速度の両方の連続性を確保する
- 範囲長が 2×fade 秒に満たない場合、フェード時間をその半分に自動短縮する(警告表示)。
  カットで分割された内部セグメント長は短縮判定に用いない(フェードは範囲端のみに掛かり、
  内部カット境界には適用しないため。§5.3)
- 本要件はベイク区間と元の補間曲線の接続部にのみ適用する。カット点には適用しない(§5.3)

### 5.2 既存キーとの接続
- 範囲端は常に直近の既存キーフレームにスナップする。
  これにより「既存キー間の補間曲線途中への割り込み」による区間モーション変化を防ぐ
- スナップの結果として複数範囲が重複した場合はエラー(終了コード2)
- スナップ後の実際の適用範囲は `--dry-run` および verbose ログで報告する

### 5.3 カット検出と波及処理

検出:
- フレーム差1の隣接キー間で、カメラ中心位置またはカメラワールド位置のジャンプが
  cut-threshold(距離)を超える、または角度のジャンプが cut-threshold(角度)を
  超える箇所をカットとみなす。カメラワールド位置を併用するのは、距離のみが
  急変するズームカットがカメラ中心位置・回転のいずれにも現れないため
- ジャンプ量の計量: 位置(カメラ中心・カメラワールド位置)は3次元ユークリッド距離、
  角度は2キーのカメラ姿勢(回転行列)間の測地角(度)とする。判定はいずれも
  厳密超過(`>`。閾値ちょうどはカットにしない)
- カットフレームFは「フレームFから新しいショットが始まる」ことを意味し、
  セグメント境界は F-1 と F の間に置く
- コアAPIではカット位置の手動指定(追加・打ち消し)が可能で、自動検出に優先する。
  手動指定のフレーム番号も上記の定義に従う。CLIからは `--cut-threshold` による
  感度調整のみを公開する
- 検出されたカット位置は `--dry-run` および verbose ログで必ず報告する

カットの波及処理
(カットはベイク範囲を独立したセグメントに分割し、以下すべてに作用する):
1. ノイズ位相: セグメントごとにシードを派生し、位相を連続させない
2. 速度解析(§6.2): カットをまたぐ差分を速度計算から除外する。
   正規化・プロファイルブレンドはセグメント単位で行う
3. settle: カット点では発動しない(前ショットの運動と無関係のため)
4. フェード: カット点ではフェード不要。揺れが非ゼロのまま
   切り替わってよい(実写でもカットをまたいで揺れは突然変わる)
5. カットの保存: ベイクは毎フレームキーのため、隣接キーの値ジャンプ自体は
   出力でもそのまま保持される(カットがなまることはない)

## 6. 揺れ生成仕様

### 6.1 ノイズ
- C1連続ノイズ(パーリン/シンプレックス)、チャンネルごとに独立シード派生
- ノイズ成分: 各オクターブ成分 `noise(freq × 2^i × t)` を生成する。主経路の合成重みは
  persistence 固定ではなく、§6.2 の静止/移動プロファイルを速度でクロスフェードした
  フレーム毎のオクターブ重みが担う(`freq` は `--freq`、オクターブ数=プロファイル長)
- 補助API `band_limited_noise` は固定重み合成 `Σ persistence^i × noise(freq × 2^i × t)` を
  提供する。等価性テストおよび単一オクターブ(octaves=1)のインパルス発振生成で使うが、
  主経路のカメラ手ぶれノイズの調整軸ではない
- 帯域制限: 実効周波数 > 8Hz のオクターブは生成しない(自動クランプ+警告)。
  ベイクは30fps固定(ナイキスト15Hz)のため、8Hz上限で線形補間でも波形が保存される

### 6.2 モーション適応
- ベイク時に元モーションの角速度・移動速度を算出し正規化する。正規化は
  **内蔵の基準速度による絶対正規化**(`正規化速度 = clamp(絶対速度 / 基準速度, 0, 1)`)とし、
  セグメント内ピークでは割らない。これにより同じカメラ速度はクリップ内の他の動きに依らず
  同じだけ適応する(ピーク正規化だと、同セグメントに速い動きがあると遅い動きが過小評価される)。
  基準速度は移動(ワールド位置)と回転(角度)で別個に持つ(内蔵・コアAPI/プリセットで調整可)。
  基準速度が 0 以下のときは退避として正規化速度を全 0(=適応無効)とする。
  速度の差分計算・プロファイルブレンドはカットで分割されたセグメント単位で行い、
  カットをまたぐ差分は除外する(§5.3)
- 実効振幅 = 基本振幅 × clamp(1 − motion_damp × 正規化速度, 0, 1)
  (速度が上がるほど揺れを減衰させ、高速ではほぼ 0。motion_damp=0 で減衰なし=無効)
- 静止/移動プロファイルを速度に応じてクロスフェード
  (振幅だけでなくオクターブ重み=周波数構成を切り替える)
- 停止検出: 角速度がしきい値を下回るゼロクロス点を検出し、
  直前の移動方向への減衰振動(初期振幅 `--settle`、収束時間は内蔵値)を加算。
  カット点では発動しない(§5.3)
- 完全静止区間: 高周波微動+長周期ドリフト(呼吸0.3Hz相当を含む)に収束させる

### 6.3 インパルス
- `--impulse F:S:D`: フレームF以降に `S × exp(-t/D)` の包絡を持つ高周波揺れを加算。
  揺れ成分は§6.1と同じ8Hz帯域制限に従う
- 方向はシードから決定(方向ベクトルの明示指定は非対応)
- 複数指定は加算合成

## 7. テスト要件

テストフレームワーク・実行方法・テストデータの扱いは ../../libs/vmd/vmd.md §4 の方針に従う
(pytest、ルートで `pytest tools/shakevmd` のみで実行可能、決定論的)。

フォーマットレベルの検証(ラウンドトリップのバイト一致、補間評価のMMD互換、
入力正規化、カメラ変換の往復一致)はvmd側のテスト要件として担保する
(../../libs/vmd/ の各仕様書)。以下のうち1・8はvmd管轄と重なるが、
shakevmdを通した統合確認として実施する。

1. 範囲外キーの無傷性: `--range` 指定時、ベイク区間外のカメラキーが入力の原本と
   レコード内容(バイト単位)で一致すること。出力はフレーム昇順に整列されるため、
   検証は格納順ではなくフレーム対応するレコード内容の一致で行う。順不同・重複キーを
   含む入力でも、出力は原本レコードをそのまま使うため一致する(§3.2。正規化は内部
   作業ビューのみで出力を決めない)
2. ベイク忠実性: 揺れ0でベイクした出力と元VMDを同一フレーム時刻でサンプリング比較し、
   全チャンネル誤差が許容値以下
3. 非対象チャンネル透過: ベイク区間内に視野角の補間とパースペクティブの切り替えを
   含む入力で、(a) 視野角が一定の区間では各密キーの視野角が元曲線のサンプル値の四捨五入
   (整数度)、視野角が変化する区間では密キーを焼かず元キーがバイト単位で温存されること
   (b) パースペクティブが直前キーの値のホールド、となること(§3.1)
4. 境界連続性: 範囲端前後の値・差分(速度)が連続
5. 再現性: 同一入力・同一引数で出力がバイナリ一致
6. 視線揺れ変換検証: 回転ノイズのみ適用時、揺れ適用後のカメラワールド位置が
   元と一致すること(§4.2)
7. カット非連続性: カット前後でノイズ位相が独立していること
8. 入力正規化: 順不同キー・重複フレームキーを含むVMDが仕様通り処理されること
9. カット波及: カットを含む範囲で (a) 速度解析にカット由来の偽速度が混入しない
   (b) カット直後にsettleが発動しない (c) カット前後で位相が独立、を検証
10. カット保存: 入力のカット(隣接キーの値ジャンプ)が出力VMDでも同一フレーム・
    同一値差で保持される
11. カット手動制御: コアAPIの手動カット指定(追加・打ち消し)が自動検出に
    正しく優先すること
12. 非対象セクション透過: ボーン/モーフ/照明/セルフ影/IKキーが混入した入力で、
    警告が表示され、これらのセクションが出力にバイト単位で保持されること
    (順不同のボーンキーがソートされずに透過することを含む)
13. スムージング(`--smooth` / `--no-smooth`): ベイク後の密キーをプロセス内で疎ベジェへ削減した出力が
    (a) 実質的に疎化し位置・回転チャンネルがベジェ補間になる (b) 固定素材で、位置・回転・距離・
    視野角がサブフレーム(60fps超を含む)でも密ベイクに対し aggressive 許容内(=手ぶれ品質を保持)
    (c) カット境界とパースペクティブが保持される (d) 中間VMDを書かず最終出力1回のみ
    (e) 密VMD経由の sparsevmd CLI パイプライン(同設定)と aggressive 許容内で整合すること
    (バイト完全一致は前提にしない。§3.3)。さらに (f) **既定 on**: フラグ無しの出力が `--smooth`
    明示時とバイト一致し疎化する (g) `--no-smooth`: 削減を無効化し全61キー・全チャンネル線形の
    密出力になること

## 8. パッケージ構成

- VMD読み書き・補間評価・カメラ座標変換は共通ライブラリ vmd に委譲し、shakevmdは
  揺れの生成と適用に専念する
- コアはCLI非依存。Jupyterからの対話利用を正式サポート(チューニングワークフロー)
- CLIはコアの薄いサブセットであり、主要パラメーターのみ公開する。
  詳細パラメーター(静止/移動プロファイルによるオクターブ重み構成・
  settle収束時間・手動カット指定・素朴な角度加算モード等)はコアAPIと
  プリセット定義でのみ調整可能とする。主経路のオクターブ重みは persistence ではなく
  静止/移動プロファイルが担い、persistence を CLI/プリセットの主調整項目には含めない
- カット検出・セグメント分割は独立した段とし、ベイク・ノイズ・モーション適応が
  セグメント列を入力として受け取る構造とする(§5.3の波及を構造で保証する)
- MMEエフェクト連携(ノイズテクスチャ共通化)は非対応

## 9. 終了コード

| コード | 意味 |
|---|---|
| 0 | 正常終了 |
| 1 | 入力ファイル不正(VMDでない / カメラキーなし) |
| 2 | 引数エラー(範囲不正・重複、上書き未許可 など) |
| 3 | 出力書き込み失敗 |
| 130 | 協調的な中断(Ctrl-C 等。§12.6) |

- `0`〜`3` は[CLI インターフェース規約](../../docs/conventions/cli-interface.md) §5 の基底と同じ意味。`130` は
  全ツール共通の中断予約コード(§12.6)で、基底 `0`〜`3` の意味へ押し込めない。
- 想定外の内部エラー(ベイク・スムージング・統計算出 等の未捕捉例外)は最も近い基底へ寄せて `1` で終える。
  機械モードでは §12.5 の `internal_error` error イベントで read 起因の `not_vmd` と識別でき、非機械モードでは
  理由を標準エラーへ最低1行出す(いずれもトレースバックは出さない)。
- 機械モードでは終了コードに加え、§12.5 の error イベントで「どのフィールド/パスが・なぜ不正か」を返す。

## 10. 既知の制約・運用上の注意

- `--no-smooth` の密出力はキー数が膨大になり、MMD上での手修正は実質不可能。既定のスムージング
  (§3.3)は疎ベジェ化でキー数を抑えるが、いずれの場合も揺れの適用は編集の最終工程とすること
  (Readme記載必須)
- VMDのキーフレームは30fps整数フレームのみ。60fps再生時の中間フレームは MMD側の補間で
  生成される。ノイズは8Hz以下に帯域制限されており線形補間でも波形(振幅・周波数)は十分
  保存されるが、密キー＋線形補間はキー間の速度が各フレームで不連続になり(角)、30fps超再生で
  微細な振動として見えることがある。既定のスムージング(§3.3)がこれを低減する。`--no-smooth` を
  指定すると密キー＋線形のままになり、この微振動が残りうる
- スムージング(§3.3)の許容判定は **30fps 整数フレーム**で行うため、キー間(サブフレーム)での
  真の揺れへの追従は保証しない。代表素材ではサブフレームでも許容内だが、強インパルスでは
  サブフレームで密出力から数度規模の乖離が出うる
- VMDの視野角は整数度(u32)でしか保存できないため、視野角への滑らかな揺れは
  フォーマット上表現不可能。本ツールは視野角を揺れの対象としない。さらに、視野角が変化する
  区間を毎フレーム密キーで整数化するとズームが1°刻みの階段になるため、その区間は密キーを焼かず
  元キーを温存して MMD の実数補間に委ねる(§3.1。温存区間には揺れが乗らない)
- カット自動検出は閾値ベースのため、誤検出(高密度キーによる高速カメラワーク)や
  見逃し(類似構図への小ジャンプカット)が起こりうる。`--dry-run` で検出位置を
  確認し、まず `--cut-threshold` で感度を調整、それでも合わない場合は
  コアAPI(Jupyter)からの手動カット指定で修正する運用を推奨する
- MMDの仕様上、入力VMDの補間曲線評価がMMD本体と完全一致することを目標とするが、
  本体の実装差異が発見された場合は本体挙動を正とする

## 12. 機械モード(機械可読インターフェース)

機械利用(子プロセス呼び出し)向けに、`--machine` で出力を JSON Lines のイベントストリームへ切り替える
(§2.8)。共通の契約・語彙は[CLI インターフェース規約](../../docs/conventions/cli-interface.md)が正、
イベント送出は共有基盤[cli_events](../../libs/cli_events/cli_events.md)を用いる。本章は **shakevmd 固有の
ペイロード形・`code` 値**を定める(規約は種別の語彙と終端規則のみを共通化し、ツール固有ペイロードは持たない)。

- **チャネル固定・符号化**(規約 §3・§10): 機械モードの標準出力は §12.2 のイベント**のみ**。人間向けログ・
  警告テキストは標準エラーへ出す。
- **終端規則**(規約 §4): ストリームは result または error の**ちょうど1つ**で終端する(強制終了時のみ
  例外。§12.6)。
- 各イベントは種別フィールド `type` を持つ。`code` は機械利用側の分岐に使い、人間向け `message` と分離する。
  shakevmd 由来の `code` は安定 snake_case。ライブラリ(`vmd.io`)由来の警告コードはライブラリの形式のまま
  (ハイフン区切り)透過する(§12.3)。
- **イベント契約の進化**は規約 §4.1 に従う(フィールド・種別・`code` の追加=MINOR、削除・意味変更=MAJOR。
  受信側は未知要素を無視できる前提)。

### 12.1 起動

- `--machine`: 機械モード。標準出力をイベント専用にする(§2.8)。
- `--machine --dry-run`: 入力検査。VMD を書かず入力メタ情報の result(§12.2 の `mode:"inspect"`)を出す。
- `--describe`: 自己記述。VMD を読まずオプション定義とプリセット一覧の result(§12.2 の `mode:"describe"`、
  中身は §12.4)を出す。`--machine` を要さず、入力 positional も要求しない独立メタ操作。
- `--help`/`--version` は `--machine` 併用でも人間向けテキストを出して終了コード0で終わり、イベント
  ストリームには載せない(§2.8)。

### 12.2 イベントペイロード

各イベントは `type` を持つ。

- **progress**: `{type:"progress", stage, done, total, note, elapsed}`。`stage` は `"bake"` / `"smooth"` の
  安定 id。`done`/`total` はフレーム進捗で、`total` が実行時に不明な段は `null`、`note` は補足文字列
  (無ければ `""`)、`elapsed` は段開始からの経過秒。各段は開始時に `done=0, total=null` の progress を1本出す。
- **warning**: `{type:"warning", code, message, section}`。`section` は対象セクション名の配列(該当が無ければ
  `null`)。複数セクションにまたがる警告は1イベントで配列に並べる。`code` 割り当ては §12.3。
- **result**: 正常終了の終端イベント。`mode` で形が決まる:
  - `mode:"bake"`(通常実行): `{type:"result", mode:"bake", output, keys, applied_ranges, max_amplitude,
    detected_cuts}`。`output` は書き出しパス(文字列)。`keys` は出力 VMD のカメラキー数(`--smooth` 適用後の
    キー数。`--no-smooth` なら密キー数)。`applied_ranges` はスナップ後の適用範囲の `[start, end]` 配列、
    `max_amplitude` は最大振幅(float)、`detected_cuts` は検出カットフレームの配列。
  - `mode:"inspect"`(入力検査 `--machine --dry-run`): `{type:"result", mode:"inspect", output, input_kind,
    keys, frame_range, duration_sec, sections, applied_ranges, max_amplitude, detected_cuts}`。VMD を書かないので
    `output:null`。`input_kind` は常に `"camera"`。`keys` は**入力カメラキー数**(正規化作業ビュー=フレーム
    ソート・同一フレーム重複を後勝ちで畳んだ入力キーの数。ベイク後の密キー数ではない)。`frame_range` は入力
    カメラキーの `[最小フレーム, 最大フレーム]`、`duration_sec` は最大フレーム÷30、`sections` は入力に存在する
    セクション名の配列(`"camera"` と混在する非カメラセクション)。加えて `--dry-run` の揺れプレビュー統計
    `applied_ranges`/`max_amplitude`/`detected_cuts` を併記する(`bake` と同義。ベイク後の密キー数はここには載せない)。
  - `mode:"describe"`(自己記述 `--describe`): `{type:"result", mode:"describe", options, presets}`(§12.4)。
    VMD を読まないので bake 統計キー(`output`/`keys`/`applied_ranges`/`max_amplitude`/`detected_cuts`)は
    載せない(キー自体を出さない)。`bake`/`inspect` は逆に `options`/`presets` を載せない。
- **error**: `{type:"error", code, exit_code, field, path, message}`。`field`/`path` は対象が無ければ `null`。
  失敗の終端イベント。`code`/`field`/`exit_code` の割り当ては §12.5。

### 12.3 warning の `code` 割り当て

- ライブラリ層(`vmd.io.read`)の警告は `VmdWarning.code` をそのまま載せる(ハイフン区切りのライブラリ形式を
  透過し snake_case へ変換しない)。`read()` が返す現行値は `decode-error` / `sections-missing`。
- shakevmd 由来の警告は安定コードを付番する:

| 発生源 | `code` | `section` |
|---|---|---|
| ベイク正規化の同一フレーム重複破棄(§3.1) | `bake_normalize_duplicate` | `["camera"]` |
| 範囲長が 2×fade 未満でのフェード自動短縮(§5.1) | `fade_shortened` | `null` |
| ノイズのオクターブ帯域クランプ(§6.1) | `octave_clamped` | `null` |
| カメラ以外のセクションを無加工透過(§3.1) | `non_camera_sections_passthrough` | 透過した全セクション名の配列(例 `["bone","morph"]`) |

shakevmd 由来の警告は現状コード無しの自由文字列で(一部は `noise` の `octave-clamped:` のように疑似接頭を
持つ)、上表の snake_case コードを **shakevmd 側で付番**し、元の自由文字列の文言は `message` に保持する。
これらはライブラリ由来のハイフンコード(上記 `vmd.io` の `VmdWarning.code` 透過)とは別物で、shakevmd 由来を
ハイフンのまま透過しない(現状の疑似接頭 `octave-clamped:` も上表の `octave_clamped` へ置き換える)。

### 12.4 `--describe` の中身

`options` は**ベイクを駆動する引数**の配列。対象は positional `input` と、§2.2–§2.7 の処理用フラグ
(`--output`/`--overwrite`/`--range`/揺れ・強度・モーション適応・カット系・`--preset`/`--dry-run`/`--smooth`/
`--seed`/`--impulse`/`--fade`/`--verbose`/`--quiet`)。メタ/モード操作(`--describe`/`--version`/`--help`/
`--machine`)は含めない(処理を駆動せず、フォーム生成の対象外)。各要素は `{name, type, constraint, default, help}`
(キーは常に5つ、該当しない値は `null`):

- `name`: 長形式フラグ文字列(例 `"--amp-rot"`)。positional は `"input"`。
- `type`: 固定語彙 `"float"` / `"int"` / `"str"` / `"flag"`(真偽) / `"enum"`(選択肢) / `"compound"`(複合
  トークン)のいずれか。
- `constraint`: `type` ごとに決まる(キーは型ごとに固定):
  - 数値(`float`/`int`): `{min, max, exclusive_min}`(3キー常設)。`exclusive_min` は常に bool。`max` は上限が
    無ければ `null`。型関数から機械導出する: 非負 float は `{min:0, max:null, exclusive_min:false}`、正 float は
    `{min:0, max:null, exclusive_min:true}`、有限のみの float は `{min:null, max:null, exclusive_min:false}`。
    範囲制約の無い裸の数値(`--seed` の `int`)は `constraint:null`。
  - `enum`: `{choices:[...]}`(例 `--preset` はプリセット名の一覧)。
  - `compound`: `{format, fields}`。`format` はトークン文法の文字列、`fields` は各トークンの制約配列で
    要素は `{name, type, min, max, exclusive_min}`(`type` は `"int"`/`"float"`、数値制約3キーは単純数値
    引数と同義。上限が無ければ `max:null`)。CLI の各 compound パーサが課す値制約を機械導出する:
    - `--rot-weights`=`"P,Y,R"`: 各 float・有限のみ。`P`/`Y`/`R` とも `{type:"float", min:null, max:null,
      exclusive_min:false}`。
    - `--cut-threshold`=`"位置,角度"`: 各 float・有限かつ非負。`位置`/`角度` とも `{type:"float", min:0,
      max:null, exclusive_min:false}`。
    - `--impulse`=`"F:S:D"`(複数可): `F`=`{type:"int", min:0, max:null, exclusive_min:false}`、
      `S`=`{type:"float", min:0, max:null, exclusive_min:false}`、`D`=`{type:"float", min:0, max:null,
      exclusive_min:true}`。
    - `--range`=`"START:END"`(各辺省略可、複数可): `START`/`END` とも `{type:"int", min:0, max:null,
      exclusive_min:false}`。各辺は省略可(省略時はそのトークンを与えない)。`START<=END` の順序制約は
      トークン横断のため `fields` に含めず、parse 時に `bad_argument`/`range_reversed`(§12.5)で返す。
  - `flag`: `null`。
- `default`: 公開オプションを次の規則で全て覆う(CLI 定義から機械導出):
  - 揺れパラメーター(`--amp-rot`/`--amp-pos`/`--rot-weights`/`--freq`/`--fade`/`--motion-damp`/`--settle`/
    `--cut-threshold`): 解決後の hard-default の値(例 `amp_rot=0.8`、`cut_threshold=[5.0, 20.0]`)。argparse 既定は
    未指定センチネルだが describe には解決後の hard-default を出す。
  - `--seed`: `1`。
  - 真偽フラグ: `--overwrite`/`--dry-run`/`--verbose`/`--quiet` は `false`、`--smooth`(既定 on)は `true`。
  - `--preset`: `null`(未指定)。
  - `--output`: `null`(既定は入力名由来の算出値 `<入力名>_shake.vmd` で固定リテラルにできないため。算出規則は
    `help` に記す)。
  - 複数指定系(`--range`/`--impulse`)は既定を持たないので `null`。
- `help`: 人間向け説明(§2.2–§2.7 の各引数説明文)。

`presets` は各要素 `{name, values}` の配列(キーは常に2つ)。`name` はプリセット名(§2.7)の文字列、
`values` は公開引数名→値のオブジェクト(キーは `amp_rot`/`amp_pos`/`rot_weights`/`freq`/`motion_damp`/`settle`/
`cut_threshold` のうちそのプリセットが定義する分)。プリセットが定義しない公開引数は `values` に載せない
(未指定でその引数の hard-default を継承する、§2.7)。内蔵パラメーターは
CLI 非公開なので `values` に出さない(§8 の非公開方針と一致)。

### 12.5 構造化エラー

失敗は終了コード(§9)に加え、機械モードでは error イベントで「どのフィールド/パスが・なぜ」を返す。
非機械モードでも理由を標準エラーへ最低1行出す(トレースバックは出さない)。各経路の `code`/`field`/`exit_code`:

| 事象 | `code` | `field` | `exit_code` |
|---|---|---|---|
| 入力が VMD でない・破損 | `not_vmd` | `"input"` | 1 |
| カメラキー0件 | `no_camera_keys` | `"input"` | 1 |
| 範囲書式・逆順 `START>END`・未知オプション・型エラー・positional 欠落等(argparse 検出) | `bad_argument` | argparse が示す引数名(オプションは長形式フラグ名、positional は `"input"`) | 2 |
| 省略端を解決した結果が逆順(例 `999:` で末尾<999) | `range_reversed` | `"--range"` | 2 |
| 出力先に既存ファイルがある・`--overwrite` 未指定 | `output_exists` | `"--output"` | 2 |
| 範囲の重複・接触(ベイクの ValueError) | `range_overlap` | `"--range"` | 2 |
| 有限だが過大な値が float32 で溢れた(ベイク中・書き込み時の OverflowError) | `value_overflow` | `null` | 2 |
| 焼き結果が inf/nan(非有限出力) | `non_finite_output` | `null` | 2 |
| 出力書き込み失敗(権限・不正パス・ディスク等の I/O 失敗) | `write_failed` | `"--output"`(+ `path`) | 3 |
| 上記いずれにも当たらない想定外の内部エラー | `internal_error` | `null` | 1 |
| 協調的な中断(Ctrl-C 等) | `cancelled` | `null` | 130 |

- `not_vmd` は握り潰していた例外の種別を `message` に載せる。`bad_argument` は複数の検証失敗が同一終了コード `2`
  に集約される場合もイベント側で1件ずつ区別する。
- `value_overflow`・`non_finite_output` の `field` を `null` にするのは、起因引数を単一に帰属させられないため
  (無理に1つ選ばず `message` に状況を載せる)。書き込み例外のうち `OverflowError` は過大値起因なので
  `value_overflow`(exit 2)、それ以外の I/O 失敗のみ `write_failed`(exit 3)。
- `internal_error` は表の各分類に当たらない未捕捉例外の受け皿で、CLI 本体の全体をトップレベルで
  捕捉して畳む。終了コードは最も近い基底へ寄せて `1` とし、機械モードでは `code:"internal_error"` で read 起因の
  `not_vmd` と識別できる。`KeyboardInterrupt` は内部エラーでなく中断(`cancelled`/`130`、§12.6)として手前で分岐する。

### 12.6 中断

長時間処理(ベイク・既定 on のスムージング)を呼び出し側から安全に中断できる。

- **出力の原子性**: VMD 出力は一時ファイルへ書き切ってから最終パスへ置換する(`vmd.io` で既達)。途中終了で
  中途半端な出力ファイルを残さない。
- **中断機構**: CLI 本体の全体で `KeyboardInterrupt`(端末 Ctrl-C / 親プロセスの中断)を捕捉する。**機械モード**
  では `cancelled` の error イベントを標準出力へ出してストリームを終端し、**非機械モード**では標準出力に JSON を
  出さず中断理由を標準エラーへ1行出す。どちらも終了コード `130` を返す。VMD 書き込みは全計算後に1回だけ起きる
  ため、ベイク・スムージング実行中の `KeyboardInterrupt` は書き込み前に処理を中断し、原子性により中途半端な出力は
  残らない。専用の停止フラグ・チェックポイント API は設けない。
- **Windows**: `CTRL_BREAK_EVENT` も上の `KeyboardInterrupt` 捕捉経路へ橋渡しし、`cancelled`/`130` として
  扱う。橋渡しの要否・実装は共有基盤([cli_events.md](../../libs/cli_events/cli_events.md) §5)が正。
- **終了コード `130`**: 基底 `0`〜`3` へ押し込めず、全ツール共通の中断予約コード(規約 §5/§8)とする。
- 呼び出し側がプロセスを強制終了した場合は終端イベントを出せないまま途切れる(規約 §4 の唯一の例外)。
  原子性により中途半端な出力は残らない。
