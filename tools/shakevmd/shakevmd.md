# shakevmd 仕様書

MMDカメラモーション(VMD)に手ぶれを焼き込むCLIツール

Version: 0.01
実装言語: Python 3.11+
依存: mmd_toolbox(同リポジトリの共通ライブラリ、../mmd_toolbox/mmd_toolbox.md), numpy, scipy, click または argparse

---

## 1. 概要

### 1.1 目的
既存のカメラVMDの指定範囲に、手持ちカメラ風の揺れを加算した新しいVMDを生成する。
レンダリング品質を損なわない「3Dカメラ方式」の揺れを、VMDベイクによって実現する。

### 1.2 基本方針
- 元モーションの補間曲線を毎フレームサンプリング(ベイク)し、揺れを加算して
  高密度キーとして出力する。適用範囲外のキーは無傷で保持する。
- 揺れは回転主体(Pitch/Yaw/Roll)+控えめな位置成分。Rollはデフォルトで弱める。
- 揺れと元モーションを相関させる(モーション適応振幅・停止過渡)ことで
  「貼り付けた揺れ」ではなく「人が持っている」質感を目指す。
- カット(シーンチェンジ)はベイク範囲を独立セグメントに分割する境界として扱い、
  ノイズ位相・速度解析・停止過渡のすべてに波及させる(§5.3)。
- 同一入力・同一引数からは常に同一出力(シードはデフォルト固定)。
- ベイクは30fps・1フレーム間隔固定。VMDのキーフレームは30fps整数のみであり、
  間隔を変えるオプションは提供しない。

### 1.3 非目標
- スクリーンスペース(ポストエフェクト)方式の揺れ → MMEエフェクト側の領分
- 視野角への揺れ → VMDの視野角は整数度のみのため表現不可(§10)
- ボーン・モーフモーションの加工(入力に含まれる場合はカメラキーのみ処理し警告)
- GUI(スコープ外。コアとCLIを分離し、追加可能な構造に留める)

## 2. コマンドライン仕様

### 2.1 書式

    shakevmd <入力ファイル名>.vmd [オプション]

### 2.2 入出力・範囲

| 引数 | 型 / 書式 | デフォルト | 説明 |
|---|---|---|---|
| `<入力ファイル名>` | パス | (必須) | 入力カメラVMD |
| `-o, --output` | パス | `<入力ファイル名>_shake.vmd` | 出力先 |
| `--overwrite` | flag | off | 入力と同一パスへの出力を許可。未指定で同一パスならエラー |
| `--range START:END` | フレーム番号(整数) | 全範囲 | 揺れ適用範囲。START/ENDは各々省略可(省略側は先頭/末尾まで)。両方省略(`:`)は全範囲と同義。`START>END`(逆順)は引数エラー。複数指定可(カット単位の運用を想定)。範囲端は常に既存キーへスナップされる(§5.2)。重複はスナップ適用後に判定しエラー |

### 2.3 揺れ生成(基本)

| 引数 | 型 / 単位 | デフォルト | 説明 |
|---|---|---|---|
| `--amp-rot` | 度 | 0.8 | 回転振幅の基準値 |
| `--amp-pos` | MMD距離単位 | 0.05 | 位置振幅。控えめ推奨 |
| `--rot-weights P,Y,R` | 比率 | 1.0,1.0,0.3 | Pitch/Yaw/Roll個別重み |
| `--freq` | Hz | 1.2 | ノイズ基本周波数 |
| `--seed` | int | 1 | ノイズシード。固定値がデフォルト(再現性) |

ノイズはC1連続なパーリン/シンプレックス系の多オクターブ合成を使用し、最高オクターブの
実効周波数を8Hzに帯域制限する(§6.1)。オクターブ数およびオクターブ重み構成
(静止/移動プロファイル、§6.2)は内蔵値とし、プリセットおよびコアAPIでのみ変更可能(§8)。

### 2.4 強度制御

| 引数 | 書式 | デフォルト | 説明 |
|---|---|---|---|
| `--impulse` | `F:S:D`(複数可) | なし | フレームFに強さS、減衰時間D秒の衝撃を加算。指数減衰(§6.3) |
| `--fade` | 秒 | 0.7 | 範囲端の自動フェードイン/アウト時間(§5.1) |

### 2.5 モーション適応(§6.2)

| 引数 | 型 | デフォルト | 説明 |
|---|---|---|---|
| `--motion-damp` | float | 1.0 | 元モーション速度に応じた振幅減衰係数(動くほど揺れを弱める)。0で無効 |
| `--settle` | 度 | 0.0 | 停止検出時のオーバーシュート減衰振動の初期振幅。0で無効(既定=無効)。収束時間は内蔵値(プリセット/コアAPIで変更可) |

静止時/移動時プロファイル(振幅・オクターブ重み構成)は内蔵値とし、
プリセットおよびコアAPIでのみ変更可能(§6.2、§8)。

### 2.6 カット制御

| 引数 | 書式 | デフォルト | 説明 |
|---|---|---|---|
| `--cut-threshold` | `位置,角度` | 5.0,20.0 | カット自動検出の感度。位置ジャンプ(カメラ中心またはカメラワールド位置、MMD距離単位)と角度ジャンプ(度)のいずれか超過で検出(§5.3) |

カット位置のフレーム単位の手動指定(追加・打ち消し)はコアAPIでのみ提供する(§5.3)。

### 2.7 プリセット・運用

| 引数 | 説明 |
|---|---|
| `--preset NAME` | `handheld` / `telephoto` / `walking` / `earthquake`。公開引数を一括設定し、個別引数の明示指定が優先。`walking`は乱数ノイズに歩調周期成分(左右=歩調f、上下=2f)を混合し gait_freq/gait_amp も設定する。静止/移動プロファイル・オクターブ構成はプリセット未設定で bake() 既定値を継承する(転送機構はコアAPI/プリセット定義で設定可能だが、プリセット別のチューニングは未対応。§8) |
| `--dry-run` | 出力せず統計表示(適用範囲、平滑化前のカメラキー総数(`--smooth` による整理はこの表示の後に行うため、出力 VMD のキー数とは別の値)、最大振幅、カット検出位置、警告)。VMD の書き込みは抑制するが、引数検証(入出力パス衝突など)は dry-run でも実施し、衝突があれば終了コード2を返す(本実行と一致した fail-fast。§9) |
| `--smooth` / `--no-smooth` | ベイク後の密キーをプロセス内で疎ベジェへ削減し、30fps超再生の微振動(キー間速度の不連続)を低減する。**既定 on**。`--no-smooth` で無効化し密キー＋線形のまま出力する。固定設定と整合基準は §3.3 |
| `-v, --verbose` | 詳細ログ |

## 3. VMD入出力

VMDの読み書き・データモデル・正規化は共通ライブラリ mmd_toolbox に委譲する
(仕様: ../mmd_toolbox/vmd-io.md。バイナリレイアウトの正は ../docs/specs/vmd/VMD_file_format.md)。
本章はshakevmdとしての利用要件のみ規定する。

### 3.1 入力
- カメラキーは元のレコードを**原本(無加工)として保持**する。実際のカメラVMDは
  ファイル内でフレーム順に並んでいない(順不同)ため、これは前提となる
- サンプリング・範囲解決(`--range`スナップ)・カット検出・セグメント分割には、
  mmd_toolboxの正規化(フレームソート・同一フレーム重複は後勝ち)を適用した
  **内部作業ビューのみ**を使う。この正規化は原本を変更せず、出力バイトを決めない
  (正規化警告はユーザーに表示する)
- カメラキー0件: エラー終了(終了コード1)
- ボーン/モーフ/照明/セルフ影/IKキーが含まれる場合: カメラキーのみ処理し、
  他セクションは無加工で透過。警告を表示
- 視野角は揺れの対象外。**視野角が一定の区間**はベイク時に元の補間曲線をサンプリングし、
  整数度へ丸めて各フレームに設定する(丸め規則は ../mmd_toolbox/vmd-interp.md §3 の既定=四捨五入)
- **視野角が複数フレームにわたって変化する区間(隣接する元キーで視野角が異なり、かつその
  フレーム間隔が2以上=ゆっくりズーム)は密キーを焼かず、その区間の元キーをバイト単位で温存する**。
  視野角は整数度でしか格納できないため(§10)、毎フレーム密キーで整数化するとゆっくりズームが
  1°刻みの階段になる。元のスパースキーを残して MMD の補間(実数評価、../mmd_toolbox/vmd-interp.md §3)に委ねる
  ことで滑らかなズームを保つ。温存区間は密ベイクの対象から外れ密キーを生成しないため、
  揺れは構造的に乗らない(motion_damp の速度抑制とは無関係。位置・回転が静止したまま視野角だけ
  変化する純粋なズームでは速度が0で motion_damp は働かないが、それでも密ベイクを行わないので
  揺れは生じない)
- **隣接フレーム(間隔1)での瞬間的な視野角変化(カット等のショット切替で視野角も変わる場合)は
  階段にならないため通常どおり密ベイクする**(温存すると短いショット内で揺れが急にオン/オフして
  不連続=ガクつきになるため)。瞬間ジャンプは1フレームで完結し、密キーでもそのまま再現される
- パースペクティブフラグは補間曲線を持たないため、各ベイクフレームには
  当該フレーム以前で最も近いキーの値をホールドして設定する(ステップ)

### 3.2 出力
- ベイク範囲: 1フレーム間隔の高密度キー。キー間補間曲線は線形(MMDデフォルト値)を設定。
  ただし**視野角が変化する区間は密キーを焼かず、その区間の元キーをバイト単位で温存**する(§3.1)。
  なお既定ではこの密キーをさらにプロセス内で疎ベジェへ削減して出力する(§3.3。`--no-smooth` で
  この削減を無効化すると本節の密キー出力のままになる)
- 範囲外: **原本のカメラレコードをバイト単位でそのまま出力**する(正規化後の
  作業ビューではなく原本を使い、各レコードの重複・補間パラメーターを改変しない)。
  出力リスト全体はフレーム昇順に整列するため範囲外キーもフレーム順に並ぶが、各レコードの
  バイト内容は不変である。VMD のカメラキーはフレーム番号で時刻が定まり、ファイル内の格納順は
  揺れ加工の対象ではない(順不同格納が常態という前提は §3.1)
- 範囲端スナップの結果、同一フレーム重複や順不同キーがベイク区間と範囲外の
  境界をまたいで分割が一意に定まらない場合はエラー終了(終了コード2)
- 揺れ強度0・範囲指定なしの場合でも、密ベイクされた区間がある限り出力は「ベイクされたVMD」であり
  元ファイルとバイナリ一致はしないが、再生結果はフレーム時刻上で一致すること(§7テスト)。
  なお全区間が視野角変化区間の場合は密キーが一切焼かれず元キーのみが温存されるため(§3.1)、
  結果的に原本と一致しうる(密ベイク区間が無い退化ケース)

### 3.3 滑らか出力(`--smooth` / `--no-smooth`)
- 密キー＋線形補間は、キー間の速度が各フレームで不連続になり(角)、30fpsを超える
  再生(60fps・無制限)で微細な振動として見えることがある。滑らか出力は**既定 on** で、
  ベイク後の密キーを**プロセス内で**疎なベジェキーへ削減し、区間内をベジェ補間にして角を
  減らすことでこの微振動を低減する(区間ごとに独立フィットするため疎キー境界の速度連続性は
  保証せず、完全な解消ではない)。`--no-smooth` を指定すると削減を行わず、密キー＋線形補間のまま出力する。
- 削減は共通ライブラリ `mmd_toolbox.vmd.reduce` の `reduce_camera_track` を**ベイク出力の
  キー列へ直接適用**する。中間VMDは書かず、最終出力を1回だけ書き出す。
- 固定設定: 曲線モード=ベジェ、許容=aggressive 相当(位置 0.10 / 回転 0.25° / 距離 0.10 /
  視野角 1.00°)、最大セグメント 5 フレーム。これは sparsevmd CLI の
  `--curve-mode bezier --preset aggressive --max-segment-frames 5` と同設定であり、両経路の
  出力は aggressive 許容内で整合する(§7。直接経路は倍精度・パイプラインは単精度ソースのため
  バイト完全一致は前提にしない)。
- カット境界: カットとして境界化するのは**ベイクが確定したカットだけ**とし、reduce 側のカット
  再検出は無効化する(パースペクティブ切替・最大セグメント・範囲端による境界化は別途行われる)。
  カット F は F-1→F の不連続なので両側(F-1, F)を必須キーにして境界をまたぐ曲線を作らない。
- 手ぶれ品質の保持: 位置・回転・距離・視野角は**整数フレーム**で密ベイクに対し許容内に保たれる
  (reduce の出力後検証が整数フレームで許容超過を検出してキー化するため)。代表素材では
  サブフレーム(60fps超)でも許容内に収まることをテストで確認している(§7)。
- 実ベジェフィットの強制: `--smooth` は `reduce_camera_track` を `force_bezier=True` で呼び、共有の
  線形ファストパス(線形・固定 ease への短絡)を無効化して `least_squares` 由来の実ベジェ曲線を
  強制する。ファストパスは「許容・キー数は不変だが曲線形状を線形へ寄せる」ため、滑らかさ
  (速度不連続の角を消すベジェ化)を契約とする smooth では退化になる。滑らかさ契約は整数フレーム
  許容適合とは別物であり、許容内でも線形に退化させない(共通ライブラリ側の機構は
  ../mmd_toolbox/mmd_toolbox.md §6.3)。sparsevmd 等は `force_bezier=False` 既定でファストパスを温存する。

## 4. ベイク仕様

### 4.1 補間曲線評価
- mmd_toolbox.vmd.interp(../mmd_toolbox/vmd-interp.md)を使用する。
  MMD互換のベジェ評価(逆解き、カメラ回転のオイラー軸独立補間など)は
  ライブラリ側の仕様・テストで担保される
- shakevmdは適用範囲(セグメント)を30fps・1フレーム間隔でサンプリングしてベイクする

### 4.2 視線揺れ変換
MMDカメラは「カメラ中心+距離+角度」表現のため、角度への素朴な加算はカメラ中心の周りの公転になる。
本ツールはカメラ位置を固定して視線を揺らす変換を常に適用する。
座標変換(ワールド位置・視線方向の算出と逆算、符号規約、逆変換の角度連続性・
ジンバル対策)は mmd_toolbox.vmd.camera(../mmd_toolbox/vmd-camera.md)を使用する。
各フレームについて:
1. 元のカメラ中心・距離・角度からカメラのワールド位置と視線方向を算出
2. 視線方向に回転ノイズを適用(カメラ位置は固定)
3. 新しい視線方向と元の距離から、新しいカメラ中心位置を逆算してキーに書き戻す
4. 位置ノイズはカメラ位置への加算として同様に逆算

実現: 回転ノイズは角度への**成分ごとのオイラー加算**(揺れ角度 = 元の角度 + 回転ノイズ。
ラップ・正規化はしない)とし、カメラのワールド位置が固定(位置ノイズ指定時はその分
ワールドでシフト)されるよう新しいカメラ中心を `中心 = カメラ位置 − R(揺れ角度)·(0,0,距離)`
で逆算する。角度を直接加算するため、姿勢の再分解・ジンバル対策は不要。

距離0のキーでは本変換は素朴な角度加算と一致する。
素朴な角度加算(カメラ中心の周りの公転、特殊演出用)はコアAPIでのみ選択可能とし、
CLIには公開しない。

## 5. 境界・カット処理

### 5.1 範囲端の連続性
- 範囲端で揺れ強度は必ず0でなければならない。範囲端には `--fade` 秒の
  自動フェードを常に挿入する
- フェードはイーズイン/アウト(滑らかな0接続)とし、位置と速度の両方の連続性を確保する
- 範囲長が 2×fade 秒に満たない場合、フェード時間をその半分に自動短縮する(警告表示)。
  カットで分割された内部セグメント長は短縮判定に用いない(フェードは範囲端のみに掛かり、
  内部カット境界には適用しないため。§5.3)
- 本要件はベイク区間と元の補間曲線の接続部にのみ適用する。カット点には適用しない(§5.3)

### 5.2 既存キーとの接続
- 範囲端は常に直近の既存キーフレームにスナップする。
  これにより「既存キー間の補間曲線途中への割り込み」による区間モーション変化を防ぐ
- スナップの結果として複数範囲が重複した場合はエラー(終了コード2)
- スナップ後の実際の適用範囲は `--dry-run` および verbose ログで報告する

### 5.3 カット検出と波及処理

検出:
- フレーム差1の隣接キー間で、カメラ中心位置またはカメラワールド位置のジャンプが
  cut-threshold(距離)を超える、または角度のジャンプが cut-threshold(角度)を
  超える箇所をカットとみなす。カメラワールド位置を併用するのは、距離のみが
  急変するズームカットがカメラ中心位置・回転のいずれにも現れないため
- ジャンプ量の計量: 位置(カメラ中心・カメラワールド位置)は3次元ユークリッド距離、
  角度は2キーのカメラ姿勢(回転行列)間の測地角(度)とする。判定はいずれも
  厳密超過(`>`。閾値ちょうどはカットにしない)
- カットフレームFは「フレームFから新しいショットが始まる」ことを意味し、
  セグメント境界は F-1 と F の間に置く
- コアAPIではカット位置の手動指定(追加・打ち消し)が可能で、自動検出に優先する。
  手動指定のフレーム番号も上記の定義に従う。CLIからは `--cut-threshold` による
  感度調整のみを公開する
- 検出されたカット位置は `--dry-run` および verbose ログで必ず報告する

カットの波及処理
(カットはベイク範囲を独立したセグメントに分割し、以下すべてに作用する):
1. ノイズ位相: セグメントごとにシードを派生し、位相を連続させない
2. 速度解析(§6.2): カットをまたぐ差分を速度計算から除外する。
   正規化・プロファイルブレンドはセグメント単位で行う
3. settle: カット点では発動しない(前ショットの運動と無関係のため)
4. フェード: カット点ではフェード不要。揺れが非ゼロのまま
   切り替わってよい(実写でもカットをまたいで揺れは突然変わる)
5. カットの保存: ベイクは毎フレームキーのため、隣接キーの値ジャンプ自体は
   出力でもそのまま保持される(カットがなまることはない)

## 6. 揺れ生成仕様

### 6.1 ノイズ
- C1連続ノイズ(パーリン/シンプレックス)、チャンネルごとに独立シード派生
- ノイズ成分: 各オクターブ成分 `noise(freq × 2^i × t)` を生成する。主経路の合成重みは
  persistence 固定ではなく、§6.2 の静止/移動プロファイルを速度でクロスフェードした
  フレーム毎のオクターブ重みが担う(`freq` は `--freq`、オクターブ数=プロファイル長)
- 補助API `band_limited_noise` は固定重み合成 `Σ persistence^i × noise(freq × 2^i × t)` を
  提供する。等価性テストおよび単一オクターブ(octaves=1)のインパルス発振生成で使うが、
  主経路のカメラ手ぶれノイズの調整軸ではない
- 帯域制限: 実効周波数 > 8Hz のオクターブは生成しない(自動クランプ+警告)。
  ベイクは30fps固定(ナイキスト15Hz)のため、8Hz上限で線形補間でも波形が保存される

### 6.2 モーション適応
- ベイク時に元モーションの角速度・移動速度を算出し正規化する。正規化は
  **内蔵の基準速度による絶対正規化**(`正規化速度 = clamp(絶対速度 / 基準速度, 0, 1)`)とし、
  セグメント内ピークでは割らない。これにより同じカメラ速度はクリップ内の他の動きに依らず
  同じだけ適応する(ピーク正規化だと、同セグメントに速い動きがあると遅い動きが過小評価される)。
  基準速度は移動(ワールド位置)と回転(角度)で別個に持つ(内蔵・コアAPI/プリセットで調整可)。
  基準速度が 0 以下のときは退避として正規化速度を全 0(=適応無効)とする。
  速度の差分計算・プロファイルブレンドはカットで分割されたセグメント単位で行い、
  カットをまたぐ差分は除外する(§5.3)
- 実効振幅 = 基本振幅 × clamp(1 − motion_damp × 正規化速度, 0, 1)
  (速度が上がるほど揺れを減衰させ、高速ではほぼ 0。motion_damp=0 で減衰なし=無効)
- 静止/移動プロファイルを速度に応じてクロスフェード
  (振幅だけでなくオクターブ重み=周波数構成を切り替える)
- 停止検出: 角速度がしきい値を下回るゼロクロス点を検出し、
  直前の移動方向への減衰振動(初期振幅 `--settle`、収束時間は内蔵値)を加算。
  カット点では発動しない(§5.3)
- 完全静止区間: 高周波微動+長周期ドリフト(呼吸0.3Hz相当を含む)に収束させる

### 6.3 インパルス
- `--impulse F:S:D`: フレームF以降に `S × exp(-t/D)` の包絡を持つ高周波揺れを加算。
  揺れ成分は§6.1と同じ8Hz帯域制限に従う
- 方向はシードから決定(方向ベクトルの明示指定は非対応)
- 複数指定は加算合成

## 7. テスト要件

テストフレームワーク・実行方法・テストデータの扱いは ../mmd_toolbox/mmd_toolbox.md §4 の方針に従う
(pytest、ルートで `pytest shakevmd` のみで実行可能、決定論的)。

フォーマットレベルの検証(ラウンドトリップのバイト一致、補間評価のMMD互換、
入力正規化、カメラ変換の往復一致)はmmd_toolbox側のテスト要件として担保する
(../mmd_toolbox/ の各仕様書)。以下のうち1・8はmmd_toolbox管轄と重なるが、
shakevmdを通した統合確認として実施する。

1. 範囲外キーの無傷性: `--range` 指定時、ベイク区間外のカメラキーが入力の原本と
   レコード内容(バイト単位)で一致すること。出力はフレーム昇順に整列されるため、
   検証は格納順ではなくフレーム対応するレコード内容の一致で行う。順不同・重複キーを
   含む入力でも、出力は原本レコードをそのまま使うため一致する(§3.2。正規化は内部
   作業ビューのみで出力を決めない)
2. ベイク忠実性: 揺れ0でベイクした出力と元VMDを同一フレーム時刻でサンプリング比較し、
   全チャンネル誤差が許容値以下
3. 非対象チャンネル透過: ベイク区間内に視野角の補間とパースペクティブの切り替えを
   含む入力で、(a) 視野角が一定の区間では各密キーの視野角が元曲線のサンプル値の四捨五入
   (整数度)、視野角が変化する区間では密キーを焼かず元キーがバイト単位で温存されること
   (b) パースペクティブが直前キーの値のホールド、となること(§3.1)
4. 境界連続性: 範囲端前後の値・差分(速度)が連続
5. 再現性: 同一入力・同一引数で出力がバイナリ一致
6. 視線揺れ変換検証: 回転ノイズのみ適用時、揺れ適用後のカメラワールド位置が
   元と一致すること(§4.2)
7. カット非連続性: カット前後でノイズ位相が独立していること
8. 入力正規化: 順不同キー・重複フレームキーを含むVMDが仕様通り処理されること
9. カット波及: カットを含む範囲で (a) 速度解析にカット由来の偽速度が混入しない
   (b) カット直後にsettleが発動しない (c) カット前後で位相が独立、を検証
10. カット保存: 入力のカット(隣接キーの値ジャンプ)が出力VMDでも同一フレーム・
    同一値差で保持される
11. カット手動制御: コアAPIの手動カット指定(追加・打ち消し)が自動検出に
    正しく優先すること
12. 非対象セクション透過: ボーン/モーフ/照明/セルフ影/IKキーが混入した入力で、
    警告が表示され、これらのセクションが出力にバイト単位で保持されること
    (順不同のボーンキーがソートされずに透過することを含む)
13. 滑らか出力(`--smooth` / `--no-smooth`): ベイク後の密キーをプロセス内で疎ベジェへ削減した出力が
    (a) 実質的に疎化し位置・回転チャンネルがベジェ補間になる (b) 固定素材で、位置・回転・距離・
    視野角がサブフレーム(60fps超を含む)でも密ベイクに対し aggressive 許容内(=手ぶれ品質を保持)
    (c) カット境界とパースペクティブが保持される (d) 中間VMDを書かず最終出力1回のみ
    (e) 密VMD経由の sparsevmd CLI パイプライン(同設定)と aggressive 許容内で整合すること
    (バイト完全一致は前提にしない。§3.3)。さらに (f) **既定 on**: フラグ無しの出力が `--smooth`
    明示時とバイト一致し疎化する (g) `--no-smooth`: 削減を無効化し全61キー・全チャンネル線形の
    密出力になること

## 10. 既知の制約・運用上の注意

- `--no-smooth` の密出力はキー数が膨大になり、MMD上での手修正は実質不可能。既定の滑らか出力
  (§3.3)は疎ベジェ化でキー数を抑えるが、いずれの場合も揺れの適用は編集の最終工程とすること
  (Readme記載必須)
- VMDのキーフレームは30fps整数フレームのみ。60fps再生時の中間フレームは MMD側の補間で
  生成される。ノイズは8Hz以下に帯域制限されており線形補間でも波形(振幅・周波数)は十分
  保存されるが、密キー＋線形補間はキー間の速度が各フレームで不連続になり(角)、30fps超再生で
  微細な振動として見えることがある。既定の滑らか出力(§3.3)がこれを低減する。`--no-smooth` を
  指定すると密キー＋線形のままになり、この微振動が残りうる
- 滑らか出力(§3.3)の許容判定は **30fps 整数フレーム**で行うため、キー間(サブフレーム)での
  真の揺れへの追従は保証しない。代表素材ではサブフレームでも許容内だが、強インパルスでは
  サブフレームで密出力から数度規模の乖離が出うる。これを解析ソースの連続時刻フィットで
  改善する将来改修案を §11 に記す(未実装)
- VMDの視野角は整数度(u32)でしか保存できないため、視野角への滑らかな揺れは
  フォーマット上表現不可能。本ツールは視野角を揺れの対象としない。さらに、視野角が変化する
  区間を毎フレーム密キーで整数化するとズームが1°刻みの階段になるため、その区間は密キーを焼かず
  元キーを温存して MMD の実数補間に委ねる(§3.1。温存区間には揺れが乗らない)
- カット自動検出は閾値ベースのため、誤検出(高密度キーによる高速カメラワーク)や
  見逃し(類似構図への小ジャンプカット)が起こりうる。`--dry-run` で検出位置を
  確認し、まず `--cut-threshold` で感度を調整、それでも合わない場合は
  コアAPI(Jupyter)からの手動カット指定で修正する運用を推奨する
- MMDの仕様上、入力VMDの補間曲線評価がMMD本体と完全一致することを目標とするが、
  本体の実装差異が発見された場合は本体挙動を正とする

## 11. 将来課題(未実装): 解析直接フィットによるサブフレーム忠実化(B-2')

ステータス: 未着手・未スケジュールの改修案。着手前に §11.4 の設計未確定点を確定し、試作で
§11.5 の効果(MMD 60fps 目視)を確認できてから本実装へ進む(効果確認は試作を要するため、
試作を本実装前の工程に置く)。

### 11.1 動機
現行の滑らか出力(§3.3。以下 B-1)は、密ベイク列を **30fps 整数フレームのサンプル**として
`reduce_camera_track` で疎ベジェへ削減し、誤差判定も整数フレームで行う。B-1 は手ぶれ振幅を
整数フレームで許容内に保つ(平坦化しない)が、**キー間(60fps 等のサブフレーム再生位置)での
真の揺れへの追従は保証しない**。強インパルスではサブフレームで密出力から無視できない乖離が出る
(実測で数度規模、§10)。本課題は、揺れの解析ソースを連続時刻で直接フィットしてサブフレーム
忠実度を高める改修(以下 B-2')を記す。

### 11.2 提案(B-2')
bake が合成する**解析揺れの全成分(ノイズ・モーション適応・呼吸ドリフト・歩調 gait・settle・
フェード・インパルス)を連続時刻の評価関数として扱い**、整数フレームのキー値にはその評価値を
用いつつ、**フィットの采否をサブフレーム(60fps 相当)での真の信号との誤差で制御**する。出力は
B-1 同様、整数キー＋区間ベジェ。連続化で一部成分(呼吸ドリフト・歩調・settle 等)を落とすと
walking 等の挙動を失うため、bake の全成分を漏れなく連続評価に載せる(対象成分は `bake.py` を正とする)。

リデュースエンジン(チャンネル評価器・分割ドライバ・ベジェフィット)は共通ライブラリ
`mmd_toolbox.vmd`(`reduce.py` / `fit.py`)に共有済み。本改修は「整数キー列ソース」に加えて
**連続ソース(実数時刻の評価関数)をサブフレームで誤差評価する経路**をエンジンへ足し、shakevmd が
それを駆動する形になる。対象ファイルは中核が `bake.py`(揺れを連続時刻評価へ作り替え、誤差制御
フィットを駆動)と共通ライブラリの `reduce.py` / `fit.py`(サブフレーム誤差評価経路の追加)、加えて
`cli.py`(`--smooth` 配線の軽微変更)と両側のサブフレーム回帰テスト。概算 約 400〜700 行。

### 11.3 B-1 比の優位と限界
優位(主に高周波・速いトランジェント・帯域上限 8Hz 付近で顕在):
- **サブフレーム誤差が真の信号に対して有界**。B-1 は整数フレームでしか誤差を見ないため、キー間で
  ベジェが真の揺れからずれうる(強インパルスでサブフレームに数度規模の乖離)。B-2' は 60fps 位置でも
  許容内に収める。
- **折返し(極値=速度0)近傍で端傾き(イーズ)を真の信号へ近づけうる**。B-1 は整数サンプルの離散差分
  しか持たず、折返しが整数上か中間かも区別できない。ただし**値残差の最小化だけでは端傾きは保証
  されない**(値が合っても傾きはずれうる)。確実に付けるには端傾きを微分制約として目的関数へ
  加える必要がある(§11.4)。
- **「サンプルの再フィット」二重損失を回避**(解析→整数化→再フィット ではなく 解析→直接フィット)。

限界(B-2' でも超えられない天井):
- VMD キーは整数フレームのみ、MMD のベジェは1区間=単調イーズ1本。**整数フレーム間に真の極値が
  あると B-1/B-2' とも表現できない**(キーが極値近傍に来ない限り)。ピーク振幅自体は上がらず、差は
  あくまでキー間の追従に出る。
- 低周波(既定 `--freq` 1.2Hz)では B-1 との差は小さい。
- 体感効果は未検証(§11.5)。「原理的に上」は「体感で有意」を意味しない。

### 11.4 設計上の未確定点(着手前に確定)
- **非整数極値の整数キー化**: サブフレーム極値を近傍整数へ寄せる / 両側整数を境界にする /
  誤差分割に委ねる、のいずれか。
- **連続化の範囲**: `motion_damp`・速度プロファイル・停止検出(settle)は現状、整数フレーム列から
  計算している。どこまで連続時刻化するか。
- **B-1 経路の扱い**: B-2' で置換するか、B-1 を残して切替にするか。
- **視野角**: 整数度保存のため、疎キー＋イーズで緩和しても完全解決ではない。視野角温存区間との整合。
- **端傾き(C1)の与え方**: サブフレーム誤差評価による値追従だけで十分か、折返し近傍で端傾きを
  微分制約として目的関数へ明示的に加えるか(現行フィットは値残差のみを最小化する)。
- **サブフレーム誤差の判定基準**: 評価点(各整数フレーム間のどのサブフレーム位置を見るか)・
  チャンネル別の誤差尺度と許容値・合格条件。現行 `reduce_camera_track()` の許容検証は整数フレーム
  対象なので、サブフレーム経路の判定基準を別途定義する必要がある(§11.5 の目視と併せて決める)。
- **連続信号(サブフレーム比較の「真の信号」)の定義**: bake() の出力は元カメラ軌道に揺れを合成
  した値で、元軌道は `interp.sample_camera()`(整数フレーム API)で得て `apply_gaze_shake()` で揺れと
  合成する。サブフレームで比較する真の信号を一意に
  するには、元カメラ軌道の実数時刻補間・揺れ全成分(§11.2)との合成方法・カット/視野角温存境界での
  扱いを定義する必要がある。モーション適応も元軌道のワールド位置・角速度に依存するため、その
  連続時刻化も含める。

### 11.5 検証
効果は **MMD の 60fps / 無制限再生での目視確認が必須**。代表素材は「ほぼ静止〜緩いパン＋高周波の
揺れ」(極値が密に出る最悪条件)。判断軸はブルブルが減るか・質感が丸まりすぎないか・キー削減率。
比較は整数フレームだけでなくサブフレーム誤差でも B-1 と突き合わせる。

### 11.6 スコープ外
- 品質プリセット体系の変更(sparsevmd 等の品質プリセット体系を含む)。
- shakevmd からの bone 経路利用(shakevmd はカメラのみ)。
