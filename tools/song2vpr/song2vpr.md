# song2vpr 要求仕様書

歌の音声ファイルから VOCALOID プロジェクトファイル(vpr)を生成する独立CLIツールの要求仕様。

本書は `song2vpr` が**満たすべきこと**を定める。推定・分割・変換の手順、内部のしきい値、データ構造の
突き合わせ方といった実現方法は本書の対象ではなく、本書が定める要求を満たす範囲で実装が選ぶ。

---

## 1. 位置づけ

### 1.1 結論

本機能は `song2vpr` という独立CLIツールとして提供する。

`song2vpr` は、日本語の歌の音声ファイル(BGM込み可)を入力に、ボーカル抽出・音素認識(共有モジュール
`vocal_analysis`)＋ ピッチ推定 ＋ 音符分割・歌詞/音素対応付けを経て、共有モジュール `vpr` で vpr を
**1コマンド**で書き出す。

```text
入力 音声ファイル(歌, mp3/wav 等)
  -> song2vpr(vocal_analysis: 分離・音素認識 → ピッチ推定 → 音符分割・歌詞/音素対応付け → vpr 書き出し)
  -> vpr
  -> VOCALOID で確認・編集
```

### 1.2 設計境界

[../../docs/conventions/layering.md](../../docs/conventions/layering.md) の設計境界に従う。

- **音声前段**(ボーカル抽出・音素認識・ボーカルWAV・RMS)は共有モジュール
  [vocal_analysis](../../libs/vocal_analysis/vocal_analysis.md) に委譲する。前段を通しで実行する結線
  (呼び出し順序・失敗の分類・進捗の中継・長尺の自動分割・診断用中間生成物の書き出し)も同モジュールの
  前段実行エンジンへ委譲し、`song2vpr` 側には実行ポリシーと保存先の選択、受け取った進捗と失敗の
  利用者向けの扱いが残る([vocal_analysis.md §11](../../libs/vocal_analysis/vocal_analysis.md#11-前段実行エンジン))。
- **vpr の書き出し**は共有の形式I/Oモジュール [vpr](../../libs/vpr/vpr.md) に委譲する。`song2vpr` は vpr の
  バイナリ/直列化構造を直接扱わない。
- **`song2vpr` 固有**: ピッチ推定、音符分割、歌詞/音素対応付け、テンポ・拍子の推定、
  ツール固有のCLI引数。
- **音声前段を駆動する共通引数群**の名前・意味・既定・検証と設定への解決は共有モジュール
  `vocal_analysis_cli` に委譲する([vocal_analysis_cli.md](../../libs/vocal_analysis_cli/vocal_analysis_cli.md))。
  `song2vpr` 側に残るのは、この共通引数群を公開するという判断と、本書が示す利用者向けの公開契約である。
- **引数の値の範囲・書式の検証**と、自己記述で公開する制約をひとつの定義から導く仕組みは共有モジュール
  `cli_options` に委譲する([cli_options.md](../../libs/cli_options/cli_options.md))。ツール固有引数について、
  どれを公開するか・その意味・既定値・型以外の意味制約は `song2vpr` 側に残る。
- **進捗の報告先の振り分け**(機械モードのイベント送出と人間向けライブ表示の切り替え)は共有モジュール
  `cli_progress_router` に委譲する([cli_progress_router.md](../../libs/cli_progress_router/cli_progress_router.md))。
  段 id の集合と、それに対応する利用者向けの工程名は `song2vpr` 側に残る([§4.3](#43-進捗表示))。
- **資源逼迫と GPU 実行構成の観測・判定**は共有モジュール `cli_resource_watch` に委譲する
  ([cli_resource_watch.md](../../libs/cli_resource_watch/cli_resource_watch.md))。判定を呼ぶタイミングと、
  成立した警告を人間向け1行・warning イベントのどちらへどう出すかは `song2vpr` 側に残る
  ([§5.2](#52-資源逼迫の警告)・[§5.3](#53-gpu-を使えない構成の警告))。

### 1.3 独立ツールとする理由

- 出力が vpr(音符＝**ピッチ**を持つ)で、リップモーションVMD(`song2vmd`)とは必要情報が異なる。`vpr` はピッチを持ち
  強弱は音符のベロシティ/ダイナミクスで表す。共有するのは音声前段(`vocal_analysis`)で、ピッチ推定・音符化は
  `song2vpr` 固有。
- 主たる新規リスクは**ピッチ系**(F0推定・音符分割)で、音素認識は `vocal_analysis` で実証済みのものを使う。
- `song2vpr` は口形イベントを要さないため、`vocal_analysis` の共有出力は音素粒度で足りる(口形イベント確定は
  `song2vmd` 入口の話で、`song2vpr` は使わない)。

## 2. 目的

### 2.1 解きたい問題

歌の音声から VOCALOID で編集できる vpr(ピッチ・歌詞・音符のあるプロジェクト)を起こすのは手間が大きい。
音声から音符(ピッチ・時刻・歌詞/音素・強弱)を自動抽出し、vpr の下書きを生成して編集の出発点にする。

### 2.2 非目標

- リップモーションVMD は生成しない(それは `song2vmd`)。
- 完全な歌唱合成・採譜の完全自動化は対象外。あくまで編集の出発点となる vpr 下書きを作る。
- 日本語以外は対象外(音素認識・歌詞対応が日本語前提)。
- 歌唱のビブラートを検出して音符へ書くことは行わない。検出の正しさを確かめる物差しが無く、想定入力
  (実歌唱・実曲)では確かめられるだけの件数が得られない。誤って付いたビブラートは利用者が全音符を
  点検して外すことになり、下書きの手直しをかえって増やす。ビブラートは利用者が VOCALOID で付ける。

## 3. 処理パイプライン

```text
入力 音声ファイル(歌, BGM込み可)
  ├─ 音声前段          vocal_analysis(共有)→ 分離後ボーカルのPCM・音素セグメント列(母音/子音/gap＋IPA)・相対正規化RMS
  ├─ ピッチ推定      song2vpr側 → 時刻ごとの基本周波数(F0)・有声/無声
  ├─ 音符分割・対応付け song2vpr側 → F0＋音素セグメント＋RMSから音符(ピッチ・開始/長さ・歌詞/音素・強弱)
  └─ vpr 書き出し      vpr(共有)→ vpr
```

- **音声前段(vocal_analysis)**: ボーカル抽出・音素認識は `vocal_analysis` に委譲し、分離後ボーカルのPCMと
  音素セグメント列・相対正規化RMSを得る([vocal_analysis.md §2](../../libs/vocal_analysis/vocal_analysis.md#2-共有出力正規化中間形式)〜[§6](../../libs/vocal_analysis/vocal_analysis.md#6-強弱エンベロープs3))。
- **ピッチ推定(`song2vpr` 固有)**: 分離後ボーカルから F0(基本周波数)と有声/無声を求める。ピッチ推定は
  `song2vmd` では不要なため `vocal_analysis` には含めず、`song2vpr` 固有処理として置く。
- **音符分割・歌詞/音素対応付け(`song2vpr` 固有)**: F0・音素セグメント・RMS から音符を切り、各音符に
  音高・開始時刻・長さ・歌詞・音素・強弱を与える([§7](#7-音符化歌詞対応テンポの規則))。歌詞・音素は音素セグメント由来で、
  意味のある歌詞書き起こしは行わない。
- **vpr 書き出し(vpr)**: 音符列・テンポ・拍子を `vpr` のデータモデルへ載せ([§7.4](#74-出力する-vpr-の構造))、vpr を書き出す([vpr.md §2](../../libs/vpr/vpr.md#2-データモデルvpr-が公開する抽象)・[§4](../../libs/vpr/vpr.md#4-書き出しwrite))。

## 4. コマンドライン仕様

### 4.1 書式

```text
song2vpr INPUT [options]
```

`INPUT` は音声ファイル。既定出力は `<入力名>.vpr`。

### 4.2 オプション

| 引数 | 既定 | 説明 |
|---|---:|---|
| `INPUT` | 必須 | 入力音声ファイル |
| `-o, --output PATH` | `<入力名>.vpr` | 出力 vpr |
| `--overwrite` | off | 出力先の既存ファイルへの上書きを許可する(上書きガードの解除。[§5](#5-入出力要件)) |
| 音声前段の共通引数群 | 共有側の既定 | ボーカル分離の実施方針・分離バックエンド・内容認識モデルとそのリビジョン・内容認識のリトライ・強制アライメント段・SOFA 設定・英語カタカナ化フォールバックの方式・実行デバイス・長尺の自動分割の目標長を選ぶ共通引数群を**全件公開する**。個々の引数名・型・既定・意味と組み合わせ検証は [vocal_analysis_cli.md §2](../../libs/vocal_analysis_cli/vocal_analysis_cli.md#2-共通引数群)・[§3](../../libs/vocal_analysis_cli/vocal_analysis_cli.md#3-組み合わせ検証) が定める |
| `--tempo BPM` | 自動推定 | テンポ(四分音符を1拍とした BPM。vpr 形式が格納できる粒度で表せる最小の正値以上の有限値)。未指定時は音声から推定する([§7.3](#73-テンポと拍子)) |
| `--time-signature N/D` | 自動推定 | 拍子(`4/4` の形式。分子は正の整数、分母は音価を表す2の冪で、1拍が整数の tick になる範囲)。未指定時は音声から推定する([§7.3](#73-テンポと拍子)) |
| `--lyrics PATH` | なし | 任意の歌詞テキスト(漢字かな交じり可。UTF-8 で読む。[§7.2](#72-歌詞音素強弱の付与)) |
| `--dry-run` | off | 出力せず診断を表示([§4.5](#45-レポートと診断))。引数検証(上書きガード等)は dry-run でも実施する |
| `--keep-intermediate` | off | 診断用の中間生成物(正規化PCM・分離後ボーカルWAV・認識結果)を残す([§5](#5-入出力要件)) |
| `-v, --verbose` | off | 通常実行でも `--dry-run` と同じ診断を標準出力へ表示する(出力 vpr は書く。[§4.5](#45-レポートと診断))。機械モードでは標準出力をイベント専用に保つためこの人間向け表示は出さない([§9](#9-機械モード機械可読インターフェース)。イベント内容も変えない) |
| `--quiet` | off | 進捗表示を抑制する([§4.3](#43-進捗表示))。警告・診断・終了コードは抑制しない |
| `--version` | — | バージョンを表示して終了する |
| `--machine` | off | 機械モード。標準出力を JSON Lines のイベントストリームにする([§4.4](#44-機械モードとメタ操作機械可読インターフェース)・[§9](#9-機械モード機械可読インターフェース)) |
| `--describe` | — | オプション定義を構造化して出力し終了する([§4.4](#44-機械モードとメタ操作機械可読インターフェース)・[§9](#9-機械モード機械可読インターフェース)) |

`--time-signature` の分母が2の冪であることは、範囲の形で表せず自己記述の制約に載せる場所が無いため
([cli_options.md §3](../../libs/cli_options/cli_options.md#3-複合トークンの検証子))、`help` に示す(分母の上限は範囲として表せるので自己記述に載る)。
`--tempo` の下限は値域なので、そのまま範囲として表す。

音声前段のバックエンド選択は共通引数群として CLI で全件公開する。引数の名前・意味・検証は共有側
([vocal_analysis_cli.md](../../libs/vocal_analysis_cli/vocal_analysis_cli.md))が定め、選択肢の追加・切り替えは
`vocal_analysis` 側で行う([vocal_analysis.md §8](../../libs/vocal_analysis/vocal_analysis.md#8-外部ツール連携機構))。挙動パラメータの取り回しは
[CLI インターフェース規約 §9](../../docs/conventions/cli-interface.md#9-入力出力とパラメータの取り回し) に従う。

### 4.3 進捗表示

重い処理(分離・認識・ピッチ推定)の間に何も表示されず無音になるのを避けるため、処理の段階を報告する。
段は音声読み込み(`load`)・ボーカル分離(`separate`)・音素認識(`recognize`)・音量解析(`rms`)・
ピッチ推定(`f0`)・音符化(`notes`)・書き出し(`write`)の7つ。前の4つは音声前段の実行エンジンから
中継し([vocal_analysis.md §11](../../libs/vocal_analysis/vocal_analysis.md#11-前段実行エンジン))、後の3つは `song2vpr` 自身が報告する。
複数のツールで共有する段の工程名は[用語規約の処理工程の利用者向け名称](../../docs/conventions/terminology.md#処理工程の利用者向け名称)が正で、
`song2vpr` 固有の `f0`・`notes` は同表に載せず本書が定める。
有効条件・表記・停滞回避・副作用専用等の一般契約は
[CLI インターフェース規約 §6](../../docs/conventions/cli-interface.md#6-横断的な一貫性)が正。

**報告先の振り分け**(機械モードのイベント送出と人間向けライブ表示の切り替え・TTY判定と `--quiet` の
反映・同一段での進行更新・送出失敗の区別)は共有モジュール
[cli_progress_router](../../libs/cli_progress_router/cli_progress_router.md) が定める。`song2vpr` は段 id と、
それに対応する利用者向けの工程名を渡す([§9](#9-機械モード機械可読インターフェース))。

音声前段は処理中に標準エラーの出力先を一時的に差し替えることがあり、その間に人間向けのライブ表示が
同じ標準エラーへ書くと書き込みに失敗しうる。これを避けるため、`song2vpr` は前段が公開する
排他の仕組みを進捗表示へ渡す([vocal_analysis.md §8.1](../../libs/vocal_analysis/vocal_analysis.md#81-アダプタinterface))。

### 4.4 機械モードとメタ操作(機械可読インターフェース)

他のソフトウェアが子プロセスとして呼ぶ機械利用のために、機械可読の起動フラグを持つ。共通の契約
(チャネル固定・イベント種別の語彙・終端規則・終了コードの基底・標準出力の UTF-8 固定)は
[CLI インターフェース規約](../../docs/conventions/cli-interface.md)が正で、イベント送出は共有基盤
[cli_events](../../libs/cli_events/cli_events.md) を用いる。song2vpr 固有のイベントペイロード・`code` 値は
[§9](#9-機械モード機械可読インターフェース)が定める。

- `--machine`: 出力を JSON Lines のイベントストリームにする([§9](#9-機械モード機械可読インターフェース))。標準出力はイベント専用、標準エラーは
  人間向けログ・警告、終了コードは[§8](#8-終了コード)。既定(非指定)の人間向け表示・終了コードは変えない。
- `--machine --dry-run`: 入力検査。vpr を書かず、入力メタ情報と診断の result イベント([§9](#9-機械モード機械可読インターフェース)の
  `mode:"inspect"`)を出す。
- `--describe`: 自己記述。音声を読まずにオプション定義の result イベント([§9](#9-機械モード機械可読インターフェース)の `mode:"describe"`)を出して
  終了する。`--machine` を要さず単独で起動でき、入力 positional も要求しない独立メタ操作。
- `--help`/`--version` は `--machine` と併用しても人間向けテキストを出して終了コード0で終わり、イベント
  ストリームには載せない(処理を起動しないメタ操作のため。規約 [§3](../../docs/conventions/cli-interface.md#3-機械モードの起動) のメタ操作の例外)。`--help` は各
  オプション・引数の役割を人間向けに説明し、対話利用者が `--help` だけで使い方を把握できるようにする。
- 真偽フラグを対で持つ場合は `--x`/`--no-x` の様式に揃える(規約 [§6](../../docs/conventions/cli-interface.md#6-横断的な一貫性))。

### 4.5 レポートと診断

`--dry-run` は以下を出力する。`-v`/`--verbose` は出力 vpr を書く通常実行のまま、同じ内容を実行完了後に
標準出力へ追加で表示する(機械モードでは表示しない。[§9](#9-機械モード機械可読インターフェース))。

- 音声前段へ渡したバックエンド選択の設定(渡さなかったものは出さない)と、
  採用したテンポ・拍子・分解能(テンポと拍子は指定値・推定値・仮置きの別を含む)。
- 分離の有無、入力音声の尺、tick へ写した後の音符数。
- 撥音「ん」を入れた音符数、母音も鼻音も得られず「あ」を入れた音符数、音素列が空の音符数([§7.2](#72-歌詞音素強弱の付与))。
- まとめる先が無く短いまま残った音符数、音節と結びつかない・ベロシティが 0・核から離れた成分の
  3つの規則で出力しなかった音符数、音高を MIDI の範囲へ
  丸めた音符数([§7.1](#71-音符))、tick へ写す
  ときにまとめられて消えた音符数と、長さを 1 tick へ引き伸ばした音符数([§7.3](#73-テンポと拍子))。
- `--lyrics` 指定時は、モーラが尽きて表示歌詞を音声から決めた音符数と、破棄した余剰モーラ数。

診断の各件数は実測値なので、`--dry-run` でも書き出し以外は通常実行と同じに実行する。機械モードでは
同じ診断を構造化して返す: 通常実行は result(`mode:"run"`)、`--machine --dry-run` は入力メタ情報を
併せた result(`mode:"inspect"`)に載せる([§9.1](#91-イベントペイロード))。

## 5. 入出力要件

- 出力 vpr の書き出しは `vpr` に委譲する。`song2vpr` は vpr のバイナリ/直列化構造を直接扱わない。
- 音声前段(分離・認識)は `vocal_analysis` の共有出力を使う。利用者は `song2vpr INPUT` の1コマンドだけを実行し、
  外部ツールは内部で呼ばれる。
- **診断用の中間生成物**: `--keep-intermediate` 未指定時、`song2vpr` は診断用の中間生成物を追加でディスクへ
  書き出さない(音声前段が内部的に使う非公開の一時領域は
  [一時ファイル・中間生成物の配置規約 §2.2](../../docs/conventions/temporary-and-intermediate-files.md#22-非公開の内部一時領域) の対象であり、本節の対象外)。指定時のみ、
  保存先を出力に隣接するディレクトリに決めて音声前段の書き出しを有効にする
  ([§4.2](#42-オプション))。何がどの名前・形式で保存されるかは
  [vocal_analysis.md §11.2](../../libs/vocal_analysis/vocal_analysis.md#112-診断用中間生成物の書き出し) が定める。置き場所・命名・有効化契約の一般規約は
  同配置規約 [§2.3](../../docs/conventions/temporary-and-intermediate-files.md#23-利用者向けオプトイン診断用中間生成物) を正本とし、本機能はそこに従う。`--dry-run` と併用した場合も、
  最終 vpr の書き出しだけが抑制され、中間生成物の保存は実施する。書き込み失敗は
  [§9.3](#93-構造化エラー)の分類で報告する。保存先に前回の中間生成物が残っていても上書きガードの対象にせず、
  `--overwrite` を要さずに上書きする(診断用の使い捨ての生成物で、利用者の作った成果物ではないため)。
- **上書きガード**: 出力先の既存ファイル保護は[CLI インターフェース規約
  §6](../../docs/conventions/cli-interface.md#6-横断的な一貫性) に従う(終了コード2。[§8](#8-終了コード))。出力先が既存のディレクトリの場合は
  `--overwrite` でも書けないため、上書きガードより前に `--overwrite` の有無に依らず専用のコードで拒否する
  ([§9.3](#93-構造化エラー))。
- **出力の原子性**: vpr は一時ファイルへ書き切ってから最終パスへ置換する。この置換は書き出し関数自身の契約
  ([vpr.md §2.1](../../libs/vpr/vpr.md#21-公開する具体型と関数))なので、`song2vpr` は書き出しへ委譲するだけで満たす(一時パスの扱いを重ねて持たない)。
  途中終了で中途半端な出力ファイルを残さない(中断は[§9.4](#94-中断))。
- **歌詞ファイルの読み取り時点**: `--lyrics` のファイルは、追加依存のガード([§5.1](#51-追加依存の未導入時の起動))を通した後、音声前段を
  始める前に読み取る。誤指定・復号失敗([§9.3](#93-構造化エラー)の `lyrics_unreadable`)が分離・認識を終えてから露見しない
  ようにするため。`--dry-run` でも同じ位置で読む。前倒しするのはファイルの読み取りまでで、読みへの変換の
  失敗([§9.3](#93-構造化エラー)の `stage_failed`)は音符へ歌詞を割り当てる段で報告する。
- **入出力の受け渡し・移植性**は規約 [§9](../../docs/conventions/cli-interface.md#9-入力出力とパラメータの取り回し)・[§10](../../docs/conventions/cli-interface.md#10-移植性パス符号化改行ロケール) に従う(ファイルパス受け渡し・非ASCIIパス対応)。

### 5.1 追加依存の未導入時の起動

音声前段([§6](#6-vocal_analysisvpr-との関係))は配布物の追加依存(`vocal-analysis` extra)を要する一方、コンソールスクリプトは
追加依存なしの導入でも登録される。したがって依存が揃わない環境からも起動されうる。

- 追加依存の取り込みに失敗した場合は、理由(取り込めなかったモジュール名と導入コマンド)を
  `missing_dependency`・終了コード4で返す([§8](#8-終了コード))。非機械モードは標準エラーへの1行、機械モードは
  error イベント([§9.3](#93-構造化エラー))で、他の失敗と同じ経路に載せる。トレースバックは出さない。理由1行の
  組み立てと、ガードをどの時点で評価するかは共有側
  ([vocal_analysis_cli.md §5](../../libs/vocal_analysis_cli/vocal_analysis_cli.md#5-追加依存の未導入))が定める。
  どの取り込みが追加依存を要するかの宣言と、ガードの評価そのものは `song2vpr` が持つ。
- 上の評価位置の帰結として、メタ操作(`--help`/`--version`/`--describe`。[§4.4](#44-機械モードとメタ操作機械可読インターフェース))と引数エラーは
  追加依存の有無に依らず成立し、それぞれ規約が定める終了コード(メタ操作は0、引数エラーは2)で終わる。
  未導入の環境でも対話利用者は `--help` で使い方を、機械利用側は `--describe` でオプション定義を得られる。
- 切り分けは取り込みの単位で行う。追加依存を要しない配布物内のモジュール(共有ライブラリ・ツール自身の
  モジュール)を直接取り込む経路は本判定の対象に含めない。導入自体の破損であり、追加依存の導入案内は
  誤った誘導になるため。追加依存を要する取り込みが連鎖して取り込む配布物内のモジュールは、この切り分けの
  外にあり本判定に含まれる。

### 5.2 資源逼迫の警告

処理中にVRAM・RAMの逼迫が実際に起きたことを観測した場合に警告を出す。**何を観測し、どの事実が成立
したときにどの警告コードで報告するか**(観測値の併載・同一コードを1実行1回に絞ること・観測手段が使えない
環境での縮退を含む)は共有モジュール
[cli_resource_watch](../../libs/cli_resource_watch/cli_resource_watch.md) が定める。

- **公開する警告コード**: GPUメモリの超過(`gpu_memory_oversubscribed`)とスワップの検出
  (`swap_detected`)の2つを warning イベントの語彙として公開する([§9.1](#91-イベントペイロード))。
- **判定タイミング**: 処理段の切り替わり時([§9.1](#91-イベントペイロード)の progress と同じ stage 語彙の各段の開始時)に
  判定を呼ぶ。進捗の報告と判定の呼び出し順は共有側が用意する接続を使う
  ([cli_resource_watch.md §4](../../libs/cli_resource_watch/cli_resource_watch.md#4-進捗との接続))。
- **本文の組み立て**: 判定が返すのは安定コードと観測値だけなので、機械モードの本文と人間向け1行は
  `song2vpr` が組み立てる。人間向け1行には観測値と、利用者が取れる対処(GPUメモリの超過では
  `--device cpu` での実行、スワップでは他のアプリケーションの終了)を添える。
- **副作用専用**: 警告は出力 vpr・終了コード・`--dry-run` の診断を変えない([§4.3](#43-進捗表示)の進捗表示と同じ位置づけ)。
  人間向けには標準エラーへ1行、機械モードでは warning イベント([§9.1](#91-イベントペイロード))を出す。`--device cpu` を
  指定した実行では GPU 側の観測手段が無いため、GPUメモリの警告は出ない。

### 5.3 GPU を使えない構成の警告

NVIDIA GPU を積んだ機材で、導入されている推論ライブラリの構成が原因で GPU を使えないときに警告を出す。
利用者が GPU を使うつもりでいるのに CPU で処理される状態を、処理を始める前に知らせる。**判定の条件**
(GPU の有無の見方・構成の区別・判定しない条件・観測できない環境での縮退)は共有モジュール
[cli_resource_watch](../../libs/cli_resource_watch/cli_resource_watch.md) が定める。

- **公開する警告コード**: CPU 専用版(`cpu_only_torch`)と、利用できない CUDA 版(`cuda_unavailable`)の
  2つを warning イベントの語彙として公開する([§9.1](#91-イベントペイロード))。
- **判定タイミング**: 実行デバイスの選択をプロセスへ適用した後、処理を始める前に1回だけ呼ぶ(適用より前に
  GPU を照会すると選択が効かなくなるため。[vocal_analysis_cli.md §4](../../libs/vocal_analysis_cli/vocal_analysis_cli.md#4-設定への解決))。
- **本文の組み立て**: [§5.2](#52-資源逼迫の警告)と同じく `song2vpr` が組み立てる。人間向け1行には、導入されている推論
  ライブラリのバージョンと、利用者が取れる対処(CPU 専用版なら CPU で処理する旨、利用できない CUDA 版なら
  別の CUDA のバージョンでの入れ直し)を添える。
- **副作用専用**: [§5.2](#52-資源逼迫の警告)と同じ位置づけで、出力・終了コード・診断を変えない。

## 6. vocal_analysis・vpr との関係

- 音声前段(分離・認識・分離後ボーカル・RMS)は `vocal_analysis`、vpr 書き出しは `vpr`。`song2vpr` は両者を束ね、
  ピッチ推定・音符分割・歌詞/音素対応付け・テンポと拍子の推定という `song2vpr` 固有処理を担う。
- 音声前段は、通しで実行する前段実行エンジンへ委譲する
  ([vocal_analysis.md §11](../../libs/vocal_analysis/vocal_analysis.md#11-前段実行エンジン))。`song2vpr` は解決した設定・
  長尺分割の実行ポリシー・中間生成物の保存先・進捗コールバックを渡し、共有出力と入力の音・分離後ボーカルの
  音・尺・強制分割の有無を受け取る。返る例外は[§9.3](#93-構造化エラー)の分類へ写す。
- 時間軸: `vocal_analysis` の出力は秒。`vpr` は vpr のテンポに基づく時間表現(tick)を扱う。秒から tick への
  変換は `song2vpr` 側で行う([§7.3](#73-テンポと拍子))。
- 設計境界どおり、CLI は別CLIに依存しない([`song2vmd.md`](../song2vmd/song2vmd.md) を参照しない)。共有は `vocal_analysis`・`vpr` を
  通じてのみ行う。

## 7. 音符化・歌詞対応・テンポの規則

音声から音符を起こすときに満たすべきこと。**音声前段の出力と F0 が同じなら、同じ引数から同じ vpr を得る**(決定論。
分離・音素認識・F0推定そのものが実行のたびに同じ結果を返すかは、選ぶ推定器の性質による)。
本章はその成果物が満たす性質を定めるもので、推定の手法・分割の手続き・内部のしきい値は定めない。

### 7.1 音符

- **音高**: 各音符は F0 から求めた MIDI ノート番号を1つ持つ。音高はその音符の中の揺れを均した代表値とし、
  ビブラートやしゃくりで瞬間的に半音を超えて動いても、それだけでは別の音符にしない。
  範囲(0〜127)を外れる値は端へ丸め、その件数を
  診断に出す([§4.5](#45-レポートと診断)・[§9.1](#91-イベントペイロード))。F0 のオクターブ誤りをそのまま vpr へ流さないため。
- **無声は音符にしない**: 無声と判定した区間には音符を作らない(休符は `vpr` が発音区間の補集合として
  導出する。[vpr.md §2.1](../../libs/vpr/vpr.md#21-公開する具体型と関数))。ただし後続の母音と同じ音節をなす子音の区間は、無声であっても
  その母音の音符に含める。音符の音素列から音節の頭の子音が落ちないようにするため([§7.2](#72-歌詞音素強弱の付与))。
- **音符を分ける条件**: 音高が変わる位置と、音節の切れ目で音符を分ける。ここでいう音節は、母音を1つ
  含む発声のまとまりと、母音を伴わない撥音を指す(標準の音節の定義とは撥音の扱いが異なる)。同じ音高が続いていても別の音節に
  なれば別の音符にする(1音符が1つの発声に対応する下書きにするため)。撥音は語中・語末を問わず1つの音符にする。促音は後続の音節に含め、単独の音符にしない。gap セグメントは音節の
  切れ目とみなさない: gap は認識器が音素を割り当てなかった区間で、発声の継続中にも出る
  ([vocal_analysis.md §5](../../libs/vocal_analysis/vocal_analysis.md#5-音素母音認識s2))。
- **音符は自分が属する音節を持つ**: 分割が決めた音節の帰属を音符が保持し、表示歌詞・音素列の付与
  ([§7.2](#72-歌詞音素強弱の付与))は音符区間との時間の重なりでなくこの帰属で行う(境界を跨ぐセグメントが隣の音符へ
  漏れないようにするため)。
- **短すぎる音符を独立させない**: 人が1音として歌っていない長さの音符は、**同じ音節に属する**隣の
  音符へまとめる(別の音節の音符へはまとめない。まとめると音節=モーラが消え、1音符が1つの発声に
  対応しなくなるため)。休符や別の音節で隔てられていてまとめる先が無いものは残し、その件数を診断に
  出す。長さの下限は内部の値で、CLI へは公開しない。
- **音節と結びつかない音符を出力しない**: 次の3つのいずれかに当たる音符は出力しない(分離しきれ
  なかった伴奏や、認識器が音素を割り当てなかった区間の残響が音符化するのを抑えるため)。
  1. どの音節にも属さない有声区間(前後に核が無く帰属を決められない区間)。
  2. ベロシティが 0 になる音符。
  3. **核へ届く音符**を1つも含まない**連続成分**のうち、成分の先頭の音符の開始が核の終端から離れて
     いるもの(成分を全件落とす)。ここで**連続成分**は、同じ音節に属し前の音符の終端と次の音符の
     開始が一致して続く音符の並びを指す。**核へ届く音符**は、その音節の核の区間と重なる音符と、
     頭子音を含むために核の開始より前から始まる音符を指す。離れの大きさは、成分の先頭の音符の開始と
     核の終端の差で測る。境目は内部の値で、CLI へは公開しない。核へ届く音符を含む成分と、核の終端の
     近くから始まる成分は全件残す——核と切れ目を挟んで続く歌唱は実在するため、成分の途中を時刻だけで
     切らない。**成分は (2) で落ちる音符も含めた並びで作る**(ベロシティが 0 の音符は成分を分断しない)。
     ベロシティは音量から決まる値で、音符の帰属と連続性はそれに依らないため。
  落とした件数は、上の3規則のいずれかで落とした音符の総数を診断に出す(1つの音符を二重に数えない。
  [§4.5](#45-レポートと診断)・[§9.1](#91-イベントペイロード))。
- **発音区間を重ねない**: 出力する音符の発音区間は互いに重ならない(`vpr` は歌唱トラックを単音想定とする。
  [vpr.md §2](../../libs/vpr/vpr.md#2-データモデルvpr-が公開する抽象))。長さ 0 の音符も出さない。

### 7.2 歌詞・音素・強弱の付与

各音符は表示歌詞・音素列・ベロシティを持つ([vpr.md §2.1](../../libs/vpr/vpr.md#21-公開する具体型と関数))。

- **音素列**: その音符が属する音節([§7.1](#71-音符))のセグメント由来の音素を時間順に並べる(音符区間との時間の
  重なりでは決めない。隣の音節の子音を載せず、同じセグメントの音素を複数の音符に重複して載せない)。
  音節が音高の変わり目で複数の音符に分かれた場合、音素列は音節の先頭の音符に載せ、2つ目以降は継続の
  音符(下記)にする。音素を割り当てられなかった
  区間(gap)と、VOCALOID の音素表記に写せない記号は音素列に載せない。載せる音素が1つも無い
  音符があってよい(継続の音符は数えない)。IPA から VOCALOID の日本語音素の表記(X-SAMPA)への対応は `song2vpr` が持つ。
  `vpr` はフォーマット層で、歌詞/音素対応付けのような生成・
  判断を持たない([vpr.md §1.2](../../libs/vpr/vpr.md#12-設計境界))。共有ドメイン層の `vocal_analysis` は VOCALOID の音素記号から
  母音・カテゴリを得る写像を持つ([vocal_analysis.md §7](../../libs/vocal_analysis/vocal_analysis.md#7-音素5母音写像))。同じ記号系を扱う表が2か所に並ぶことになるが、
  こちらは vpr を書き出すときにだけ要り、使うのは `song2vpr` だけなので共有側へは置かない。
- **表示歌詞(`--lyrics` なし)**: その音符が属する音節の頭子音と核の母音から、下記の**かな表**で
  表示歌詞を決める。核が撥音の音符には子音に依らず「ん」を入れる。頭子音が複数あるときは核に隣接する
  子音でかなを決め、残りの子音は音素列にだけ載せる(隣接する子音が `j` で、その前に別の子音があるときは、
  その子音の**拗音行**を使う)。母音も鼻音も得られない音符には「あ」を入れ、その件数を
  診断に出す。母音の5母音への写像は共有側が定める([vocal_analysis.md §7](../../libs/vocal_analysis/vocal_analysis.md#7-音素5母音写像))。
- **かな表**: 行は頭子音(認識器の音素語彙を写した VOCALOID の音素表記。「(なし)」は頭子音を
  持たない音節)、列は核の5母音。表は認識器の音素語彙(閉集合)と5母音の全組を覆う。

  | 子音 | a | i | u | e | o |
  |---|---|---|---|---|---|

  | `k` | か | き | く | け | こ |
  | `k'` | きゃ | き | きゅ | きぇ | きょ |
  | `g` | が | ぎ | ぐ | げ | ご |
  | `g'` | ぎゃ | ぎ | ぎゅ | ぎぇ | ぎょ |
  | `s` | さ | すぃ | す | せ | そ |
  | `S` | しゃ | し | しゅ | しぇ | しょ |
  | `z` | ざ | ずぃ | ず | ぜ | ぞ |
  | `dZ` | じゃ | じ | じゅ | じぇ | じょ |
  | `t` | た | てぃ | とぅ | て | と |
  | `ts` | つぁ | つぃ | つ | つぇ | つぉ |
  | `tS` | ちゃ | ち | ちゅ | ちぇ | ちょ |
  | `d` | だ | でぃ | どぅ | で | ど |

- **拗音行**: 隣接する子音が `j` のとき、その前の子音から次の行を引く。`k` → `k'` の行、`g` → `g'` の行、
  `b` → `b'` の行、`p` → `p'` の行、`m` → `m'` の行、`h` → `C` の行、`4` → りゃ/り/りゅ/りぇ/りょ、
  それ以外 → `j` の行。
- **継続の音符**: 同じ音節に属する2つ目以降の音符(音高の変わり目で分かれたもの)は、表示歌詞・
  音素列をともに `-` にする(1つの音節を複数の音高で歌う箇所の表記。実 vpr が用いる形)。音節の
  先頭・継続の判定とモーラの割り当ては、[§7.1](#71-音符)の抑制で落ちた音符を除いた後の音符列で行う(先頭の
  音符が落ちた音節は、残った最初の音符が先頭になる)。
- **音素の保護**: 音素列を載せた音節の先頭の音符は、`vpr` の `is_protected` を真にして書き出す
  ([vpr.md §2.1](../../libs/vpr/vpr.md#21-公開する具体型と関数))。継続の音符と音素列が空の音符は偽のまま。狙いは、発音を決める情報を
  音声由来の音素列の側に置き、表示歌詞には表示だけを担わせることにある(下記のとおり `--lyrics` は
  表示歌詞だけを変える)。この真偽値が編集器で持つ意味は形式仕様の推定で、編集器の実挙動は未検証
  ([VPR_file_format.md の音符フィールド定義](../../docs/specs/vpr/VPR_file_format.md#notes))。`song2vpr` が定めるのは真を書き出すところまでで、編集器が
  表示歌詞から音素を導き直さないことは保証しない。
- **表示歌詞(`--lyrics` あり)**: 歌詞テキストをかな読みへ変換し、モーラ単位に分けて先頭から、
  音節の先頭の音符だけへ1音符=1モーラで対応付ける(継続の音符は `-` のまま)。かな読みへの変換は共有側へ委譲する
  ([vocal_analysis.md §12](../../libs/vocal_analysis/vocal_analysis.md#12-日本語テキストのかな読み))。共通引数群の英語カタカナ化の方式([§4.2](#42-オプション))は音素認識に効くもので、
  この歌詞の読みには効かない(共有側が方式を選ばせないため)。読みは歌詞テキスト全体を1つのまとまりとして決める(行や段落へ切って
  求めると語の切れ目が変わり、同じ歌詞でも読みが変わるため)。歌詞ファイルは UTF-8 として読み、復号できなければ
  `lyrics_unreadable`([§9.3](#93-構造化エラー))で終わる。
  読みはひらがなと長音記号へ揃えてから扱い、表示歌詞にもそれを入れる(共有側は返す読みの仮名種を定めて
  おらず、`--lyrics` なしの表示歌詞はひらがなのため。同じ vpr の中で仮名種が混ざらないようにする)。
  **モーラの単位**: 次の規則で1モーラを切る。標準の日本語のモーラとは切り方が異なり、音符の切り方
  ([§7.1](#71-音符))と揃うように定めてある。ただし数が一致する
  ことは求めない。音声と歌詞が食い違う場合のほか、無声区間を音符にしない規則と音節と結びつかない
  音符の抑制では、音節そのものが音符に現れなくなるぶんモーラ数が音節の先頭の音符の数を上回り、逆に
  認識器が余分に音節を出せば音符側が上回る(短い音符をまとめる規則は同じ音節の中でしかまとめないので、
  この不一致を生まない)。どちらも歌唱として普通に起きるので不一致そのものは警告にせず、件数だけを診断に出す。
  表示歌詞は音符とモーラの位置がずれたまま付くので、
  歌詞どおりに揃えたい利用者は出力した vpr を VOCALOID で開いて直す(下書きのため厳密な整合は求めない)。かな1文字を
  1モーラとし、小書きのかな(促音「っ」を除く)は直前のモーラに含める(直前に結合できるモーラが無ければ
  単独で1モーラ)、長音記号
  「ー」は直前のモーラに含める(音を伸ばすだけで音符が増えないため。直前に結合できるモーラが無ければ
  後続のモーラに含める)、促音「っ」は後続のモーラに含める(無声の詰まりで音符が増えないため。後続に
  結合できるモーラが無ければ直前のモーラに含める)、撥音「ん」は前のモーラに含めず、新しいモーラを成す(母音を伴わない
  音節として独立した音符になるため。直後の長音記号・小書きのかなと、直前の促音は、上の各規則どおり
  このモーラに含める)。長音記号・促音の
  どちらも、結合できるモーラが前後どちらにも
  無ければ単独で1モーラとする(下記のとおり読み飛ばした文字を挟んだ側とは結合できない)。この場合だけは
  音符側に対応物を持たない単位になるが、読みを捨てないことを優先する。
  かなと長音記号以外の文字はモーラにせず読み飛ばし、
  その前後を結合させない。歌詞の改行を曲のフレーズや休符には対応させない(両者は一致するとは
  限らないため)。先頭のバイト順マークは読み込み時に取り除く。
  読みの文字は、かな・長音記号(モーラを作る)、かなへ変換されるべきだった文字(漢字・英数字など、読みとして
  残っては困る文字)、それ以外(空白・改行や記号など、体裁の文字)の3つに分ける。**かなへ変換されるべき
  だった文字**が、かな・長音記号との合計に占める割合が高い場合は、
  かな読みへの変換が効いていないおそれがあるため警告を出す([§9.1](#91-イベントペイロード))。判断の境目は内部の値で、CLI へは公開しない。かな・長音記号もかなへ変換されるべきだった文字も1文字も無い場合は
  割合を求められないため、この警告は出さない。音節の先頭の音符の数とモーラ数が一致しないときは、
  余った音符の表示歌詞を `--lyrics` なしと同じ規則で決め、余ったモーラは捨てる。どちらの向きの
  件数も診断に出す([§4.5](#45-レポートと診断)・[§9.1](#91-イベントペイロード))。
- **`--lyrics` が与えるのは表示歌詞だけ**で、音素列は音声から採ったままにする(書き起こしの取り違えで
  発音を壊さないため。発音を歌詞に合わせたい利用者は、出力した vpr を VOCALOID で開いて音符の歌詞を
  確定させる)。
- **ベロシティ**: 音符の強弱を相対正規化RMS から求め、0〜127 のベロシティに入れる。発声している区間
  どうしの強弱の差がベロシティの差として現れるようにする(共有出力の相対正規化は無音を含む曲全体の分布を
  基準にしているため、その値をそのまま写すと発声区間どうしの差が出にくい)。もとの値が曲の中での相対値
  なので、同じ歌唱を録音レベル違いで入れても近い値になる。

### 7.3 テンポと拍子

- **分解能**: vpr 形式が固定している値を使う([vpr.md §3](../../libs/vpr/vpr.md#3-読み込みread))。採用した値は診断に出す([§4.5](#45-レポートと診断)・[§9.1](#91-イベントペイロード))。
- **テンポ**: 四分音符を1拍とした BPM を、拍子の分母に依らず用いる。`--tempo` 指定時はその値を曲全体で
  一定に使う。未指定時は音声から推定する。推定できない
  場合は 120 BPM を仮置きし、警告を出す([§9.1](#91-イベントペイロード))。採用テンポは vpr 形式が格納できる粒度
  ([vpr.md §5](../../libs/vpr/vpr.md#5-形式レイアウトの正本))へ丸めた値とし、秒から tick への変換にも診断にも同じ値を使う(出力ファイルと診断が
  食い違わないようにするため)。`--tempo` が受け取る下限はこの粒度で表せる最小の正値とし、上限は設けない
  ([§4.2](#42-オプション))。極端な値でも[§7.1](#71-音符)の要件は下の量子化の規則が保つ。
- **拍子**: `--time-signature` 指定時はその拍子を使う。未指定時は音声から分子を推定し、分母は四分音符を
  1拍とする。推定に必要な周期を取り出せなかった場合は 4/4 を仮置きし、警告を出す。
- **秒から tick への変換**: 採用したテンポと分解能で音符の時刻・長さを tick へ写す。入力音声の 0 秒を
  tick の 0 とし、音符は入力音声の時刻をそのまま写した位置に置く(小節線に合わせて音符をずらさない)。
  したがって曲の頭が小節線に揃っていない音源では、音符と小節線がずれた vpr になる。秒の時点で切れ目なく
  続いていた音符は tick でも切れ目なく続き、丸めによる隙間や重なりを作らない([§7.1](#71-音符)の発音区間の要件は
  tick へ写した後も保つ)。丸めによって音符の長さが 0 になったり複数の音符が同じ位置に潰れたりする
  場合は、[§7.1](#71-音符)の要件(重ねない・長さ 0 を出さない)を優先し、同じ位置に潰れた
  音符は1つにまとめ、長さが 0 になった音符には 1 tick を与える。まとめた音符が持つ値(音高・表示歌詞・
  音素列・強弱・音素の保護)は、まとめる前の**秒の区間が最も長い音符**(同じ長さなら先の音符)のものとし、区間は
  まとめた範囲の終端までとする(潰れて長さを失った音符の値が、その位置を占める音符の値を
  置き換えないようにするため。同じ位置に潰れた音符は最後の1つ以外は必ず tick 長が 0 になるので、
  tick で比べると常に最後の音符(全員が 0 なら先頭の音符)が選ばれ、区間の長短を反映しない)。
  **ただし表示歌詞・音素列・音素の保護は、まとめた音符の中に音節の先頭の音符([§7.2](#72-歌詞音素強弱の付与))があれば
  その音符のものにする**(複数あれば先の音符のもの)。継続の音符は自分より前に同じ音節の音符がある
  ことを表す表記なので、先頭の音符を飲み込んだ結果としてそれだけが残ると、音素列を持つ音符が
  1つも無い音節ができてしまうため。まとめられて消えた音符の数と、引き伸ばした音符の数を診断に出す
  ([§4.5](#45-レポートと診断)・[§9.1](#91-イベントペイロード))。

### 7.4 出力する vpr の構造

出力 vpr へ載せるデータモデルの形。直列化の一般規則は `vpr` が持ち
([vpr.md §4](../../libs/vpr/vpr.md#4-書き出しwrite))、どんなモデルを組み立てるかは `song2vpr` が決める。

- **トラック・パート**: 歌唱トラック1つ、その中のパート1つとする。曲名・トラック名・パート名には出力 vpr の
  ファイル基底名(拡張子を除いた名前)を入れる。パートの開始位置は 0 とする。
- **パート長**: 最後の音符の終了位置とする。音符が1つも無い場合は1小節分の長さとし、長さ 0 のパートを作らない。
- **テンポ・拍子**: 先頭位置に採用テンポの1件、先頭位置に採用拍子の1件を置く([§7.3](#73-テンポと拍子))。
- **コントローラ曲線**: 持たない。下書きの段階では音符ごとの値だけを与え、曲線は利用者が VOCALOID で付ける。
- **ボイスバンク(歌手)**: 形式が要求するボイスバンクの指定は `song2vpr` が与える(値の選別はツール側の
  判断で、フォーマット層は持ち込まない。[layering.md §3](../../docs/conventions/layering.md#3-フォーマット層共通の設計原則))。指定は形式を満たす最小限の固定値とし、
  利用者の環境に何が導入されているかを調べて選び分けることはしない。特定の歌手を推すものではなく、
  利用者は出力した vpr を VOCALOID で開いて差し替える。

## 8. 終了コード

| コード | 意味 |
|---|---|
| 0 | 正常終了 |
| 1 | 入力不正(存在しない・音声として読めない・破損・非対応形式、`--lyrics` ファイルの読み込み不可を含む)、および内部生成ファイルの読み直し失敗([§9.3](#93-構造化エラー)) |
| 2 | 引数エラー(範囲・書式・上書きガード・未知オプション など) |
| 3 | 出力書き込み失敗 |
| 4 | 音声前段の外部依存の失敗(復号器未検出・分離/認識のモデル取得・実行失敗)、歌詞のかな読みの失敗、追加依存の未導入。復号器未検出と追加依存の未導入を除き、失敗した段を明示する([§9.3](#93-構造化エラー)) |
| 130 | 協調的な中断(Ctrl-C 等。[§9.4](#94-中断)) |

- `0`〜`3` は[CLI インターフェース規約 §5](../../docs/conventions/cli-interface.md#5-エラーと終了コード) の基底と同じ意味。
  `4` は song2vpr 固有の追加コード、`130` は全ツール共通の中断予約コードで、いずれも基底 `0`〜`3` の意味へ
  押し込めない。
- 想定外の内部エラー(F0推定・音符分割・書き出し等の未捕捉例外)は最も近い基底へ寄せて `1` で終える。
  機械モードでは `internal_error` の error イベント([§9.3](#93-構造化エラー))で入力起因の `not_audio` と識別でき、非機械モードでは
  理由を標準エラーへ最低1行出す(いずれもトレースバックは出さない)。
- 失敗は理由を必ず表に出す: 機械モードでは終了コードに加えて error イベントで「どのフィールド/パスが・なぜ
  不正か」を返し([§9.3](#93-構造化エラー))、非機械モードでも失敗理由を標準エラーへ最低1行出す(終了コードだけで返す経路は
  持たない)。

## 9. 機械モード(機械可読インターフェース)

機械利用(子プロセス呼び出し)向けに、`--machine` で出力を JSON Lines のイベントストリームへ切り替える
([§4.4](#44-機械モードとメタ操作機械可読インターフェース))。共通の契約・語彙は[CLI インターフェース規約](../../docs/conventions/cli-interface.md)が正、
イベント送出は共有基盤 [cli_events](../../libs/cli_events/cli_events.md) を用いる。本章は **song2vpr 固有の
ペイロード形・`code` 値**を定める(規約は種別の語彙と終端規則のみを共通化し、ツール固有ペイロードは持たない)。

- **チャネル固定・符号化**(規約 [§3](../../docs/conventions/cli-interface.md#3-機械モードの起動)・[§10](../../docs/conventions/cli-interface.md#10-移植性パス符号化改行ロケール)): 機械モードの標準出力は [§9.1](#91-イベントペイロード) のイベント**のみ**。人間向けログ・
  警告テキストは標準エラーへ出す。
- **終端規則**(規約 [§4](../../docs/conventions/cli-interface.md#4-イベントストリーム標準出力)): ストリームは result または error の**ちょうど1つ**で終端する(同節が定める
  終端保証の例外を除く。強制終了は [§9.4](#94-中断))。
- 各イベントは種別フィールド `type` を持つ。`code` は機械利用側の分岐に使い、人間向け `message` と分離する。
  song2vpr 由来の `code` は安定 snake_case とする。
- **イベント契約の進化**は規約 [§4.1](../../docs/conventions/cli-interface.md#41-イベント契約の進化と前方互換) に従う(フィールド・種別・`code` の追加=MINOR、削除・意味変更=MAJOR。
  受信側は未知要素を無視できる前提)。実装で増える警告・統計は本章へ追記して追加する。

### 9.1 イベントペイロード

各イベントは `type` を持つ。

- **progress**: `{type:"progress", stage, done, total, note, elapsed}`。`stage` は処理段階の安定 id
  `"load"`・`"separate"`・`"recognize"`・`"rms"`・`"f0"`・`"notes"`・`"write"` のいずれか(対応する
  工程名は[§4.3](#43-進捗表示))。`done`/`total` は
  長尺の自動分割時の処理済み/総チャンク数(分割しない場合や内訳の無い段は `done=0, total=null`)、
  `note` は補足文字列(無ければ `""`)、`elapsed` は段開始からの経過秒。各段は開始時に最低1本の
  progress を出す。ただし `--dry-run` では書き出しを行わないため `write` 段を報告しない。
  外部推論の内部進捗は、同じ段 id と `done`/`total` を保ったまま `note` を差し替えた progress として
  追加で届く([vocal_analysis.md §11](../../libs/vocal_analysis/vocal_analysis.md#11-前段実行エンジン))。
- **warning**: `{type:"warning", code, message}`。警告によっては、この3つに加えて件数や観測値を持つキーを
  伴う(どのキーを持つかは各警告の定義による)。仕様が定める警告は次のとおり。
  - `tempo_defaulted`: テンポを推定できず 120 BPM を仮置きした([§7.3](#73-テンポと拍子))。
  - `time_signature_defaulted`: 拍子を推定できず 4/4 を仮置きした([§7.3](#73-テンポと拍子))。
  - `kana_reading_ineffective`: 歌詞の読みに、かなへ変換されるべきだった文字が多く残り、かな読みへの
    変換が効いていないおそれがある([§7.2](#72-歌詞音素強弱の付与))。かなへ変換されるべきだった文字数と、判定に使った文字数
    (かな・長音記号と、かなへ変換されるべきだった文字の合計。体裁の文字は含めない)を、本文と
    `unconverted_chars`・`counted_chars` の各キーに載せる(受け手が割合を再現できるようにするため)。
  - `no_notes`: 音符が1つも得られなかった。この場合も正常終了するため、入力や分離の選択を見直す
    手がかりとして知らせる(`--dry-run` でも出す)。
  - `forced_split`: 長尺の自動分割で、目標境界そのもので強制分割した境界があった。成立条件と分割の機構は
    [vocal_analysis.md §11.1](../../libs/vocal_analysis/vocal_analysis.md#111-長尺の自動分割) が定める。
  - 資源逼迫の2件 `gpu_memory_oversubscribed`・`swap_detected`([§5.2](#52-資源逼迫の警告))、GPU を使えない構成の
    2件 `cpu_only_torch`・`cuda_unavailable`([§5.3](#53-gpu-を使えない構成の警告))。この4件は、成立条件と追加で持つ観測値のキーを
    [cli_resource_watch.md §2](../../libs/cli_resource_watch/cli_resource_watch.md#2-資源逼迫の観測)・[§3](../../libs/cli_resource_watch/cli_resource_watch.md#3-gpu-を使えない実行構成の判定) が定める。`song2vpr` は判定が返した観測値を
    そのまま warning イベントへ載せる。

  その他の警告は実装で本章へ追記して増やす(追加は後方互換。規約 [§4.1](../../docs/conventions/cli-interface.md#41-イベント契約の進化と前方互換))。
- **result**: 正常終了の終端イベント。`mode` で形が決まる:
  - `mode:"run"`(通常実行): `{type:"result", mode:"run", output, notes, tempo_bpm, tempo_source,
    time_signature, time_signature_source, resolution, duration_sec, separated, backends,
    vowel_undetermined_notes, moraic_nasal_notes, fallback_lyric_notes, dropped_morae, short_notes,
    suppressed_notes, pitch_clamped_notes, quantized_merged_notes, quantized_stretched_notes,
    no_phoneme_notes}`。`output` は書き出しパス(文字列)、`notes` は tick へ写した後の音符数(まとめや引き伸ばしを済ませた最終の数。[§7.3](#73-テンポと拍子))、
    `tempo_bpm` は採用テンポ、`tempo_source` はその出どころ(`"option"`/`"estimated"`/`"default"`)、
    `time_signature` は採用拍子(`"4/4"` の形式)、`time_signature_source` はその出どころ(同じ語彙)、
    `resolution` は tick/四分音符、`duration_sec` は入力音声の尺(秒)、`separated` は分離を実施したか(bool)、
    `backends` は音声前段へ渡したバックエンド選択の設定
    (`{separator, recognizer, recognizer_revision, forced_aligner, english_katakana_method}`。
    `separator`・`forced_aligner` は共有側が定めるアダプタの安定 id、`recognizer` は内容認識
    モデルの id、`recognizer_revision` はそのリビジョン、`english_katakana_method` は英語カタカナ化の
    方式。渡した設定をそのまま載せ、その処理が実際に走ったかは問わない。渡さなかった設定は `null` とする
    (内容認識モデルを指定しつつリビジョンを指定しなかった実行の `recognizer_revision` がこれに当たり、
    その実行はリビジョンを固定しないため使われるリビジョンが変わりうる))、
    `vowel_undetermined_notes` は母音も鼻音も得られず「あ」を入れた音符数([§7.2](#72-歌詞音素強弱の付与))、
    `moraic_nasal_notes` は撥音「ん」を入れた音符数([§7.2](#72-歌詞音素強弱の付与))、`fallback_lyric_notes` はモーラが尽きて
    表示歌詞を音声から決めた音符数([§7.2](#72-歌詞音素強弱の付与))、`dropped_morae` は破棄した余剰モーラ数([§7.2](#72-歌詞音素強弱の付与))、
    `short_notes` はまとめる先が無く短いまま残った音符数([§7.1](#71-音符))、`suppressed_notes` は[§7.1](#71-音符)の3つの規則
    (どの音節にも属さない有声区間・ベロシティが 0 の音符・核から離れて始まる連続成分)のいずれかで
    出力しなかった音符の総数(1つの音符を二重に数えない)、`pitch_clamped_notes` は音高を
    MIDI の範囲へ丸めた音符数([§7.1](#71-音符))、`quantized_merged_notes` は tick へ写すときにまとめられて
    消えた音符数、`quantized_stretched_notes` は長さを 1 tick へ引き伸ばした音符数(いずれも[§7.3](#73-テンポと拍子))、
    `no_phoneme_notes` は音素列が空になった音符数(継続の音符 `-` は数えない。[§7.2](#72-歌詞音素強弱の付与))。
    [§4.5](#45-レポートと診断)の診断を構造化したもので、キーは常に載せる(`--lyrics` 未指定時の
    `fallback_lyric_notes`・`dropped_morae` は `0`)。音符を数えるキーのうち、tick へ写す段が判定するもの
    (`pitch_clamped_notes`・`quantized_stretched_notes`)は写した後の音符列を、写す前の段が判定するもの
    (`short_notes`・`suppressed_notes`・`vowel_undetermined_notes`・`moraic_nasal_notes`・
    `fallback_lyric_notes`・`no_phoneme_notes`)は判定した時点の音符列を数える(写した後の音符列からは数え直せない。
    tick で潰れてまとめられた音符が残らず、短い音符は引き伸ばしとまとめで痕跡が消え、表示歌詞からは
    音声由来かモーラ由来かを区別できないため)。`quantized_merged_notes` は写す前にあって消えた音符を数える。`vowel_undetermined_notes`・`moraic_nasal_notes` は
    表示歌詞を音声から決めた音符(`--lyrics` 未指定時の音節の先頭の音符と、指定時にモーラが尽きた
    音節の先頭の音符)だけを数える。継続の音符は表示歌詞を音声から決めないので、どちらにも数えない。
  - `mode:"inspect"`(入力検査 `--machine --dry-run`): `mode:"run"` と同じキーをすべて持ち、加えて
    `input_kind, sample_rate, channels` を持つ。vpr を書かないので `output` は `null`。`input_kind` は常に
    `"audio"`、`sample_rate`/`channels` は入力音声のメタ情報。
  - `mode:"describe"`(自己記述 `--describe`): `{type:"result", mode:"describe", options, presets}`([§9.2](#92---describe-の中身))。
    処理統計のキーは載せない。
- **error**: `{type:"error", code, exit_code, field, path, message}`。`field`/`path` は対象が無ければ `null`。
  `stage_failed` のみ、このキーに加えて失敗ステージを示す `stage` キーを持つ([§9.3](#93-構造化エラー))。失敗の終端イベント。
  `code`/`field`/`exit_code` の割り当ては [§9.3](#93-構造化エラー)。

### 9.2 `--describe` の中身

`options` は**処理を駆動する引数**の配列(本書 [§4.2](#42-オプション)が定める `song2vpr` 固有引数と、そこで公開すると
宣言した共通引数群([vocal_analysis_cli.md §2](../../libs/vocal_analysis_cli/vocal_analysis_cli.md#2-共通引数群))の全引数の
うち、メタ/モード操作 `--describe`/`--version`/`--help`/`--machine` を除く全引数)。**配列の要素が持つキー・
名前の採り方・掲載対象・検証子からの型と制約の導出は共有側が定める**
([cli_options.md §4](../../libs/cli_options/cli_options.md#4-自己記述の-options-配列の導出))。本書は `song2vpr` 固有引数が
そこで何を持つかだけを述べる(共通引数群の分は共有側の型情報が与える)。

- `type`: `song2vpr` が型表で与えるのは `"str"` / `"flag"`(真偽)で、検証子を持つ引数の型名は共有側が導く。
  区切り文字で複数の値を並べる `--time-signature` は複合トークンの検証子を持ち、型名も書式の公開形も
  そこから導かれる([cli_options.md §3](../../libs/cli_options/cli_options.md#3-複合トークンの検証子))。
- `constraint`: `flag` と制約なしは `null`。数値引数の制約は、その形も値も共有側の検証子から機械導出し、
  手書きで複製しない。
- `default`: 解決後の既定値。入力名由来の `--output`、未指定が既定の `--lyrics`、未指定時に音声から
  推定する `--tempo`・`--time-signature` は単一リテラルで表せないため `null`(算出規則と仮置きの値は
  `help` に記す)。
- `help`: その引数の役割を人間向けに述べた文字列。

`presets` はプリセット一覧の配列。song2vpr はプリセットを持たないため常に空配列 `[]` とする。

### 9.3 構造化エラー

失敗は終了コード([§8](#8-終了コード))に加え、機械モードでは error イベントで「どのフィールド/パスが・なぜ」を返す。
非機械モードでも理由を標準エラーへ最低1行出す(トレースバックは出さない)。各経路の `code`/`field`/
`exit_code`:

| 事象 | `code` | `field` | `exit_code` |
|---|---|---|---|
| 入力ファイルが存在しない、または音声として読み込めない・破損(利用可能な復号経路で試みて失敗した) | `not_audio` | `"input"` | 1 |
| 内部生成ファイル(分離後ボーカルWAV)の読み直しに失敗した | `not_audio` | `null`(+ `path`) | 1 |
| 出力先が既存のディレクトリ([§5](#5-入出力要件)) | `output_is_directory` | `"--output"`(+ `path`) | 2 |
| 未知オプション・型/範囲エラー・positional 欠落等の引数エラー。共通引数群の組み合わせ検証([vocal_analysis_cli.md §3](../../libs/vocal_analysis_cli/vocal_analysis_cli.md#3-組み合わせ検証))も含む | `bad_argument` | 引数エラーからの抽出規則は[cli_events.md §4](../../libs/cli_events/cli_events.md#4-argparse-エラー変換ヘルパ)が正(抽出できなければ `null`)。組み合わせ検証は共有側が返す対象引数の長形式フラグ名 | 2 |
| `--time-signature` の分子・分母が受理集合を外れる(分母が2の冪でない場合を含む。[§4.2](#42-オプション)) | `bad_argument` | `"--time-signature"` | 2 |
| 出力先に既存ファイルがある・`--overwrite` 未指定([§5](#5-入出力要件)) | `output_exists` | `"--output"` | 2 |
| `--lyrics` のファイルを読めない | `lyrics_unreadable` | `"--lyrics"`(+ `path`) | 1 |
| 出力書き込み失敗、または `--keep-intermediate` 指定時の中間生成物書き込み失敗(権限・不正パス・ディスク等の I/O 失敗) | `write_failed` | `"--output"` または `"--keep-intermediate"`(+ `path`) | 3 |
| 標準の読み込みが対応しない形式で、フォールバック復号器(ffmpeg)が未検出のため復号を試みられない([vocal_analysis.md §3](../../libs/vocal_analysis/vocal_analysis.md#3-入力読み込みs0)) | `decoder_missing` | `"input"` | 4 |
| 分離・認識・かな読みのモデル取得/実行失敗 | `stage_failed`(+ `stage`) | `null` | 4 |
| 音声前段の追加依存が未導入で取り込めない(理由1行は[vocal_analysis_cli.md §5](../../libs/vocal_analysis_cli/vocal_analysis_cli.md#5-追加依存の未導入)が組み立てる) | `missing_dependency` | `null` | 4 |
| 上記いずれにも当たらない想定外の内部エラー | `internal_error` | `null` | 1 |
| 協調的な中断(Ctrl-C 等) | `cancelled` | `null` | 130 |

- `stage_failed` は失敗ステージの安定 id([§9.1](#91-イベントペイロード) progress の `stage` と同じ語彙)を `stage` キーで併載し、
  元例外の要旨を `message` に載せる。取得に失敗したのか実行に失敗したのかは委譲先の公開契約が区別しない
  ため、その別は載せない(委譲先の例外メッセージの文面から推し量って別を騙らない)。
  対象は、vocal_analysis が**どの段で起きたかを特定して**返す失敗(分離の失敗・認識の失敗と、それらの
  呼び出しから段付きで上がる失敗)と、歌詞のかな読み
  ([vocal_analysis.md §12](../../libs/vocal_analysis/vocal_analysis.md#12-日本語テキストのかな読み))の失敗。`stage` は
  その失敗が起きた段の id とする。段を特定できない失敗(委譲先が内部で使う一時領域への書き込み失敗など)は
  この行では扱わず、`internal_error` が受ける。かな読みの失敗は音符へ歌詞を割り当てる段の失敗なので `stage` は
  `"notes"` になる。入力読み込みの失敗は `not_audio`・`decoder_missing` の行が引き取る。
  song2vpr 自身の処理(F0推定・音符分割・対応付け)の未捕捉例外は `internal_error`。
- `not_audio` は利用者入力の読み込み失敗と内部生成ファイルの読み直し失敗の双方で使い、`field` で
  区別する: 利用者入力は `"input"`、内部生成ファイルは `null` とし、代わりに `path` へ対象ファイルを
  載せる(内部生成ファイルの失敗を利用者入力の不備として指し示さない)。復号器未検出による
  `decoder_missing`(4)への分岐は利用者入力の読み込みだけの扱いとする(復号経路の有無は入力読み込み時に
  判定済みで、内部生成ファイルは音声前段自身が書いた wav のため)。
- `internal_error` は表の各分類に当たらない失敗の受け皿で、どの経路の想定外の失敗もこのコードと終了コード 1 で
  終わる(処理の途中で止まったまま終了コードや終端イベントを返さない経路を作らない)。中断は内部エラーに
  含めず `cancelled`/`130`([§9.4](#94-中断))として区別する。
- 複数の検証失敗が同一終了コードへ集約される場合も、`code`/`field` でどの検証がなぜ失敗したかを区別できる
  ようにする(規約 [§5](../../docs/conventions/cli-interface.md#5-エラーと終了コード))。

### 9.4 中断

長時間処理(分離・認識・F0推定)を呼び出し側から安全に中断できる。

- **出力の原子性**: vpr 出力は一時ファイルへ書き切ってから最終パスへ置換する([§5](#5-入出力要件))。途中終了で中途半端な
  出力ファイルを残さない。診断用の中間生成物は `song2vpr` 自身が既定では追加で書き出さず([§5](#5-入出力要件))、
  `--keep-intermediate` 指定時のみ出力に隣接するディレクトリへ保存されるため、最終出力先を汚さない。
- **中断の扱い**: 端末の Ctrl-C と親プロセスからの中断は、処理のどの時点で届いても中断として扱う。
  **機械モード**では `cancelled` の error イベントを標準出力へ出してストリームを終端し、**非機械モード**では
  標準出力に JSON を出さず中断理由を標準エラーへ1行出す。どちらも終了コード `130` を返す。
- **Windows**: `CTRL_BREAK_EVENT` も上の `KeyboardInterrupt` 捕捉経路へ橋渡しし、`cancelled`/`130` として
  扱う。橋渡しの要否・実装は共有基盤([cli_events.md §5](../../libs/cli_events/cli_events.md#5-中断シグナルの橋渡し))が正。
- 呼び出し側がプロセスを強制終了した場合は終端イベントを出せないまま途切れる(規約 [§4](../../docs/conventions/cli-interface.md#4-イベントストリーム標準出力) が定める
  終端保証の例外の 1 つ)。原子性により中途半端な出力は残らない。
