# mocapvmd 要求仕様書

モーションキャプチャー由来のボーンVMDを、ノイズ軽減・足IK安定化してから疎化まで1コマンドで行う独立CLIツールの要求仕様。

---

## 1. 位置づけ

### 1.1 結論

本機能は `sparsevmd` のプリセットではなく、`mocapvmd` という独立ツールとして提供する。

`mocapvmd` は、モーションキャプチャー由来VMDのノイズ軽減・足IK安定化・ボーン種別別の信号整形を行い、続けてキーフレーム疎化までを**1コマンドで**実行し、MMDで扱いやすい疎なVMDを直接出力する。中間VMDファイルは介さない。

```text
入力 mocap VMD
  -> mocapvmd(ノイズ軽減・足IK安定化 → 疎化)
  -> MMDで確認・編集
```

疎化の中核機構(区間分割・キー削減・継ぎ目処理・誤差検証・ベジェ採否)は `sparsevmd` と共通であり、`vmd.reduce` の共通実装を再利用する。mocapvmd は疎化を再実装せず、クリーニング後の信号に共通の削減機構を適用する。

mocapvmd はボーン選択オプションを持たず、クリーニングと疎化を全ボーンに適用する。どのボーンを処理するかは選ばせず、ボーン種別([§4.1](#41-ボーン分類))ごとに異なるパラメータを使うことで効かせ方を変える。

### 1.2 独立ツールとする理由

- 既存の `sparsevmd` は「入力モーションを指定誤差以内で疎化する」汎用ツールであり、仕様上もモーションキャプチャーのノイズ除去、足接地補正、IK補正を非目標としている。
- モーションキャプチャー由来データの問題は、単なる許容誤差や分割閾値ではなく、入力モーションそのものを変える整形である。ノイズ生成の逆問題・足IK接地推定・ボーン種別別パラメータはドメイン固有であり、`sparsevmd` の汎用削減ポリシーとは分けた方が安全である。
- クリーニングと疎化を同一実行内に置くのは、中間VMDを介さず、滑らかになった信号にそのまま削減を適用するためである。これによりキー削減率・補間曲線の自然さ・編集しやすさを同時に改善しやすい。
- 共通化により疎化機構は二重持ちしない。mocapvmd と `sparsevmd` は同じ `vmd` の削減機構を共有し、mocapvmd 側にはクリーニングと、削減の起動・パラメータ解決だけを持つ。

---

## 2. 目的

### 2.1 解きたい問題

モーションキャプチャー由来VMDでは、以下の問題が起きやすい。

- 1フレームごとの微小な位置・回転ノイズが多く、疎化がノイズまで忠実に残そうとしてキーが減りにくい。
- 足IKボーンが接地中に細かく揺れ、足元が氷の上で滑っているように見える。
- 手首・指・頭などは細かな動きが表情として重要な一方、センターや足IKでは同じ揺れが不自然に見えやすい。
- 接地中と遊脚中で、同じボーンでも望ましいフィルタ強度が異なる。
- ノイズ軽減を強くしすぎると、ステップ、ジャンプ、ターン、手振りなどの意図したアクセントが鈍る。

### 2.2 目標

- モーションキャプチャー向けのノイズ軽減・足IK安定化と、それに続く疎化を1コマンドで行い、疎なVMDを直接出力する。
- 足IKの接地中ぐらつきを重点的に抑制する。
- ボーン種類ごとに異なる既定パラメータを持つ。
- ボーン種類ごとの効かせ方を実データでチューニングできる。
- 元モーションのタイミング、接地、重心移動、ポーズの意図を壊さない。
- 処理結果を数値レポートで確認できるようにする。

### 2.3 非目標

- キーフレーム削減機構は `vmd.reduce` の共通実装を再利用し、再実装しない。
- カメラ、照明、セルフ影は対象外とする。mocapvmd はボーンのみを扱う。
- 物理シミュレーションや足裏接触の完全な解剖学的補正は行わない。
- モーションキャプチャーの誤認識による大きなポーズ破綻を自動修復することは初期対象外とする。
- モデル固有のボーン構造を完全に推定しない。標準・準標準名を中心に扱う。

## 3. コマンドライン仕様

### 3.1 書式

```text
mocapvmd <入力ファイル名>.vmd [オプション]
```

既定出力:

```text
<入力ファイル名>_mocap.vmd
```

### 3.2 主なオプション

| 引数 | 既定 | 説明 |
|---|---:|---|
| `<入力ファイル名>` | 必須 | 入力VMD |
| `-o, --output PATH` | `<入力ファイル名>_mocap.vmd` | 出力VMD |
| `--overwrite` | off | 出力先の既存ファイルへの上書きを許可 |
| `--preset NAME` | `medium` | キーフレーム圧縮の許容誤差プリセット(速度観点)`slower` / `slow` / `medium` / `fast` / `faster`。種別スケールの基準値([§5.3](#53-疎化プリセットと種別別許容誤差))。本ツール唯一の名前付きプリセット |
| `--clean-strength X` | `1.0` | ノイズ軽減の効き量の倍率(ブレンド率に掛ける。0で無加工相当、上げるほど強く平準化する。窓幅は据え置き)。[§5.2](#52-クリーニング強度--clean-strength) |
| `--denoise` | on | ノイズ軽減を有効化 |
| `--no-denoise` | off | ノイズ軽減を無効化 |
| `--denoise-mode MODE` | `bone` | ノイズ軽減の方式 `bone`(ボーン単位)/ `pose`(MMDで実際に見える動き=表現空間で評価)。[§4.2](#42-一般ノイズ軽減) |
| `--pmx PATH` | なし | `pose` 方式が参照するモデルPMX。未指定時は内蔵の既定モデルプロファイル([§4.2](#42-一般ノイズ軽減)) |
| `--foot-ik-stabilize` | on | 足IK接地安定化を有効化 |
| `--no-foot-ik-stabilize` | off | 足IK接地安定化を無効化 |
| `--foot-slide-suppression S` | `1.0` | 足IK接地中の横滑り抑制の強さ(0〜1)。既定(1.0)は接地中の横滑りを除去する。意図的に足を滑らせるダンスは下げる(0で従来どおり滑りを保持)。検出の接地判定・X/Zロック・最大補正量を連動制御する([§4.3](#43-足ik安定化) / [§5.4](#54-接地ロック強度) / [§5.5](#55-最大変更量最大補正量)) |
| `--reduce-error-bone-pos U` | プリセット値 | キーフレーム圧縮の位置許容誤差の基準値(MMD単位)。明示値はプリセットに優先。種別スケールを掛ける |
| `--reduce-error-bone-rot DEG` | プリセット値 | キーフレーム圧縮の回転許容誤差の基準値(度)。明示値はプリセットに優先。種別スケールを掛ける |
| `--curve-mode MODE` | `bezier` | 出力補間曲線 `bezier` / `linear` |
| `--reduce` | on | キーフレーム圧縮を有効化(既定 on)。少ないキー+ベジェ補間で出力する。`--no-reduce` の対の明示形 |
| `--no-reduce` | off | キーフレームを圧縮せず、圧縮前の密キー(線形補間)を出力(診断・比較用)。`--reduce` の対 |
| `--list-bones` | off | ボーン一覧と分類結果を表示して終了 |
| `--dry-run` | off | 出力せず処理計画と診断を表示 |
| `--quiet` | off | 進捗表示を抑制する |
| `-v, --verbose` | off | 通常実行でも [§4.4](#44-レポートと診断) のレポートを標準出力へ表示する(dry-run と同内容。出力VMDは書く)。機械モードでは標準出力をイベント専用に保つため、この人間向け表示は出さない(イベント内容も変えない) |
| `--machine` | off | 出力を JSON Lines のイベントストリームにする(標準出力=イベント専用・標準エラー=人間向けログ)。既定の人間向け表示・終了コードは変えない([§10](#10-機械モード機械可読インターフェース)) |

| `--version` | — | バージョンを表示して終了 |

工程は `denoise`(ノイズ軽減 [§4.2](#42-一般ノイズ軽減))・`foot_ik`(足IK接地安定化 [§4.3](#43-足ik安定化))・`reduce`(キーフレーム圧縮 [§5.3](#53-疎化プリセットと種別別許容誤差))の
3段。有効条件・表記・停滞回避・副作用専用等の一般契約は
[CLIインターフェース規約 §6](../../docs/conventions/cli-interface.md#6-横断的な一貫性)が正。

キーフレーム圧縮段はカウンタ(done/total)に完了ボーン数・総数を反映し、ノイズ軽減・足IK接地安定化の
2段は少なくとも経過時間を反映する。mocapvmd はいずれの段でも行末の補足(note)を使わない。

名前付きプリセットは疎化の許容誤差 `--preset` 1つに集約する。`--preset` は疎化後の再生誤差上限(=出力キー数・処理時間)を決める。クリーニング(ノイズ軽減・足IK安定化)の効き量は名前付きプリセットを持たず、数値の倍率 `--clean-strength`(既定 1.0)で指定する。疎化の許容誤差を名前でなく数値で詰めたいときは `--reduce-error-bone-pos` / `--reduce-error-bone-rot` で基準値を上書きする。`--preset` と `--clean-strength` は別系統で、前者は疎化後の再生誤差上限、後者はクリーニングの効き量を決める。疎化の区間分割・継ぎ目処理・カット検出・誤差検証は `vmd.reduce` の共通機構をそのまま用いる。疎化プリセットの名称・値は mocapvmd 独自の運用ポリシーとして持ち、`sparsevmd` とは共有しない。mocapvmd はボーンのみを扱うため、許容誤差はボーンの位置・回転だけで指定し、カメラ用の許容誤差は持たない。

mocapvmd はボーン選択オプションを持たない。一般ノイズ軽減と疎化は全ボーンに適用し、足IK接地安定化は [§4.1](#41-ボーン分類) の分類で `foot_ik` / `toe_ik` と判定されたボーンにのみ適用する。いずれもボーン種別([§4.1](#41-ボーン分類))ごとに異なるパラメータで効かせ方を変える。足IK安定化は `--foot-ik-stabilize` / `--no-foot-ik-stabilize` で切り替える。分類は名前パターンに基づくため、英語名 `foot IK` のような標準外の名前でも一致すれば安定化対象になる。

### 3.3 入出力要件

- VMDの読み書きは `vmd.io` に委譲する。
- 対象はボーンキーのみとする。
- 対象外セクション(モーフ・カメラ・照明・セルフ影など)は無加工で透過する。
- VMDヘッダ(`model_name`)は入力の値をそのまま出力に引き継ぐ(変更しない)。
- 全ボーンキーを処理対象とする。一般ノイズ軽減と疎化は全ボーンに適用し、足IK安定化は分類 `foot_ik` / `toe_ik` のボーンに適用する。分類できないボーンは `unknown` として扱い、クリーニングは保守的な弱設定、疎化スケールは標準(位置・回転とも 1.0)で処理する。
- 初期実装は入力が1フレームごとの密なキーであることを前提とし、疎な入力の密化は行わない。クリーニングは内部で30fps整数フレームの密サンプル上に行う。
- クリーニング後、`vmd.reduce` の共通機構で疎化し、疎なキーとベジェ補間曲線を出力する。`--no-reduce` 指定時のみクリーニング後の密キー(線形補間)を出力する。
- 疎化の出力誤差は、種別スケール適用後の解決済み許容値([§5.3](#53-疎化プリセットと種別別許容誤差)。`--preset` / `--reduce-error-*` の基準値 × 種別スケール)以内に収める。誤差検証も共通機構に従う。
- 同一入力・同一引数からは同一出力を生成する。

## 4. 機能要求

### 4.1 ボーン分類

ツールはボーン名から種別を推定し、種別ごとにノイズ軽減パラメータを切り替える。

初期分類:

| 種別 | 例 | 要求 |
|---|---|---|
| `root` | `全ての親`, `root` | 原則弱め。大域移動を壊さない |
| `center` | `センター`, `グルーブ`, `center`, `groove` | 低周波を保ち、微小な上下左右揺れを軽減 |
| `torso` | `上半身*`, `下半身`, `首`, `頭` | 回転の微振動を軽減。頭は弱め |
| `arms` | `*肩*`, `*腕*`, `*ひじ*`, `*手首*` | 手振りを残すため中程度 |
| `fingers` | `*指*`, `*finger*` | 細部保持を優先し弱め。スパイク除去中心 |
| `legs` | `*足*`, `*脚*`, `*ひざ*`, `*膝*`, `*つま先*` | 接地と歩幅を壊さない範囲で中程度 |
| `foot_ik` | `*足IK*`, `*足ＩＫ*`, `*leg IK*`, `*foot IK*` | 接地中は強く、遊脚中は中程度 |
| `toe_ik` | `*つま先IK*`, `*つま先ＩＫ*`, `*toe IK*` | 接地X/Zロックは弱め。つま先の動きと回転を保持 |

分類は具体度の高い種別を優先する。標準ボーン名は包含関係を持ち、例えば `右足ＩＫ` は `legs`(`*足*`)と `foot_ik`(`*足ＩＫ*`)の両方に一致し、`右つま先ＩＫ`(全角ＩＫ)は `legs`(`*つま先*`)と `toe_ik` の両方に一致する。`foot_ik` と `toe_ik` を `legs` より先に判定し、足IK・つま先IKボーンが `legs` に分類されないようにする。

ボーン種類ごとにパラメータを変える必要がある。同じ0.02 MMD単位の揺れでも、センターでは全身の揺れになり、指では許容できる細部になる。足IKは接地中の水平ぐらつきが視覚的に目立つため、他ボーンより強い安定化が必要である。

また、種別ごとの効かせ方は初期値だけで固定しない。入力VMD、モデルスケール、モーションの演技内容によって適切な平滑化量が変わるため、プリセット値は実データで調整できる前提とする。

### 4.2 一般ノイズ軽減

ツールは各ボーンの位置・回転ノイズを、種別ごとのパラメータで軽減する。

要求:

- 単発スパイクを軽減する。
- 高周波の微小振動を軽減する。
- 大きなステップ、ジャンプ、ターン、手振りなどのアクセントを保護する。
- ボーン回転はquaternionとして扱い、符号反転による見かけのジャンプを避ける。
- 不連続境界をまたいで平滑化しない。
- 元値からの最大変更量を制限する(初期値は [§5.5](#55-最大変更量最大補正量))。

一般ノイズ軽減は2つの方式を持ち、`--denoise-mode` で選ぶ(既定 `bone`)。

- `bone`(既定): 上記のとおりボーンごとに位置・回転チャンネルを個別に平滑化する。`pose` を明示しない限りこの方式で動く。
- `pose`: MMDで実際に見える表現空間(主要ボーン・仮想マーカーのワールド軌跡)でノイズを評価・除去する。VMD姿勢をPMXボーン階層で前方評価(FK)し、マーカーのワールド軌跡を平滑化してから、平滑化マーカーへ合うようボーン姿勢を小さく補正する。複数ボーンに分散した揺れや、合成結果として末端で目立つ揺れを狙って抑える。出力は密キーで、後段の足IK安定化・疎化へ `bone` と同じ形式で渡る。

`pose` はモデル情報に依存する。`--pmx PATH` を指定するとそのPMXを読んでモデル固有に評価し、未指定時は内蔵の既定モデルプロファイル(標準的なモデル近似)を使うため、ユーザーがPMXを用意しなくても動く。PMX読み取りとFK評価はフォーマット層 `pmx` に委譲する。`--no-denoise` 時は方式によらず一般ノイズ軽減を行わない(`pose` 指定でもPMXは不要)。

`--pmx` のパスが存在しない/通常ファイルでない場合・PMX形式が不正な場合・指すモデルが必須標準ボーンを欠く場合は、いずれも入力不正として終了コード1(非VMD入力と同じ扱い、[§9](#9-終了コード))とする。

`bone` 方式の検出・平滑化の確定基準は次のとおり(初期値。実データで調整。フィルタの数値計算の内部実装は、この挙動・初期パラメータ・テストを満たす範囲で実装側で決める)。

チャンネル別の平滑化方式:

| チャンネル | 方式 |
|---|---|
| 位置 | 種別の位置の窓幅([§5.2](#52-クリーニング強度--clean-strength))で中央値フィルタ後、同じ位置の窓幅で Savitzky-Golay(2次、端はミラー反射)。結果を種別の位置のブレンド率で合成 |
| 回転 | quaternion を同一半球へ揃え、種別の回転の窓幅内で成分平均してから正規化(slerp の近似)した値を回転のブレンド率で合成 |
| 足IK接地中の位置 | 接地アンカーへ寄せるロック型平滑化([§4.3](#43-足ik安定化) / [§5.4](#54-接地ロック強度)) |

スパイクとアクセントは別の量で判定する。スパイクは窓基準からの逸脱(外れ値)、アクセントはフレーム間変化量(速度)で捉える。一定速度の継続運動は窓中央値・窓内平均が注目値に一致して逸脱が出ないため、逸脱ではアクセントを検出できず速度で見る。

- スパイク候補: 窓基準からの逸脱が 位置 0.3 MMD単位(各軸)/ 回転 5度 を超えるフレーム(0.3 / 5度ちょうどは非候補。[§5.5](#55-最大変更量最大補正量) のクランプ閾値と同じ)。位置は窓中央値、回転は窓内正規化平均を基準にする。
- スパイク(補正対象): スパイク候補のうち、速度がそのフレームで単発の符号反転(往復)をするもの。位置は該当軸のみ窓中央値で置換し、回転は窓内正規化平均へ寄せる(回転は中央値を使わない)。前後双方の差分が要るため、区間端・カット隣接はスパイクにしない。
- アクセント(保護対象): フレーム間変化量(速度)が 位置 0.3 MMD単位(各軸)/ 回転 5度 を超え(スパイク閾値と同じ値を速度に適用)、符号が反転せず同方向に 2本以上連続する差分の区間(run)。その run が張るフレーム全体(位置は該当軸)を保護マスクに入れ、平滑化・スパイク補正の対象にしない。
- 競合時の優先: アクセント run の終端の山・谷などで往復に見えるフレームはアクセント保護を優先する。最終スパイク = 候補 ∩ 往復 − アクセント − 境界(カット・範囲端)。アクセント run と境界を先に確定してからスパイクを差し引く。

速度は連続フレームの値の差(位置は各軸の差、回転は前フレームからの相対回転)。符号反転は注目フレームの前後の差分の符号が逆転すること。位置は各軸ごとに差分の正負で判定する。回転は前後の相対回転を回転ベクトル(quaternion の log)で表し、前後ベクトルの内積が負を往復、正を同方向とみなす(角度距離は非負なので大小では向きを定義できない)。差分の大きさが実質ゼロ(位置は各軸の絶対差、回転は相対回転ベクトルのノルム(ラジアン)が `1e-9` 以下)のフレームは往復にも同方向継続にも数えない。

平滑化前の保護マスクで使う不連続・カットの検出は、疎化と同じカット閾値(位置 1.0 MMD単位 / 回転 30度)を用いる。これを越える急変はカット境界として保護し、平滑化はこの境界をまたがない。カット境界はカットフレーム F とその直前 F-1 の両側を保護し(疎化の継ぎ目規約と同じ)、範囲端(先頭・末尾フレーム)も保護する。検出・平滑化は各ボーンの密サンプルを 0 始まりの相対インデックスで扱い、レポートへ出すフレームのみ範囲開始フレームを足して絶対フレームへ戻す。窓は奇数で中心フレームを含み、区間長が窓に満たない短区間では区間長以下の最大奇数へ縮め、実効窓が 3 未満なら平滑化しない。中央値フィルタ・Savitzky-Golay はカット区間ごとに適用する。指数移動平均・双方向IIR は初期実装では使わず、効果不足時の代替候補とする。

### 4.3 足IK安定化

足IKボーンが接地中に小刻みに移動すると、足裏が床を噛まず、氷上を滑るように見える。ツールは足IKまたはつま先IKの接地区間を推定し、接地中の水平X/Zぐらつきを重点的に抑える。

接地判定は**接地高さ(低Y)を主基準**とする。モーションキャプチャーの足は接地したまま水平に滑る(ドリフトする)ことが多く、水平移動を厳しく接地除外条件にすると、まさに抑えたい「滑っている接地」が検出から漏れてロックがかからない。そこで接地判定での水平速度の許容(どこまで速く動いても接地候補とみなすか)を横滑り抑制パラメータ `--foot-slide-suppression S`(0〜1)で制御する。

接地候補条件:

- Y位置が局所的に低い(接地高さ)。
- 垂直方向に持ち上がっていない(垂直速度が小さい)。
- 水平速度の許容は `S` で決める(接地候補とみなす水平速度の上限。`S=0`→0.08 / `S=1`→1.0 MMD単位/フレームを線形に写像)。`S=0` は従来どおり「水平速度が小さい(0.08 以下)」フレームのみ接地候補とし、意図的に滑らせる動きを保持する。`S=1`(既定)は許容を大きく緩め、接地高さで水平に滑っている足も接地として拾う(速い遊脚=許容を超える水平速度だけを接地から除く)。
- 一定フレーム以上継続する。
- 足IKとつま先IKの相対位置が急変していない。

**既定は `S=1.0`(規定=横滑りなし)** で、接地中の横滑りを除去する。意図的に足を滑らせるダンスは `S` を下げる(`0` で従来の検出=滑りを保持)。`S` は接地ロックのX/Zロック強度([§5.4](#54-接地ロック強度))と最大補正量の上限([§5.5](#55-最大変更量最大補正量))も併せて制御する。

接地区間検出の初期閾値(初期値。実データで調整):

| 項目 | 値 |
|---|---:|
| 最小接地長 | 4 フレーム |
| 水平速度許容 | 横滑り抑制 `S` 連動(`S=0`→0.08 / `S=1`(既定)→1.0 MMD単位/frame を線形) |
| 垂直速度閾値 | 0.04 MMD単位/frame |
| 接地Y局所窓 | ±5 フレーム |
| 接地Y許容幅 | 局所最小(上記窓内) + 0.08 MMD単位 |
| 相対位置急変閾値 | 足IKとつま先IKのVMD位置差分の1フレーム変化が 0.08 MMD単位以下 |

足IKとつま先IKの相対位置が急変するフレームは接地候補から除外する。ここでの「相対位置」はPMX階層や基準姿勢を読まないモデル非依存の量で、同側の足IKとつま先IKのVMD位置値(チャンネル値)の差分ベクトルの1フレーム変化量を用いる。接地中は両IKが静止して差分も静止し、差分が急変するフレームは少なくとも一方が動いている=非接地の指標になる。差分の絶対値は真の空間距離である必要はなく、変化量のみを判定に使う。対応するつま先IKが無いモデルでは相対位置条件をスキップし、速度・Y変化・継続長で判定する。

接地区間ごとに、足IK・つま先IKそれぞれの位置の中央値を各自のアンカーとする。各IKは自身の中央値を使い、VMDチャンネル値は同一座標とは限らないためアンカーを共有しない。中央値は外れ値に強く、片足を置いた瞬間の1フレーム跳ねに引っ張られにくい。

足IKとつま先IKは役割が異なるため接地ロックを分ける。足IKは足首・足裏の接地ターゲットで水平X/Zの滑り(氷上感)が主問題、つま先IKは足IKに対するつま先の向き(かかと上げ・つま先離れ・ロール)を担うため、強く固定するとつま先の動きが潰れる。

接地中の要求:

- `foot_ik`: X/Zは接地アンカーへ強く寄せる。Yは完全固定ではなく、床への沈み込みや段差表現を壊さない範囲で弱めに寄せる。
- `toe_ik`: X/Zロックは弱くし、つま先離れ・ロール・爪先立ちを保つ。回転は保持し、一般の弱い平滑化を中心にする。
- ロック係数の確定値(接地中央・接地端)は [§5.4](#54-接地ロック強度) に定義する。
- 接地開始・終了ではフェードを入れ、足が急に吸い付く見た目を避ける。
- 最大補正量([§5.5](#55-最大変更量最大補正量))を超える場合はロック強度を下げ、警告する。
- 左右足の接地が交互に切り替わる区間では、初期実装ではセンター補正を行わない。

### 4.4 レポートと診断

`--dry-run` は以下を標準出力へ表示する。

- ボーン一覧、分類結果、キー数、フレーム範囲。
- 適用予定のプリセットと主要パラメータ。
- 足IK候補、つま先IK候補。
- スパイク候補、接地候補、保護されたフレーム。
- 最大位置変更量、最大回転変更量。
- 足IKロックを適用した区間、見送った区間、見送り理由。
- 疎化のキー削減率、適用した許容誤差、検出カット数、最大再生誤差。
- `pose` モード([§4.2](#42-一般ノイズ軽減))では、表現空間ノイズ除去の診断を `pose_denoise` 要約として表示する。PMX使用有無(または既定モデルプロファイル使用)・有効マーカー数・必須標準ボーン検証・平滑化前後のマーカー変位(最大/平均)・姿勢フィットの誤差改善(補正前後)・フォールバック数を含む。

`-v, --verbose` は通常実行(出力VMDを書く)でも上記と同じレポートを標準出力へ表示する。診断素データの収集は `--dry-run` / `--verbose` のときだけ行い、通常実行のオーバーヘッドを増やさない。機械モード(`--machine`)では標準出力をイベント専用に保つため、この人間向けレポート表示は出さない(入力検査は `--machine --dry-run` の inspect result で得る。[§10.2](#102-イベントペイロード))。

### 4.5 チューニング支援

ツールは、ボーン種別ごとの効かせ方を調整できるようにする。

要求:

- プリセットは固定値ではなく、実データで調整する対象として扱う。
- ボーン種別ごとに、位置の窓幅、回転の窓幅、位置のブレンド率、回転のブレンド率、最大補正量を確認できる。
- レポートでは、ボーン種別ごとの最大変更量、平均変更量、保護フレーム数、接地ロック適用率を確認できる。
- チューニング時に、効かせすぎで演技が丸まったボーン種別と、効き不足でノイズが残ったボーン種別を判別できる情報を出す。
- 初期実装ではCLI上書きオプションを必須としないが、将来 `--tuning-file` のような外部設定で種別別パラメータを上書きできる余地を残す。

## 5. プリセット要求

### 5.1 チューニング初期方針

初期チューニングでは、足IKとセンターの安定を優先しつつ、手首・指・頭の細かい演技を潰さない保守的な値から始める。

方針:

- `foot_ik` は接地中のX/Z滑り抑制を最優先し、接地中央だけ強めに固定する。
- `toe_ik` はX/Z固定を弱め、つま先の動き・回転を保つ。
- `center` は全身の微振動を抑えるため中程度に効かせる。ただし上下動と重心移動は保護する。
- `torso` は回転ノイズを中心に抑え、切り返しや姿勢変化は残す。
- `arms` は弱から中程度に留め、手振りやポーズのアクセントを優先する。
- `fingers` は最初は弱めにし、単発スパイク除去を中心にする。
- `root` は全体移動への影響が大きいため、初期値ではほぼ保持する。

なぜそうするのか:

- 足IKの接地中の揺れは少量でも滑って見えやすく、見栄えへの悪影響が大きい。
- センターの揺れは全身に伝わるため、微振動を抑える効果が大きい一方、効かせすぎると重心移動が鈍る。
- 手首・指・頭の高周波成分は、ノイズではなく演技や表情として見える場合がある。
- 初期値を強くしすぎると、モーションキャプチャーの生っぽさや細かなニュアンスを失いやすい。
- 先に保守的な値で破壊を避け、レポートと視覚確認で不足箇所だけ強める方が、原因を追いやすい。
- 疎化は滑らかになった信号ほどキーが減りやすいため、ノイズを抑える対象は「見た目と疎化の両方に効く箇所」から優先する。

このため、初期プリセットは「足元と全身揺れを先に整え、細部は守る」方向に置く。実データで足IKの滑り、センターの震え、手指の丸まりを確認しながら、種別ごとの値を調整する。

### 5.2 クリーニング強度(`--clean-strength`)

クリーニング強度は名前付きプリセットを持たず、数値の倍率 `--clean-strength`(既定 1.0)で指定する。種別ごとの基準パラメータ(下表)に対し、この倍率を**位置のブレンド率・回転のブレンド率のみ**に掛けて全体の効き量を変える(窓幅は据え置き)。0で無加工相当、1.0で下表の基準どおり、上げるほど強く平準化する。倍率が掛かるのは `bone` 方式([§4.2](#42-一般ノイズ軽減))の種別別ブレンド率に限る。`pose` 方式([§4.2](#42-一般ノイズ軽減))はワールド軌跡を専用パラメータで平滑化する別系統で、`--clean-strength` では倍率変更しない(方式は `--denoise-mode` で選ぶ)。

初期パラメータ(初期値。実データで調整):

| 種別 | 位置の窓幅 | 回転の窓幅 | 位置のブレンド率 | 回転のブレンド率 | 備考 |
|---|---:|---:|---:|---:|---|
| `root` | 3 | 3 | 0.15 | 0.10 | ほぼ保持 |
| `center` | 7 | 5 | 0.45 | 0.25 | 微小揺れを抑える |
| `torso` | 5 | 5 | 0.25 | 0.35 | 回転ノイズ中心 |
| `arms` | 5 | 5 | 0.25 | 0.25 | ジェスチャ保持 |
| `fingers` | 3 | 3 | 0.10 | 0.15 | スパイク除去中心 |
| `legs` | 5 | 5 | 0.30 | 0.25 | 接地を壊さない |
| `foot_ik` | 7 | 3 | 0.65 | 0.20 | 接地中のX/Z滑りは別途ロック([§4.3](#43-足ik安定化) / [§5.4](#54-接地ロック強度)、`--foot-slide-suppression`) |
| `toe_ik` | 5 | 3 | 0.50 | 0.20 | 足IKより少し弱め |
| `unknown` | 3 | 3 | 0.10 | 0.10 | 分類不能。保守的に弱く処理する |

分類できないボーンは除外せず `unknown` として一般ノイズ軽減・疎化の対象に含める。クリーニングは上表のとおり保守的な弱設定、疎化スケールは標準([§5.3](#53-疎化プリセットと種別別許容誤差) で位置・回転とも 1.0)。

`位置のブレンド率` と `回転のブレンド率` は、元値と平滑化値のブレンド係数として扱う。0なら元値を保持し、1なら平滑化値を採用する。`--clean-strength` の倍率を掛けた結果は 0〜1 にクランプする(倍率を上げてもブレンド率は1.0=完全平滑化を超えない。窓幅は倍率で変えない)。`--clean-strength` は有限の非負値のみ受け付け、範囲外・非有限は引数エラー(終了コード2)とする。

`--clean-strength` の例: `0.5` で全種別の効き量を半分にし変化を最小化(スパイク除去中心)、`1.0`(既定)で上表どおり、`1.4` で全種別を一様に強める(演技の丸まりに注意)。倍率は全種別へ一様に掛かる。

接地ロックの強度はブレンド率の倍率では変えない。`foot_ik` の X/Z 滑りロックは `--clean-strength` ではなく横滑り抑制パラメータ `--foot-slide-suppression` で制御する([§5.4](#54-接地ロック強度))。`--clean-strength` が制御するのは一般ノイズ軽減の効き量であり、接地中の横滑り抑制とは別系統である。

上記は初期値であり、実データでチューニングする。特に `center`、`foot_ik`、`toe_ik`、`fingers` は見た目への影響が大きいため、削減率だけでなくMMD上の視覚確認で調整する。

### 5.3 疎化プリセットと種別別許容誤差

疎化の許容誤差はボーン種別ごとに変える。プリセット(`--preset`)が基準値を与え、種別ごとのスケール係数を掛けた値を各ボーンの許容誤差として疎化に使う。mocapvmd 独自の初期値で `sparsevmd` とは共有せず、実データでチューニングする。名前は速度の観点で統一する(遅い=高忠実でキーが多く処理も遅い、速い=高圧縮でキーが少なく処理も速い)。許容を緩める(値を大きくする)ほどキーが減って編集しやすく処理も速いが細部が丸まる。既定は中央の `medium`。

プリセット基準値(位置許容と回転許容は連動。`fast` / `faster` は粗く疎化するため出力キーが少なく疎化処理も速い):

| プリセット | 基準位置許容(MMD単位) | 基準回転許容(度) | 用途 |
|---|---:|---:|---|
| `slower` | 0.05 | 0.40 | 最も忠実(キー多め・処理遅め) |
| `slow` | 0.10 | 0.75 | やや忠実 |
| `medium` | 0.20 | 1.50 | 既定。編集しやすさと品質の両立 |
| `fast` | 0.80 | 6.0 | 削減・速度優先 |
| `faster` | 1.60 | 12.0 | 最大削減・最速 |

種別スケール(基準値への倍率。1未満で厳しく=キーを残し、1超で粗く=よりキーを減らす):

| 種別 | 位置スケール | 回転スケール | 備考 |
|---|---:|---:|---|
| `root` | 1.0 | 1.0 | 標準 |
| `center` | 0.7 | 0.8 | 全身に効くため厳しめ |
| `torso` | 0.8 | 0.9 | 姿勢変化を残す |
| `arms` | 1.0 | 1.0 | 標準 |
| `fingers` | 1.5 | 1.5 | 細部は粗くてよい |
| `legs` | 1.0 | 1.0 | 標準 |
| `foot_ik` | 0.7 | 1.0 | 接地の水平位置を残す |
| `toe_ik` | 1.0 | 0.8 | 位置は粗く、つま先の回転は残す |
| `unknown` | 1.0 | 1.0 | 分類不能。標準 |

各ボーンの許容誤差 = プリセット基準値 × その種別のスケール。`--reduce-error-bone-pos` / `--reduce-error-bone-rot` を明示した場合は `--preset` の基準値を上書きし(種別スケールは引き続き掛ける)、プリセット基準値より優先する。カメラ用の許容誤差は持たない。

### 5.4 接地ロック強度

接地ロックは接地中に足IK・つま先IKを接地アンカーへ寄せるブレンド係数(0〜1。1に近いほど強く固定)。接地中央の値を効かせ、接地区間の開始・終了端では端値から中央値へ線形フェードして急な吸い付きを避ける。フェード幅は端から既定3フレームで、接地長が6フレーム未満なら接地長の半分ずつに按分する。係数は0〜1に近い直接値で与える(倍率ではない)。`foot_ik` の X/Z 接地中央は横滑り抑制パラメータ `--foot-slide-suppression` で決め、他チャンネルは固定値とする。

各チャンネルの接地中央値・接地端値:

| 種別/チャンネル | 接地中央 | 接地端 |
|---|---:|---:|
| `foot_ik` X/Z | `S` 連動(下記) | `S` 連動(0→0.25) |
| `foot_ik` Y | 0.50 | 0.10 |
| `toe_ik` X/Z | 0.30 | 0.10 |
| `toe_ik` Y | 0.30 | 0.10 |

`foot_ik` の X/Z 接地中央(横滑り抑制の主役)は横滑り抑制パラメータ `--foot-slide-suppression S`(0〜1)で決める。`S=0` で `0.0`(アンカーへ寄せない=滑りを保持)、`S=1`(既定)で `0.97`(強く固定)へ、間は線形に写像する(初期値。実データで調整)。これにより接地中の横滑り抑制をクリーニング強度(`--clean-strength`)から切り離し、専用パラメータで指定できる。既定 `S=1.0` では X/Z 接地中央が最強(0.97)となり、接地高さで滑る足を強くアンカーへ固定する(規定=横滑りなし)。

`foot_ik` の X/Z 接地端も `S` で連動させ(`S=0`→`0.0` / `S=1`→`0.25`)、フェードの端値とする。端値も `S` で動かすのは、端を固定値にすると `S` が小さいとき端>中央となりフェードが逆転する(端の方が強く寄る)ため。常に端≤中央を保ち、`S=0` では中央・端とも `0.0` で横滑りロックを完全に外す。`foot_ik` Y・`toe_ik` の各値は `S` ・プリセットによらず固定する。`toe_ik` は一貫して弱く、つま先の動き・回転を保つ。

### 5.5 最大変更量・最大補正量

クリーニングが元モーションを壊さないよう、変更量に上限を設ける(初期値。実データで調整):

- 一般ノイズ軽減: 1フレームあたり元値からの変更を 位置 各軸 0.3 MMD単位 / 回転 5度 に制限し、超える分はクランプする(位置はスパイク判定と同じ各軸尺度)。
- 足IK接地安定化: 接地区間内で元値からの1フレーム最大変位(X/Z/Y のユークリッド距離)の上限は横滑り抑制パラメータ `--foot-slide-suppression S` で線形に決める(`S=0`→`0.5` / `S=1`→`2.0` MMD単位を線形写像。初期値。実データで調整)。`S=1`(既定)では上限を大きく取り、接地高さで大きく滑った足もアンカーへ十分に引き戻す。上限を超える場合はその接地区間のロック係数を、変位が上限以内に収まるまで下げ、レポートに警告を出す([§4.3](#43-足ik安定化))。上限が低いと大きな滑りが上限で頭打ちになって残るため、既定では上限を緩めて横滑りを除去する(規定=横滑りなし)。

## 6. sparsevmd との関係

`mocapvmd` と `sparsevmd` は別CLIだが、疎化機構を `vmd` で共有する。

- 役割: `sparsevmd` は任意の密モーションをボーン選択しつつ指定誤差以内で疎化する汎用ツール。`mocapvmd` はモーションキャプチャー向けクリーニングを全ボーンに行ってから同じ機構で疎化する専用ツール。
- 共有: 区間分割・キー削減・継ぎ目処理・誤差検証・ベジェ採否は `vmd.reduce`。`sparsevmd.reduce` は既に再公開層。`mocapvmd` はボーン選択を行わないため、`sparsevmd` のボーン選択機構は共有しない。
- 連結方法: 中間VMDを介した `mocapvmd` → `sparsevmd` のパイプライン連結は採用しない。クリーニングと疎化は `mocapvmd` の1コマンド内で完結させる。
- `sparsevmd` にクリーニング機能は持たせない。クリーニングはモーションキャプチャー固有のドメイン処理として `mocapvmd` 側に置く。

## 7. 制約と考慮事項

- カット、ワープ、瞬間的なポーズ変更は平滑化しない。
- モーフは補間曲線を持たず表情の意図が強いため、ノイズ軽減対象に含めない。
- VMDのIKプロパティは初期実装では透過する。ただし足IKが無効になる区間が明示されている場合、将来的には接地安定化対象から外す。
- MMDモデルには標準ボーン名から外れた名前や追加IKがあるため、分類結果を `--list-bones` とレポートで確認できるようにする。
- MMD距離単位はモデルスケールに依存して見え方が変わるため、将来的には入力モーションの足IK移動量やセンター移動量から自動スケール推定し、閾値を補正する。
- ボーン種別ごとの効かせ方はモーション内容に依存するため、初期値で全ケースを固定的に満たそうとしない。診断、プレビュー、視覚確認を通じて調整できる設計にする。
- 全身の密ボーンは本数が多く疎化のコストが大きいため、ボーン単位で並列に疎化して実時間を短縮する。各ボーンの疎化は独立かつ決定論的なので、並列実行の出力(疎キー列・診断)はワーカ数や実行順に依らず逐次実行と完全に一致する。並列のワーカ数は既定で実行環境のCPUコア数を基準とし、疎化対象のボーンが少ないときはオーバーヘッドを避けて逐次実行する。

## 8. 未決事項

実データでのチューニングと視覚確認を通じて決める設計判断。初期実装では確定しない。

- 両足接地中にセンターを安定化するか(初期実装ではセンター補正を行わない。[§4.3](#43-足ik安定化))。
- 接地判定に足IKだけでなく足首・つま先ボーンを併用するか。
- プリセット値の定量的な合否基準(許容する最大変位・残ノイズ量などの数値しきい値)をどう定義するか。定性的な調整観点・手順は [`TUNING.md`](TUNING.md) で定義済み。
- 種別別パラメータをCLIオプションにするか、外部チューニングファイル(`--tuning-file`)にするか([§4.5](#45-チューニング支援)。初期実装では必須としない)。

## 9. 終了コード

| コード | 意味 |
|---|---|
| 0 | 正常終了 |
| 1 | 入力不正(VMD でない・入力パス不在・ボーン値が非有限等・PMX 形式不正・`--pmx` パス不在・モデルプロファイル不正) |

## 10. 機械モード(機械可読インターフェース)

機械モードは、他のソフトウェアが mocapvmd を子プロセスとして呼ぶための構造化出力を提供する。共通契約(イベント種別の語彙・終端規則・チャネル固定・stdout の UTF-8/LF 固定・終了コードの基底)は規約 [§3](../../docs/conventions/cli-interface.md#3-機械モードの起動)〜[§6](../../docs/conventions/cli-interface.md#6-横断的な一貫性)・[§8](../../docs/conventions/cli-interface.md#8-キャンセルと出力の原子性)・[§10](../../docs/conventions/cli-interface.md#10-移植性パス符号化改行ロケール) と、共有基盤 [cli_events](../../libs/cli_events/cli_events.md) が正本であり、本節は mocapvmd 固有のイベントペイロードと `code` 値だけを定める。イベント送出は共有基盤 cli_events に委譲する。

### 10.1 チャネルと終端

- **構造化出力モード**は `--machine` 指定時と `--describe` 指定時(規約 [§3](../../docs/conventions/cli-interface.md#3-機械モードの起動)。`--describe` は人間向け既定を持たない独立メタ操作)。どちらかが argv にあれば引数解析前に先取り判定し、使用法エラー・想定外エラーも error イベントで終端する(例: `--describe` と未知オプションの併用も `bad_argument` イベント+終了コード 2)。
- 構造化出力モードの標準出力は [§10.2](#102-イベントペイロード) のイベントのみ。バイナリストリームとして標準出力へ UTF-8・行区切り LF で書き、ロケール符号化・CRLF 変換に依存しない(規約 [§10](../../docs/conventions/cli-interface.md#10-移植性パス符号化改行ロケール))。
- 人間向け標準エラーは、ロケール符号化で表せない文字を置換して出し、符号化失敗でプロセスを落とさない(規約 [§10](../../docs/conventions/cli-interface.md#10-移植性パス符号化改行ロケール)。機械モードに限らず常に適用する)。
- ストリームは result または error のちょうど 1 つで終端する(規約 [§4](../../docs/conventions/cli-interface.md#4-イベントストリーム標準出力) が定める終端保証の例外を除く)。終端は CLI 本体の単一経路で送出し、終端後の送出は拒否される。
- `--help` / `--version` は `--machine` 併用でも人間向けテキストを出して終了コード 0 で終わり、イベントストリームには載せない(規約 [§3](../../docs/conventions/cli-interface.md#3-機械モードの起動) のメタ操作の例外)。
- イベント契約の進化は規約 [§4.1](../../docs/conventions/cli-interface.md#41-イベント契約の進化と前方互換) に従う(フィールド・種別・`code` の追加=MINOR、削除・意味変更=MAJOR。受信側は未知要素を無視できる前提)。

### 10.2 イベントペイロード

- **progress**: `{type:"progress", stage, done, total, note, elapsed}`。`stage` は安定 id `"denoise"`(ノイズ軽減)/ `"foot_ik"`(足IK接地安定化)/ `"reduce"`(キーフレーム圧縮)。各段は開始時に `done=0, total=null, note:"", elapsed:0.0` を 1 本出す。`reduce` 段はさらに疎化対象ボーンの完了数を `done`/`total` で出す(`total`=多キートラック数。値列はワーカ数・完了順に依らない)。`denoise` / `foot_ik` 段は開始 1 本のみ。`elapsed` は段開始からの経過秒(float)。無効化した段(`--no-denoise` 等)はイベント自体を出さない。
- **warning**: `{type:"warning", code, message, section}`。`section` は対象セクション名の配列(該当が無ければ `null`)。`vmd.io.read` の警告は `VmdWarning.code`(ハイフン区切り。`decode-error`・`sections-missing` など)をそのまま透過し、`section` は単一要素配列にする。人間向け経路と同じ基準(code・section・message の同一組は 1 件)で重複をまとめる。
- **result**: 正常終了の終端イベント。`mode` で形が決まる:
  - `mode:"process"`(通常実行): `{type:"result", mode:"process", output, input_keys, output_keys}`。`output` は書き出しパス(文字列)、`input_keys` / `output_keys` は入力/出力のボーンキー総数。
  - `mode:"inspect"`(入力検査 `--machine --dry-run`): VMD を書かず `{type:"result", mode:"inspect", output:null, input_kind:"bone", keys, frame_range, duration_sec, sections, preset, clean_strength, denoise, denoise_mode, foot_ik_stabilize, foot_slide_suppression, curve_mode, reduce, bones, reduction, pose_denoise}` を出す。`keys` は入力ボーンキー総数、`frame_range` は全ボーンキーの `[最小フレーム, 最大フレーム]`(キー 0 件なら `null`)、`duration_sec` は最大フレーム÷30(キー 0 件なら `null`)、`sections` は入力に存在するセクション名の配列。`preset`〜`reduce` は解決済みの実行計画(引数値)。`bones` は初出順の `{name, category, keys, frame_range:[first,last]}` の配列。`reduction` は疎化診断(`--no-reduce` 時は `null`)で、トラック名→ `{input_keys, output_keys, tol_pos, tol_rot, cuts, errors:{pos_x,pos_y,pos_z,rot_deg}}` のオブジェクト。`pose_denoise` は `--denoise-mode pose` かつノイズ軽減有効のときの診断 `{pmx, frames, markers:{available, required_bones_ok}, marker_displacement:{max, mean}, fit:{mean_error_before, mean_error_after, fallback_frames, max_bone_delta_deg, max_center_delta}}`(それ以外は `null`)。クリーニング診断の詳細(スパイク・保護・接地区間)は人間向け dry-run テキストに残し、inspect には載せない(必要になれば規約 [§4.1](../../docs/conventions/cli-interface.md#41-イベント契約の進化と前方互換) の後方互換追加で拡張する)。
  - `mode:"list_bones"`(`--machine --list-bones`): `{type:"result", mode:"list_bones", bones}`。`bones` は初出順の `{name, category}` の配列。VMD は書かない。非機械の `--list-bones` は人間向けテキストを出す。`--list-bones` と `--dry-run` の併用は `--list-bones` を優先する。
  - `mode:"describe"`(自己記述 `--describe`): `{type:"result", mode:"describe", options, presets}`([§10.3](#103---describe-の中身))。VMD を読まないので他 mode のキーは載せない。
- **error**: `{type:"error", code, exit_code, field, path, message}`。`field` / `path` は対象が無ければ `null`。失敗の終端イベント([§10.4](#104-構造化エラー))。

### 10.3 `--describe` の中身

`options` は処理を駆動する引数の配列(メタ/モード操作 `--describe` / `--version` / `--help` / `--machine` は含めない)。各要素は `{name, type, constraint, default, help}`(キーは常に 5 つ、該当しない値は `null`)。`type` は固定語彙 `"float"` / `"int"` / `"str"` / `"flag"` / `"enum"`。数値の `constraint` は `{min, max, exclusive_min}` の 3 キー常設(上限が無ければ `max:null`)、`enum` は `{choices:[...]}`、`flag` / `str` は `null`。`help` はその引数の役割を人間向けに述べた文字列。真偽フラグの対(`--denoise` / `--no-denoise`・`--foot-ik-stabilize` / `--no-foot-ik-stabilize`・`--reduce` / `--no-reduce`)は**肯定形の長形式 1 要素だけ**を載せる(型 `flag`。無効化の起動形は名前に `--no-` を前置した否定形。規約 [§6](../../docs/conventions/cli-interface.md#6-横断的な一貫性) の `--x/--no-x` 様式。呼び出し側は `default` が `true` のフラグを無効化するとき否定形を発行する)。否定形を別要素として重複列挙しない。全 18 要素:

| name | type | constraint | default |
|---|---|---|---|
| `input` | str | null | null |
| `--output` | str | null | null(既定は入力名由来 `<入力名>_mocap.vmd` の算出値。規則は help に記す) |
| `--overwrite` | flag | null | false |
| `--preset` | enum | `{choices:["slower","slow","medium","fast","faster"]}` | `"medium"` |
| `--clean-strength` | float | `{min:0, max:null, exclusive_min:false}` | 1.0 |
| `--denoise` | flag | null | true |
| `--denoise-mode` | enum | `{choices:["bone","pose"]}` | `"bone"` |
| `--pmx` | str | null | null |
| `--foot-ik-stabilize` | flag | null | true |
| `--foot-slide-suppression` | float | `{min:0, max:1, exclusive_min:false}` | 1.0 |
| `--reduce-error-bone-pos` | float | `{min:0, max:null, exclusive_min:false}` | null(プリセット値) |
| `--reduce-error-bone-rot` | float | `{min:0, max:null, exclusive_min:false}` | null(プリセット値) |
| `--curve-mode` | enum | `{choices:["bezier","linear"]}` | `"bezier"` |
| `--reduce` | flag | null | true |
| `--list-bones` | flag | null | false |
| `--dry-run` | flag | null | false |
| `--quiet` | flag | null | false |
| `--verbose` | flag | null | false |

`presets` は各要素 `{name, values}` の配列。`name` は疎化プリセット名(`slower`〜`faster`)、`values` は `{reduce_error_bone_pos, reduce_error_bone_rot}`([§5.3](#53-疎化プリセットと種別別許容誤差) の基準位置許容・基準回転許容)。種別スケール・クリーニング基準・接地ロック係数は CLI 非公開の内蔵パラメータなので載せない。

### 10.4 構造化エラー

失敗は終了コードに加え、構造化出力モード(`--machine`・`--describe`。[§10.1](#101-チャネルと終端))では error イベントで「どのフィールド/パスが・なぜ」を返す。それ以外では理由を標準エラーへ最低 1 行出す(書式 `error: <message>`。トレースバックは出さない)。

| 事象 | `code` | `field` | `exit_code` |
|---|---|---|---|
| argparse 検出(未知オプション・型エラー・choices 外・positional 欠落)、および解析後の値検証(`--clean-strength` の非有限/負・`--foot-slide-suppression` の範囲外/非有限・`--reduce-error-bone-pos`/`--reduce-error-bone-rot` の非有限/負) | `bad_argument` | argparse が示す引数名、値検証は該当オプション名 | 2 |
| 入力パスが不在・通常ファイルでない | `input_not_file` | `"input"` | 1 |
| `--pmx` パスが不在・通常ファイルでない(pose 方式時) | `pmx_not_file` | `"--pmx"` | 1 |
| 出力先が既存のディレクトリ(`--overwrite` の有無に依らない) | `output_is_directory` | `"--output"`(+ `path`) | 2 |
| 出力先に既存ファイルがある・`--overwrite` 未指定 | `output_exists` | `"--output"` | 2 |
| 入力が VMD でない・破損 | `not_vmd` | `"input"` | 1 |
| ボーン値の非有限・ゼロノルム quaternion | `invalid_bone_values` | `"input"` | 1 |
| PMX 形式不正(`PmxFormatError`) | `not_pmx` | `"--pmx"` | 1 |
| モデルプロファイル不正(必須標準ボーン欠落等) | `model_profile_invalid` | `--pmx` 指定時 `"--pmx"`、内蔵プロファイル時 `null` | 1 |
| 出力書き込み失敗 | `write_failed` | `"--output"`(+ `path`) | 3 |
| 上記いずれにも当たらない想定外の内部エラー | `internal_error` | `null` | 1 |
| 協調的な中断(Ctrl-C 等) | `cancelled` | `null` | 130 |

- `not_vmd` は読み込み例外の種別・文言を `message` に載せる。
- 構造化出力モードの argparse エラーは `bad_argument` イベントへ振り替える。`field` の抽出規則は [cli_events.md §4](../../libs/cli_events/cli_events.md#4-argparse-エラー変換ヘルパ) が正。
- `internal_error` は CLI 本体の全体をトップレベルで捕捉して畳む。`KeyboardInterrupt` は内部エラーでなく中断(`cancelled`/130)として手前で分岐する([§10.5](#105-中断と出力の原子性))。
- 出力先が既存のディレクトリの場合は `--overwrite` でも書けないため、上書きガードより前に `--overwrite` の有無に依らず `output_is_directory` で拒否する(上書きの許可を促す案内を出さない)。
- `--list-bones` は書き込み・疎化をしない診断モードとして、処理固有の検証(出力先のディレクトリ検査・上書きガード・疎化許容値・ボーン値検証)に阻まれない(`--machine --list-bones` でも同じ)。機械モードではボーン値の非有限等をこの短絡位置では弾かず、読み込み失敗のみ `not_vmd` にする。

### 10.5 中断と出力の原子性

- VMD 出力は一時ファイル+原子置換で行う。書き込みは全計算後に 1 回だけ起きるため、途中終了で中途半端な出力ファイルは残らない。
- CLI は本体の全体で `KeyboardInterrupt` を捕捉し、構造化出力モードでは `cancelled` の error イベントでストリームを終端、それ以外では理由を標準エラーへ 1 行出し、どちらも終了コード 130 で終える。
- **Windows**: `CTRL_BREAK_EVENT` も上の `KeyboardInterrupt` 捕捉経路へ橋渡しし、`cancelled`/`130` として扱う。橋渡しの要否・実装は共有基盤([cli_events.md §5](../../libs/cli_events/cli_events.md#5-中断シグナルの橋渡し))が正。
- 進捗のライブ表示は try/finally で中断時も止まり、行を消す。機械モードではライブ表示自体を無効化する。
- 呼び出し側がプロセスを強制終了した場合は終端イベントを出せないまま途切れる(規約 [§4](../../docs/conventions/cli-interface.md#4-イベントストリーム標準出力) が定める終端保証の例外の 1 つ。規約 [§8](../../docs/conventions/cli-interface.md#8-キャンセルと出力の原子性))。このとき並列ワーカ子プロセスも残りうるため、強制終了する呼び出し側はプロセスツリーごと終了する。出力の原子性により、その場合も中途半端な出力ファイルは残らない(ワーカはファイルを書かない)。

### 10.6 並列疎化と中断・イベントストリームの整合

疎化はプロセス並列(spawn)で走る([§7](#7-制約と考慮事項))。中断・機械モードと衝突しないよう次を守る。

- **イベントの単一送出者**: イベントを送出するのは常に親プロセス。並列ワーカは標準出力・標準エラーへ書かず、ファイルも書かない。
- **中断の一元化**: Ctrl-C 等の中断はワーカを巻き込まず親プロセスが一元的に畳み、ワーカ停止後に `cancelled` イベントをちょうど1つ送出する(終端後の出力混入は起きない)。
- **決定論**: 各ボーンの疎化は決定論的で実行順非依存、再結合は入力順で行う。progress の `(done, total)` 値列と result・診断はワーカ数・完了順に依らず逐次実行と一致する(`elapsed` のみ実時間依存)。
- 生成スクリプト等から CLI 本体を直接呼ぶ利用でも、並列疎化の子プロセスはワーカ処理だけを実行し CLI 本体を再実行しない。
