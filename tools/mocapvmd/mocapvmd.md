# mocapvmd 要求仕様書

層: **CLIツール層**([../../docs/conventions/layering.md §1](../../docs/conventions/layering.md#1-層タクソノミー))。

モーションキャプチャー由来のボーン VMD を、ノイズ軽減・足IK接地安定化してからキーフレーム圧縮まで
1 コマンドで処理し、MMD で扱いやすい疎な VMD を中間 VMD を介さずに出力する。

## 目的

モーションキャプチャー由来の VMD で起きやすい次の問題を抑える。

- 1 フレームごとの微小な位置・回転ノイズが多く、キーフレーム圧縮がノイズまで残そうとしてキーが減りにくい。
- 足IKボーンが接地中に細かく揺れて横滑りし、足元が氷の上で滑っているように見える。
- 手首・指・頭などの細かな動きは演技として重要な一方、センターや足IKでは同じ揺れが不自然に見える。
- 接地中と遊脚中で、同じボーンでも望ましいフィルタ強度が異なる。

## 要求

- 元モーションのタイミング・接地・重心移動・ポーズの意図を壊さない。ステップ・ジャンプ・ターン・手振りなどの
  意図したアクセントを鈍らせない。
- ボーンを選ばせず、ボーン種別ごとに異なる既定パラメータで効かせ方を変える。
- 種別ごとの既定値の良否は、実データの出力を MMD で視聴して判断する。
- 処理結果を数値のレポートで確認できる。レポートでは、ボーン種別ごとの最大変更量・平均変更量・保護フレーム数・
  接地ロック適用率を確認でき、効かせすぎで演技が丸まった種別と、効き不足でノイズが残った種別を判別できる。
- 診断のための集計で、通常実行の処理時間を増やさない。
- 全身の密なボーンモーションでも、キーフレーム圧縮の実時間は CPU コア数に応じて短くなる。

## 対象範囲

- 処理するのはボーンキーだけで、モーフ・カメラ・照明・セルフ影は処理しない。
- 物理シミュレーションや足裏接触の解剖学的な補正は行わない。
- 誤認識による大きなポーズ破綻は自動修復しない。
- モデル固有のボーン構造は推定せず、標準・準標準のボーン名で種別を決める。
- 検出・平滑化の閾値は MMD 単位の固定値で、モデルのスケールに合わせて補正しない。

## 呼び出し側への約束

- 呼び出し側がプロセスを強制終了するときは、キーフレーム圧縮の子プロセスが残らないよう、プロセスツリーごと
  終了する。
- Python のスクリプトから CLI 本体を直接呼ぶときは、その呼び出しを `if __name__ == "__main__":` の内側に置く。
  キーフレーム圧縮の子プロセスは、起動時に呼び出し元のスクリプトを読み込み直す。
