# mocapvmd 既定値の調整手順

mocapvmd のコードに**暫定で置かれている既定値**を、実際のモーキャプ VMD で処理して MMD で見比べ、
妥当な値に**確定する**手順。対象は「暫定で置かれている既定値」(いずれも実データでチューニングする前提):

- クリーニング強度基準 `presets._BASE`(種別別の位置の窓幅・回転の窓幅・位置のブレンド率・回転のブレンド率。倍率 1.0 基準)と
  `--clean-strength` のブレンド率の倍率(数値。既定 1.0。倍率適用後のブレンド率は 0〜1 にクランプ)。
- 横滑り抑制 `--foot-slide-suppression S`(0〜1)。`S` が foot_ik の X/Z 接地中央(0.97×S)・接地端(0.25×S)・
  接地検出の水平速度許容・最大補正量上限を連動制御。固定係数(foot_ik の Y、toe_ik の各チャンネル、接地端フェード
  `_FOOT_LOCK_FADE_WIDTH`)は `S` 非依存。[mocapvmd.md §5.4](mocapvmd.md#54-接地ロック強度)。
- スパイク閾値([mocapvmd.md §5.5](mocapvmd.md#55-最大変更量最大補正量)。1フレーム 位置 0.3 / 回転 5度。接地ロックの最大補正量は `S` 連動 `S=0`→0.5 / `S=1`→2.0)。
- 疎化の許容誤差プリセット `presets._REDUCTION_BASE`(速度観点の `slower`/`slow`/`medium`/`fast`/`faster` の位置・回転基準値。
  既定は中央 `medium`)と種別スケール `presets._REDUCTION_SCALE`。[mocapvmd.md §5.3](mocapvmd.md#53-疎化プリセットと種別別許容誤差)。

固定で調整対象外(仕様で確定): 整数フレーム上で処理する基準、分類規則([mocapvmd.md §4.1](mocapvmd.md#41-ボーン分類))、補間チャンネルの扱い、疎化の中核機構
(区間分割・継ぎ目処理・誤差検証・ベジェ採否は `vmd.reduce` の共通実装)。

確定したら該当コード値を更新し、`pytest` で回帰を確認 → codex レビュー → コミットする。

**進め方は対話的**: AI が候補値で一括処理 → ユーザーが MMD で一番良い1本を選んで伝える → AI が範囲を絞って
次の候補、を繰り返す。ユーザーがやるのは**並んだ出力から一番良い1本を選ぶ**ことだけ。

## 出力形式と視聴

mocapvmd の**既定出力は疎なキー＋ベジェ補間**で、密な線形キーのような折れ線由来の微振動が出にくく、**60fps/無制限でも
扱いやすい**。効かせすぎ/効き不足の**質感判定は、この既定出力(クリーニング＋疎化)を MMD で視聴して行う**(再生 fps は
制限しない)。プリセットや許容値を変えた候補を並べ、入力と見比べる。

`--no-reduce` は疎化を切って**密キー＋線形補間**(`BONE_LINEAR_INTERP`)を出す診断用モード。密な線形キーは、高 fps 再生で
隣接区間の傾きが変わる箇所が速度不連続(微振動)として**見えることがあり質感の視聴判断を妨げうる**ので、質感の視聴は
上記の既定ベジェ出力で行い、`--no-reduce` 出力は視聴の判定には使わない。`--no-reduce` の用途は**診断用の密キー出力**で、
疎化を挟まないクリーニング後のキーを確認したい場合に使う。
ただし数値は当たり付け・破綻チェック止まりで、効きの質は数値では決めない([観測と判断の基本](#観測と判断の基本))。

## 入出力

- **入力**: 代表的なモーキャプ VMD を用意する。確認したい要素を含めておく:
  **微小ジッタの乗った静止/低速区間**(クリーニング判断)、**手・指のジェスチャ**(効かせすぎで演技が丸まらないか)、
  **足の接地と踏み替え**(足IK安定化・滑り/沈み)、**歩行**(接地の交互切替)、**大きな動作**(疎化後の追従)。
- **出力**: **桁を揃えた値入りファイル名**で出す(例 `clean_0.50` / `clean_1.00` /
  `reduce_pos_0.010` / `0.020` / `0.050`。Windows で数値順に並ぶようゼロ埋めで桁を揃える)。毎ラウンド残して見比べる。

## 観測と判断の基本

- **判断は MMD での視聴**。入力と各候補を見比べ、
  次の2つの破綻の間でちょうど良い所を探す。見た目の妥当性は数値では決まらない:
  - **効かせすぎ**: ジッタは消えるが**演技が丸まる**(指・手首の細かい動き、踏み込みのキレが失われる)。
  - **効き不足**: 演技は残るが**ノイズが残る**(静止区間のブルブル、足の細かい滑り)。
- **足の接地**は専用に見る: 接地中に足IKが水平に滑らないか、床へ沈み込みすぎないか、接地開始/終了で急に吸い付かないか。
- **疎化**は、キーが減って編集しやすくなりつつ、**接地感**と**演技の追従**が保たれているかで見る。
- 候補を見る前に、AI が**その要素がどのフレームにあるか**(例: 指のジェスチャは frame 1200〜1400、踏み替えは
  frame 800 付近)を示す。該当区間を再生して判断する。
- **診断は破綻チェックと当たり付けに使い、質感の最終判断には使わない**:
  - `--list-bones`: 分類が想定どおりか(標準外のボーン名・追加IKが `unknown` や誤分類になっていないか)。
  - `--dry-run`: **ボーンごと**の診断をテキスト要約で表示する。各ボーンに 分類・キー数・フレーム範囲・最大フレーム間速度・最大角速度・
    スパイク候補数・保護フレーム数・解決済みクリーニングパラメータ。足IK/つま先IKには加えて 接地候補・接地区間
    (絶対フレーム)・最大/平均変更量・足IKロック適用率・クランプ警告数。疎化時には 削減率・最大再生誤差・カット数・
    適用許容・出力キー数。トップレベルに 適用プリセット・各有効化フラグ・全体フレーム範囲・IK候補一覧。**効かせすぎ/
    効き不足の当たり**を付ける(下の各節に着眼点)。各ボーン1行＋IK候補一覧として、主要なトークンを並べる。
- 処理は決定論的(同じ入力・同じ引数なら同じ出力)。再現性のため入力と引数を記録する。

## 探索のやり方(全パラメータ共通)

1. AI が対象パラメータの候補を**一括処理**して出力する。`seed` 等の乱数はなく決定論的。
   - **公開引数(CLI フラグあり)** はシェルでループ: `--preset`、`--clean-strength`、`--reduce-error-bone-pos`、
     `--reduce-error-bone-rot`、`--curve-mode`、`--no-reduce`。
   - **内蔵パラメータ(フラグなし)** は `presets.py` の該当値を編集して処理するか、コア層の関数(`denoise.apply_denoise` /
     `footik.stabilize_foot_ik` / `reduce.reduce_bones`)を直接呼んでループする。1次元の量は**対数等比で広く**散らす(×2刻みで5本程度)。
2. ユーザーが MMD で見比べ、**一番良い1本**(の値)を伝える。極端なら範囲をずらす。
3. AI が選値の**両隣の間に範囲を絞って**次の候補を出す(範囲が半分以下に縮む)。
4. 見分けがつかなくなるまで 2〜3 を反復(通常 2〜3 ラウンドで収束)。

**順番**(必要素材でまとめた効率順。同じ素材で連続して判断できる):

1. **全体のクリーニング強度**: `--clean-strength`(微小ジッタの静止＋ジェスチャ)。まず全体の効き具合を決める。
2. **足IK接地(横滑り抑制)**: `--foot-slide-suppression S`(踏み替え・接地区間・滑らせるダンス)。`S` が X/Z ロック・検出・最大補正量を連動。
3. **種別別のクリーニング基準**: `_BASE`(指・手首=fingers/arms、上半身=torso、脚=legs)。種別ごとに効かせ方を詰める。
4. **疎化レベル**: `--preset` と `--reduce-error-*`(クリーニング確定後。キー削減率と接地感・追従の両立)。
5. **種別別の疎化スケール**: `_REDUCTION_SCALE`(接地は誤差を絞る・指は粗くてよい等、種別ごとの許容の効かせ方)。

**同時化**: 直交して見分けやすい量(例 位置許容 × 回転許容)は 2 次元グリッドで 1 本選ぶ。同質の量(全体強度と
種別強度のように「どちらも効きの強さ」)は 1 つずつ動かす。

## 1. クリーニング強度(`--clean-strength`)

- 対象: `--clean-strength`(数値倍率。既定 1.0)。倍率は**位置のブレンド率・回転のブレンド率のみ**に掛かる
  (窓幅は据え置き)。位置のブレンド率・回転のブレンド率は元値と平滑化値のブレンド係数(0 で元値保持、1 で
  平滑化値採用)で、倍率適用後は 0〜1 にクランプする。
- 素材: **微小ジッタの乗った静止/低速区間**と**手・指のジェスチャ**。
- 候補例: `--clean-strength 0.5` / `1.0` / `1.4` を一括出力(対数等比で広く散らしてもよい)。
- 着眼点: 静止のブルブルが取れて、かつジェスチャの演技が丸まらない強さ。強すぎると指・手首の細部が消える、
  弱すぎると静止にノイズが残る。
- 診断の当たり(判定は視聴): `--dry-run` の**スパイク候補数・保護フレーム数**を当たりに使う。候補が多いボーン・区間は
  ノイズやアクセント保護の確認対象にする。ただし効かせすぎ/効き不足は MMD 視聴で判定する。

## 2. 種別別クリーニング基準(`presets._BASE`)

- 対象: `_BASE`(種別 -> 位置の窓幅・回転の窓幅・位置のブレンド率・回転のブレンド率。倍率 1.0 基準)。CLI フラグはないので `presets.py` を
  編集して処理する。`--clean-strength` の倍率はブレンド率のみに掛かるので、**窓幅と基準ブレンド率はここで決める**。
- 素材: 種別ごとに効きを見たい区間(指=細かいジェスチャ、脚=踏み込み、上半身=ゆっくりした演技)。
- 候補例: 1種別ずつ、位置のブレンド率/回転のブレンド率を対数等比(例 fingers の位置のブレンド率 0.05 / 0.10 / 0.20)、窓幅を 3 / 5 / 7 で振る。
- 着眼点: その種別の演技が丸まらず、ノイズだけ取れる窓幅・強度。窓を広げる/強度を上げるほど平滑化が強い。
  指は細部優先で弱め(現 0.10 / 窓 3)、center は安定優先で強め(現 0.45 / 窓 7)。
- 注意: 窓幅は奇数。短い区間では区間長以下の最大奇数へ自動短縮される(実効窓 3 未満は平滑化しない)。

## 3. 横滑り抑制(`--foot-slide-suppression S`)

- 対象: 横滑り抑制 `--foot-slide-suppression S`(0〜1, 既定 1.0)。`S` が foot_ik の X/Z 接地中央(0.97×S)・
  接地端(0.25×S)・接地検出の水平速度許容(`S=0`→0.08 / `S=1`→1.0)・接地ロックの最大補正量上限(`S=0`→0.5 /
  `S=1`→2.0)を連動制御する。foot_ik の Y(中央 0.50 / 端 0.10)、toe_ik の各係数(X/Z 0.30・Y 0.30・端 0.10)、
  接地端フェード幅 `_FOOT_LOCK_FADE_WIDTH`(現 3)は `S` 非依存。`--clean-strength` は足ロックを制御しない(クリーニング強度だけを変える)。
  `--foot-ik-stabilize` / `--no-foot-ik-stabilize` で切替。
- 素材: **足の接地・踏み替え・歩行**。加えて**意図的に足を滑らせるダンス**(`S` を下げて滑りを保持できるか)。
- 候補例: `--foot-slide-suppression` を 0.0 / 0.4 / 0.7 / 1.0 で振る(`0`=従来検出＋ロックなしで滑り保持、`1`=規定「横滑りなし」)。
- 着眼点: 既定 `S=1` で接地中の横滑り(氷上感)が消えるか、かつ踏み替え・遊脚で足が不自然に固まらないか。`S` を下げると
  滑らせるダンスの滑りが保たれるか。`toe_ik` は爪先離れ・ロール・爪先立ちを保つため弱め(X/Z 0.30)で固定しすぎない。
  Y は床への沈み込み・段差表現を壊さない範囲で弱く寄せる。
- 診断の当たり: `--dry-run` の**足IKロック適用率**と**接地区間**(絶対フレーム)、**クランプ警告数**。ロック適用率は
  全フレームに占める接地区間フレームの割合なので、接地時間が短い動作でも低くなる(低い＝判定不良とは限らない)。
  接地しているはずの区間が**接地区間に出ていない**なら接地判定の効きを疑い、素材のフレームと突き合わせる。クランプ警告は
  最大補正量超過の合図([§4](#4-最大補正量スパイク閾値mocapvmdmd-55))。

## 4. 最大補正量・スパイク閾値([mocapvmd.md §5.5](mocapvmd.md#55-最大変更量最大補正量))

- 対象: 接地ロックの最大補正量上限は `--foot-slide-suppression S` で連動する(`S=0`→0.5 / `S=1`→2.0 MMD単位)ので
  [§3](#3-横滑り抑制--foot-slide-suppression-s) の `S` スイープで一緒に振れる。1フレームの位置 0.3 / 回転 5度の平滑化クランプ(スパイク検出閾値と共通。
  0.3 / 5度 ちょうどは非スパイク)は別系統で、CLI フラグはないのでコード値を編集して処理する。
- 素材: **大きな踏み込み・素早い手の振り**(補正が過大になりうる動き)。
- 候補例: 接地最大補正量は `S`([§3](#3-横滑り抑制--foot-slide-suppression-s))で振る。1フレームクランプ 位置 0.2 / 0.3 / 0.4・回転 3 / 5 / 8度。
- 着眼点: 大きな動作のキレを保ちつつ、明らかなスパイク(1フレームの飛び)だけ抑える閾値。小さすぎると大きな
  動作まで削られて演技が鈍る、大きすぎるとスパイクが残る。
- 診断の当たり: 一般クリーニングのクランプは発生回数がレポートに出ないので、`--dry-run` の**スパイク候補数**を
  疑う区間の当たりに使う。ただしスパイク候補は入力側の検出なので、残ったノイズや削れすぎ自体は視聴で判定する。
  足IK接地ロックの最大補正量超過は [§3](#3-横滑り抑制--foot-slide-suppression-s) の**クランプ警告数**で分かる。

## 5. 疎化レベル(`--preset` / `--reduce-error-*`)

- 対象: `_REDUCTION_BASE`(速度観点で `slower` (0.05, 0.40) / `slow` (0.10, 0.75) / `medium` (0.20, 1.50) /
  `fast` (0.80, 6.0) / `faster` (1.60, 12.0)。位置 MMD単位・回転 度の基準値。既定は中央 `medium`)。
  `--reduce-error-bone-pos` / `--reduce-error-bone-rot` は基準値を上書きする(種別スケールは
  引き続き掛かる)。**クリーニング・足IK安定化を確定してから**調整する(疎化は滑らかになった信号ほどキーが減る)。
- 素材: 全体(クリーニング後)。**接地区間**と**大きな動作**の両方を含む区間で見る。
- 候補例(直交ペア): `--preset` 5段の比較、または `--reduce-error-bone-pos` 0.05 / 0.20 / 0.80 ×
  `--reduce-error-bone-rot` 0.40 / 1.50 / 6.0 を 2 次元グリッドで 1 本選ぶ。`--curve-mode bezier`(既定)で見る。
- 着眼点: キーが減って編集しやすく、かつ再生誤差が許容内で**接地感・演技の追従**が保たれる許容値。許容を上げるほど
  キーが減って処理も速いが細部が丸まる。`slower` は忠実度優先(キー多・処理遅)、`faster` は削減・速度優先。
- 診断の当たり: `--dry-run` の**キー削減率**・**最大再生誤差**・**カット数**・適用許容値を当たりに使う。削減率は
  許容誤差・意図的な複雑動作・カット・トラック長にも左右されるので断定はできないが、削減率が低いままなら**原因の一つ**
  としてクリーニング不足(信号がまだノイジー)を疑う。最大再生誤差(レポートは軸別最大、疎化の検証はユークリッド距離で
  単純比較はしない)が許容近くまで使われていても異常ではなく、許容を緩める/曲線で詰めるかは**接地感・追従の視聴**で決める。

## 6. 種別別の疎化スケール(`presets._REDUCTION_SCALE`)

- 対象: `_REDUCTION_SCALE`(種別 -> 位置スケール・回転スケール。基準値に掛ける)。CLI フラグはないので `presets.py` を
  編集して処理する。現値: center (0.7, 0.8)・torso (0.8, 0.9)・fingers (1.5, 1.5)・foot_ik (0.7, 1.0)・
  toe_ik (1.0, 0.8)、root/arms/legs/unknown は (1.0, 1.0)。
- 素材: 種別ごとに見たい区間(指=細かいジェスチャ、足=接地)。
- 候補例: 1種別ずつスケールを 0.7 / 1.0 / 1.5 で振る(基準は [§5](#5-疎化レベル--preset----reduce-error-) で確定した値)。
- 着眼点: **スケールが大きいほど許容が緩んでキーが減り、細部が丸まる**。細かさを残したい種別は小さめ、削減を効かせたい
  種別は大きめにする。現値は接地の誤差を絞るため foot_ik 位置を小さめ(0.7)、指は仕様(疎化では細部は粗くてよい)に
  従い大きめ(fingers (1.5, 1.5)=許容を緩めてキーを減らす方向)にしている。実データで「種別ごとに丸まりすぎ/残りすぎ」を
  見て、この初期値が妥当かを決める。

## 7. 種別別チューニング観点(効かせすぎ/効き不足の仕分け)

クリーニング・疎化を一巡したら、種別(root / center / torso / arms / fingers / legs / foot_ik / toe_ik)ごとに
**効かせすぎで演技が丸まったもの**と**効き不足でノイズが残ったもの**を仕分け、[§2](#2-種別別クリーニング基準presets_base)・[§6](#6-種別別の疎化スケールpresets_reduction_scale) のスケール/強度へ戻す。

- 判断材料: MMD 視聴に加え、`--dry-run` の**スパイク候補数・保護フレーム数**(全ボーン)と**足IKロック適用率・
  最大/平均変更量**(足IK/つま先IKのみ)、疎化の**ボーン別 削減率・最大再生誤差・カット数**。演技が丸い種別は弱め、
  変動・スパイクが残る種別は強める。なお [mocapvmd.md §4.5](mocapvmd.md#45-チューニング支援) が求める種別ごとの
  最大/平均変更量・保護フレーム数・接地ロック適用率の集計(現レポートはボーン別までで種別集計は未実装)は、当面は上記の
  ボーン別項目で代替する。
- 完了の目安: 既定 `--foot-slide-suppression 1.0` で接地中の横滑りが消え、弱め(例 `--clean-strength 0.5`)で手首・指の演技が過度に丸まらない。
  種別別の初期値が代表 mocap VMD で説明可能な値になっている。
- 将来の `--tuning-file`(種別別パラメータの外部上書き)の要否は、ここで「プリセット固定では足りない」と判断した
  ときに検討する(初期実装では必須としない)。
