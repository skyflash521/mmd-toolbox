# ツール公開手順

各CLIツールを公開(初回リリース)するときの標準手順。版番号の付け方は [versioning.md](versioning.md) を正とし、本書は公開時に踏む作業を定める。`<tool>` は対象ツールのパッケージ名に読み替える。

## 原則

- 公開対象以外のツール・共通ライブラリには触れない。
- 正本ドキュメント(versioning.md / 対象ツールの仕様書)を先に整えてから、実装・テストと整合させる。
- ブランチ運用・コミット手順はリポジトリの開発ルールに従う。各まとまりごとにコミットする。

## A. 版付け

版番号の付与・正本の所在・表示内容はすべて versioning.md に従う。本節はその「作業」を列挙するに留め、規約自体は再掲しない。

1. `<tool>/__init__.py` に `__version__` を付与する(初期版の選び方は versioning.md §4)。
2. CLI に `--version` を追加する(表示内容と番号源は versioning.md §1)。依存ライブラリ版の併記は「判断ポイント」を参照。

## B. 利用者向けドキュメント

3. `<tool>/README.md` を新規作成する。利用者目線で次を含める:
   - 冒頭に「何ができるか」(手段でなく目的)。
   - 最小コマンド・主なオプション・入出力の説明。
   - 非目標と既知の制約。
   - 詳細は仕様の重複を避け、対象ツールの仕様書へ誘導。
4. トップ `README.md` に対象ツールを追記する(ツールの列挙は名前順):
   - ツール表へ行(できること・まず試すコマンド・`<tool>/README.md` リンク)。
   - 対象ツールの概要節(目的・最小コマンド・要点)。
   - リポジトリ構成表へ `<tool>/` 行。
   - 依存・開発環境に対象ツール固有の事項があれば反映(無ければ変更不要)。
5. 対象ツールの仕様書を公開水準に点検する: 目的・非目標・CLI仕様・既知の制約が現実装と整合するか。作業過程参照(ラウンド番号・計画書参照)が残っていれば除去。→ [terminology.md](terminology.md) の観点で参照切れ・用語規約を直接確認。

## C. 公開前検証

6. **テスト緑**: `pytest <tool>` と全体を素で実行し緑を確認する(pytest はパイプ・連結せず素で単体実行)。
7. **CLI スモークテスト**: 代表入力で end-to-end 実行する。終了コード0・出力の実体(サイズ・件数)・`--version`・`--help`・`--dry-run` を確認。前景で exit と生成物の実体を見届けてから合格判断する。生成物は利用者から見える所定ディレクトリに置く。
8. **配布物の確認**: `pyproject.toml` の `project.scripts` に対象コマンド、`packages.find` に対象パッケージが含まれることを確認。開発インストールで `<tool> --version` が通ること。

## D. リリース確定

9. `pyproject.toml` の version をリリース日の CalVer へ更新する(値の付け方は versioning.md §1)。
10. すべて緑・収束後、リリースとしてタグを打つ(タグの形式・種別・版の一致は versioning.md §5)。タグ付けは明示指示で行う(自動で打たない)。

## 順序の目安

A(版)→ B(ドキュメント)→ C(検証)を一巡し、各まとまりでコミット。D は最後。

## 判断ポイント(公開ごとに決める)

- `--version` に依存ライブラリ(共通ライブラリ等)の版を併記するか。併記するなら依存側にも `__version__` の導入が要る。最小範囲では対象ツール版のみとし、依存版導入は別作業に切り出してよい。
