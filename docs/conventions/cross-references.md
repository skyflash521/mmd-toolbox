# ドキュメント間参照規約

ドキュメント間の節参照・ファイル相互参照をどう書くか、および編集後にその参照が壊れていないかを
どう確認するかをまとめる。用語の正記法は [terminology.md](terminology.md) を正本とし、本書はそれへ
委譲する。

## 1. 参照は必ずMarkdownリンクとして書く

- **節参照**: 見出しを指す言及は必ず**アンカー付きMarkdownリンク**として書く。リンクにしておけば
  リンク先の見出しが実在するかを機械検査でき、改名・削除で参照が切れたときに気づける。
  **見出しを指す言及はすべて節参照であり、見出しの番号の有無・種類を問わず同じ規則に従う**
  ——「N章」「(N.M)」「N.M節」「N.M の…」のように番号だけで指す書き方も、「A〜C」のように英字
  見出しを指す書き方も、無番号見出しを名前だけで指す書き方も、リンクでない以上リンク先の実在を
  検証できないため使わない。例外: リポジトリ外の文書(SemVer仕様など)を指す参照はリンク化しない。
- **ファイル相互参照**: 節番号を伴わないファイル相互参照も、必ずMarkdownリンクとして書く。
  地の文やコードスタイル表記で相対パス・ファイル名をそのまま書かない。
- **見出しでない箇所を離れた場所から参照しない**: 別の節・別のファイルにある手順の項番・箇条書きの
  項番・表の行などは、アンカーを持たずリンクにできない。番号で指す(「B の手順2」)のも項目名で指す
  (「リンク検査で確認する」)のも、リンクとして機能しているのに検証できない点は同じで、指した先が
  改名・削除されても気づけない。**リンクにできないものは離れた場所から参照しない**——参照したい
  内容は見出しへ昇格させてリンクするか、参照せずに済むようその場で述べる。同じ節の中で直前・直後の
  内容を「上記」「次の」と指すのは、読み手の目の前にあり離れた参照ではないので対象外。

## 2. リンクの書き方(検出可能性を保つ)

[§1](#1-参照は必ずmarkdownリンクとして書く) のリンクを書くとき、以下を守らないと機械的に検出・
検証できないリンクになる。

- **リンクを入れ子にしない**。既存のリンクの外側へさらに角括弧を重ねると構文が壊れ、片方または
  両方が解決されなくなる。既存のリンクに節参照を足すときは、そのリンクの表示テキストへ取り込むか、
  独立したリンクとして並べる。
- **リンク先は参照元からの相対パスで書く**。拡張子込みのファイル名だけでは、同名のファイルが
  複数実在する場合にどれを指すか決まらない。
- **実在しない特定ファイルを、実在するかのような具体名で書かない**。命名パターンの例示や、
  各モジュール/ツールに共通する一般的な言及(「各ツールの README」等)は、実在する1ファイルを
  指すかのような具体的なファイル名を書かず、`<モジュール>.md`・`<ツール>/README.md` のように
  `<...>` を使ったプレースホルダー表記にする。
- **見出し本文に意図しないリンク構文を作らない**。見出しの本文中で `[...]`(空でも中身があっても)の
  直後に空白なしで `(...)` を続けると、地の文のつもりでもMarkdownのリンク構文として解釈される
  (例: `parts[](説明)` は空リンクとして解釈され、意図した表示にならない)。このような並びが
  避けられない場合は、`` `parts[]` `` のようにバックティックで囲むか、`[]` と `(` の間に半角
  スペースを1つ挟む。
- **YAML frontmatter(ファイル先頭の `---` で挟まれた領域)で他の文書を参照しない**。
  frontmatterはMarkdownとして描画されないメタデータであり、リンク構文を書いても機能しない。
  かといって平文でファイル名を書けば検証できない参照になる。参照は本文に置き、frontmatterでは
  文書名を出さずに内容を述べる。

## 3. 適用対象と機械チェックの範囲

本書の規則は恒久ドキュメント(ツール/ライブラリ仕様、フォーマット仕様、README、プロジェクト規約、
エージェント手順書)に適用し、一時文書(実装計画書・設計メモ・作業ログ)は対象外。

**CIの機械チェックが検出するのは、リンク先の実在と、`§N` 形式の平文参照・裸の `.md` パス参照だけ**
である。`§N` 以外の表記による節参照(「N章」「(N.M)」「N.M節」等)と、離れた場所からの非見出し参照は、
値との区別に文脈判断が要るため機械検査できない——**これらはCIを通過してしまうので、書いた本人が
確認する**。
