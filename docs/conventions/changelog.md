# 変更履歴規約

公開CLIツール(利用者向け `<ツール>/README.md` を持つ `tools/<ツール>/`)ごとに、利用者向けの変更履歴を
`tools/<ツール>/CHANGELOG.md` として提供する。本書はその所在・形式・粒度・GitHub Releases への
転記規則の正本。リリース作業のどの時点で書くかは [publishing.md](publishing.md) が定める。

## 1. 対象と所在

- 対象は公開CLIツールのみ。共通ライブラリには置かない。ライブラリ由来の変更は、それが挙動に
  効くツールの変更履歴に利用者の言葉で書く(「内部ライブラリを更新」とは書かない)。
- 置き場所は `tools/<ツール>/CHANGELOG.md`。対象ツールの `<ツール>/README.md` からリンクする。
- 内容の正本は常にこのファイル。GitHub Releases は転記先([§4](#4-github-releases-への転記))であり、Release 側だけを編集しない。

## 2. リリースとの対応

- 1見出し = 1リリース。リリースの単位は [versioning.md §5](versioning.md#5-タグ付け) のタグと1:1で対応させ、
  見出しの版をタグ(= `__version__`)と一致させる。
- 未リリースの変更は書かない(「未リリース」節を置かない)。今回リリースの節は、リリース作業の
  一部として一括で書き起こす(手順・素材は [publishing.md](publishing.md))。
- ファイルはツールの初回リリース時に作成する。初回リリースの節は変更点を列挙せず「初版。」と記す。

## 3. 形式と粒度

新しいリリースが上、古いリリースが下(降順)。

```markdown
# 変更履歴

## <MAJOR.MINOR.PATCH> - <YYYY-MM-DD>

### 破壊的変更
- ...

### 追加
- ...

### 変更
- ...

### 修正
- ...
```

- 日付はその節を確定した日(リリース作業でエントリを書き上げた日)。
- カテゴリ節は「破壊的変更」「追加」「変更」「修正」の4種で、該当のない節は置かない。
  - **破壊的変更**: [versioning.md §2](versioning.md#2-互換性の契約の定義) の契約を後方非互換に壊す変更。既存の引数・フラグの削除も
    ここに入る。版のレジームに関わらずこの節に書く(0.x で MINOR に入る場合も)。[versioning.md
    §3](versioning.md#3-どの桁をいつ上げるか) の「変更履歴に『破壊的』と明記する」の実体は本節。
  - **追加**: 新しいオプション・機能。
  - **変更**: 互換を保った挙動の変更。意図的な出力/品質の変更もここ。
  - **修正**: 利用者に見える不具合の修正。
- 書くのは利用者に見える変更だけ: [versioning.md §2](versioning.md#2-互換性の契約の定義) の契約面に触れる変更、意図的な出力/品質の
  変更、利用者に見える不具合の修正。内部リファクタ・テスト・開発者向けドキュメントの変更は
  書かない。書くことが無いリリースは、カテゴリ節を置かず見出しの下に「内部改善のみ。」と記す。
- 書き方:
  - 利用者の言葉で、1変更 = 1行の箇条書き。何がどう変わり、利用者に何が起きるかを具体に書く。
  - 自己完結にする: コミットハッシュ・内部モジュール名・行番号・作業過程への参照を書かない。
  - 工程の呼称は [terminology.md](terminology.md) の「処理工程の利用者向け名称」に従う。

## 4. GitHub Releases への転記

タグの push をトリガに、CI が該当ツールの CHANGELOG から該当版の節を抽出して GitHub Release を
作成する(workflow の実体は `.github/workflows/` 配下。リリース工程の中での位置づけは
[publishing.md](publishing.md) が定める)。Release を作るのは公開CLIツールのタグに対してだけ(タグは CLIツール
ごとに打つ。[versioning.md §5](versioning.md#5-タグ付け))。

- 方向は CHANGELOG → Release の一方向。本文を直すときは CHANGELOG を直し、Release を作り直す。
- 対象タグは [versioning.md §5](versioning.md#5-タグ付け) の `<ツール>/v<MAJOR.MINOR.PATCH>`。
- タイトルは `<ツール> v<MAJOR.MINOR.PATCH>`。Releases 一覧では全ツールが混在するため、
  タイトルにツール名を必ず含める。
- 本文は該当版の節の内容(カテゴリ節と箇条書き)をそのまま用いる。版見出しの行は含めない。
