# 用語規約とドキュメント整合

ツール横断で守る用語の正記法と、ドキュメント編集後に確認する整合の観点をまとめる。
仕様書・README を編集したエージェントは、編集の一部として本書の観点で**直接**確認する。
確認は read-only で、修正するかは別途レビュー/ユーザー判断に従う。

## 用語規約

下表は候補列挙の基準であり、例外規則があるため機械的に違反と断定しない。文脈で正否を判断する。

| 禁止・注意表記 | 正 | 例外 |
|---|---|---|
| 補間カーブ、裸の「カーブ」 | 補間曲線 | なし |
| FOV | 視野角 | コード識別子 `fov` |
| 注視点、ターゲット | カメラ中心 | なし |
| モーフセクションの呼称としての「表情」 | モーフ | 表情モーフ(モーフの種類名)は可 |
| セルフシャドウ | セルフ影 | 英語見出し Self Shadow は可 |
| パースペクティブ(UI操作・データ作成手順の文脈) | パース | バイナリ仕様・データモデル記述では「パースペクティブフラグ」が正 |
| カメラキー格納値としての「回転」 | 角度 | 補間チャンネル名の「回転」、回転行列・回転ノイズ等の一般用語は可 |
| 条件記述での「変更した」「変化する」等の基準点が不明瞭な語 | 観測可能な性質(「値が2種類以上ある」等) | 条件・手順以外の文脈は可 |
| 利用者向けの表面での「疎化」「疎ベジェ」 | 次節の表の利用者向け名称 | 仕様書・規約・コード内は「疎化」が正 |
| ノイズ軽減の工程名としての「平滑化」「クリーニング」「ノイズ除去」 | ノイズ軽減 | 工程名以外の文脈(平滑化フィルタ等の機構説明、仕様書内部の総称「クリーニング」)は可 |
| 「足IK最適化」 | 足IK接地安定化 | 仕様書内部の略記「足IK安定化」は可 |

## 処理工程の利用者向け名称

CLIツールの処理工程は、利用者向けの表面(README・`--help`・進捗表示の段ラベル・診断表示)では
下表の「利用者向け名称」で呼ぶ。仕様書内部の呼称と異なってよいが、利用者向けの表面どうしは
同じ工程を必ず同じ名称で呼ぶ(進捗の段ラベルは README・help の工程名と一致させる)。

- 同じ語を、ツールが違っても別の工程の名称に使わない。とくに「平滑化」は shakevmd の `--smooth`
  工程の名称であり、ノイズ軽減やキーフレーム圧縮の意味では使わない。
- 新しいツール・工程の追加や名称変更は、先に本表を更新して既存名称と衝突しないことを確認してから
  README・help・段ラベルへ反映する。

| ツール | 工程(仕様書の呼称) | 利用者向け名称 | 機械モード stage id |
|---|---|---|---|
| shakevmd | 手ぶれベイク | ベイク | `bake` |
| shakevmd | 滑らか出力(`--smooth`。密キーのベジェ整理) | 平滑化 | `smooth` |
| mocapvmd | 一般ノイズ軽減(`--denoise`) | ノイズ軽減 | `denoise` |
| mocapvmd | 足IK安定化(`--foot-ik-stabilize`) | 足IK接地安定化 | `foot_ik` |
| mocapvmd | 疎化(`--reduce`) | キーフレーム圧縮 | `reduce` |

## ドキュメント編集後の整合確認

編集した(または編集に関係する)ドキュメントについて、次を確認する。

1. **節参照**: 「§x」「§x.y」「§x.y.z」「テストn」等の節・テスト参照が参照先に実在するか。
   同一ファイル内参照と「vmd-io.md §5」のようなファイル指定参照の両方。番号の桁数・区切りの異形も拾う。
2. **ファイル相互参照**: パス参照・Markdown リンクの参照先ファイルが実在するか。相対パスは
   **参照元ファイルのあるディレクトリ基準**で解決する。`file.md#見出し` 形式は、ファイル実在に加え
   **アンカー(見出し)が参照先に実在するか**も確認する。
3. **用語規約**: 「用語規約」の表と「処理工程の利用者向け名称」の表の表記を候補として拾い、例外規則と文脈で正否を判断する。

確認対象は恒久ドキュメント(ツール/ライブラリ仕様、フォーマット仕様、README、プロジェクト規約)で、
一時文書(実装計画書・設計メモ・作業ログ)やエージェント手順書は対象外。新規作成して未コミットの
ドキュメントは、編集したエージェントが同じ観点で直接確認する。
