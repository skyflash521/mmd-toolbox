# 一時ファイル・中間生成物の配置規約

リポジトリ内のモジュール(ライブラリ層・CLIツール層)が、最終成果物そのものではない一時ファイル・
中間生成物をディスクへ書く際に、どこに・どう置き・誰がいつ破棄するかを、本書が**正本**として定める。
モジュールの追加・削除で本書を更新せずに済むよう、本書では個別モジュール名を列挙しない。各モジュールは、
自身が下記のどの分類に従うかを自身の仕様書に記す。

## 1. 適用範囲

- 対象: `libs/`・`tools/` 配下の全モジュール(ライブラリ層・CLIツール層)。
- 非対象: 最終出力そのものの書き込み方式([§2.1](#21-出力の原子書き込み用一時ファイル) が参照する正本に委譲)。

## 2. 分類

一時ファイル・中間生成物への需要は、性質の異なる3種類に分かれる。各モジュールはまず自分の需要が
どれに当たるかを[§3](#3-判定の手引き)の判定で決め、対応する規約に従う。

### 2.1 出力の原子書き込み用一時ファイル

最終出力ファイルそのものを、書き切ってから原子的に置換するために使う一時ファイル。本書の対象外とし、
CLIツールの契約は [cli-interface.md §8](cli-interface.md#8-キャンセルと出力の原子性)、書き出し方式は
各フォーマット層の仕様書がそれぞれ定める書き出し処理の規定を正本とする。本書は重複記載しない。

### 2.2 非公開の内部一時領域

外部ライブラリ・外部プロセスと連携するためだけに使う、実装内部の一時作業領域(ディレクトリ構成・
保持ファイル・命名は実装に閉じる)。呼び出し元(他モジュール・利用者を含む)へこの領域の構成そのもの
(何を・何個・どう名付けて置くか)を約束しない。ライブラリ層・CLIツール層のどちらのモジュールにも
生じうる需要であり、どちらの層かではなく「領域の構成を公開しない」という性質だけでこの分類に決まる。

呼び出し元へ渡す公開契約が「この領域内にあるとある1ファイルのパス」であること自体は妨げない(例:
処理結果のファイルパスを戻り値で返す)。その場合も、領域自体の構成は契約に含めず、返したパスの
生存期間がこの領域の破棄に従うこと・削除タイミングを呼び出し元が制御できないことを、そのモジュールの
仕様書に明記する。

- **配置**: OSの一時ディレクトリを使う。
- **破棄**: 正常終了時に自動削除を試みる(自動クリーンアップの機構を用いる)。プロセスの強制終了時や
  削除自体の失敗時に残置することは許容する。呼び出し元が削除タイミングを制御できる経路を設けない。
- **契約範囲**: 領域の構成・保持ファイルの一覧は、そのモジュールの仕様書に書かない(実装詳細として
  公開契約から除外する)。この領域内の1ファイルのパスを公開契約の戻り値として返す場合は、その戻り値の
  意味と、寿命が本節の破棄規則に従うことを仕様書に明記する。

### 2.3 利用者向けオプトイン診断用中間生成物

利用者が明示的に指定したときだけ、処理途中の中間データを診断・検査用にディスクへ残す任意機能。
利用者が明示指定するには指定手段(コマンドライン引数等)が要るため、実際にはCLIツールの機能として
利用者に提供される。ただし本書が定めるのは置き場所・命名・有効化契約であり、その中間データを
どの層のコードが生成するかは規定しない。[§2.2](#22-非公開の内部一時領域) の領域内の1ファイルパスを結果として返す契約
(例: 分離済み音声のパス)は、利用者の明示指定なしに常に生じるものなので本節の対象ではない。

- **既定は無出力**: 指定しない限り何もディスクへ書き出さない。既定でも一旦書いてから破棄するような
  実装(利用者価値のない書き込みを増やすだけ)はしない。
- **配置**: 出力ファイルに隣接させ、`<出力ファイル名>.intermediate/` の形で置く。OSの一時ディレクトリ
  は使わない(利用者が処理終了後に発見・検査できる必要があるため)。
- **保持**: 明示指定時に生成したものは処理後も保持し、ツール自身は削除しない。
- **有効化フラグ名**: 全ツール共通の統一名は
  [cli-interface.md §6](cli-interface.md#6-横断的な一貫性) を正本とする。本書は重複記載しない。
- **仕様書への記載分担**: 保存する具体的な中間生成物の内容(ファイル名・形式)は、それを生成する側の
  仕様書に書く。単一ツールが生成するならそのツール自身の仕様書、複数ツールが共有するモジュールが生成する
  なら、そのモジュールの仕様書とする。ツール側には保存先の決定・有効化・失敗の報告が残る。本書は
  置き場所・命名・有効化契約の一般規約のみを定める。

## 3. 判定の手引き

新たに一時ファイル・中間生成物が必要になったモジュールは、次の順で分類を決める。

1. 最終出力ファイルそのものの書き込みか → [§2.1](#21-出力の原子書き込み用一時ファイル)。
2. 呼び出し元・利用者に領域の構成を一切見せない、実装内部の配管か(結果の1ファイルパスだけを戻り値で
   返すことはこれに反しない)→ [§2.2](#22-非公開の内部一時領域)。
3. 利用者が明示指定したときだけ見せる診断・検査用の成果物か → [§2.3](#23-利用者向けオプトイン診断用中間生成物)。
