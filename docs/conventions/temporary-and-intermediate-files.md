# 一時ファイル・中間生成物の配置規約

リポジトリ内のモジュールが、最終成果物そのものではない一時ファイル・中間生成物をディスクへ書く際に、
どこに・どう置き・誰がいつ破棄するかを、本書が**正本**として定める。各モジュールは、自身が下記の
どの分類に従うかを自身の仕様書に記す。

## 1. 適用範囲

- 対象: `libs/`・`tools/` 配下の全モジュール(ライブラリ層・CLIツール層)。

## 2. 分類

一時ファイル・中間生成物への需要は、性質の異なる3種類に分かれる。各モジュールは自分の需要が当たる
分類の規約に従う。

### 2.1 出力の原子書き込み用一時ファイル

最終出力ファイルそのものを、書き切ってから原子的に置換するために使う一時ファイル。本書の対象外とする。

### 2.2 非公開の内部一時領域

外部ライブラリ・外部プロセスと連携するためだけに使う、実装内部の一時作業領域。
呼び出し元(他モジュール・利用者を含む)へ領域の構成(何を・何個・どう名付けて置くか)を約束しない
ものがこの分類に当たる。

- **配置**: OSの一時ディレクトリを使う。
- **破棄**: 正常終了時に自動クリーンアップの機構で削除を試みる。プロセスの強制終了時や削除自体の
  失敗時に残置することは許容する。呼び出し元が削除タイミングを制御できる経路を設けない。
- **契約範囲**: 領域の構成・保持ファイルの一覧は公開契約に含めない。領域内の1ファイルのパスを公開契約の
  戻り値として返してよく(例: 処理結果のファイルパス)、その場合は戻り値の意味と、寿命が本節の破棄規則に
  従い呼び出し元が削除タイミングを制御できないことを、その関数の呼び出し契約として示す。

### 2.3 利用者向けオプトイン診断用中間生成物

利用者が明示的に指定したときだけ、処理途中の中間データを診断・検査用にディスクへ残す任意機能。

- **既定は無出力**: 指定しない限り何もディスクへ書き出さない。既定でも一旦書いてから破棄する実装は
  しない。
- **配置**: 出力ファイルに隣接させ、`<出力ファイル名>.intermediate/` の形で置く。OSの一時ディレクトリ
  は使わない。
- **保持**: 明示指定時に生成したものは処理後も保持し、ツール自身は削除しない。
- **有効化フラグ名**: 全ツール共通の統一名は
  [cli-interface.md §6](cli-interface.md#6-横断的な一貫性) に従う。
- **分担**: 保存する具体的な中間生成物の内容(ファイル名・形式)は、それを生成する側が定める。単一ツールが
  生成するならそのツール、複数ツールが共有するモジュールが生成するならそのモジュールとする。保存先の決定・
  有効化・失敗の報告はツール側が持つ。
