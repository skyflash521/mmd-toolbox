# 層タクソノミーと配置規約

リポジトリのモジュールを 3 つの層に分類し、各層の責務・判定基準・物理配置・設計原則・依存方向を定める。
本書はその正本とする。

## 1. 層タクソノミー

| 層 | 責務 | 判定基準(この層に置くもの) |
|---|---|---|
| フォーマット層 | 単一ファイル形式の読み書きと、その形式に閉じた評価・変換 | 特定のファイル形式の入出力と形式に閉じた処理だけを担い、ツール固有の判断を持たないもの。1 形式 = 1 ライブラリ |
| 共有ドメイン層 | 複数ツールが共有するドメインロジック | 形式層でも単一ツール固有でもないドメイン処理。形式の入出力はフォーマット層へ委譲するもの |
| CLIツール層 | 公開する引数の選択・ツール固有の引数・プリセット・そのツール限定のポリシー | エンドユーザー向けコマンド。形式の入出力・共有ドメインロジックは下位層へ委譲するもの |

- **フォーマット層**: 1 形式 = 1 ライブラリの規律は、MMD 形式か否かを問わず適用する。
- **共有ドメイン層**: 複数 CLI が共有する **CLI 出力契約(機械モードのイベント送出)** と **CLI 入力契約
  (引数の定義・検証・設定への解決)** もこの層に含める。
- **CLIツール層**: 共有する入力契約に含まれる引数を公開する場合、その名前・意味・検証は共有側の定義に
  従い、ツールごとに独自の定義を置かない。

## 2. 物理配置

| ディレクトリ | 配置するもの |
|---|---|
| `libs/` | ライブラリ層(フォーマット層・共有ドメイン層の各モジュール) |
| `tools/` | CLIツール層(各 CLI のコマンド本体・仕様・テスト) |
| `docs/` | どの層にも属さない参照資料・規約(形式仕様 `docs/specs/`、プロジェクト規約 `docs/conventions/`) |

- モジュールの仕様書はそのモジュールのディレクトリ直下に置き、冒頭でそのモジュールの属する層を
  宣言する。
- バイナリレイアウト・形式レイアウトの正本は `docs/specs/` 配下に置く。

## 3. フォーマット層共通の設計原則

フォーマット層の各モジュールは次の原則に等しく従う。

- **形式の事実のみを扱う**: ファイル構造の読み書きと、その形式に閉じた評価・変換だけを行う。ツール固有の
  判断(検出閾値、プリセット、生成・推定、値の選別・正規化など)は持ち込まない。
- **ロスレス原則**: 解釈しないデータ(未解釈のバイト列・末尾の残バイト・未マップの形式エントリなど)も
  保持し、無加工なら入力と同じ内容を書き戻せる。到達できる同一性の水準は形式によって異なり、解析と
  再直列化で字句表現が変わる形式ではバイト一致が原理的に成立しない。どこまでを保持し、往復で何の一致を
  保証するかは、当該形式の仕様書が定める。
- **CLI非依存・無出力**: 警告は構造化オブジェクトとして返し、表示の判断は呼び出し側(各ツール)へ委ねる。
  `print` や `logging` へ直接出力しない。
- **構造化警告・構造化エラー**: エラーにせず続行できる事象は構造化された警告のリストで報告し、正しい
  データモデルを構築できない構造異常は専用の構造化エラー(例外)で返す。両者を区別して扱う。

## 4. 依存方向

### 4.1 モジュール間の依存

- モジュール(`libs/<m>`・`tools/<t>` 単位)間の依存を循環させない。層内・層をまたぐを問わず A→…→A を
  作らない。
- 層をまたぐ依存は**下向きのみ**: CLIツール層 → 共有ドメイン層 → フォーマット層。
- 循環が必要に見える場合は、共有概念を下位層へ抽出して解消する。

### 4.2 コードとドキュメントの間

コードとドキュメントは互いを参照せず、それぞれ自己完結で書く。

- **コードからドキュメントを参照しない。** コメント・docstring・出力メッセージ・テストコードを
  含め、仕様書・規約などのドキュメントを指ささない。
- **ドキュメントからコードを参照しない。** ソースファイルのパス・`file:line`・関数/クラス名などの
  コード内部の識別子を指して説明を代替しない(「詳細は◯◯.py を参照」も含む)。ドキュメントは
  挙動・契約を自己完結で述べる。
- **対象外**: 次のものは本節の禁止に当たらない。
  - 仕様書・規約が自ら定義する外部契約の名前(CLI フラグ、機械モードの stage id、ライブラリの公開
    API 名など)と、配置規約が定めるディレクトリ構成。
  - ドキュメントファイルを処理対象のデータとして読み書きするコードのパス指定(リリーススクリプトが
    `<ツール>/CHANGELOG.md` を抽出する等)。
  - コード値の編集そのものを指示する調整手順書が編集対象を指す記述と、実装計画書が変更対象と
    裏取りの所在を指す記述。
