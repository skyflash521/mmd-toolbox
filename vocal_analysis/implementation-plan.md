# vocal_analysis 実装計画書

要求仕様 [vocal_analysis.md](vocal_analysis.md) を実装へ落とす計画。TDDで見出し単位のステップを進める。
本書は仕様を変更せず、仕様が実装での確定に委ねた詳細(認識器固定・CTC区間化・IPA→5母音写像表・RMS算出・
S-1ゲートの評価設計)を定め、着手順序とテスト方針を決める。仕様と矛盾が生じた場合は仕様(vocal_analysis.md)を
正とし、本書を直す。

---

## 1. 前提と依存

- 実装言語 Python 3.11+。重い依存は `vocal_analysis` 側(パッケージのextra等)に閉じ、`mmd_toolbox` 本体の
  必須依存 `numpy`/`scipy` は保つ。
  - S0: `soundfile`(BSD-3)。読めない形式のみ ffmpeg(自動検出・非再配布)。
  - S1: `demucs`(adefossez fork・MIT)を `demucs.api` で in-process。`torch`(BSD-3)。
  - S2: `transformers`(Apache-2.0)+ 音素モデル `facebook/wav2vec2-lv-60-espeak-cv-ft`(Apache-2.0)。
    `torch` は S1 と共有。
  - S3: `numpy/scipy`(外部ツールに依存しない)。
- 共有出力(ボーカルWAV＋音素セグメント列＋RMS)と IPA→5母音写像を利用先へ渡す。RMS を消費する判断・口形
  イベント確定・ピッチ推定は利用先(vocal_analysis.md §10)。
- S-1ゲートの自動ラベル生成は [vpr_io](../vpr_io/vpr_io.md) を読む。

---

## 2. 実装ステップ(着手順)

各ステップは「テスト作成 → レビュー → 収束ならコミット」「実装 → レビュー → 収束ならコミット」を回す。
外部ツールに依存するステップは、ユニットテストではモックまたは短い小サンプルを使い、ネットワーク・GPU・
実モデルを必須にしない。

| ステップ | 内容 | 主な受入条件 |
|---|---|---|
| A-0 | 雛形・中間形式の型(正規化PCM・ボーカルWAVパス・セグメント列・RMS)。**モデルid/revision・推論条件の固定** | 中間形式の型が定まり、モデル条件が固定され再現可能 |
| A-1 | S0 入力読み込み(`soundfile` 優先/ffmpeg フォールバック。ch/SR 保持)＋**入力レベル正規化**(斉次スカラ) | 各形式を読み ch/SR 保持。mp3 も読める。正の一様ゲイン違いで正規化後PCMが一致 |
| A-2 | S1 ボーカル抽出(`demucs.api`、`shifts=0`、Separator 抽象、mode 解釈) | S0出力(正規化PCM・ステレオ)からボーカルWAVを出力。決定論 |
| A-3 | S2 音素認識(Recognizer 抽象。16kHz monoへ変換 → 母音/子音/gap の全被覆セグメント列＋IPAラベル) | 全時間軸を重複・欠落なく被覆。母音/子音は音素ラベルと任意信頼度。CTC区間化(4.2)済み |
| A-4 | S3 強弱RMS(相対正規化=パーセンタイル、入力ゲイン不変) | ミックス全体の一様ゲイン差でRMSが不変。相対強度へ正規化 |
| A-5 | IPA→5母音写像(4.3) | 母音セグメントのIPAを a/i/u/e/o へテーブル参照で写像。テーブルに無いIPA・判定不能は gap(決定論的) |
| A-G | S-1 認識ゲート(4.1)。代表データで母音正解率・境界ずれ等を測り受入基準を判定 | 受入基準を満たす。満たさなければ Julius 等を評価して認識器を確定 |

依存関係: A-2/A-3 は A-1 の出力に依存。A-4/A-5 は A-3 の出力(母音区間・IPA)に依存。A-G(ゲート)は A-3
(認識)と A-5(写像)を用い、`vpr_io` の read(自動ラベル生成)を使える。

## 3. テスト方針

- `mmd_toolbox` のテスト規約(pytest・決定論・乱数シード固定・ネットワーク/GPU 不要)に従う。
- S1/S2 など外部モデル依存は薄いアダプタ層に隔離する。純関数の核(S0 のレベル正規化、S3 のRMS相対正規化、
  IPA→5母音写像、CTC区間化)は合成入力フィクスチャで決定論的にテストする。アダプタ呼び出し部は小サンプル
  またはモックで確認する。
- 実モデルを使う検証(S-1ゲート)は別途、手動または重テストとして分離し、通常の `pytest` には含めない。
- 共有出力(セグメント列・RMS)は、利用先がそれだけに依存して中核処理をモックテストできる形に保つ。

## 4. 確定する詳細(初期値・手順)

仕様が実装での確定に委ねた項目を定める。値は出発点で、代表サンプルで調整する(ただし §4.1 の S-1ゲートの
評価集合・閾値・集計規則は除く。採点前に固定する)。**時間単位**: 音声解析は秒/ms で扱う。

### 4.1 S2受入基準(S-1ゲート。客観的に判定)

- **代表データ**: 日本語歌唱5曲以上(ジャンル・テンポ・声質・男女に幅)の**伴奏込み音源**と、**ボーカル単体
  2点以上**。さらに**ペア音源**(同一歌唱のボーカルステムと、それを含むミックス)を**1組以上必須**で含める
  (分離の寄与の切り分けに使う)。数は初期目安だが、評価集合は対象モデルの出力を評価データで観測する前に確定・
  記録し、以後は固定する。
- **使い分けの理由(誤差の切り分け)**: ボーカル単体/ステムは分離をかけず S2 へ直入力し、**S2(音素認識)単独の
  精度**を測る。分離(S1)の寄与は、**同一歌唱のペア**で「ボーカルステム」対「そのミックスから分離した
  ボーカル」を比べて測る(別音源どうしの差は歌唱内容・声質・録音条件が混じり、切り分けにならない)。
  ボーカルステムは**真にアカペラな音源**(公式ステム/アカペラ、または自録)を使い、本ツールで分離した出力を
  S2 単独測定には使わない(循環を避ける)。
- **ラベル(基準)**: 各音声に区間ラベルを付与し、**全時間軸を被覆**する。ラベルは**対象ボーカルの内容**で
  判定する(伴奏の有無に依らない): **a/i/u/e/o**(母音)・**c**(対象ボーカルの子音・非母音有声区間)・
  **sil**(対象ボーカルが母音も子音も発していない区間。伴奏・残響があっても sil)。ラベルの作り方は次の2通り:
  - **人手付与**。
  - **vpr 由来の自動生成**: 音声と対の vpr があれば、その音素から 母音→a/i/u/e/o・全子音区間→c・休符→sil
    として全時間軸ラベルを自動生成する(vpr の解析は共有モジュール [vpr_io](../vpr_io/vpr_io.md) を再利用。
    c は両唇音に限らず全子音・非母音有声区間)。一から手付与するより軽いが、**ゲート正解に使うには監査必須**:
    vpr は書き起こしで実発音とアドリブ・簡略化・時刻ずれで食い違いうるため、採点前に**実発音との一致と境界
    精度を人手監査して固定**する。**未監査の自動ラベルはゲート正解にしない**。ラベルの境界精度は監査で確認して
    固定する(実行時の RMS オンセット補正は利用先の責務であり、ゲート正解ラベルの作成には用いない)。

  ペアの**ステムとミックスは同一歌唱なので同じラベルを使う**(ペア比較が成立する)。形式は **Audacity ラベル**
  (TSV: 開始秒・終了秒・ラベル)で、1音声につき同名の `.txt` を1つ。
- **音声形式**: 測定への符号化ノイズ混入を避けるため **WAV(可逆)** を使う。サンプルレート・チャンネルは
  原音のまま。
- **配置**: 評価データ(著作物の楽曲音声を含む)は**リポジトリに置かない**。利用者がローカルに用意し、ゲートへ
  **パス指定で渡す**。各音源の**役割**(伴奏込み/ボーカル単体/ステム/ミックス)と**ペア関係**は利用者が
  マニフェスト(または命名規約)で宣言する。再現性のため、各音源・ラベルのダイジェスト(ハッシュ)を
  マニフェストまたは結果レポートに記録する(音源自体のリポジトリ保存はしない)。
- **採点対象の段階**: S-1 は S2(認識)の品質を測る。アダプタ出力は CTC区間化(60ms吸収。4.2)済みの
  母音/子音/gap＋IPAラベルのセグメント列であり、採点対象はそれに **IPA→5母音写像**(4.3)を適用した
  セグメント列とする(60ms吸収を採点時に再適用しない)。RMS補正・gap解決などの利用先のRMS依存処理は
  **含めない**。
- **母音正解率**: 採点対象セグメント列を 10ms フレームへ展開し、**基準が母音(a/i/u/e/o)のフレーム**のうち
  母音種別が一致した割合(= 一致母音フレーム / 基準が母音のフレーム)。
- **過開口率(フレーム単位)**: 基準が c/sil のフレームのうち、予測が母音(口が開く)になったフレームの割合。
  母音区間が後続の c/sil へはみ出す過剰開口を捕捉する。
- **区間の対応付け**: 予測区間と基準区間を、母音種別が一致し**時間重なりが正(0より大)**の組に限り、**総重なり
  時間を最大化する全体最適割当**(ハンガリアン法等)で1対1対応させる。最適割当が複数あるときは一意化のため、
  基準区間・予測区間をそれぞれ開始時刻昇順(同時刻なら終了時刻昇順)で番号付けし、割当を(基準番号, 予測番号)の
  組の昇順リストとして辞書式比較した最小の割当を採る。基準にあって対応が無いものを未検出、予測にあって対応が
  無いものを余剰とし、いずれも失敗側に数える。
- **境界時刻ずれ**: 対応した区間の開始時刻差 |予測 − 基準| の中央値と95パーセンタイル(単位 ms)。対応区間が
  0件の曲は境界ずれが未定義なのでマクロ平均から除外し、そうした曲が1つでもあればゲート全体を不合格とする。
- **集計と受入基準(初期値)**: 指標は**曲ごとに算出し、その曲数マクロ平均**で判定する。基準: フレーム母音
  正解率 ≥ 80%、**過開口率 ≤ 10%**、境界ずれ中央値 ≤ 50ms かつ 95パーセンタイル ≤ 120ms、かつ
  (未検出+余剰) / 基準区間数 ≤ 10%。未検出区間のフレームは母音正解率でも不一致として数える。
- **判定**: 合否は **S2単独**(ボーカルステム/単体)の基準で決める。S2単独が不合格なら Julius(phone-loop)等を
  同じ手順で評価し、認識器を確定する。**ペア音源では Demucs をアドホックに用いてミックス側(通し)も必ず
  評価する**(切り分けのため)。**S2単独は合格だがミックス側が悪い**ときは分離(S1)側の問題として S1 側で
  対処する(認識器は変えない)。
- **再現性と客観性**: ゲートは固定したモデル(id・revision)と推論条件(4.2)で実施する。評価集合(マニフェスト)・
  受入基準の閾値・集計規則は、対象モデルの出力・指標を評価データ上で観測する前に固定して記録する。観測した
  出力・指標を見てから標本数や閾値を緩める変更は禁止。評価集合・規則の修正は観測結果と独立した事由(ラベル
  誤り・データ不備・固定条件の誤り等)に限り、修正後は最初から採点をやり直す。**ゲート用データ・vpr由来
  ラベルとその監査は `vocal_analysis` が最終所有する。**

### 4.2 認識器の固定とCTC区間化

- **固定(ゲート開始前)**: モデル `facebook/wav2vec2-lv-60-espeak-cv-ft` の revision、主要依存パッケージ版、
  入力16kHz mono と再サンプリング方式、実行デバイス/dtype、推論のバッチ/スレッド・乱数シードを固定する。
  ゲートはこの固定環境で実施し、実装も同条件を使う。
- **CTC区間化(アダプタ側。RMS不要)**: 同一音素ラベルの連続フレームを1区間に連結。最小区間長 60ms(未満は隣接へ
  吸収。吸収先はより長い隣接(母音/子音)区間、同長なら直前。先頭/末尾で片側しか無ければその側。gap は吸収先に
  しない。非gapの隣接が無い場合はその短区間自体を gap にする)。blank/未割当は gap とする(全時間軸を被覆。
  時間は秒で保持)。

### 4.3 IPA→5母音写像・RMS算出

- **IPA→5母音写像(中核共用)**: 母音セグメントの IPA を5母音へ**完全一致のテーブル参照**でバケット化する
  (a/ɑ/ʌ/æ→あ、i/ɪ/j→い、ɯ/u/ʊ/w→う、e/ɛ→え、o/ɔ→お)。テーブルは**採用認識器の音素インベントリ
  (espeak)からS-1ゲート採点前に確定・固定**する(評価データの出力を見てからの変更は §4.1 の客観性規定で禁止。
  写像表は採点規則の一部)。テーブルは認識器が出力する母音IPAを網羅するよう作り、母音の取りこぼしを表の網羅で
  防ぐ。**テーブルに無い母音IPA・判定不能なラベルはいずれも gap とする**(「最近接」のような曖昧な距離判定は
  使わず決定論的にする。安全側=誤った母音を立てない)。この gap フォールバックは想定外ラベル向けの稀な経路で
  あり、S-1ゲートでは gap は母音不一致として数える(=取りこぼしは表の網羅で防ぐ前提)。母音/子音の判別は
  アダプタ側で済んでいるため再分類しない。**閉鎖(両唇音)判定・無音/閉口の確定は写像に含めない**
  (利用先の入口処理)。
- **RMS算出**: フレーム長 25ms・ホップ 10ms。**曲全体**のフレームRMSから 10パーセンタイル `p10`・90パーセンタイル
  `p90` を取り、各フレームを `values = clip((rms - p10) / (p90 - p10), 0.0, 1.0)` で正規化する(`p10`→0・`p90`→1、
  範囲外はクリップで外れ値を除外。`p90 == p10`(無音・定常)は 0 除算を避け全フレーム 0.0)。差の比なので入力
  ゲインに不変。相対正規化したRMS、および曲全体のダイナミックレンジ `dynamic_range_db`(95/5 パーセンタイル RMS の
  dB 差。ゲイン不変)を共有出力として渡す(`dynamic_range_db` は正規化済み値からは復元できないため別に持たせる。
  利用先の低ダイナミクス抑制=song2vmd 実装計画 §4.3 がしきい値判定に使う)。RMS を使う判断(無音ヒステリシス・
  低ダイナミクス抑制・母音中央代表・低信頼閉口)は利用先(`song2vmd` 入口)。

### 4.4 中間形式の公開データ型

各ステージをつなぐ正規化中間形式(vocal_analysis.md §2)を公開型として確定する。S1出力(ボーカルWAV)以外は
Python の dataclass、S1出力は `pathlib.Path`(専用型を設けない)。時刻は**秒(float)**(本章冒頭のとおり音声解析は
秒/ms)。numpy 配列は `np.ndarray`。

- `AudioPcm`(S0出力 正規化PCM): `samples: np.ndarray`(形状 (フレーム数, チャンネル数)、float32、値域 [-1, 1])、
  `sample_rate: int`。チャンネル数は `samples.shape[1]`(ch/SR 保持。mono化・再サンプリングしない。§3)。
- **S1出力(ボーカルWAV)**: `pathlib.Path`(分離器が書き出したボーカルWAVのパス。専用 dataclass は設けない)。
  出力形式は分離器に従う(§4・§8.1)。
- `Segment`(S2出力の要素): `type: Literal["vowel", "consonant", "gap"]`、`start_sec: float`、`end_sec: float`、
  `phoneme: str | None`(IPA。母音/子音のみ。gap は None)、`confidence: float | None`(任意。0〜1)。
  セグメント列は時間順・隙間なく連続・非重複で全時間軸を被覆する(§5・§8.1)。
- `RmsEnvelope`(S3出力): `times_sec: np.ndarray`(各フレーム中心時刻、秒)、`values: np.ndarray`(相対正規化済み
  RMS、4.3)、`dynamic_range_db: float`(曲全体のダイナミックレンジ = 95/5 パーセンタイル RMS の dB 差。比なので
  ゲイン不変)。`dynamic_range_db` は正規化済み `values`(クリップ済み)からは復元できないため別フィールドで持つ
  (利用先の低ダイナミクス判定用。song2vmd 実装計画 §4.3)。フレーム長・ホップは 4.3(25ms / 10ms)。
- `AnalysisResult`(共有出力コンテナ): `vocal_wav: Path`、`segments: list[Segment]`、`rms: RmsEnvelope`。
  利用先は必要な部分集合だけを使う(vocal_analysis.md §1.3)。
- IPA→5母音写像は公開関数として提供する(4.3 のテーブル参照)。S-1 ゲートと `song2vmd` 入口が同一規則で使う
  (vocal_analysis.md §7)。

### 4.5 S0 入力レベル正規化(式・目標値)

vocal_analysis.md §3 の「入力に斉次・絶対ゲート無し」を満たす式を確定する。**ピーク正規化**を採用する:

- `peak = max(|samples|)`(全チャンネル・全フレームの絶対値の最大)。
- `peak > 0` なら `samples_out = samples * (target_peak / peak)`、`target_peak = 0.95`(確定値)。
- `peak == 0`(完全無音)は 0 除算を避けて入力をそのまま返す。

正の一様ゲイン g に対し peak も g 倍になり `target_peak/peak` で相殺されるため、正規化後PCMは g に不変
(斉次)。絶対ゲートを持つ測定(ゲート付きラウドネス)は使わない(§3)。`target_peak` は **0.95 に確定**し、実装が
独自に変えない(変更が要れば本計画を先に更新する)。

## 5. リスクと未確定

- **S2品質(最大リスク)**: 歌唱での母音認識が受入基準に届くか。S-1ゲートで先に潰す。届かなければ認識器を
  差し替える。
- 依存の重さ・速度: `transformers`+モデル取得(ダウンロード・キャッシュ・メモリ・初回ネットワーク)。モデルの
  版(revision)は A-0 で固定(4.2)。キャッシュ先・オフライン挙動・必要ディスク/RAM・CPU実行時間は A-3 で確定する。
- 決定論: 外部ツール(分離・認識)の非決定性。Demucs `shifts=0`、スレッド/シード固定で可能な範囲に収める。
- Demucs 保守終了: adefossez fork を版固定。将来、保守活発な audio-separator への切り替え余地。

## 6. 仕様への影響

- 仕様(vocal_analysis.md)の記述変更が必要な不整合は無い。本計画は仕様が実装での確定に委ねた詳細(4章)の
  置き場であり、仕様の決定を覆さない。
- 実装着手後に 4章の数値確定や S-1ゲートの結果で仕様の前提が崩れた場合(例: 認識器の差し替え)は、正本である
  vocal_analysis.md を先に更新してから本計画と実装を整合させる。
