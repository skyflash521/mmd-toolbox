# レビュー専用サブエージェント起動の共通基盤

レビュー専用サブエージェント(`Agent` ツールで直接起動する read-only のレビュー担当)を
レビュアーに使う反復レビュー・ループが共有する起動契約と手順。レビュアーの正体に依らない
判断ロジックは [review-loop-judgement](../review-loop-judgement/SKILL.md) スキルが持つ。
Codex をレビュアーに使うループの起動契約は [codex-watchdog](../codex-watchdog/SKILL.md) スキルが
別に持つ。

## 呼び出し元が定める項目

次の2点だけを呼び出し元スキルが定め、以下の手順に当てはめる(このスキルはこれらを定めない)。
以下「レビュアーエージェント」「固定モデル」は呼び出し元が定めたものを指す。

- **レビュアーエージェント**: `Agent` ツールの `subagent_type` に渡すレビュー専用エージェント名。
  リポジトリを読み差分を自分で取得できること、読み取り専用の確認だけを行いファイルを編集しないよう
  エージェント定義で縛られていること
- **固定モデル**: そのエージェントが frontmatter で固定しているモデルと、その表示名

## 手順0: 起動可否ゲート・対象確認

`review-loop-judgement` スキルの[手順0](../review-loop-judgement/SKILL.md#手順0-起動可否ゲート対象確認)のとおり実行する。

## 手順1: レビュー実行(1ラウンド)

### ラウンド1(新規起動)

`Agent` ツールで以下を**同期実行**する:

- `subagent_type`: 呼び出し元が定めたレビュアーエージェント
- `name`: このループの間ずっと使う固定の名前(2ラウンド目以降の継続に使うため**必須**)
- `run_in_background: false`(`Agent` ツールが完了まで戻らずハングの心配が無いため、
  codex を起動するループのような watchdog・stall検知・タイムアウト監視は不要)
- `prompt`: `review-loop-judgement` スキルの[レビュー依頼に含めるべき内容](../review-loop-judgement/SKILL.md#レビュー依頼に含めるべき内容レビュアーに依らない共通要件)を満たし、
  [レビュー依頼に含めてはならない内容](../review-loop-judgement/SKILL.md#レビュー依頼に含めてはならない内容レビュアーに検査作業をさせない)(検査をレビュアーに割り当てない・読む量や読み方を指定しない)に
  反する記述を含まないレビュー指示文
- レビュー指示文に「応答の末尾に、自分のシステムプロンプトに示されている実行モデル表示名を
  そのまま記載せよ」を必ず含める(下記[既知の限界](#既知の限界自己申告に依存する検知)で使うモデル代替の検知手段)

レビュアーエージェントはモデルが frontmatter で固定された専用エージェントなので、`model` を
呼び出し側で指定する必要はない。

### ラウンド2以降(同じエージェントを継続する)

**新規に `Agent` を起動せず、`SendMessage` の `to` にラウンド1で付けた名前を指定して次ラウンドの
依頼を送る**。エージェントは完了後もその名前で再開でき、前ラウンドの会話コンテキスト——自分が出した
指摘・読んだファイル・受け取った観点と品質基準——を保ったまま続きを処理する。レビュアーが
`SendMessage` を持たないことは継続の妨げにならない: 応答は再開したエージェントの
最終テキストとして呼び出し側に届く。

- 継続の依頼には `review-loop-judgement` スキルの[レビュー依頼に含めるべき内容](../review-loop-judgement/SKILL.md#レビュー依頼に含めるべき内容レビュアーに依らない共通要件)が求める前ラウンドの文脈
  (修正した内容・反証した理由・受容したい項目と認否の要求・スコープ外として却下した理由)を渡す。
  **レビュアーは自分が出した指摘を覚えているので指摘そのものの再掲は要らず、各指摘への対応結果と
  今回問うことを書けば足りる**。**常設観点は毎ラウンドすべて適用させる**ので、前ラウンドで渡した
  観点をすべて適用して再レビューせよと明記する(観点を減らさない)。[レビュー依頼に含めてはならない内容](../review-loop-judgement/SKILL.md#レビュー依頼に含めてはならない内容レビュアーに検査作業をさせない)
  (検査をレビュアーに割り当てない・読む量や読み方を指定しない)は継続の依頼にも同じく適用する。
- 実行モデル表示名の申告は継続ラウンドでも毎回求める。
- **応答は `SendMessage` の戻り値としては返らない**。エージェントは背景で再開し、完了時のタスク通知で
  応答が届く。その通知の到着がそのラウンドの完了であり、届く前に同じレビュアーへ次の依頼を重ねない。
- **継続ラウンドは自分で締切を持つ**: ラウンド1と違い `Agent` ツールの戻りが締切にならないので、
  送信後は300秒以下のハートビート(`ScheduleWakeup`)を張って待つ(背景で走るエージェントの完了通知には
  取りこぼしとハングの既知の問題があり、待ち続けると自律進行が黙って止まる)。ハートビートが続けて
  空振りし進展のないまま待ちが伸びるラウンドは `TaskStop` で締め切る(対象は再開したエージェントの
  タスクで、`SendMessage` の戻り値が返す再開先のIDで特定できる)。締め切ったラウンドは
  `review-loop-judgement` スキルの[1ラウンドが時間内に終わらないとき](../review-loop-judgement/SKILL.md#1ラウンドが時間内に終わらないとき)に従って取り直し、
  **失敗ラウンドに数える**(締切超過を理由に観点や論点を削らない)。

### 失敗時の扱い

- Agent呼び出しがエラーで終わる、または応答が契約違反(観点ごとの確認結果を伴わない無指摘の
  一言、編集を試みた形跡等)の場合は失敗ラウンドとして新規エージェントで再実行する。
  **失敗ラウンドの取り直しは継続(`SendMessage`)ではなく新規 `Agent` 起動で行う**(契約違反を犯した
  文脈を引き継がせない)。名前はラウンド1と同じものを使ってよく、以後の `SendMessage` は新しい方の
  エージェントに届く。**新規起動ではそれまでの会話コンテキストが失われるので、前ラウンドまでの文脈と
  レビュー指示文一式を改めて渡す**。
- **エラー内容が固定モデル自体の利用不可(モデル未対応・権限エラーなど、モデルを名指しする
  エラー)を示す場合は、原因を「<固定モデルの表示名>が使用不可」として明示し、再試行せず直ちに
  ユーザーへ報告して停止する**(恒久的な利用不可は再試行しても解消しない)。
- **応答末尾のモデル表示名が固定モデルを示していない場合は、モデルが黙って代替された疑いとして
  契約違反扱いにし、失敗ラウンドとして新規エージェントで再実行する**(下記[既知の限界](#既知の限界自己申告に依存する検知)参照)。
- **レビュアーが本レビューへ進まず差し戻してきた場合は失敗ラウンドに数えない**(呼び出し側が
  レビュー指示文の組み立てを誤ったことが原因で、レビュアー側の障害ではない)。差し戻しが明示する
  不備を直した指示文で、同じラウンドを即座に取り直す。**差し戻しはレビュアーの契約違反ではないので
  エージェントを捨てない**: ラウンド1の差し戻しは新規起動、継続ラウンドの差し戻しは同じエージェントへ
  直した依頼を送り直す形で取り直す。
- **2回連続で失敗ラウンド扱いになったら「問題発生」として停止**し、状況をユーザーに報告する。

### 既知の限界(自己申告に依存する検知)

レビュアーエージェントは frontmatter でモデルを固定しているが、組織・プロジェクト・ユーザーいずれかの
スコープの settings で `availableModels` の許可リストによりそのモデルが除外されている場合、
Claude Codeはエラーを出さず親会話のモデルへ黙って切り替えて実行を継続しうる。`Agent` ツールの
戻り値自体には実行モデルを示す情報が無いため、上記[失敗時の扱い](#失敗時の扱い)が求める、応答末尾への実行モデル表示名の申告
([手順1](#手順1-レビュー実行1ラウンド)のレビュー指示文で要求)がこの経路の唯一の検知手段になる。この申告は、サブエージェントの
システムプロンプトにハーネス自身が注入した表示名をそのまま書き写させるものであり、モデルが
学習知識から自己のバージョンを推測して答える場合より信頼できる。いずれかのスコープの settings で
`availableModels` が設定されない限りこの経路は発動しない。設定された場合に備えて、この申告
ベースの検知を安全網として置く。
