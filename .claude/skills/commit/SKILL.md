# コミット(Haiku委譲)

トークンを使う作業(diffを読む・コミットメッセージを起草する・コミットする)を
Haikuサブエージェントに委譲する。**メインモデルはコミットメッセージを書かない。**

## 役割分担

- **メインモデル**: 何をこのコミットに含めるか(対象ファイルの範囲)だけを決める。
  これはリポジトリ全体の文脈が要る判断のため。対象が曖昧ならユーザーに確認する。
  メッセージ本文は書かず、必要なら一行の意図ヒントだけ渡す。
  **このスキルを起動してよいのは、対象変更がレビューゲートを通過した後だけ**(下記)
- **Haiku**: 指定範囲をステージし、diffを読んでコミットメッセージを起草し、コミットする。
  ただし**起草・コミット前に「不正コミット防止チェック」を必ず行う**(下記)

ユーザーがコミットメッセージを明示指定した場合は、それをHaikuに渡し
**起草させず件名・本文にそのまま使わせる**(規約のtrailerのみ付与)。

## 不正コミット防止チェック(レビューゲート確認)

レビューゲート未通過のコミット(=不正コミット)を防ぐためのチェック役割。**未通過ならコミットしない。**

「通過(=コミットしてよい)」の定義は **収束のみ**。収束=codex 反復レビューで指摘がゼロ、
または出た指摘を全て修正/反証して**再収束**した状態。**結末の種類(収束/千日手/要ユーザー
判断)とその定義は [[codex-review-loop]] が正**で、本スキルは定義を二重に持たずそれを参照する。
本スキルが持つのは、渡されたレビュー最終応答に対する**コミット可否の語検出ガード**(下記の
不正条件1〜8)という enforcement 機構だけ。**収束以外はすべてコミット不可**:

- **千日手 / 要ユーザー判断**: レビューループは終了するが**未解決の論点が残る**状態。
  コミットしてはならない。**ユーザーに諮る**。
- **未完了**(実行中 / stall / タイムアウト / 失敗 / バックグラウンド化など判定未取得):
  tooling を直して再レビューする。コミット不可。
- 「もう十分」「テストが通ったから」も通過にしない。
- **レビューがハング・stall・無出力で完走しない場合、メインモデルの判断や合理化で代替して
  コミットしてはならない。** codex 自身が収束を述べたレビューの完走だけが通過。判定が
  取れなければ未完了=コミット不可(tooling を直して取り直す)。これは過去に実際に犯した
  違反(ハング時に自分で判断してコミット)であり、明確に禁止する。

- **メインモデルの責務**: **収束してから**本スキルを起動する。起動時にプロンプトへ次を必ず渡す:
  - **codex レビューの最終応答テキストそのもの**(要約でなく、verdict を含む原文)
  - **レビュー済みファイルの明示リスト**(= ステージ対象と一致するべき範囲)
  千日手・要判断・未完了の変更では**本スキルを起動しない**(ユーザーへ諮る / tooling を直す)。
- **Haiku の責務(チェック実行)**: コミット前に下記の不正条件を判定し、**1つでも該当すれば
  コミットせず「不正コミットの疑い: <該当条件>」と報告して停止**する。

### 不正コミットの条件(いずれか該当で不正)

1. **verdict 未提示**: codex レビューの最終応答テキストが渡されていない。
2. **収束が明示されていない**: テキストに収束を肯定的に示す記述が無い、または収束を打ち消す
   表現を含む(「未収束」「収束していない」「収束せず」「収束未達」「再収束待ち」等)。
   「収束」の文字を含んでも否定・保留の文脈なら収束とみなさない。
3. **コミット不可の終了**: テキストに「千日手」「要ユーザー判断」「要判断」のいずれかを含む
   (=ユーザーに諮るべき状態。収束ではない)。
4. **未完了・失敗・判定未取得**: テキストに「実行中」「途中」「stall」「タイムアウト」「失敗」
   「バックグラウンド」「未完走」「ハング」「無出力」「早期復帰」「判定未取得」のいずれかを含む。
5. **未対応の指摘**: 本文に指摘(file:line 形式・「指摘N」等の列挙)があるのに、各指摘へ対応する
   決着(修正した/反証/誤検出/解消/対応済み 等)の記述が見当たらない。対応関係が曖昧なら
   未対応とみなし不正側に倒す。
6. **範囲外混入**: ステージ対象がレビュー済みファイルのリストに無いものを含む。
7. **判定未取得を自己判断で代替(原則)**: codex 自身の収束宣言が無いのにコミットしようとして
   いる。語で現れる場合は条件2(収束明示なし)と条件4(ハング/無出力等)で捕捉する。完全に
   作り込まれた偽の収束テキスト(語検出を抜ける)は Haiku の語検出では捕捉できないため、
   「**codex の最終応答原文をそのまま verdict として渡す**」というメインモデルの責務で防ぐ
   (要約・地の文・自己判断のテキストを verdict にしない)。これは本スキルが過去に犯した違反
   (ハング時に自分で判断してコミット)への明示的な歯止め。
8. **合理化による通過の試み**(条件2とは独立の純粋な語検出): テキストに、未収束のまま
   コミットへ進める**正当化の定型句**が含まれる。これらは codex のレビュー本文には現れず、
   メインモデルが「進めてよい」と地の文で書くときの言い回し:
   「収束扱いにする」「収束とみなしてコミット」「収束とみなして進める」「ツール都合でコミット」
   「実質満たすのでコミット」「実質的に満たすのでコミット」「もう十分なのでコミット」
   「テストが緑だからコミット」「ハングしたが進める」「ハングしたがコミット」。
   これらの句が含まれれば不正。

判定はテキストの語検出とファイル集合の包含で行う。迷う場合・条件が競合する場合は
**不正側に倒す**(安全側)。語の引用や反証文脈で偽陽性が出ても、結果はコミットを止めるだけで
安全側(=破壊的でない)。その場合はメインモデルが codex の収束原文をそのまま渡し直して解消する。

## 手順

1. `git status --short` で状態を確認し、コミット対象ファイルを特定する。
   - **コミット対象の変更が無ければ**、その旨を報告して終了する(空コミットはしない)
   - **指定ファイル以外に既にステージ済みの変更があれば**、混入を避けるため
     ユーザーに知らせ、含める範囲を確定してから進める
2. **レビューゲート確認**(上記「不正コミット防止チェック」): 渡された codex レビュー最終応答が
   収束を示すか(不正条件1〜8に該当しないか)を確認する。**収束していなければ Haiku を起動せず**、
   該当した不正条件を添えて報告し、コミットせずに終了する。
3. Agentツール(`model: "haiku"`)を起動し、プロンプトに以下を渡す:
   - 作業ディレクトリ(リポジトリルートの絶対パス)
   - ステージするファイルの明示的なリスト(`git add <files>` の形。
     `git add -A` / `git add .` は使わない)
   - **codex レビューの最終応答テキスト原文**(要約でなく原文)と**レビュー済みファイルのリスト**
   - 任意: 一行の意図ヒント(例「ベジェ評価の実装」)。メッセージ本文は渡さない
   - 任意: ユーザー指定のコミットメッセージ(あれば。そのまま使わせる)
   - 下記「Haikuへの指示」をそのまま含める
4. Haikuの報告からコミットハッシュ・件名・残りの作業ツリー状態を確認し、ユーザーに報告する。
   成功と確認できない報告なら、成功扱いにせずユーザーに知らせる。
   **Haiku が「不正コミットの疑い」で停止した場合はコミットせず、その理由をユーザーに報告する**

## Haikuへの指示(プロンプトに含める)

> 指定ファイルだけをステージ(`git add <files>`)し、`git diff --staged -- <files>` で
> 変更内容を読んでから、内容に即したコミットメッセージを**あなたが起草して**コミットせよ。
> ユーザー指定メッセージが渡された場合は起草せず、それを件名・本文にそのまま使う。
>
> コミット前の確認:
> - **不正コミット防止チェック**: 上記「不正コミットの条件(いずれか該当で不正)」の1〜8を
>   渡されたレビュー最終応答テキストとステージ対象に対して判定せよ。1つでも該当すれば
>   **コミットせず「不正コミットの疑い: <該当した条件番号と内容>」と報告して停止**せよ。
>   迷う場合は不正側に倒す。
> - `git status --short` でステージ済みが指定ファイルと一致するか確かめる。
>   指定外がステージされていたら**コミットせず、その事実を報告して停止**せよ(混入防止)
> - 意図ヒントは起草の参考に留め、件名・本文へ逐語コピーしない。diffと矛盾するヒントは無視する
>
> メッセージの規約:
> - `git log --oneline -10` で既存コミットの文体(日本語・簡潔な件名)に合わせる
> - 1行目: 何をしたかの簡潔な件名(日本語、句点なし)
> - 必要なら空行を挟み本文に「何を・なぜ」を箇条書き(自明なら件名のみで可)
> - 末尾に空行を挟んで `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`
>
> 禁止: `--amend` / `push` / `rebase` / 指定外ファイルのステージ / `rm -rf` /
> 作業ツリー・履歴を壊す操作(`git reset` / `git restore` / `git checkout -- <path>` /
> `git clean` / `git stash` / `git rm`)。
>
> コミット後の検証と報告:
> - `git commit` の成否を確認する。失敗(フック拒否・対象なし等)なら**成功と報告するな**。
>   失敗内容をそのまま報告せよ
> - 成功時は `git log --oneline -1` と `git status --short` を出力し、コミットハッシュ・
>   件名・残りの未コミット内容を報告せよ

## 対象外

`--amend` や rebase など履歴の書き換えを伴う操作はこのスキルの対象外。
メインモデルがユーザーに確認した上で直接行う。
