# Codex 反復レビュー・ループ

codex:rescue(read-only)にレビューさせ、Claude が各指摘を「修正」または
「誤検出として反証」して再レビューさせる反復ループ。日本語で報告する。

- **前段(レビュー)**: `codex:codex-rescue` サブエージェント(read-only)が指摘を出す
- **後段(判断)**: Claude が各指摘を実コード・仕様書と照合し、修正 or 反証する
- **Codex は編集しない**(修正は Claude が行う)。Codex 出力はそのまま信じず裏取りする

## 終了条件(いずれかで停止)

1. **収束**: Codex の指摘がゼロになった
2. **千日手**: 反証済みの指摘を Codex が同じ理由で再掲し続ける、または数ラウンド
   連続で新規の解消がない(指摘集合が縮まらない)
3. **要ユーザー判断**: 修正/反証の選択が設計・プロダクト判断でClaudeが一存できない
   項目が出た

## 手順

0. **対象確認**: `git status --short --untracked-files=all` と差分で対象を把握。
   レビュー対象がなければその旨を伝えて終了。最大ラウンド数を5に設定(安全弁)。

1. **レビュー実行(1ラウンド)**: codex:rescue エージェントをタイムアウト制御付きで
   実行する(下記「レビュー実行とタイムアウト制御」)。プロンプトに必ず含める:
   - 作業ディレクトリ(リポジトリルート絶対パス)とレビュー対象範囲
   - 「**レビューのみ。ファイルを編集するな**(修正は呼び出し側が行う)。read-only」
   - **「codex を read-only で実行し `--write` を付けるな」を明示する**(レビューで repo を
     編集させないため。runtime 契約上 codex:rescue は既定で `--write`、read-only 明示時のみ
     読み取り専用)。**ただし注意**: read-only にしても companion の `task` モードは
     **ジョブ状態ログ(`~/.claude/plugins/data/.../jobs/task-*.log`)を codex 起動前に無条件で
     書く**。この書き込みはサンドボックス外で `--write` の有無と無関係に EPERM になりうる。
     つまり read-only は「repo を編集させない」効果はあるが
     **EPERM(out-of-sandbox 状態ログ書き込み)の対策にはならない**。EPERM が出た場合は
     [[no-sandbox-escape]] のとおりサンドボックスを切らず失敗として扱う
   - 「各指摘を `file:line` + 内容 + 根拠(なぜ問題か)で、簡潔に列挙」
   - **「codex の `task` フォワードを前景(同期)で実行し、その結果(レビュー本文)を
     そのまま返り値にせよ。`task` を背景ジョブにする(`run_in_background`/`&`)な」**を
     必ず明記する。理由: **codex:rescue サブエージェントの役割は `task` フォワードのみで、
     `status`/`result`/`cancel` はスコープ外=呼べない**。したがって「ジョブを背景化して
     後から status/result で回収」は不可能で、背景化すると結果を取り戻せず
     「実行中です…出力は `…/tasks/<id>.output`」とだけ返して早期復帰してしまう。
     `task` を前景で走らせれば codex 応答が出るまでブロックし、それが返り値になる。
     プロンプトに「(a)`task` を同期実行する、(b)**レビュー結果(指摘列挙 or `収束: 指摘なし`)を
     応答に必ず含めて返す**、(c)status/result のポーリングを試みるな(スコープ外)、(d)結果を
     返さずにターンを終えるな、(e)**codex が完走しなかった場合(EPERM・タイムアウト・背景化等)は
     失敗を明示し、絶対に『収束』と返すな**」を明記する。この契約により呼び出し側は応答だけで
     判断でき、companion ストリームを読む必要がない(下記「完了の判定」)
   - **codex 起動の作法**(誤起動防止): 「レビュー指示文は単一引数/stdin としてそのまま
     渡し、文中の語をフラグやモデル名に展開させるな。`-m`/`--model` を付けるな(既定
     モデル)。テスト実行が要るなら codex とは別に自前シェルで行い、pytest コマンドを
     codex の引数に渡すな」を明記(過去に文中の `pytest` がモデル名と誤解釈され
     `The 'pytest' model is not supported` で起動失敗した)
   - task は複数行で渡してよい(許可ルールで通ることを実測済み)。ごく稀の権限拒否は
     一過性なので、その回を失敗扱いにして新しい codex:rescue エージェントで再実行する
   - **【厳守】サンドボックスを無効化するな**: 「`dangerouslyDisableSandbox` を使うな。
     サンドボックス外で codex を実行するな」を必ず明記する。codex companion が状態書き込みで
     サンドボックス制限(EPERM 等)に当たっても、**サンドボックスを切って回避してはならない**。
     大半のラウンドはサンドボックス内で完走できる(=無効化は不要)。サンドボックス制限で
     どうしても完走できない場合は**それを失敗として報告**し、勝手にサンドボックス外実行へ
     切り替えない。隔離を破る回避は禁止。`settings.json` への `sandbox.allowWrite` 追加も禁止
     (呼び出し側も同様)
   - 2ラウンド目以降は前ラウンドの文脈:「前回これを修正した(要約)」
     「これは誤検出として理由Xで却下した(再掲不要)」を明記し、解消済み/却下済みを
     蒸し返さないよう伝える

   ### レビュー実行とタイムアウト制御
   - レビューは **`codex:codex-rescue` エージェント(`Agent` ツール、`subagent_type:
     "codex:codex-rescue"`)** で実行する。エージェントが内部で companion
     (`node …/codex-companion.mjs task`)を read-only で起動する。**`node` を Bash で
     直接叩かない**(層違い。許可ルール `Bash(node */codex-companion.mjs*)` は
     エージェント内部の node 実行を通すためのもので、呼び出し側の直打ち用ではない)
   - タイムアウトを自分で握るため、エージェントは **`run_in_background: true`** で起動し、
     同時に **締切タイマー**(バックグラウンド Bash `sleep 600` ≒10分。共有ランタイムは
     通常5〜13分かかるため短い締切は誤検知を生む)を張る

   #### 完了の判定(エージェントの応答を信頼する。companion ストリームは読まない)
   - **エージェントの応答そのものが結果**。プロンプトで「レビュー結果(指摘列挙 or `収束: 指摘なし`)を
     応答に必ず含めよ。codex が完走しなかった場合(EPERM・タイムアウト・背景化等)は失敗を明示し、
     **絶対に『収束』と返すな**」と契約させているので、`…/tasks/*.output`(companion ストリーム)を
     読んで検証する必要はない(無駄。やらない)。応答を以下で分岐するだけ:
     - **指摘列挙** → そのまま採用(照合・仕分けへ)。締切タイマーは `TaskStop`。
     - **`収束: 指摘なし`** → 収束として採用。締切タイマー `TaskStop`。
     - **失敗報告 / 「実行中です…」等の早期復帰** → 失敗ラウンド扱い。新規に codex:rescue を
       起動してやり直す(プロンプトで「`task` を前景同期実行・背景化禁止・失敗は明示」を強調)。
       背景化された codex ジョブはオーファンになるが追いかけない(`status`/`result`/`cancel` 不可)。
     - **締切タイマーが先に切れる** → ハング判定。エージェントと監視 Bash を `TaskStop` で打ち切り、やり直す。
   - 補足: ごく稀に「短時間で `収束`」が返ることがあるが、契約上それは「指摘なしの正規レビュー結果」か
     「失敗を収束と詐称した違反」のどちらか。後者を疑う場合でも**ストリームは読まず**、失敗ラウンドとして
     新規起動でやり直せばよい(やり直して再び `収束` なら正規結果と判断)。
   - **オーファンが累積して問題化したらユーザーへ通知**(`status`/`cancel` 不可で自力清掃
     できないため。掃除はユーザーの手動操作/再起動に委ねる)

   #### 再試行と継続
   - **`SendMessage` はこの環境で使えない**(ツール一覧に無い)。エージェントの継続は行わず、
     **毎ラウンド新規に codex:rescue エージェントを起動**し、プロンプトに前ラウンドの文脈
     (修正済みの要約・却下理由・今回問うこと)を要約して渡す
   - タイムアウト時も同様に新規起動して再試行(「前回タイムアウトしたので再実行」を明記)
   - **2回連続でタイムアウトしたら「問題発生」として停止**し、状況をユーザーに報告する
     (自律進行を止める)

2. **照合・仕分け**: Codex の各指摘を該当コード(必要なら仕様書 mmd_toolbox.md /
   vmd-*.md / shakevmd.md)と突き合わせて判定:
   - **修正する**(妥当 = 実コードで再現する/仕様に照らし要対応): 修正を適用し、
     テストがあればグリーンを確認(必要なら回帰テストを追加)
   - **反証する**(誤検出 = 事実誤認・不可能・対処済み・仕様で意図的にそう決めた):
     修正せず却下理由を記録(次ラウンドで Codex に伝える)
   - **保留する**(要ユーザー判断 = 仕様変更・設計トレードオフ・方針判断): 終了条件3

3. **終了判定**:
   - 指摘ゼロ → 収束終了
   - 反証済みの蒸し返しが続く/数ラウンド新規解消なし/最大ラウンド超過 → 千日手終了
   - 保留(要ユーザー判断)あり → 終了してユーザーに諮る
   - いずれでもなければ次ラウンド(手順1へ。修正点・却下理由を文脈として渡す)

4. **報告(日本語)**: 修正した指摘・反証した指摘(理由つき)・保留(要ユーザー判断)・
   終了理由(収束/千日手/要判断)をまとめて提示する。**コミットはしない**
   (コミットは別途ユーザーの指示で commit スキルに委譲)

## 注意

- 各修正後はテストでグリーンを確認してから次ラウンドへ進む
- Codex の指摘は実コード・仕様書で裏取りしてから残す/落とすを決める(誤検出除去が後段の役目)
- 千日手は「Claude が正しいと考える反証」を Codex が受け入れないケースが典型。
  無限に押し問答せず、双方の主張を要約してユーザーに委ねる
- 設計・方針への異議出しが主目的なら、前段プロンプトを挑戦的(approach/design を問う)
  に寄せてよい(/codex:adversarial-review 相当の枠組み)
