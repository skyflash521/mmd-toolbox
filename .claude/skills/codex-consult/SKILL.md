# Codex 単発相談(ハング防止付き)

Codex への**一回限りの相談・調査・診断・修正方針のヒアリング**を、`codex-watchdog` スキルの契約で
ハングを防ぎながら実行する。`codex-review-loop` と異なり、**反復・収束判定・コミットゲートは
持たない**(一回相談すれば終わり)。

## いつ使うか

- 行き詰まって Codex に一回相談したい、調査・診断を依頼したい場面。
- コミット前のレビュー収束を取りに行く場面は対象外(`codex-review-loop` を使う)。

## 起動可否

特別なゲートはない(呼び出し判断は通常どおり Claude が行う)。ただし `codex-watchdog` スキルの
「使用不可の検知と再試行」のとおり、前ラウンドで記憶した「使用不可」の状態が無いか先に確認する。

## 手順

1. **相談内容の整理**: 依頼を、Codex に渡すタスク指示文としてまとめる。グラウンド済みの事実
   (実コードで確認した内容)と、評価・判断を求める論点を分けて書き、何を達成するための相談かを
   冒頭に明記する。

2. **実行モードの決定**: 既定は**read-only**(相談・調査・診断が目的で、repo を編集させない
   ため)。ユーザーが明示的に「Codex に直してもらう/修正を実行してもらう」ことを求めている場合に
   限り、`codex-watchdog` の作法に従って write-capable(`--write`)で起動する。

3. **相談実行(1回)**: `codex:codex-rescue` エージェント(`Agent` ツール、
   `subagent_type: "codex:codex-rescue"`)を、`codex-watchdog` スキルの契約(RUNID 生成・
   `TASK-RUNID` マーカー埋め込み・起動作法・禁止記号規約・サンドボックス規約・
   `run_in_background: true` 起動・エージェント内部の同期実行契約・watchdog 監視・完了判定の
   機械的な部分)のとおりに実行する。タスク指示文には手順1でまとめた内容と、手順2で決めた
   read-only/`--write` の指定を含める。`node` を Bash で直接叩かない(層違い)。

   ### 合否解釈(codex-watchdog の機械的な判定に、相談固有の解釈を重ねる)
   - **エージェントの応答に、codex/companion/app-server が起動失敗・完走不能だったことを示す記述
     (EPERM・初期化失敗・アクセス拒否等)と、タスク内容への回答(確認結果・分析・助言等)が同時に
     含まれる場合(自己代行)** → **契約違反として失敗と同様に扱い、応答内容を採用しない**(参考にも
     しない)。「念のため自分で確認した」等の注記が付いていても、codex 自身が完走していない以上
     採用しない(`codex-watchdog` の禁止事項参照)。新しい RUNID を発行して1回だけ再試行する
     (下記「失敗と判定した場合」と同じ再試行ルールに従う)。
   - **上記の自己代行に該当せず、かつ codex が完走した(起動コマンドとエラーのみを報告する失敗報告
     ではない)応答を返す** → Codex の回答として採用する。
   - **`codex-watchdog` のフォールバック(watchdog `OUTCOME=0` だがエージェント応答が来ずログ走査で
     代替する経路)** → 抽出できた内容を**参考情報**としてユーザーへ提示してよいが、**「Codex の
     正式な回答」として断定しない**(ラウンド同一性が保証されないため)。通知取りこぼしが起きた旨も
     明示する。
   - **`codex-watchdog` が失敗と判定した場合(stall/no-start/wall-cap/失敗、エージェントの失敗報告・
     早期復帰)** → 新しい RUNID を発行して1回だけ再試行する。**再試行後に(失敗理由が初回と同じか
     異なるかを問わず)再び失敗と判定されたら、その時点で再試行を止め**、試みた内容と失敗理由
     (stall/no-start/wall-cap/失敗のいずれか、拒否されたコマンドがあればそれも)をユーザーへ平文で
     報告する(このスキルは反復ループを持たないため、`codex-review-loop` のような千日手・複数
     ラウンドの再試行はしない)。

4. **報告(日本語)**: Codex の回答の構造(判定・要約・根拠・確認事項の区別)を保ったまま提示する。
   **コミットや修正の自動適用はしない**(相談結果を踏まえてどうするかはユーザー/呼び出し元が
   判断する)。
