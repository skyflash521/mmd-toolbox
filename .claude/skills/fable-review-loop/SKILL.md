# Fable 反復レビュー・ループ(codex-review-loopのフォールバック)

`fable-reviewer` サブエージェント(read-only, Fableモデル)にレビューさせ、Claude が各指摘を
実コードで検証して修正/反証/受容/保留に仕分け、再レビューさせる反復ループ。日本語で報告する。

判断ロジック(大前提・常設観点・レビュー依頼に含めるべき共通内容・照合仕分けの定義・終了条件・
報告フォーマット)は [review-loop-judgement](../review-loop-judgement/SKILL.md) スキルを見よ。

## 起動前ガード

Codexの可用性は `codex-review-loop` の判定に従う。可用性の判定基準・手順をこのスキル側で
独自に再定義しない(判定は `codex-review-loop` の[手順0](../codex-review-loop/SKILL.md#手順0-起動可否ゲート対象確認可用性確認)を適用して行う)。このスキルを起動して
よいのは、`codex-review-loop` が(このセッション内で)使用不可と判定済みで、かつ**このループへの
切り替えをユーザーが承認済み**のときに限る(フォールバックへ進む向きの切り替えはユーザー確認を
要する。戻る向きとは非対称):

1. **この会話内**で `codex-review-loop` が直近に使用不可と判定した記録(理由・リセット予定時刻)が
   無ければ、このスキルを起動せず `codex-review-loop` を使う。
2. 記録があるときは、`codex-review-loop` 自身の[手順0](../codex-review-loop/SKILL.md#手順0-起動可否ゲート対象確認可用性確認)(可用性確認・自動復帰の判定)を適用する。
   その結果「復帰した」であればこのスキルを起動せず `codex-review-loop` を使う(戻る向きの
   切り替えはユーザー確認不要)。「まだ使用不可」であれば、**このセッション内でこのループへの
   切り替えをまだユーザーに承認されていなければ、無断で起動せずユーザーに確認する**(承認済み
   なら再確認せずそのまま次ラウンドへ進んでよい)。
3. 進行中にユーザーから「Codexに戻して」等の明示的指示があれば、直ちに本ループを打ち切り、
   `codex-review-loop` の利用へ切り替える。
4. このループの実行中に `codex-review-loop` の[手順0](../codex-review-loop/SKILL.md#手順0-起動可否ゲート対象確認可用性確認)の自動復帰条件が満たされたと分かったら、
   **ラウンドの区切りで自動的に本ループを打ち切り、`codex-review-loop` へ切り替える**
   (ユーザーへは報告するだけで、承認は待たない)。

## 手順1: レビュー実行(1ラウンド)

`Agent` ツールで以下を**同期実行**する:

- `subagent_type: "fable-reviewer"`
- `run_in_background: false`(ネイティブサブエージェントでハングの心配が無いため、
  Codex版のようなwatchdog・stall検知・タイムアウト監視は不要)
- `prompt`: `review-loop-judgement` スキルの[レビュー依頼に含めるべき内容](../review-loop-judgement/SKILL.md#レビュー依頼に含めるべき内容レビュアーに依らない共通要件)を満たすレビュー
  指示文。`fable-reviewer` はツール定義上 Read/Grep/Glob のみで編集不可なので、
  「レビューのみ・編集するな」の指示はツール権限による二重の安全網になる
- レビュー指示文に「応答の末尾に、自分のシステムプロンプトに示されている実行モデル表示名を
  そのまま記載せよ」を必ず含める(下記[既知の限界](#既知の限界自己申告に依存する検知)で使うモデル代替の検知手段)

`fable-reviewer` はモデルが `fable` に固定された専用エージェントなので、`model` を呼び出し側で
指定する必要はない。

### 失敗時の扱い

- Agent呼び出しがエラーで終わる、または応答が契約違反(観点ごとの確認結果を伴わない無指摘の
  一言、編集を試みた形跡等)の場合は失敗ラウンドとして新規エージェントで再実行する。
- **エラー内容が `fable` モデル自体の利用不可(モデル未対応・権限エラーなど、モデルを名指しする
  エラー)を示す場合は、原因を「Fableモデルが使用不可」として明示し、再試行せず直ちにユーザーへ
  報告して停止する**(このループは codex-review-loop の最終フォールバックでさらに先の代替が無いため、
  原因が恒久的な利用不可なら再試行しても解消しない)。
- **応答末尾のモデル表示名が Fable(`Fable`/`claude-fable-*`)を示していない場合は、モデルが
  黙って代替された疑いとして契約違反扱いにし、失敗ラウンドとして新規エージェントで再実行する**
  (下記[既知の限界](#既知の限界自己申告に依存する検知)参照)。
- **2回連続で失敗ラウンド扱いになったら「問題発生」として停止**し、状況をユーザーに報告する。

### 既知の限界(自己申告に依存する検知)

`fable-reviewer` は frontmatter で `model: fable` に固定されているが、組織・プロジェクト・
ユーザーいずれかのスコープの settings で `availableModels` アローリストによりFableが除外されて
いる場合、Claude Codeはエラーを出さず親会話のモデルへ黙って切り替えて実行を継続しうる。`Agent`
ツールの戻り値自体には実行モデルを示す情報が無いため、上記[失敗時の扱い](#失敗時の扱い)が求める、応答末尾への実行モデル表示名の申告
([手順1](#手順1-レビュー実行1ラウンド)のレビュー指示文で要求)がこの経路の唯一の検知手段になる。この申告は、サブエージェントの
システムプロンプトにハーネス自身が注入した表示名をそのまま書き写させるものであり、モデルが
学習知識から自己のバージョンを推測して答える場合より信頼できる。いずれかのスコープの settings で
`availableModels` が設定されない限りこの経路は発動しない。設定された場合に備えて、この申告
ベースの検知を安全網として置く。

## 手順

0. **起動可否ゲート・対象確認**: `review-loop-judgement` スキルの[手順0](../review-loop-judgement/SKILL.md#手順0-起動可否ゲート対象確認)のとおり実行する。
1. **レビュー実行**: [手順1](#手順1-レビュー実行1ラウンド)のとおり実行する。
2. **照合・仕分け**: `review-loop-judgement` スキルの[手順2](../review-loop-judgement/SKILL.md#手順2-照合仕分け)のとおり判定する。関連する仕様書
   (該当モジュール/ツール直下、必要なら `docs/specs/`)とも突き合わせる。
3. **終了判定**: `review-loop-judgement` スキルの[手順3](../review-loop-judgement/SKILL.md#手順3-終了判定)のとおり。
4. **報告(日本語)**: `review-loop-judgement` スキルの[手順4](../review-loop-judgement/SKILL.md#手順4-報告日本語)のとおり。**コミットはしない**
   (コミットは別途ユーザーの指示で commit スキルに委譲)
