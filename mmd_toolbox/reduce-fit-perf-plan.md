# 性能改善計画: 疎化ベジェフィットの高速化

ステータス: 計画(未着手)。本書は方針の確定が目的で、実装は別工程。各レバーは
**実装 → 計測 → 目標未達なら次のレバー**の順で重ねる。

## 1. 問題と要件

- **現状(実測)**: 代表入力 `tuning/dense_dance_motion_in.vmd`(88ボーン・0〜932フレーム・44687キーの毎フレーム密、
  約31秒相当)で、最多キーボーン1本(933キー)の疎化が **44.8秒**(計測条件は §2)。単純計算で **×88 ≈ 66分**。
- **要件(達成可能な形に限定する)**: 「入力長に関わらず10分以内」は入力長が無制限なので原理的に不可能。次で縛る:
  - (a) **代表入力(上記 dense_dance、~933フレーム×88ボーン)の全体処理(クリーニング+足IK安定化+疎化)を 10分以内**
    (目標は更に短く、できれば5分以内)。
  - (b) **処理時間が入力規模(フレーム数・キー数)に概ね線形**で、典型的な mocap クリップ(数十秒〜数分)が余裕で
    10分内に収まる水準にする。
  - 入力長別の計測(切詰め 200/500/933 フレーム等)で (a)(b) を確認する。
- 疎化以外(クリーニング・足IK安定化)は配列演算主体で軽い。超過の主因は疎化。

## 2. 真因(cProfile による特定。計測条件: mocapvmd 既定、現行 `max_seg=15`)

1ボーン(933キー)疎化 44.8秒の支配項(`scipy` 反復最適化):

- `scipy.optimize._lsq.trf.trf_bounds`(非線形最小二乗の本体): 1ボーンで **2053回**、cumtime 42秒。
- その残差評価 `mmd_toolbox/vmd/fit.py` の `residual` cumtime 18秒。中で純Pythonの `_bezier_y_at`
  (x→t を毎サンプル Newton 最大20回+二分法60回)を **約149万回**、内側の `_bez`/`fx`/`dfx` を数百万回評価。

真因は **`fit.py` のベジェフィットが、区間ごとに `scipy.optimize.least_squares` を複数初期値で反復し、純Pythonの
スカラー評価を多数回回す**こと。対象は**位置の `fit_bezier_curve` と回転の `_fit_coeff_curve` の両方**
(回転はカメラ・ボーンとも `least_squares` + スカラー `_bezier_y_at` を使う)。

- この 44.8秒は **現行 `max_seg=15`** での値。`max_seg` は必須境界間の事前分割数・区間長を変える(`reduce.py` の
  `_presplit`)ので perf に影響するが、支配項は **1フィットあたりの `scipy` 反復コスト**。`max_seg` はフィット数を
  変えても1フィットのコストは残すため、`max_seg` の調整だけで目標に届くとは限らない(`max_seg=180` との厳密な
  フィット回数・時間比較は別計測で残す)。

`fit.py` は **mocapvmd / sparsevmd / shakevmd が共有**する疎化エンジン。出力(量子化後の制御点バイト)が変わると
3ツールの期待値・バイト一致テストが動くため、不変条件(§3・§5)を守る。

## 3. 採否の流れ(不変条件の前提)

- **フィット**(`fit_bezier_curve` / `_fit_coeff_curve`): 複数初期値で `least_squares` を回し、**量子化前の残差コストが
  最小の解**を選ぶ。`early_exit_err` は量子化後誤差で初期値試行を途中打ち切りする。
- **区間採否**(`reduce.py`): 各チャンネルの**量子化後誤差を許容で正規化**し、全チャンネルの**最大正規化誤差 ≤ 1.0**
  なら採用、超えれば分割する。
- 品質・互換の歯止めは**区間採否(出力後の量子化後誤差を正規化した最大値 ≤ 1.0)**で、これは §4 のどのレバーでも
  保つ。フィットがどの初期値の解を選ぶか(残差最小・早期終了の先勝ち)は許容内で変わりうる(不変条件ではない)。

## 4. 改善レバー(評価回数側を削る。レバー1 → レバー2 の順で重ねる)

支配項は「内部点を持つ候補区間ごとの `least_squares` 最適化の回数 × 1回あたりの評価回数」
([mmd_toolbox.md §6.1](mmd_toolbox.md#61-コストモデルどこが支配的か))。本計画はこの支配項を
削る2レバーを採る。

- **レバー1: 線形ファストパス＋初期値順(出力が変わりうる)**
  線形制御点で許容内に収まる区間は `least_squares` を呼ばず即採用する(呼び出し回数そのものを減らす)。
  呼ぶ場合も初期値を当たりの良い順(線形・前回採用解など)に並べ、許容由来の早期終了で打ち切り回数を減らす。
  **先勝ちの初期値順序を変えるため量子化後の制御点が変わりうる**(許容内の別解)。扱いは §5 に従う。

- **レバー2: `least_squares` の収束許容緩和＋反復上限＋初期値数削減(出力が変わりうる)**
  采否は量子化後誤差で判定するので、`scipy` 既定精度(現環境 SciPy で `ftol=xtol=gtol≈1e-8`)まで詰める必要はない。
  許容を緩め(例 1e-3〜1e-4)、`max_nfev` で反復に上限を設け、初期値数を削る。反復が減って速くなるが、
  **フィット解が変わり量子化後制御点が変化しうる**。

- **棄却(採らない): 残差・ベジェ評価の numpy ベクトル化**
  `_bezier_y_at`/`residual` の配列一括化は **棄却済み**。曲線評価ループは支配項ではなく、小区間では numpy の
  固定オーバーヘッドが上回って **むしろ遅化**する(出力はビット一致・速度のみ悪化)。複数回実装・計測して棄却された。
  詳細は [mmd_toolbox.md §6.2](mmd_toolbox.md#62-棄却済み最適化曲線評価の-per-sample-numpy-ベクトル化)。本計画では着手しない。

## 5. 不変条件と出力変化の扱い

- **采否の歯止めは「区間の最大正規化誤差 ≤ 1.0(許容内)」**(§3)。許容内で疎化する性質・キーの粗密の妥当性は
  変えない。フィットの初期値選択は許容内で変わりうる(残差最小は保証しない)。**決定論**を保つ(同入力・同引数で同出力)。
- **レバー1・2**: いずれも出力(量子化制御点)が変わりうる。採用時は (a)変化が「許容内の別解」に留まることを
  テストで担保、(b)3ツール(mocapvmd/sparsevmd/shakevmd)の期待値・バイト一致テストの更新要否を洗い出し、
  (c)疎化品質(キー削減と再生の自然さ)を代表入力で確認してから入れる。各レバーは効果が出る最小の変更に留め、
  目標に届いた時点で次レバーは採らない。

## 6. 目標・計測・段取り

- **計測の安全策(暴走防止)**: (i)各レバーの効果は **1ボーン単位**で測る(`fit_bezier_curve`/`_fit_coeff_curve` の
  時間・呼び出し回数)。(ii)全体計測は **入力を 200/500/933 フレームに切詰めた3点 ＋ 全体**で行い、各実行に
  **明示の上限時間を設け、子プロセスごと確実に停止できる手段(サブプロセス実行＋タイムアウト)で回す**
  ([mmd_toolbox.md §6.4](mmd_toolbox.md#64-暴走防止性能計測性能テストの作法))。性能チューニングはミスると
  フィットが収束せず止まりうるので、性能ガードのテストも対象処理をサブプロセスで実行し上限超過を失敗として
  検出し、pytest スイート全体を巻き込まない。
- **段取り**(各段 実装→計測→`pytest` 緑→レビュー→コミットのマイクロループ):
  1. **レバー1** → 1ボーン＋長さ別計測 → 出力変化の扱い(§5)→ 緑＋品質確認 → レビュー → コミット。
  2. 目標未達なら **レバー2** → 計測 → §5 → 緑＋品質確認 → レビュー → コミット。
  3. 各コミット後、代表入力で全体時間と入力長別スケール(§1 (a)(b))を上限時間厳守で計測し、要件を確認する。

## 7. スコープ外

- 解析直接フィット(`shakevmd/analytic-direct-fit-plan.md` の B-2'。サブフレーム品質の別件で、本書の出力不変方針とは別)。
- 疎化の分割戦略・カット検出・許容誤差プリセット値の設計変更。
- `max_seg` の値や sparsevmd の `--max-segment-frames` 既定の見直しは**編集容易性の観点の別件**。ただし `max_seg` は
  事前分割で perf にも影響するため「性能と無関係」ではない。本書は真因(1フィットあたりの `scipy` コスト)の解消を主とし、
  `max_seg` 調整は補助・別件として扱う。
